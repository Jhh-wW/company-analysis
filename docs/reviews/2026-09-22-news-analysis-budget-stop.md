# 뉴스 분석 예산 소진 뒤 불필요한 본문 요청 중단

2026-09-22 · 사용자 로그인 내부 브라우저 확인 후 수행

## 문제와 변경

뉴스 분석 호출 예산이 소진돼도 수집기는 다음 배치의 기사 본문을 먼저 읽고, 분석 호출 직전에야 중단했다. 뤼튼 운영 진단의 본문 읽기 15개와 분석 3회는 서로 다른 단계의 수치다. 이 차이만으로 실제 15개가 모두 분석됐다고 볼 수 없다.

현재 코드의 무료 회귀 시험에서 분석 예산 0·1·3회일 때 각각 본문 요청 4·8·16회를 재현했다. 다음 분석 호출을 할 수 없으면 새 본문 요청도 예약하지 않도록 수정한 뒤 요청이 각각 0·4·12회로 줄었다. 순차 실행과 최대 3개 동시 실행에서 같은 결과다. 이 숫자는 외부 공급자를 대역으로 바꾼 합성 시험이며 운영 절감률은 아니다.

회사·원문 검증 규칙, 분석 모델, 분석 호출 상한, 기존 채택 근거는 변경하지 않았다. 예산을 정확히 다 쓰면서 모든 후보를 처리한 경우에는 잘못된 예산 소진 경고를 추가하지 않는다. 동일한 4개 기사의 최종 근거·기사 객체가 제한 없는 기존 경로와 일치함을 비교했다.

## 검증

- 새 회귀 시험: 수정 전 **6개 실패·2개 통과**, 수정 후 **8개 통과**.
- 뉴스 수집 전체 및 뉴스 스위치: **575개 통과, 15.00초**. 앞의 8개를 포함하므로 합산하지 않는다.
- 초기 실행 한 번은 임시 폴더의 상위 경로가 없어 준비 단계에서 실패했다. 폴더를 만든 뒤 재실행했으며 제품 결함으로 집계하지 않는다.
- `app/conftest.py`의 공통 DB·관측 격리를 유지했고 `STORAGE_DB_PATH`도 별도 임시 경로로 지정했다. 기존 로컬 저장소와 운영 DB는 시험에 사용하지 않았다.
- 시험에서 기사·검색·AI 응답은 대역이며 추가 유료 보고서를 생성하지 않았다.
- 변경 파일은 `news_intake/collection.py`, `news_intake/constants.py`, `news_intake/tests/test_analysis_budget_prefetch.py`다. Claude가 별도로 진행 중인 PDF 품질 수정 파일은 편집하지 않았다.

## 남은 범위

이 변경은 사용할 수 없는 본문 요청의 낭비를 줄인다. 뤼튼의 검증 통과 0건 전체를 해결하는 변경이 아니다. 매체 등록, 회사 별칭, 원문·주체 결속의 개별 탈락 대조와 수정은 여전히 필요하다. 운영 배포와 새 보고서 품질 검증도 이번 변경 완료에 포함하지 않는다.

사용자가 로그인한 내부 탭에서 관리자 대시보드 및 [해당 실행의 진단 화면](https://company-analysis-beta.onrender.com/admin/runs/b0fa583b8249006769d57b4a8c23fd15/diagnostics)을 실제로 열었다. 화면의 54개 단계 중 뉴스 단계에서 검색 200·선별 56·본문 시도 20·본문 읽기 15·분석 3회·검증 및 본문 사용 0을 다시 확인했고 이전 운영 DB 조회와 일치했다. 조작에는 [Orca CLI 스킬](C:/Users/jh-wo/.agents/skills/orca-cli/SKILL.md)을 사용했다.
