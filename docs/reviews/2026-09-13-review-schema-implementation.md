# 검수 형식 재시도 개선

정상 검수의 비용을 늘리지 않도록, 기존 본문·독립 도식 검수에서 JSON 판독에 실패해 재요청하는 경우에만 공급자의 JSON 출력 계약을 사용한다. 최초 호출과 재시도 없는 묶음 검수는 기존 방식 그대로다. 검수 모델, 원문, 기존 재시도 횟수, 의미 검증과 공개 제외 규칙을 유지한다.

이 변경의 목적은 형식 재시도마저 잘못된 JSON으로 끝나는 위험을 줄이는 것이다. 정상 보고서의 큰 폭 비용 절감이나 실제 재생성 비용 절감은 아직 확인하지 못했다. 기존 반복 입력·JSON 공백 축소 변경은 별도 [측정 기록](2026-09-13-prompt-cost-implementation.md)에 있다.

## 운영 기록에서 확인한 문제

2026-09-13 운영 DB를 읽기 전용 연결과 `PRAGMA query_only=ON`으로 조회했다. 최근 100건까지 요청했으나 저장된 진단은 31건이었고, 그중 본문 검수 판독 기록이 있는 실행은 4건이었다. 나머지 27건을 형식 오류 0건으로 계산하지 않았다.

- 현대글로비스 실행 `774c34aead1c`는 최초 검수 73행 모두 판독 성공했다. 전체 AI 원가는 721.61원이고 본문 검수는 160.23원이었다. 이 실행에 이번 변경으로 절약됐다고 주장할 형식 재시도 비용은 없다.
- 실행 `c40acd521983`는 공급자 종료 사유가 `end_turn`이지만 68행 전체가 `json_syntax`로 판독되지 않았다. 본문 검수 비용은 199.33원, 전체 원가는 713.14원, 결과는 게이트 중단이었다. 진단에는 요청 예산 소진도 기록됐다. 전체 원가를 확정 절감액으로 보지는 않는다.
- 나머지 2건은 최초 판독에 성공했다. 이 표본에서 `시도 > 1`인 본문 판독 기록은 없었다. 재검수·요약 등 다른 호출도 같은 `v2_review` 단계에 들어가므로 비용 사건의 수만으로 형식 재시도 비용을 계산하지 않았다.

조회 당시 운영 커밋은 `eaa20aedd51b7b7c0b5fcc66d79e8842aaaab5ff`였다. 소수 표본이며, 상세 진단 도입 시기와 저장 누락에 영향을 받는다. 독립 도식에는 같은 상세 판독 기록이 없어 도식 오류 빈도를 확정하지 못했다.

## 최종 변경

- 본문 `flat`과 독립 도식의 기존 형식 재시도 문자열에만 `ReviewPrompt.response_schema`를 붙인다. 최초 builder는 일반 문자열을 반환한다. `grouped` 검수의 1회 호출 계약은 유지한다.
- 공급자 연결부는 표시된 요청만 `output_config.format.type=json_schema`로 전송한다. 표식이 없는 작성·검수의 요청과 작성용 캐시 블록은 유지한다.
- 수치의 직접 인용·앞 행 원문 참조, 추세 관측, 활동 시점, 역할·과금·인과관계, 미래 계획 근거의 구조를 보존한다. 근거의 생략을 거짓 증명으로 채우지 않는다.
- 생성 계약에서는 기존 지시대로 정수 번호와 대조 설명을 요구한다. 기존 파서는 설명이 없는 구형 응답과 숫자 문자열 번호를 계속 읽는다.
- SDK가 정규화한 출력 계약을 무료 토큰 계수에도 함께 전달한다. 계수 실패 시 기존 전체 요청의 보수적 추정과 예산 차단을 사용하고, 실제 비용은 공급자 사용량으로 정산한다.
- 새로운 유료 재시도나 비구조화 출력 재호출을 추가하지 않는다. 기존 허용 횟수의 형식 재시도만 바꾼다.
- 별도로 병합된 PR #81의 초기 검수 재요청 호출자·동적 출력 한도·예약액 계산을 통합한 상태에서 검증한다. 이번 변경으로 그 한도를 다시 조정하지 않는다.

공급자의 형식 강제는 의미의 정확성을 보장하지 않으며, 거절·출력 한도 도달 시 정상 구조가 반환되지 않을 수 있다. 그래서 기존 파서와 원문 결속 검사를 유지한다. [Anthropic 구조화 출력 문서](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)

## 실제 공급자 시험

같은 합성 자료와 검수 프롬프트를 `claude-haiku-4-5-20251001`, 온도 0으로 비교했다. 첫 스키마는 실제 API에서 문법 크기 초과로 거절됐다. 불필요한 행 분기를 없애고 설명·번호 타입을 기존 생성 지시에 맞춘 뒤, 본문·묶음·도식 세 스키마가 모두 `end_turn`으로 응답했다. 묶음 스키마는 초기 적용 비용을 알아보기 위한 비교였으며 최종 코드에서는 사용하지 않는다.

| 작은 검수 표본 | 기존 입력/출력 토큰 | 형식 강제 입력/출력 토큰 | 기존 원가 | 형식 강제 원가 |
|---|---:|---:|---:|---:|
| 본문 3행 | 9,997 / 669 | 12,638 / 557 | 18.68원 | 21.60원 |
| 묶음 3행 | 11,211 / 694 | 13,872 / 631 | 20.56원 | 23.84원 |
| 독립 도식 2행 | 8,561 / 100 | 11,202 / 87 | 12.69원 | 16.30원 |

본문·묶음 비교의 출력 상한은 1,800, 도식 비교는 600으로 양쪽이 같았다. 모두 상한에 닿지 않았다. 출력 토큰은 줄었으나 스키마 입력이 추가되어 원가가 증가했다. 이 결과 때문에 최초 검수 전체 적용을 채택하지 않았다. 최종 재시도에서도 공급자 입력 비용은 추가되므로 재시도 단가 자체가 낮아졌다고 설명하지 않는다.

응답을 기존 본문·묶음·도식 검증기에 다시 넣었을 때, 양쪽 모두 정상 수치 1행을 유지하고 잘못된 금액·추세 2행을 제외했다. 도식은 양쪽 모두 정상 제품 1행을 유지하고 근거에 없는 제품 1행을 제외했다. 이 작은 비교는 전체 회사·보고서 품질의 동등성 검증이 아니다.

추가로 실제 재요청 문구를 붙여 추세·개발 역할·미래 계획의 정상 주장 3행을 시험했다. 역할·계획은 유지됐고, 추세 주장은 모델이 반환한 근거의 결속 문제로 기존 검증기가 제외했다. 관측 3개는 정상이었지만 수치의 `원문값`이 `2025년 120억원`으로 작성되어 실제 인용 `매출액 | 2025년 | 120억원`에 연속해서 존재하지 않았다. JSON 구조가 맞아도 사실의 누락·잘못된 근거 표현이 남을 수 있음을 보여준다. 이 사례를 통과시키려고 검증기를 완화하지 않았다.

성공한 시험 7회 사용량의 환산 원가는 총 **136.95원**이다. 최초 400 오류는 사용량이 없어 0원으로 확정하지 않았고, 해당 요청의 보수 예약액 34.1082원을 합쳐도 171.0582원으로 사전 설정한 200원 이내다. 실제 결제 청구서나 운영 보고서의 고객 청구액이 아니며, 시험은 운영 DB·앱 파일 변경이나 보고서 생성 없이 별도로 수행했다. [호출 사용량과 응답 기록](2026-09-13-review-schema-probe.json)

## 검증과 배포 상태

새 JSON 계약은 시험 전용 `jsonschema` 검증기로 원본·SDK 변환 스키마에 정상 근거를 대조한다. 직접·참조 수치, 선택 필드 생략, 추세·시점·역할·과금·미래 근거와 잘못된 근거의 공개 제외를 확인한다. 의존성은 `.github/requirements-ci.txt`에만 추가했다.

최초 호출에 스키마가 없고 기존 형식 재시도에만 전달되는지, 초기 재시도 전용 호출자와 동적 상한이 유지되는지, 비용 계수·예약·실제 정산이 일치하는지 통합 시험으로 확인했다. 최종 본문 전체 및 네이티브 계량 시험 2,616개가 통과했고, 독립적으로 작성한 통합 시험 9개도 통과했다. 본문 전체 시험에는 기존 경고 11개가 남았다. 저장소 전체 자동 시험 결과는 PR #80의 검사 결과에 기록한다.

이번 개선은 검토용 PR에 포함하며 운영에 배포하지 않는다. 정상 생성과 의미가드 보존을 확인했더라도 실제 형식 재시도 실패율·재생성 횟수·평균 비용 개선은 배포 후 별도로 측정해야 한다.
