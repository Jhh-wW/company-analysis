# 뉴스 본문 동시 수집 독립 시험

작성일: 2026-09-22. 담당: Astra 독립 시험 작업자.

`app/src/features/news_intake/tests/test_body_prefetch.py`에 작성한 독립 모듈 시험 **49개가 통과**했다. Fable이 복구한 `test_collection_body_concurrency.py`의 통합시험 24개와 함께 실행한 최종 결과는 **`73 passed in 3.34s`**이다. 운영 코드와 통합시험 파일은 수정하지 않았으며 유료 API, 외부 통신, 배포, 커밋, 푸시는 실행하지 않았다.

## 검증 근거

| 대상 | 실제 확인 방법과 결과 |
| --- | --- |
| 본문 I/O 동시 상한 2·3 | 서로 다른 호스트의 본문 콜백을 Event로 붙잡았다. 해제 전 활성 콜백이 설정 폭에 정확히 도달하고, 두 배 수의 작업을 제출해도 전체 실행의 최대 활성 수가 그 폭을 넘지 않았다. |
| 같은 호스트 제한 | 실행기가 생성한 실제 호스트 슬롯을 사용해 `media.example`과 `www.MEDIA.example`를 함께 제출했다. 첫 본문이 붙잡힌 동안 같은 호스트 작업은 대기하고 다른 호스트는 완료했다. 기본 최대 활성 수는 1이고, 명시적으로 호스트 폭 2를 허용했을 때는 전체 폭 3에서도 같은 호스트가 정확히 2개까지만 겹쳤다. |
| 완료 순서와 후보 식별 | 세 작업 모두 본문에 들어간 뒤 Event를 후보 역순으로 해제했다. 완료 순서는 2→1→0이며 각 Future의 후보와 본문은 원래 제출 대상에 결속됐다. 최종 collection의 선택·정렬 동치는 별도 통합시험 범위다. |
| 기본 순차 실행 | 동시 옵션 미지정 및 폭 1은 호출 스레드에서 즉시 실행됐으며 스레드 실행기를 만들지 않았다. |
| Context 복사 | 두 제출 시점의 서로 다른 ContextVar 값이 Barrier에서 실제로 겹치는 작업에 각각 전달됐다. 작업 내부 변경은 다른 작업이나 부모 문맥으로 새지 않았다. |
| 실제 호출횟수 상한 | 12개 스레드를 Barrier로 동시에 출발시켜 3회분을 경쟁시켰다. 직접 소비와 예약 후 소비 모두 성공한 실제 호출은 정확히 3개였다. 금액 원장이나 유료 호출을 사용하지 않았다. |
| 미사용 예약 반환 | 예약 자체는 실제 호출 수를 늘리지 않았다. 원문 성공 후 남은 포털 예약, 중단, 치명예외의 잔여 예약이 반환됐고 이중 반환으로 잔액이 늘어나지 않았다. |
| 동시 폴백의 예산 | 서로 다른 호스트에서 시작한 세 본문 요청이 Barrier에 함께 도달했다. 3회 상한을 모두 사용한 뒤에는 포털 요청이 추가되지 않았다. |
| 원문→포털 판정 유지 | HTTP 403, 알 수 없는 실패, 메타 설명, 미처리 HTML, 해독 깨짐, 짧은 본문, 비신뢰 리다이렉트, 잘못된 날짜, 미래 날짜, 기간 밖 날짜를 원문에서 주입했다. 각 사유가 유지되고 포털 본문·실제 URL·발행일 보정·발행처가 올바르게 반환됐다. |
| 날짜·신뢰 경계 | 수집일 및 12개월·36개월 경계 날짜를 허용했다. 기사 메타 날짜가 없으면 검색 날짜와 출처 표기를 유지했다. 확인된 뉴스 발행자 분류 없이 포털을 신뢰하지 않았으며 비신뢰 원문을 건너뛸 때 호출 수를 쓰지 않았다. |
| 중단·마감·예산 재확인 | 요청 시작 전과 호스트 슬롯 대기 후 각각 stop/deadline/budget 경계를 주입했다. 모든 경우 콜백 전송은 0회였다. |
| 실패·취소 후 추가 요청 | 실행 중 중단 뒤 실패 반환 또는 예외가 발생해도 포털로 진행하지 않았다. 치명예외는 상위로 전달되고 호스트 슬롯이 해제됐다. 대기 Future를 취소하면 본문 콜백이 실행되지 않았고 제출자가 예약을 반납했다. `close()`는 실행 중 작업을 기다리는 동안 대기 작업을 취소했다. |

속도 차이 또는 `sleep` 경과시간을 동시성 근거로 사용하지 않았다. Event·Barrier·Future 대기는 각각 5초 제한을 갖는다. 정리 단계는 중단 신호를 보내고 모든 시험용 Event를 해제한다. 아래 실행은 pytest 전체를 별도 프로세스의 90초 제한 안에 두므로 실행기 자체가 교착해도 무한히 대기하지 않는다.

## 재현 명령

저장소 루트의 PowerShell에서 실행한다. 지정된 가상환경과 전용 임시 경로를 사용한다.

```powershell
$env:PYTHONPATH = 'app'
@'
import subprocess
import sys
sys.exit(subprocess.run([
    sys.executable, '-m', 'pytest',
    'app/src/features/news_intake/tests/test_body_prefetch.py',
    'app/src/features/news_intake/tests/test_collection_body_concurrency.py', '-q',
    '--basetemp=.tmp/news-prefetch-astra',
    '-o', 'cache_dir=.tmp/news-prefetch-astra-cache',
], timeout=90).returncode)
'@ | & .venv/Scripts/python.exe -
```

## 검토사항과 총괄 보강

독립 검토 시 `BodyFetchLane.close()` 뒤 `submit(fetch_article_body)`가 순차 모드로 다시 본문을 요청하는 것을 재현했다. 총괄은 이후 종료 상태와 상태 잠금을 추가해 재제출을 거부하고, `close()` 자체에서 중단 신호도 보내도록 보강했다. 순차·동시 폭별 재제출 거부와 종료 중 포털 폴백 차단 시험 5개를 추가했다.

기존 `collection.py`는 `finally`에서 중단 후 종료하고 재제출하지 않아 정상 호출 경로의 추가 전송 결함은 재현되지 않았다. 이번 보강은 실행기 자체에도 이 종료 계약을 명시한 것이다. 추가로 취소·빌드 변경·Future 취소가 기사 실패나 분석 실패로 삼켜지지 않도록 재전파하고 시험 9개를 추가했다. 보강 후 뉴스 기능 전체 **558개가 통과**했다.

## 시험 파일 보존 확인

작성 중 같은 시험 경로에 Fable의 통합시험이 먼저 생성됐을 가능성을 확인했다. 최초 파일 목록에는 해당 시험 파일이 없었으나 패치 직전 존재 여부를 다시 확인하지 않은 점은 작업자의 실수다. 총괄의 조율에 따라 독립시험은 현 경로에 유지하고 Fable이 통합시험을 **`test_collection_body_concurrency.py`**로 복구했다. 최종 두 파일의 합동 실행에서 독립 49개와 통합 24개, 총 73개가 모두 통과해 양쪽 시험의 보존을 확인했다.

## 범위와 한계

독립시험은 주입한 오프라인 본문 콜백의 겹침과 모듈 계약을 검증한다. 실제 네트워크 전송기의 내부 재시도 횟수 및 ContextVar 안의 가변 객체 격리는 증명하지 않는다. 전체 collection의 후보 선택·기간별 이월·본문 글자 상한·최종 진단 동치는 Fable 소유 통합시험 범위이며 이번에는 해당 24개 시험의 합동 통과까지 확인했다. 취소되어 시작하지 않은 작업은 본문의 `finally`가 실행되지 않으므로 제출자가 예약을 반환해야 한다는 현 계약을 시험에 명시했다.
