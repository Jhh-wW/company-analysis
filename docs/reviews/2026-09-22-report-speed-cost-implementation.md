# 보고서 속도·비용 개선 구현

2026-09-22 · 총괄 통합 기록 · 실제 서비스 배포 전

보고서 내용을 줄이지 않고 기다리는 시간을 겹치는 방식이다. 아홉 장을 한 장씩 쓰던 FULL 작성은 안전한 호출 경로에서 최대 세 장씩 쓴다. 모델, 장별 자료, 작성 지침, 출력 상한, 검수와 출고 기준은 유지한다. 이전 장의 문장을 참고하는 기존 작성 방식은 계속 순차 실행한다.

## 장별 동시 작성

장별 입력과 실적표 인용을 먼저 검증한 뒤 부모 실행 문맥에서 유료 단계와 지연 클라이언트를 준비한다. 자식마다 별도 문맥을 복사하고, 결과는 완료 순서에 관계없이 원래 목차 순서로 합친다. 치명적 실패가 관측되면 새 작업 배정을 멈추고 이미 시작한 요청은 정산이 끝날 때까지 기다린다.

호출 장부는 작업을 배정할 때 장 ID와 순서를 고정하되, 실제 완료하거나 실패한 호출만 영수증으로 남긴다. FULL의 최초 작성 아홉 번과 묶음 검수 한 번 계약을 유지한다. 원문 없는 `v2_작성_실행방식` 기록에 동시 상한·장 수·작성 소요 시간을 담아 실행 진단으로 전달한다.

## 비용 보호

호출별 단계·캐시 설정·후속 호출 예약을 불변 문맥으로 나누고, 총 호출 수와 사용량 합산을 잠금으로 보호한다. 프로세스 전체 공급자 호출도 함께 제한한다. SQLite 원장은 명시적으로 허용된 본조사 경로에서만 최대 세 건의 예상액을 원자적으로 예약한다.

형제 요청이 잠시 돈을 예약하고 있으면 정산을 기다린 뒤 다시 계산한다. 실제 사용액과 다음 호출 예상액만으로 한도를 넘으면 기존대로 중단한다. 한 요청이 실패하거나 사용량이 불명확해져도 이미 전송한 나머지 요청의 정산은 보존한다. 취소·소유권·임대 만료 검사도 유지한다.

독립 검토에서 발견한 초과 정산 문제도 수정했다. 예를 들어 300원을 예약하고 실제 비용이 420원이 나온 경우, 이미 전송한 형제의 보호 금액이 새로운 사용 가능 잔액으로 되살아나지 않는다. 마지막 정산 뒤 예약액은 0원이고 신규 요청은 차단된다.

## 검수 지침 재사용

검수 프롬프트의 고정 지침에만 선택적으로 캐시 표식을 붙인다. 원문·후보·모델·출력 상한·응답 스키마와 실제 호출 수는 바꾸지 않는다. 형식 재시도에서도 캐시 경계와 기존 스키마를 함께 보존한다.

캐시는 기본적으로 꺼져 있다. 한 번만 만들 때는 캐시 저장 할증이 붙을 수 있으므로 무조건 켜지 않는다. 같은 지침을 짧은 시간에 반복 사용하는 환경에서만 실제 캐시 쓰기·읽기 토큰과 전체 원가를 확인해 켠다. 캐시를 채우기 위한 추가 AI 호출은 없다.

## 기사 본문 동시 수집

같은 기간·같은 분석 묶음 안의 기사 본문을 최대 두 건씩 읽도록 운영 기본 콜백을 연결한다. 같은 호스트에는 한 번에 한 건만 보내며, 원문·포털·발행일·중복·분석 묶음은 기존 후보 순서로 판정한다. 다음 기간을 미리 읽거나 분석 호출을 추가하지 않는다. 동시 안전성이 확인되지 않은 주입 콜백은 순차로 실행한다.

실제 요청 수 상한과 후보 순위별 예약을 유지한다. 다만 먼저 시작한 본문이 중복 또는 글자 한도로 버려질 때는 순차보다 HTTP 요청이 조금 늘 수 있다. 이 요청도 상한에 포함하고 미사용 진단으로 남긴다. AI 호출 수가 늘어나는 변경은 아니다.

본문 실행기는 종료 뒤 새 작업을 거부하고, 취소·빌드 변경·시간 제한을 기사 한 건의 실패로 숨기지 않는다. 비용 예약과 별개인 읽기 전용 검사를 추가해 취소·전체 마감·관측된 임대 실패·닫힌 이용 링크를 확인한다. 이 검사로 유료 단계나 비용 예약을 새로 열지 않는다.

DNS·접근 규칙 캐시와 진단 목록은 작업마다 분리하되, 완료된 규칙은 수집 한 건 안에서 잠금으로 보호해 재사용한다. 같은 언론사 기사 세 개에서도 접근 규칙은 한 번만 읽는다. 원래의 요청별 시간 제한과 상위 절대 마감을 유지하며, 속도를 얻기 위해 정상 기사에 줄 대기 시간을 줄이지 않는다.

## 설정과 복귀

| 설정 | 기본값 | 의미 |
|---|---:|---|
| `REPORT_WRITER_MAX_PARALLEL_CALLS` | 3 | 안전성이 확인된 장별 작성의 동시 상한. 1이면 작성 자체를 순차 실행한다. |
| `PROVIDER_MAX_CONCURRENT_CALLS` | 5 | 프로세스 전체 공급자 호출 상한. 허용 범위 1~5. |
| `COMPOSER_REVIEW_PROMPT_CACHE_ENABLED` | 꺼짐 | 검수 고정 지침 캐시. 반복 사용 이익을 관측할 환경에서만 켠다. |
| `NEWS_BODY_FETCH_CONCURRENCY` | 2 | 운영 기본 본문 수집 동시 상한. 1이면 순차, 최대 3. |

잘못된 동시 상한 설정은 1로 내려간다. 유료 단계별 금액 한도와 요청 전체 호출 한도는 늘리지 않았다.

## 오프라인 속도 확인

[시험 기록](2026-09-22-section-parallel-offline-benchmark.json)은 가짜 공급자가 호출마다 80밀리초 기다리는 작성 시험이다. 세 번씩 실행한 중앙값은 순차 724.35밀리초, 세 장 동시 242.77밀리초였다. 입력과 결과가 같고 두 방식 모두 정확히 아홉 번 호출했다. 유료 API 호출은 0회였다.

이 수치는 대기 시간을 겹치는 구현이 작동한다는 증거다. 실제 보고서 전체 시간이나 요금의 실측값은 아니다. 실제 반감 여부는 동일 회사·동일 자료 조건에서 전체 시간, 작성 시간, 사용 토큰, 원가, 완성도와 최종 출고 통과를 비교해야 확인할 수 있다.

## 검증 범위

유료 API와 실제 외부 기사 요청 없이 가짜 응답으로 검증했다. 모델 품질의 실서비스 동등성을 새로 측정한 결과는 아니며, 같은 입력·검수 기준·호출 수·정산·취소 계약을 유지하는지 확인한 것이다.

- 앱 전체 1차 실행: 11,847개 통과, 기존 취소 시험 2개 실패. 안전 검사 횟수에 의존하던 시험을 실제 첫 전송 뒤 취소하도록 고친 뒤 관련 37개가 통과했다. 서비스의 취소 검사를 제거하지 않았다.
- 뉴스 최종 보강: 558개 통과. 장별 동시 작성까지 포함한 앞선 묶음은 565개 통과했으며 두 집합은 중복된다.
- 읽기 전용 취소·마감 검사와 기존 웹 회귀: 77개 통과.
- 최종 웹 전체 회귀: **1,607개 통과**, 로컬 통합 표식 3개 제외. 외부 패키지의 기존 사용 중단 예정 경고가 있었으며 실패는 없다.
- 요청별 시간 제한 보강 후 파이프라인·홈페이지·뉴스·핵심 어댑터 전체 재검증: **2,662개 통과**, 1개 건너뜀, 하위 시험 10개 통과. 웹 전체와 서로 다른 시험 파일 집합으로 최종 두 묶음은 **4,269개 통과**다.
- 분석 엔진 563개, 배포 검사 123개, 운영 도구 135개 통과. 운영 도구 3개는 환경 조건으로 건너뛰었다.

시험 건수는 반복 실행과 겹치는 파일을 단순 합산하지 않는다. 실제 서비스 배포·커밋·푸시는 하지 않았다.
