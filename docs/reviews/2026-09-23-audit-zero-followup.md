# 감사보고서 평문 표의 실제 0 보존 후속 수정

작성일: 2026-09-23. 기준 코드는 `22844768`이며, 작업 시작 브랜치는 `fix/report-quality-two-pdfs-20260922`이다. 최종 통합 대상은 총괄이 관리하는 `fix/report-quality-integration-20260922`이며 이 작업에서는 브랜치 변경·커밋을 수행하지 않았다.

## 결론

감사보고서 평문에서 실제 숫자 0을 버리고 다음 계정의 금액을 가져오던 결함을 공개 함수 `parse_audit_financials`에서 재현하고 수정했다. XML에서 빈 금액 칸 대신 주석 번호를 금액으로 옮기는 같은 결함도 독립적으로 재현하여 보완했다. 최종 관련 회귀는 **108개 통과**했고 기존 공개 fixture 세 개의 평문·XML 결과 여섯 벌은 수정 전과 전체 payload가 같다.

총괄에게 재현과 수정범위를 `orca orchestration ask`로 전달한 뒤 승인을 받았다. 총괄은 다른 PDF 작업자와 수정이 겹치지 않음을 확인하고 해당 기능의 소유권을 부여했다. 제품 수정은 `app/src/features/audit_financials/logic.py`, `constants.py`에 한정했으며, 시험은 같은 기능의 `tests/test_plain_amounts.py`에 추가했다.

## 원인과 수정 전 재현

공통 머리말은 다음과 같다.

```text
손익계산서 2025.01.01부터 2025.12.31까지
2024.01.01부터 2024.12.31까지 (단위: 원)
```

| 입력 본문의 핵심 | 수정 전 공개 파서 결과 | 수정 후 |
| --- | --- | --- |
| 매출액 `0 90,000`, 영업이익 `20,000 10,000`, 당기순이익 `5,000 4,000` | 매출액이 당기 `90,000`, 전기 `20,000`으로 이동 | 매출액 당기 `0`, 전기 `90,000` 보존 |
| 세 계정이 모두 `0 0` | 표 없음, `금액 미확인` | 두 해의 모든 원수치·표시값이 `0`인 표 생성 |
| 매출액 `- 90,000` | 당기 `-90,000`, 전기에는 다음 계정 `20,000` | 결측으로 거절, 표 없음 |
| 매출액의 당기 빈칸과 전기 `90,000` | 전기 값과 다음 계정 값으로 두 해를 채움 | 결측으로 거절, 표 없음 |
| 인이지 XML의 당기 매출액 셀만 빈칸 또는 대시로 교체 | 주석 `19`를 당기 매출액으로 사용 | 해당 기간 셀을 결측으로 거절 |
| 매출액 `0`, 이어서 부문매출액 `30,000 25,000` | 다른 계정명 안의 `매출액`을 찾아 사용 | 계정명의 일부를 대체 근거로 사용하지 않음 |

평문 `_plain_observation`은 계정 뒤 260자를 훑어 쉼표가 있는 숫자를 우선 선택했다. 실제 0에는 쉼표가 없어 탈락하고, 검색 창이 다음 계정까지 이어져 그 숫자가 당기·전기 금액으로 들어갔다. 전체 0에서는 여러 계정의 숫자가 한꺼번에 모여 기간 수 검사를 통과하지 못했다. 같은 정규식은 단독 대시와 다음 칸의 숫자를 공백 너머로 붙여 음수로 읽기도 했다.

XML `_row_amounts`는 금액으로 읽히지 않는 셀을 먼저 버리고 남은 숫자의 끝에서 기간 수만큼 선택했다. 그 결과 빈 금액 셀의 자리에 앞쪽 주석 번호가 들어왔다.

## 수정 내용

- 평문은 계정 바로 뒤의 연속 숫자 구간만 읽으며, 쉼표 유무에 따른 우선순위를 없앴다. 숫자 수가 기간 수와 맞고 각 숫자를 온전히 읽을 수 있어야 원래 순서대로 채택한다.
- 독립된 대시와 공백 뒤 숫자를 합치지 않는다. 빈칸·대시·설명문·다른 계정의 값으로 부족한 금액을 메우지 않는다.
- 주석 열이 머리말에 명시된 경우에만 맨 앞의 단일 양의 정수 주석 번호를 제외한다. 상한은 기능 내부 상수 `PLAIN_NOTE_NUMBER_MAX`로 옮겼다. 주석 번호와 결측 금액을 구별할 수 없으면 빈 결과를 돌려준다.
- `2025 0`처럼 정확한 금액 위치에 있는 숫자는 정상 양수와 0으로 보존한다. 숫자 범위만으로 연도라고 추정하지 않고 `년`, `월`, `일`, `기말`, `기초` 등 명시된 기간 문맥을 거절한다. 날짜 구분자가 남은 구간도 금액 토큰으로 온전히 읽히지 않으면 거절된다.
- XML은 오른쪽의 실제 기간 셀 위치를 먼저 고정한 뒤 검증한다. 그 셀의 결측을 주석 번호로 대체하지 않는다.
- 계정 셀이 확인된 XML의 결측은 태그 제거 재시도로 복구하지 않는다. 같은 XML의 평문 사본을 두 인자로 함께 준 경우에도 중복 재시도로 결측을 되살리지 않는다. 구조화된 계정 셀이 없는 XML의 평문 대체 경로는 유지했다.
- 다른 기능으로의 직접 import를 추가하지 않았으며, 파이프라인 제품 코드와 표시 단위·반올림·근거 지문 계약을 수정하지 않았다.

## 검증

1. 수정 전 기존 기능 시험과 감사보고서 파이프라인 대체 경로 시험: **20개 통과**. 기존 시험만으로는 결함을 발견하지 못했다.
2. 제품 수정 전에 추가한 최초 공개 파서 회귀 81개: **62개 실패, 19개 통과**. 0의 계정·기간 이동, 전체 0 누락, 결측·주석 오연결을 확인했다.
3. 경계 보완과 총괄 검토 반영 후 최종 시험: **108개 통과, 2.38초**. 최종 신규 시험은 88개이며 기존 20개를 함께 실행했다.
4. 기존 fixture `20260406001240`, `20260410001926`, `20260320000802`를 각각 평문과 XML로 읽어 기준 커밋의 파서와 대조했다. 표·원수치·숫자검산·근거 위치·발췌·해시를 포함한 `dataclasses.asdict` 전체 결과가 **6/6 동일**했다.
5. 기능 외부 import의 구문 트리는 기준 코드와 같다. 새 모델 호출, 네트워크 호출, 외부 패키지를 추가하지 않았다. `git diff --check`도 통과했다.

신규 시험은 세 계정과 두 기간 각각의 0, 괄호·부호가 붙은 0, 전체 0, 양수·음수·작은 정수·혼합값, 빈칸·여러 대시·미공시, 주석 열과 기간 표기, 다른 계정의 숫자, XML 결측과 평문 사본, 세 기간 fixture에서 최신 기간의 0을 검증한다. 기존 대체 경로 시험은 API 우선 사용, 감사보고서 두 해 표 생성, 근거 검증과 봉인, 실패 시 진단만 남기는 처리를 그대로 확인한다.

시험마다 새 짧은 임시 폴더를 먼저 만들고, 제품 모듈 import 전에 DB와 관측 기록 경로를 그 안으로 지정했다. 저장소 루트 `.venv` Python을 사용했고 `app/conftest.py`는 유지했다. 실행 형태는 다음과 같다.

```powershell
$auditTemp = Join-Path 'C:\tmp' ('az' + [guid]::NewGuid().ToString('N').Substring(0, 8))
New-Item -ItemType Directory -Path $auditTemp -ErrorAction Stop | Out-Null
$env:PYTHON_DOTENV_DISABLED = '1'
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:PYTHONUTF8 = '1'
$env:STORAGE_DB_PATH = Join-Path $auditTemp 'test.db'
$env:OBSERVABILITY_RECORDS_PATH = Join-Path $auditTemp 'runs.jsonl'
$env:PYTHONPATH = Join-Path (Get-Location) 'app'
& .\.venv\Scripts\python.exe -B -m pytest -q -p no:cacheprovider `
  --basetemp (Join-Path $auditTemp 'pytest') `
  app/src/features/audit_financials/tests `
  app/src/features/pipeline/tests/test_audit_financials_fallback.py
```

서버·운영 DB·비밀 파일·유료 API를 사용하지 않았다. 관련 없는 대규모 회귀는 수행하지 않았다.

## 처리시간과 남은 한계

로컬에서 세 fixture 묶음을 50회씩 세 번 읽고 중앙값을 호출당 시간으로 환산했다. 평문은 수정 전 **0.401ms**, 수정 후 **0.463ms**, XML은 **0.661ms → 0.561ms**였다. 평문 검증에 약 0.062ms가 더 들었으며 모델 비용은 추가되지 않았다. 이는 작은 fixture의 로컬 관측으로 운영 전체 보고서의 지연시간을 대표하지 않는다.

평문은 태그 제거 과정에서 셀 경계를 잃는다. 주석 열의 작은 양수와 실제 작은 금액이 구별되지 않는 경우, 여러 주석 번호가 한 칸에 있는 비정형 경우, 부호와 숫자가 분리된 경우에는 추정해 채우지 않고 표를 내지 않는다. 셀 위치가 유지된 XML은 기존 금액 파싱을 계속 사용한다. 이번 수정은 확인된 숫자 선택·경계 결함에 한정되며 비정형 표 전체를 지원하도록 파서를 확장하지 않았다.

최종 브랜치 통합과 커밋은 총괄의 후속 작업이다. 이 작업 범위의 코드 수정·문서화·회귀 검증은 완료했다.
