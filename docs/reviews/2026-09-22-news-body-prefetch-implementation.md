# 뉴스 본문 수집 대기 겹치기 구현 기록

2026-09-22 · 기준 코드 `7a15b073` · [속도 제안](2026-09-22-report-generation-speed-proposal.md) 2순위 구현

**같은 기간·같은 분석 묶음 안에서만 기사 본문 요청을 최대 3개까지 겹친다.** 기사 선택·소비 순서·원문·발행일 보정·조기 충분 종료·기간별 예산·글자 예산·호출 상한·수집 마감 계약은 순차 실행과 같다. 호출자가 명시적으로 opt-in하지 않으면 오늘과 같은 순차 수집이다. 유료 호출·배포·커밋은 하지 않았다.

## 설계

1. **출발 상한 = 분석 묶음의 빈자리.** 진행 중 사슬 수 ≤ `batch_size − len(batch) − (계획된 이월 본문)`. 그래서 분석 호출이 도는 순간에는 진행 중인 요청이 0이고, 분석 결과(조기 충분·분석 상한)를 앞질러 읽은 본문이 생기지 않는다. 다음 기간의 후보는 앞 기간이 끝나기 전에 요청하지 않는다.
2. **요청 상한은 예약 원장.** 사슬을 띄울 때 그 기사가 요청할 수 있는 주소 수(신뢰 검사를 통과한 원문·포털)를 먼저 예약하고, 끝나면 남는 예약을 돌려준다. 예약할 몫이 모자라면 다른 사슬이 모두 끝난 뒤 순차 규칙(주소마다 남은 호출 확인)으로만 띄운다. 상한을 절대 넘지 않고, 마지막 호출 몫이 뒤 순위 기사로 먼저 넘어가지 않는다.
3. **소비는 후보 순위 순서.** 완료 순서가 뒤집혀도 분석 묶음 구성·본문 중복 판정·앞 기사 실제 주소와의 중복 판정·날짜 보정 이월은 순차와 같은 순서로 일어난다. 앞 기사 결과에 기대는 판정(실제 주소 중복·글자 예산)은 사슬이 아니라 소비 시점에 한다.
4. **같은 호스트는 직렬화.** 언론사 원문·포털 호스트마다 동시 요청 1개(상수). 호스트 자리를 기다리는 동안 마감·중단이 오면 요청 없이 끝낸다.
5. **중단·정산.** 멈추면 `stop_event`로 새 요청을 막고, 이미 보낸 요청은 성공·실패를 가리지 않고 `본문호출`에 남긴다. 요청을 하나도 보내지 않은 사슬은 시도로 세지 않고 `취소`로, 보냈지만 쓰지 않은 결과는 `선행미사용`·`선행미사용호출`로 진단에 남긴다.
6. **opt-in.** `BodyFetchConcurrency`는 정책 지문에 들어가지 않는다(실행 방식이지 결과를 바꾸는 정책이 아니다). 없으면 `BodyFetchLane`이 스레드 없이 호출 스레드에서 사슬을 그대로 돌린다 — 기존 471개 시험이 이 경로의 동치를 잠근다.

## 순차와 달라질 수 있는 지점(정직하게 남긴 것)

- 마감이 «이미 떠난 요청 도중»에 지나면, 순차라면 요청하지 않았을 기사 본문이 1~2개 더 읽힌다. 분석 단계가 마감을 다시 확인하므로 근거 조각은 달라지지 않고 `본문호출`·`본문시도기사`만 늘어난다.
- 앞 기사의 실제 주소가 뒤 후보와 같은 경우, 순차라면 요청을 건너뛰지만 동시 모드에서는 이미 떠난 요청 1건이 소비 시점에 `duplicate_effective_url`로 버려진다. 선택 결과는 같고 호출 1건이 더 든다.
- 글자 예산·짧은 본문으로 멈추는 순간 진행 중이던 사슬의 결과는 버린다. 선택 결과는 같고 `선행미사용`으로 보인다.

## 시험

- 기준선: news_intake 471개 통과 → 재구성 뒤에도 471개 통과(순차 경로 동치).
- 신규 통합 24건(`test_collection_body_concurrency.py`): 세 요청 실제 동시 진입, 역순 완료에서도 분석 순서·결과 동일, 같은 호스트 직렬화, 묶음 빈자리 상한(분석 중 진행 요청 0), 다음 기간 선행 요청 없음, 조기 충분 종료 동일, 예외·실패 격리, 포털 폴백·날짜 보정 이월·중복 본문 혼합에서 순차 동치, 호출 상한 7에서 7건 정확, 마감 뒤 새 출발 없음, 호스트 대기 사슬의 취소 정산, 글자 예산 정지 시 선행 요청 정산, 중단 신호 사슬 단위, 원장 스레드 경쟁(8×50 시도에 상한 20 정확).
- 회귀: `news_intake` 전체 542개, `core` 전체, `pipeline/tests` 전체 1256개 통과(같은 작업 트리에 다른 작업자의 미커밋 변경이 함께 있는 상태에서 실행).
- 3회 반복 실행으로 흔들림 없음을 확인했다. 게이트(Event) 기반 가짜 콜백으로 시간 sleep 의존을 최소화했다.

## 성능 측정 범위와 한계

외부 통신 없이 요청당 50ms 고정 지연을 흉내낸 오프라인 합성 벤치마크(스크립트는 저장소 밖 임시 폴더). 분석 지연은 동시 폭과 무관하므로 0으로 두고 본문 요청 구간만 봤다. 세 조건 모두 결과(조각·기사·진단)는 순차와 동일했다.

| 후보 구성(24기사) | 순차 | 동시 2 | 동시 3 |
|---|---:|---:|---:|
| 도메인 12개 순환 | 1.29s | 0.97s (−25%) | 0.67s (−48%) |
| 도메인 3개 순환 | 1.31s | 1.07s (−18%) | 1.04s (−20%) |
| 단일 도메인 | 1.36s | 1.29s (−6%) | 1.31s (−4%) |

한계: 실제 언론사 응답·robots 확인·리다이렉트 시간이 아니다. 같은 호스트 직렬화와 분석 묶음 상한(묶음 4 기준 동시 폭 3→3→2→1)이 이득을 제한한다. 운영 절감량은 후보의 발행처 다양성에 크게 좌우되며, 실측 전에는 «수집 구간 최대 절반 미만»으로만 말해야 한다.

## 호출자 계약(총괄·real.py 담당 확인 필요)

후속 통합 완료: 운영 기본 콜백은 기본 동시 2로 연결됐으며, 작업별 캐시·진단 격리와 완료 판정 재사용, 요청별 시간 제한 보존, 취소 전파를 추가했다. 아래는 Fable 구현 시점의 호출자 요구사항이다. 최종 적용과 시험은 [운영 연결 검토](2026-09-22-news-parallel-runtime.md)를 따른다.

- 켜는 방법: `collect_from_snapshot(..., body_fetch=BodyFetchConcurrency(max_in_flight=2 또는 3, max_per_host=1))`. `core/news_research_adapter.NewsResearchSession.collect`가 인자를 그대로 넘겨야 파이프라인에서 쓸 수 있다(그 파일은 이번 범위 밖).
- opt-in은 «`fetch_text`를 여러 스레드에서 동시에 불러도 안전하다»는 선언이다. 사슬은 `contextvars.copy_context()`로 문맥을 복사해 돌리지만, 복사는 ContextVar 값의 참조만 복사한다. 운영 `_fetch_news_article_text` 경로의 `_CollectionCache.robots_cache`·`dns_cache`(공유 dict, 확인 뒤 저장 방식)와 관측 단계 목록은 스레드 간에 그대로 공유된다. CPython dict의 단일 읽기·쓰기는 원자적이라 깨지지는 않으나, 같은 origin의 robots 확인이 중복될 수 있고 관측 기록 순서가 달라질 수 있다. real.py 담당이 이를 확인·수용한 뒤 opt-in을 넘기는 것이 계약이다.
- 적용 순서는 제안서대로 1→2→3. 운영 실측에서 429·꼬리 지연·품질이 나빠지면 opt-in을 빼면 즉시 순차로 돌아간다.
