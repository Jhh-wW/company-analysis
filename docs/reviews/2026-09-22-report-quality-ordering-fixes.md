## 수정 대상

[앞선 실제 비교](2026-09-22-report-speed-live-evaluation.md)에서 드러난 재판정 미실행, 투자표의 매출 오인, 조직문화 장의 주제 불일치를 수정한다. 보고서 작성의 시간 반감이나 품질 유지가 이미 입증됐다는 뜻은 아니다. 실제 생성 시간·비용·출고 품질은 별도로 확인한다.

## 최종 본문과 저장본

마지막 근거 대조에서 사실 원장에 없는 문장을 거절해도 composer의 `lines` 복사본에 남는 오류를 재현했다. 이후 `prose_lines`, `prose_paragraphs`, `lines`가 같은 삭제 결과를 사용하도록 고쳤다. canonical 보고서의 유효한 별도 감사 원문은 새 산문으로 덮어쓰지 않는다. 기존에 무효 출처·사실에 결속된 감사 줄을 지우던 규칙도 유지하며 두 경우를 실제 필터 경로에서 시험한다.

기존 문단의 살아남은 문장만 다시 묶으므로 같은 출처의 문장마다 번호를 반복하지 않는다. 인용 표시를 맡은 문장을 삭제해 문단이 무출처가 된 경우에는 변경되지 않은 사실 결속과 봉인된 출처 번호를 다시 확인해 표시한다. 다른 장·표의 번호로 대신하지 않으며 새 근거를 붙이지 않는다. 내용 변경이 없는 FULL 보고서의 기존 승인·캐시 권한은 유지한다.

수정 전 세 회귀 단정이 실패했고 수정 후 통과했다. 원문 감사 기록 보존, 문단 묶음 보존, 저장 왕복, 정상 FULL 출고 유지도 검증한다.

## 재판정 실행 순서와 중복 비용

무료 준비와 캐시 조회를 먼저 수행한다. 캐시가 없을 때만 재판정 전용 작업 소유권을 확보하고 계량된 AI 호출을 허용한다. 동시에 들어온 같은 요청은 기다렸다가 저장된 결과를 읽는다. 재판정 결과를 반영한 뒤 공식 근거 준비 상태를 다시 판단하고 최종 생성 모드·입력 지문·보고서 캐시 신원을 고정한다. 부족한 자료를 FULL로 강제하지 않는다.

준비 소유권은 최종 보고서 소유권과 구분하지만 비용 예약과 원가는 같은 요청에서 정산한다. 취소·예산·임대 만료·전체 마감·미정산 상태를 우회하지 않는다. 준비 호출 뒤 최종 보고서가 캐시나 다른 요청의 결과를 재사용하더라도 준비 비용은 남는다.

독립 검수에서 같은 접수번호에 다른 입력을 처리하면 준비 캐시를 덮어쓰는 문제가 추가로 발견됐다. A 입력, B 입력, 다시 A 입력의 순서에서 마지막 A가 첫 A와 다른 최종 자료로 돌아가는 재현을 고정했다. 캐시 키에 분류 입력 지문을 포함해 A와 B를 별도로 보관하도록 수정했다. 준비 소유권도 같은 키를 사용한다. 기존 캐시는 새 키의 첫 요청에서 미적중할 수 있다.

전체 앱 시험에서는 12,080건이 통과하고 수집 완료 상태에 관한 기존 시험 한 건이 실패했다. 수집 시도·스캔 완료 상태만 달라져도 재판정을 반복하도록 키를 너무 넓게 묶은 문제였다. 분류 원문·문서 결속·기존 배정·프롬프트·모델·회사 신원은 키에 넣고, 시도·스캔 완료 상태는 현재 수집 결과로 다시 적용한다. 같은 분류 자료에는 추가 호출을 하지 않으면서 현재의 `INCOMPLETE`는 보존하는 기존 시험을 유지했고, 실패 시험과 실제 세션 등을 포함한 30건이 통과했다.

환경 설정은 FULL이어도 실제 자료 부족으로 SHADOW가 된 경우, 재사용 검사가 처음 환경값을 다시 읽던 문제도 수정했다. 최종 모드를 캐시 신원과 함께 전달한다. 실제 `GenerationSession`, 웹 링크 검사 wrapper, 가짜 provider, 비용 원장으로 준비 owner 1회·waiter/캐시 0회와 최종 부분보고서 재사용을 확인했다. DB 스키마와 모델·가격은 바꾸지 않았다.

## 조직문화

감사위원회 구성 요건과 채무보증·특수관계인 자산거래 승인 규정은 인재상이나 일하는 방식의 근거로 쓰지 않는다. 직원 복지·보상·교육·업무 담당 조직에 관한 실제 설명은 보존한다. 회사명·금액을 예외로 쓰지 않는다.

앞선 두 보고서의 실패 문장 다섯 개를 최소 재현에 사용했다. 원문 조각 전체가 산출물에 없어 보고서 문장 자체를 근거로 놓았다는 한계를 시험에 명시했다. 완전히 같은 근거 문장이 있어도 조직문화에 배치해서는 안 된다는 검사다. 새 시험 27건과 관련 검수·복구·렌더 시험을 포함한 410건이 통과했다. 별도 AI 호출이나 새 UI 경고는 추가하지 않았다.

## 투자표 거절과 실제 매출표 복구

투자계획 표의 기대효과 칸에 있던 `매출증대`가 평문 변환 후 다음 행 이름에 붙었다. 국내법인·해외법인이라는 지역 힌트와 금액 합계까지 맞아 지역별 매출로 오인됐다. 투자액·투자기대효과·설비투자·CAPEX 등의 명시된 표 문맥을 확인해 비중형·다개년·금액 전용 세로형·가로형 경로에서 거절한다. `투자중개` 같은 실제 사업부문 매출은 보존한다.

정상 매출표도 복구했다. 단위 표시 바로 뒤의 `수익(매출액)` 열 머리말을 첫 행 이름에서 분리하되 먼 앞 문장의 매출 표현을 빌리지 않는다. 현대글로비스의 2026년 제출 공시에서 2025년 고객소재지 기준 매출 합계 **29,566,409,337천원**, 2025년 제출 공시에서 2024년 법인소재지 기준 매출 합계 **28,407,374,301천원**을 원문과 대조했다. 두 지역 기준은 섞지 않는다. 표 안에 없는 비중이나 숫자 연도를 추정해서 붙이지 않는다.

`중남미`를 `남미`로 잘라 표시하던 지역 이름도 보존했다. 표별 합계와 모든 행의 원문 결속을 검증하고 금액·지역명을 바꾼 반례는 거절한다. 실제 원문의 연속 구간을 자른 작은 fixture 세 개를 남겼다. 투자표 거절은 feature 160건, 정상표 복구는 관련 호출부를 포함한 244건, 총괄의 최종 매출표·공유 결속·pipeline 재시험은 187건이 통과했다. 서로 겹치는 시험 수를 합산하지 않는다.

최종 커밋에서도 저장된 공시 XML 두 건 전체를 다시 읽어 표를 추출했다. 각각 정상 매출표 한 개만 선택됐고, 전체 행의 합계·중남미 이름·모든 행의 공시 원문 대조가 통과했다. 이 검사는 외부 호출이나 추가 비용 없이 수행했다.

## Windows 동시 사용량 기록

전체 회귀에서 기존 일일 API 계수기의 잠금 초기화 경합이 두 번 드러났다. 잠금 파일에 먼저 한 바이트를 쓰던 작업이 다른 프로세스의 잠금과 충돌했다. 다른 프로세스가 빈 파일을 잠근 상황을 고정한 시험으로 수정 전 실패를 재현했다.

Windows는 파일 끝을 넘는 범위도 잠글 수 있으므로 초기화 쓰기를 제거했다. 잠금·원자적 저장·사용량 한도는 유지한다. [Microsoft `_locking` 문서](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/locking?view=msvc-170)의 계약을 확인했고, 수정 후 실제 스레드·프로세스 동시 증가 시험을 포함한 엔진 564건이 통과했다.
