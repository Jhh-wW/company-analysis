# 확보한 자료로 보고서를 제공하는 정책 변경

## 사용자 요구

분석 대상 회사는 자료가 많든 적든 보고서가 나와야 한다. 자료가 많으면 충분히 활용하고, 적으면 확보한 내용을 모아 보고서를 만든다. 대상이 아닌 경우만 대상 외로 처리한다.

이 요구는 기존의 '필수 자료 미완료·문서 수·사실 수·장 수 부족이면 전체 중단' 정책보다 우선한다. 보고서 출력을 위한 허위 내용 생성이나 원문 검증 해제는 요구하지 않았다.

## 결과 계약

| 상황 | 제공할 결과 |
|---|---|
| 대상 회사이며 자료 충분 | 기존 완성 보고서의 내용을 유지한 보고서 |
| 일부 문서 누락·접속 실패·수집 한도 | 확보한 유효 내용과 확인하지 못한 범위를 담은 보고서 |
| 자료가 적거나 일부 장만 작성 가능 | 작성 가능한 내용을 보존하고 미확인 항목을 표시한 보고서 |
| 대상은 확정했으나 추가 자료를 전혀 확보하지 못함 | 확인한 회사 기본정보와 자료 확인 상태를 담은 짧은 보고서 |
| 일부 문장·표·도식 검증 실패 | 실패 항목을 제외하고 나머지 검증 내용을 담은 보고서 |
| 정책상 제외 사실을 확인 | 대상 외 안내 |
| 대상 판정에 필요한 자료를 확인하지 못함 | 대상 외라고 단정하지 않고 확인 상태를 구분 |

자료가 풍부한 회사까지 안내문 위주 보고서로 바꾸는 것은 요구를 충족하지 못한다. 기존 수집·작성 결과를 최대한 보존하며, 일부 실패 때문에 성공한 재무 연도나 이미 검증한 문장을 함께 버리지 않는다.

## 구현 작업과 소유권

- Astra 수집: 문서 전체 순회와 제한된 후보 보관, 문서 순회 상태 계약, 앱 수집 정규화·스냅샷·수집 진단.
- Astra 파이프라인: 대상 판정과 수집량 분리, 부분 수집 보존, 사전검사와 전체 중단 경로, 작성 경로 연결.
- Claude FABLE / max: 확보 자료 작성·품질 평가·웹/PDF 출고, 관련 회귀와 반례 검증.
- 총괄 Codex: API와 파일 소유권 조정, 독립 검증, 두 모델 결과 비교, 변경 기록.

실제 실행 모델은 영수증의 effective 설정으로 확인했다. 이후 사용자가 수정과 배포 완료까지 명시적으로 요청했으므로, 총괄이 최신 main 통합·검증·배포·운영 확인까지 진행한다. 각 구현 에이전트는 자기 범위의 코드와 시험만 담당한다. 기존 Kiwoom 뉴스 수정은 보존한다.

## 필수 확인 시나리오

1. 4,096개 제목·8,192개 문단 뒤의 유일한 근거도 수집하고 원문 위치·해시가 일치한다.
2. 대상 회사의 필수 사업보고서 일부가 잘려도 확보 근거로 보고서와 PDF가 제공된다. 잘림은 그대로 기록된다.
3. 문서 한 건·사실 몇 개·일부 장만 있어도 수량 하한 때문에 전체가 중단되지 않는다.
4. 상장사 감사 목록 조회 실패와 재무 일부 연도 실패가 기존 성공 자료를 지우지 않는다.
5. 재분류 실패·AI 작성 실패 시 이전의 정상 자료를 보존한다.
6. 틀린 수치·다른 회사의 근거·잘못된 인용은 제외하고, 올바른 내용은 남는다.
7. 자료가 충분한 정상 보고서의 내용과 기존 Kiwoom 뉴스 검수 개선을 유지한다.
8. 실제 정책상 제외 대상은 그대로 구분한다.
9. 저장 후 웹과 PDF에서도 같은 확보 자료와 미확인 안내를 볼 수 있다.

현재 구현·검증 중이며, 최종 명령·결과·제한은 완료 후 기록한다. 실제 SK 실패 실행의 원문과 전체 운영 기록은 확보하지 못했으므로 합성 시험을 실제 운영 재성공으로 표현하지 않는다.

배포 준비 중 현재 운영 환경의 무료 DART 조회에서 SK 고유번호 `00181712`, 사업보고서 (2025.12), 접수번호 `20260318001157`, 접수일 `20260318`을 확인했다. 원 XML은 23,852,604바이트, 텍스트 변환 결과는 2,063,690자이며 SHA-256은 `94b94f9de828b63b65c1ac1dce3776861018c46ffc195d695e747c35956f72a7`이다. 원문은 해당 운영 컨테이너의 임시 파일 `/tmp/sk-real-evidence-20260914.txt`에 있다. 이는 현재 선택기의 실제 선택 결과이며 원래 실패 실행과 접수번호가 같다는 검증이나 수정 후 보고서 생성 성공을 뜻하지 않는다.

## 배포 후 품질 확인과 비용 한도

사용자가 배포 후 실제 보고서를 생성하고 품질이 충족될 때까지 수정·재시험하도록 요청했다. 이번 실제 보고서 생성과 재시험의 API 비용 한도는 누적 **20,000원**이다. 실패 실행도 포함하며 청구가 미확정이면 예약액을 유지한다.

SK와 키움을 우선 확인한다. 생성·다운로드 성공 외에 핵심 사업과 수익 구조, 주요 사업·제품, 실적·위험·변경 내용, 최근 뉴스의 사용과 제외 사유, 수치·인용 일치, 근거 없는 단정, 본문 누락과 PDF 가독성을 확인한다. 확인된 결함은 수정 후 관련 시험과 실제 결과를 다시 검사한다. 한도를 넘겨 추가 호출하지 않으며 남은 제한은 결과 기록에 명시한다.
