# 회사명·주소 검색 누락 수정 검증

2026-09-09, 기준 커밋 `e3d6762d`의 로컬 작업이다. 사용자가 추가로 요청한 회사 검색 수정이며, 앞서 종료한 Orca 알림 조사와 별개다. 운영 배포·푸시·설정 변경은 수행하지 않았다.

`SM`과 회사 주소를 입력해 에스엠엔터테인먼트를 찾지 못하는 문제가 재현됐다. SM만의 사전을 추가하지 않고 공식 회사명 색인, 후보 조회 폭, 주소 비교, AI 재정렬 연결을 함께 수정했다. 기존 작업자의 공급자 오류 진단 변경은 유지했다.

## 확인한 원인

- 공식 회사 후보의 주소를 읽기 전에 기업개황 조회를 5개로 제한했다. 근거 종류가 같은 동명 법인은 이 범위 밖으로 밀려나면 주소가 정확해도 비교하지 못했다.
- DART 어댑터와 실제 파이프라인은 최종 후보를 3개로 잘랐지만 AI 재정렬은 4개 이상 동점이어야 실행됐다. 기존 웹 AI 테스트는 테스트에서만 어댑터 상한을 5개로 바꿔 이 연결 단절을 가렸다.
- 주소 점수는 행정구역의 원문과 축약형을 중복 계산해 서울만 같아도 상세주소가 맞는 것처럼 점수가 포화됐다.
- 상세주소와 다른 보조 근거를 더한 점수를 1에서 잘라, 같은 건물의 계열사들이 동점으로 뭉쳤다. DART 목록 이름과 기업개황의 최신 법인명이 다른 경우 최신 법인명의 정확 일치도 충분히 반영하지 않았다.
- 전체 이름 정규화는 일반적인 공백 차이를 일관되게 처리하지 않았다. 최초 로컬 색인 구축과 주소 조회가 합쳐지면 기존 30초 제한도 초과했다.

## 수정한 동작

1. 공식 이름의 공백 차이를 검색 전용 색인에서 흡수한다. 예를 들어 `삼성 전자`, `현대자동차`, `한빛 정밀 기술`을 해당 공식 이름의 고유번호와 연결한다. 공통 법인 확정 규칙은 확대하지 않았다.
2. 공식 후보를 최대 15개까지 기업개황으로 보강하고, 주소 비교와 AI 재정렬 뒤 화면에서 최대 3개로 줄인다. 조회는 한 요청당 최대 3개씩 병렬로 실행하며 요청 문맥과 후보 순서를 보존한다.
3. 주소는 광역지역, 시군구·읍면동, 도로명, 도로명과 건물번호 일치로 구분한다. 다른 도시·구의 같은 도로명이나 다른 건물번호를 상세주소 일치로 처리하지 않는다.
4. 점수는 전체 근거의 최대 합으로 정규화해 상위 후보의 차이를 보존한다. 기업개황의 현재 법인명 정확 일치도 반영한다.
5. 공식 후보가 화면 밖에 남아 있고 보조 점수 차이만으로 갈린 경우에도 기존 AI 재정렬을 한 번 사용할 수 있다. 고유번호 일치나 단독으로 명확한 주소 일치는 AI로 덮어쓰지 않는다. AI 실패·비용 승인 거절 시 결정적 후보 목록을 유지한다.
6. DART의 `013` 기업개황 없음은 해당 후보만 제외한다. 인증·한도·형식 오류는 기술 실패로 유지한다. 응답의 고유번호가 요청과 다르면 후보로 사용하지 않는다.
7. 무료 DART 검색의 전체 대기는 최대 60초로 조정했다. 일반 공급자와 AI 대기는 기존 8초이며, 시간초과 후 다음 묶음을 계속 조회하거나 미완료 목록을 정상 성공으로 반환하지 않는다.

## 검증

수정 전 새 회귀 시험 11개가 모두 실패했고 수정 후 통과했다. 관련 시험 179개가 통과했다. 실제 HTTP `/confirm` 경로에서 공식 응답 자료로 SM 후보를 표시하고, 사용자가 선택한 고유번호 `00260930`으로 확인 카드까지 이동하는 시험을 포함한다. 기존 AI 웹 시험에서 원시 후보 상한을 임의로 풀던 우회도 제거했다.

전체 `app/src`와 `app/tools/tests` 실행은 9,042개 통과, 4개 실패, 1개 건너뜀, 9개 로컬 통합 시험 제외, 하위 시험 10개 통과였다(744.09초). 실패 4개는 검증용 임시 경로가 길어 생긴 Windows 경로 제한이었다. PDF 출고 시험 3개는 저장 경로 길이 검사에서, 로컬 실행기 시험 1개는 긴 파일명의 복사에서 멈췄다. 기능 코드를 추가로 바꾸지 않고 임시 루트를 `%TEMP%/cs_5456c018`로 줄여 해당 두 시험 파일을 재실행했고 **20개 모두 통과**했다(19.70초). 따라서 한 번의 전체 실행이 처음부터 모두 통과했다고 기록하지 않는다. 검색 관련 실패는 남아 있지 않다. `git diff --check`도 통과했다.

실제 무료 DART 응답을 사용하는 최종 검증은 8개 회사, 10가지 입력 모두 기대한 법인이 화면 후보 범위 안에 있었다. 기업개황 API는 최종 실행에서 42회 호출했고 유료 API 및 보고서 생성 호출은 0회다. 회사 목록은 2026-09-08 로컬 공식 목록을 읽기 전용으로 복사했으며, 기업개황은 검증 시점에 조회했다. 반복 검색의 중복 기업개황 응답은 검증 스크립트 내부에서만 재사용했다.

## 남은 적용 경계

현재는 로컬 소스 수정이다. 사용자가 실패를 경험한 사이트 URL과 실제 입력 주소는 아직 전달받지 못해 해당 운영 배포의 버전·화면은 확인하지 못했다. 배포 시 회사 후보 모듈·파이프라인·신규 파일을 함께 반영해야 하며, 어댑터만 바꾸거나 설정만 바꾸는 것으로는 해결되지 않는다.

실행 코드에 함께 반영할 파일은 다음과 같다. 각 기능 안의 신규·변경 회귀 시험과 SM 공식 응답 자료도 같이 보존한다.

- `app/src/features/business_candidate/`: `address_constants.py`, `address_match.py`, `ai_rerank.py`, `constants.py`, `dart_identity.py`, `logic.py`, `providers.py`
- `app/src/features/pipeline/`: `candidate_profile_constants.py`, `candidate_profiles.py`, `real.py`의 회사 후보 검색 부분
- 회귀 시험: 위 두 기능의 `tests/`, `app/src/web/tests/test_company_candidate_flow.py`

`pipeline/real.py`에는 기존 공급자 오류 진단 작업도 함께 있으므로 그 변경을 지우거나 파일 전체를 이전판으로 교체하면 안 된다.

모든 실재 법인의 검색 성공을 보장하는 전수 검증은 아니다. DART 미등록 법인, 공식 이름과 연결되지 않는 임의 별칭, 공식 후보가 15개를 넘는 밀집 동명 입력에는 추가 식별정보가 필요할 수 있다. 기존 유료 외부 검색의 동의·예산 경계와 사용자의 후보 확인 절차는 유지한다.
