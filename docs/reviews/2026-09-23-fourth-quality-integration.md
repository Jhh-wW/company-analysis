# 보고서 4차 품질·성능 수정의 통합 결정

## 독립 검토와 선택

Astra xhigh와 Claude Fable xhigh에 같은 P1~P30 및 품질을 유지하는 속도·비용 개선 과제를 맡겼다. 별도 재현·렌더 담당은 저장 산출물과 무료 합성 시험으로 경계를 확인했다. 초기 Claude 전달의 문자 인코딩 오류는 UTF-8 과업 파일 읽기로 정정했고, 최종 응답의 API 재시도 후 두 검토를 취합했다.

통합 후 사용자의 추가 지시에 따라 Claude Fable xhigh에는 내용 정확성·사실 손실, Claude Opus xhigh에는 운영 연결·병렬 작성·정산·추가 비용 절감의 독립 재검토를 맡겼다. 실행 초기화가 확인한 실제 모델은 각각 `claude-fable-5`, `claude-opus-5-5`다. 검토 결과의 주장과 총괄이 재현한 사실을 구별해 반영한다.

Fable 재검토의 두 관찰을 무료 시험으로 재현해 추가 수정했다. 쉼표가 수익인식 특례의 기간 조건을 분리하는 원문에서는 열린 조건절만 다시 연결하며, 다른 문장·조각·독립 주어로 조건을 넘기지 않는다. 마지막 사실 결속 선택에서 장의 모든 본문이 제외되면 안내문을 새로 남기고, 기존 안내 조정이 실제 남은 자료 종류에 맞게 확정하도록 했다. 일반·부분보고서 모두 무안내 빈 장이 사라지는 것을 검증했다.

공통 제안인 회계정책 규칙 보강, 장별 근거 소유권, 부분보고서의 제한된 병렬 작성, 실패 사유 세분화, 회복 가능한 문장 우선 재작성, 도식 일반어 정본 통일, 독자용 표시 정리를 채택했다.

서로 다른 제안은 다음처럼 결정했다.

| 논점 | 채택한 경계 |
| --- | --- |
| 기사에 있는 수가 인용 조각에는 없는 경우 | 숫자 검사를 완화하지 않는다. 필요한 조각을 명시 인용하고 원문 조건을 보존한다. 같은 문서 전체·제목을 암묵적인 수치 근거로 추가하지 않는다. |
| 기사 발행일과 사건 연도 | 발행연도를 사건연도로 자동 차용하지 않는다. 상대시점만 확인되면 그 표현을 유지한다. |
| 미결속 확인 문장 | ‘해석’ 표지만 붙여 공개하지 않는다. 공개 후보에서 제외하고 실제 사실 결속을 확보한 문장만 재사용한다. |
| 빈 장 | 목차를 숨겨 품질 수치를 높이지 않는다. 근거가 없는 장은 호출을 생략하고 실제 자료 범위를 알린다. |
| 요약 | 추가 AI 선택 호출을 없애고 정확한 본문 사실 결속을 재사용한다. FULL의 최소 품질 계약은 그대로이며 확보자료 정책은 0~2개의 확인된 요약도 허용한다. |
| 중복 기사 부록 | 출처 원장·인용 번호는 보존한다. 독자용 기사 표시 그룹만 별도로 만들고 새 공개 projection에 봉인한다. |
| 공개 상태 | FULL 출고 권위와 SHADOW 관측을 혼동하지 않는다. 부분자료·수집 미완료는 독자용 문구로 알린다. |
| 계획 보도를 완료 보도로 대체 | 같은 사건 표지만으로 삭제하지 않는다. 검증된 완료 사실이 공개 후보로 살아 있고, 예고의 주체·행동·대상·조건을 완료 원문이 보존할 때만 제거한다. 발표 완료와 향후 시행 계획은 별개로 남긴다. |
| 이동 안내 | 실제 도착 장과 그곳에 살아 있는 문장의 원문·인용·주장 칸 지문으로 확인한다. 다른 숫자의 유사 문장이나 나중에 제외된 후보를 이동 근거로 쓰지 않는다. |
| 본문과 보도표 중복 | 기사에 A와 B 두 사실이 있으면 본문에 A만 있다는 이유로 B까지 없애지 않는다. 새 보도표는 원문 전체 포함 여부로 판단하고 공개 후보 제외 뒤 다시 계산한다. |
| 부분보고서 근거 | 작성에 허용한 인용 번호뿐 아니라 실제 인용이 지원하는 주장 칸도 검사한다. 구형 근거를 함께 인용해 명시된 칸 제한을 우회할 수 없다. |

## 성능의 검증 범위

기존 저장 실측에서 장별 작성은 순차 89.2초, 전체는 236.3초였다. 동일한 일을 3개씩 완전히 겹친다는 이상적인 계산으로도 전체 절감은 약 59.5초, 약 25%다. 이 계산은 실측 예측값이 아니며 공급자 지연·캐시·수집 시간은 별도로 남는다. 50% 단축이나 비용 절감률을 새 유료 실행 없이 달성했다고 판단하지 않는다.

무료 시험은 부모 실행 문맥·예산·동시상한·실패 후 합류·목차 순서·직렬과 병렬 결과 일치, 빈 장의 호출 생략을 검증한다. 요약 추가 호출 0회는 코드 경로와 가짜 공급자 호출 수로 검증한다. 기존 공급자 예산·정산 및 FULL 출고 규칙은 완화하지 않는다.

Opus 재검토에서 부분보고서의 검수 후보가 0개여도 FULL의 호출 장부 관례에 따라 검수 1회를 보내는 경로를 확인했다. 부분보고서에만 빈 검수를 생략하고 FULL의 호출 계약과 도식이 있는 검수는 유지하도록 보완했다. 작성 진단의 ‘장수’는 목차 장수, ‘동시상한’은 설정 상한으로 유지하며 부분보고서에 ‘작성대상장수’와 ‘빈근거생략장수’를 추가했다. 이 대상 수를 파싱 재요청까지 합한 실제 공급자 호출 수로 표현하지 않는다.

추가 제안은 다음처럼 구분했다.

| 제안 | 통합 판단 |
| --- | --- |
| 부분보고서의 0개 후보 검수 생략 | 사용하지 않는 응답을 만드는 낭비이므로 채택한다. 본문·요약·도식 검수 대상이 하나라도 있으면 기존 검수를 실행한다. |
| 원문 전체 복사를 조각·위치 참조로 대체 | 출력 토큰을 줄일 가능성이 있지만 새 참조 해석 계약과 모델 품질 검증이 필요하다. 이번 수정에서는 검수 응답 형식을 추가 변경하지 않는다. |
| 수집 단계 하위 시간 계측 후 추가 동시화 | 다음 실측에서 병목을 분리한 뒤 결정한다. 기존 95.9초를 그대로 줄일 수 있다고 가정하지 않는다. |
| 첫 요청의 캐시 생성 후 나머지 병렬 요청 | 캐시 생성 비용을 줄이는 대신 첫 묶음의 시작을 늦춘다. 실제 캐시 생성·읽기 토큰과 모델별 요율을 측정하기 전에는 기본 실행을 직렬 대기로 바꾸지 않는다. |

동시 요청의 캐시는 첫 응답이 시작된 뒤 사용할 수 있다는 조건을 공식 문서에서 확인했다. 따라서 동시 작성이 항상 비용도 줄인다고 단정하지 않는다. 캐시 읽기 배율은 모델별 예외가 있으므로 독립 검토의 일반식에 나온 0.1배나 비용 증가량을 모든 모델에 일괄 적용하지 않는다. [Anthropic 프롬프트 캐시 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

## 재현용 원문 보관

기본값은 꺼짐이다. 로컬 평가 프로세스에서만 `REPORT_LOCAL_REPLAY_ENABLED=1`과 영문 소문자·숫자·밑줄·하이픈으로 된 `REPORT_LOCAL_REPLAY_RUN`을 함께 지정한다. 실행 표지는 개인·회사 이름을 넣지 않는 불투명한 식별자를 사용한다. 배포 서비스 식별 환경이 있으면 보관하지 않는다.

정식 로컬 평가 런처는 `-EnableLocalReplay`와 `-LocalReplayRun`을 함께 받아 이 값을 자식 프로세스에 전달한다. 부모 환경이나 provider 환경 파일만으로는 보관을 켜지 않는다. 실행설정 영수증에는 보관 활성화 여부만 기록하고 실행 표지는 넣지 않는다. 가짜 자식 프로세스를 사용한 런처 회귀 59개로 기본 OFF, 명시 전달, 잘못된 표지의 기동 전 거절을 검증했다.

보관 위치는 Git에서 제외한 `app/.local_evaluation_runs/private_replay/<실행표지>/`다. 요청·응답 text와 모델·단계·응답 스키마·출력 상한·종료 사유·소요시간을 기록하고, 요청·응답 text와 응답 스키마의 지문을 함께 저장한다. 인증 헤더·환경 전체·클라이언트 객체는 받지 않으며 일반 로그와 진단에는 원문을 넣지 않는다. 파일당 2 MiB, 전체 200개, 다음 보관 시 7일이 지난 보관 파일 정리 상한을 적용한다. 실행할 때마다 사용자 승인 없이 유료 보고서를 생성하는 기능은 아니다.

`private_replay.read_local_provider_replay`는 스키마와 지문을 다시 검산한다. 파일 보관에 실패하거나 상한을 넘으면 이미 끝난 공급자 응답이나 정산 결과를 바꾸지 않는다.

목록 정리와 파일 생성을 운영체제의 파일 잠금으로 함께 보호해 여러 프로세스가 같은 전체 보관 상한을 넘지 않게 한다. 잠금 경합 때는 기다리지 않고 해당 보관만 생략한다. 프로세스가 종료되면 운영체제가 잠금을 해제하며 공급자 결과와 비용 정산은 유지한다. 명시적 로컬 보관이 켜진 경우에만 단계별 시도·저장·미보관 수를 진단에 남긴다. 병렬 실행의 모든 응답이 보관된다고 보장하지 않으며, 누락은 이 집계로 확인한다. 보관 진단에는 원문·회사·경로·오류 메시지를 넣지 않는다.

## 지문의 차이

- 근거 검수 후보 지문: `candidate-raw-utf8-v1`. 검수 직전 후보 문자열을 바꾸지 않고 UTF-8로 인코딩한 SHA-256이다. 후보 안에 실제 있는 보도 접두사는 포함한다. 렌더가 나중에 붙이는 인용 번호나 ‘— 해석’ 표시는 입력에 없다.
- 공급자 원문 보관 지문: `sha256-utf8-raw-v1`. 요청·응답 각각의 전체 문자열에 같은 UTF-8 원문 해시 알고리즘을 적용한다. 입력 범위와 용도가 후보 지문과 다르므로 버전 표지를 구별한다.
- 빈 장 재승인 방지 지문: 원래 후보에서 인용 표시를 제거한 뒤 NFKC 정규화와 공백 제거를 적용하는 별도 계약이다. 위의 원문 바이트 지문과 혼용하지 않는다.
- 도식 검수 결속: 소유 장·순서 있는 칸·인용 목록·기준일·정확 근거 해시를 묶는다. 작가가 JSON에 검수 표지를 넣어도 승인으로 읽지 않는다. 칸·인용·원문·기준일이 바뀌면 다시 검수해야 한다.

## 검증 상태

수정 전 기준은 앱 13,085개, 엔진 564개, 배포 123개, 운영 도구 135개 통과였다. 이 수치는 수정 후 회귀 결과가 아니다.

수정 후 필수 회귀 4묶음이 모두 통과했다. 집중 시험 묶음은 서로 겹치므로 아래 전체 결과에 더하지 않는다.

| 묶음 | 결과 |
| --- | --- |
| 앱 `app/src app/tools/tests -m "not local_integration"` | 13,530개 통과, 2개 건너뜀, 15개 선택 제외, 경고 99개, 하위 시험 10개 통과 · 1,173.85초 |
| 엔진 `analysis_engine/src` | 564개 통과 · 20.74초 |
| 배포 `deploy/tests` | 123개 통과 · 8.14초 |
| 운영 `ops` | 135개 통과, 3개 건너뜀 · 59.58초 |

앱 검사 전후 1,438개 소스 파일의 지문이 같았다. 검사 종료 후 상수 파일 끝의 빈 줄 한 곳만 정리했고 Python AST가 그대로임을 확인했다. 최종 스테이지 공백 검사도 통과했다. 개인정보·비밀 패턴과 회사별 고정 분기는 신규 0건이며 운영 코드의 신규 기능 간 직접 import도 0건이다. 기존 통합 시험은 실제 결속·저장·출력 경계를 검증하기 위해 관련 기능과 시험 fixture를 참조한다.

중간 앱 전체 검사에서 51개 실패를 확인한 뒤 현재 코드로 다시 분류했다. 중복 보도표·인용 표기·감사 문구의 옛 기대값은 실제 본문 사실·원장·공시일 의미를 확인하도록 갱신했다. 운영 시험은 차별점이 없는 9장 임시 문장과 사실 근거 없는 요약 채우기 대신 원래 검증점까지 도달하는 정상 근거를 사용했다. 공용 검수 도우미가 새 등급 줄을 읽지 못해 본문 후보를 누락하는 문제도 고쳤다. 재판정 OFF 골든은 승인되지 않은 3장 공개를 제거하되 정상 재무표·증감률·결속 사실이 보존되는지 먼저 확인했다. 숫자 기대값이나 품질 하한을 낮춰 실패를 감추지 않았다.

저장 보고서 재렌더, 무봉인 표시 합성, 봉인 표시 합성, 가짜 공급자를 통한 FULL 생성의 네 경우를 각 4쪽씩, 총 16쪽 직접 확인했다. 잘림·겹침은 없었다. 저장본은 5쪽에서 4쪽으로 줄었고 기존 사실·출처 원장, 인용 번호 17개와 URL 7개는 보존했다. 중복 기사 부록 두 그룹과 안내문 앞 번호는 제거됐다. 저장본의 본문 내용은 과거 작성 결과이므로 새 생성 품질을 입증하는 자료로 쓰지 않는다. 기존 저장본의 옛 4장 제목·표지의 짧은 미감사 문구·과거 안내 내용은 재작성하지 않았다.
