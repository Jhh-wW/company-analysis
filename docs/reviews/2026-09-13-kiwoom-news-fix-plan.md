# 키움증권 뉴스 누락 수정안 비교·통합

기준 코드: `810472df893af5767387bf09bc40cbb5f8dd5c46`. 조사일: 2026-09-13. 구현·검토일: 2026-09-14. 원인 조사와 비교를 마친 뒤 사용자의 지시에 따라 Claude가 앱 코드와 회귀 시험을 구현했고, 총괄 Codex가 변경과 반례를 독립 검토했다. 커밋·배포·원 PDF 재생성은 수행하지 않았다.

총괄은 Codex이며, 독립 작업자로 Codex와 Claude Code를 사용했다. Claude는 실행 영수증에서 요청·적용 설정 모두 `model=fable`, `effort=max`임을 확인했다. 두 작업자에게 같은 원인 조사 과제를 주고, 이후 상대의 실제 보고서를 읽어 비교하도록 했다.

상태: 앱 코드 구현과 작성 기능 검증 완료. 아래 비교·구현 순서는 조사 단계의 결정 기록이며, 실제 반영 결과는 다음 항목과 [Claude 구현 보고서](../../tmp/kiwoom-news-investigation/implementation/claude-implementation.md)에 정리했다.

## 실제 반영 결과 (2026-09-14)

- Claude Code는 실행 영수증에서 확인한 `model=fable`, `effort=max`로 구현했다. 총괄은 운영 소스를 직접 수정하지 않고 코드 검토와 별도의 반례 검사를 수행했다.
- 검수 안내와 실제 검사가 같은 요구사항 계산을 쓴다. 검증된 단일 뉴스 조각을 원문 전체 그대로 인용하고, 해당 장의 소유권이 맞으며, 반복 낱말 하나가 행사 참여 조건일 때만 불필요한 반복 결속 요구를 제외한다.
- 정확한 키움증권 원문과 합성 검수 응답을 사용한 단일·묶음 검수에서, 관계 항목이 없어도 본문 1건·뉴스 목록 1건으로 이어졌다. 잘못 제출한 유형·대상·인용·원문은 계속 거절하며, 유형 누락·계약 밖 유형·빈 항목도 예외로 숨지 못한다.
- 행사 참여 조건을 고객의 실제 재가입 행동으로 바꾼 후보는 차단한다. 실제 행동을 명시한 별도 원문은 인정하며, 명사형 수익 주장 5개의 기존 검사도 유지한다.
- 총괄이 발견한 검증 표시의 자료형 오류, 존재하지 않는 의미 칸의 소유권 인정, 미지 유형 항목 무시, 역할·과금 안내와 인과 안내의 충돌을 Claude가 보완했다. 총괄의 독립 검사에서도 모두 기대한 결과를 확인했다.
- 새 회귀 시험 134개, 관련 기존 시험 198개, 작성 기능 전체 시험 2,576개가 통과했다. 총괄의 앱·도구 기존 시험은 10,287개 통과 시점에 Windows 임시 경로 길이로 출고 관련 3개가 실패하여 중단됐다. 짧은 새 임시 경로로 웹·도구 범위를 다시 실행해 1,760개 모두 통과했다(3개 제외). 범위가 겹치므로 합산하지 않으며, 하나의 최종 전체 앱 실행이 모두 통과했다고 주장하지 않는다. 이는 이후 시작된 SK·자료 부족 보고서 정책 변경 이전 Kiwoom 구현의 검증 기록이다.
- 변경은 `app/src/features/composer/`에 두고, 공유 진단 계약에는 새 사유코드 2개만 등록했다. 추가 AI 호출이나 유형 자동 교정은 도입하지 않았다.

운영 검수 응답 원본은 확보하지 못했으며 재현 응답은 합성값이다. 새 안내를 받은 실제 모델의 응답과 새 PDF는 별도 생성으로 확인해야 한다. 또한 「이 행사는 매년 반복된다」처럼 기존 결속 검사의 어휘 범위 밖에 있는 덧붙인 문장의 진위는 계속 AI 의미 검수가 맡는다. 이 기존 한계는 새 시험과 구현 보고서에 명시했으며, 모든 잘못된 문장을 코드만으로 차단한다고 주장하지 않는다.

## 사용자가 이해할 수 있는 설명

뉴스는 찾아 놓았지만 ‘재가입’이라는 단어를 보고 프로그램이 반복 거래에 관한 검사표를 요구했다. AI가 낸 검사표가 코드의 분류와 맞지 않으면 뉴스 문장을 지우고 목록에서도 뺀다. 같은 기사라도 검사표의 분류만 맞추면 통과할 수 있다는 것을 실제 코드로 재현했다.

그렇다고 재가입 검사를 전부 없애면 안 된다. ‘재가입 고객에게 주는 혜택’은 행사 참여 조건이고, ‘고객이 실제로 재가입해 수익이 늘었다’는 별도의 주장이다. 첫 번째 문장은 보존하면서 두 번째 주장에는 실제 근거를 요구해야 한다.

- 안내문과 실제 검사 목록이 어긋난 사실은 확인했다. 다만 ‘안내에 재가입이 없어서 AI가 무엇을 적을지 몰랐다’는 구체적인 인과는 원응답 없이 확정하지 않는다. 안내문 정렬은 재발 가능성을 줄이는 개선안이다.
- 본문에 남지 못한 뉴스 조각을 보도표 입력에서도 제외하는 현재 정책 때문에 최종 뉴스가 0건이 됐다. PDF 2쪽에도 해당 제외 안내가 표시된다.

Claude의 정식 독립 보고서는 접미 정규식 축소를 가장 작은 안전한 안으로 추천했다. 그러나 총괄이 추가한 아래 반례 때문에 그대로 채택하지 않았다. Codex의 초기 범위 구분 실험도 완성품으로 채택하지 않고, 인용 소유권·원문 전체 일치·단일 조건까지 좁힌 설계로 수정했다. 두 모델의 제안을 비교한 뒤 각각의 취약점을 줄인 결정이다.

상호 검토에서 Claude는 다섯 반례를 직접 재현한 뒤 접미 정규식 축소안과 사유코드로 목록을 별도 승인하는 안을 철회했다. Codex가 발견한 참여 조건→실제 행동 일반화도 직접 확인했다. 최종적으로 두 작업자 모두 프롬프트 계약 정렬을 먼저 하고, 원문 보존 범위를 좁혀 참여 조건을 처리하는 방향에 동의했다.

남는 차이는 원문 전체가 같을 때 검사를 얼마나 생략할 수 있는지다. Claude는 더 넓은 생략도 가능하다고 보았지만 총괄은 채택하지 않았다. 전체 일치만으로 출처·인용 소유권·다른 관계 항목의 검증까지 보장되지는 않는다. 첫 적용은 아래 단일 참여 조건으로 제한하며, 생략한 표지가 0개가 됐다는 이유로 다른 관계 항목 검사를 건너뛰는 경로도 허용하지 않는다.

## 총괄이 추가한 반례

Claude의 정규식 실험에서는 아래 문장들이 기존의 반복 결속 검사 대상에서 새로 빠졌다.

1. 고객의 재가입 증가가 매출 확대를 이끌었다.
2. 재구매 기반 수익이 발생한다.
3. 재계약 매출이 핵심이다.
4. 재가입 고객이 주요 수익원이다.
5. 계약 연장 수익을 얻는다.

이는 해당 문장들이 전체 검수를 모두 통과한다는 증명이 아니다. 필요한 검사 하나가 빠지는 직접적인 반례다. 따라서 ‘뒤에 명사가 오면 반복 검사를 생략한다’는 변경은 그대로 적용하지 않는다. 기존 저장 보고서 256문장에 반복 표지가 원래 0개인 전후 비교 역시 이 변경의 안전성을 증명하지 않는다.

Codex는 반대 방향의 허점도 재현했다. 행사 참여 조건만 있는 원문으로 ‘키움증권 고객은 재가입한다’는 후보를 만들고 가짜 검수자가 참을 주면 기존 검수에서 살아남는다. 원문의 참여 조건을 실제 반복 행동의 증거로 이용하지 못하게 막는 검사가 필요하다.

## 통합 구현 순서

### 1. AI에게 요구하는 검사표와 코드의 요구사항을 일치시킨다

`composer/role_binding.py`에서 찾은 검사 대상 표지와 유형을 `composer/grounding.py`의 후보별 안내에 같이 싣는다. `role_binding_constants.py`의 공통 안내도 같은 정의를 사용한다. ‘관계가 필요하다’만 적지 말고 어느 표현 때문에 어떤 유형이 필요한지 알려 준다. 회사명·기사 날짜·금액을 하드코딩하지 않는다.

추가 모델 호출 없이 기존 검수 요청의 안내를 개선하는 범위다. 이것만으로 모델이 항상 올바른 응답을 한다고 보장하지는 않는다.

### 2. 정확한 행사 참여 조건과 실제 반복 행동을 양쪽에서 구분한다

역방향 오류를 막는 검사를 먼저 구현·검증한 뒤, 같은 단계에서 아래의 좁은 참여 조건 처리를 연결한다. 정상 원문 복구와 잘못된 일반화 차단을 한 쌍으로 검증한다.

첫 적용 범위는 검증된 뉴스 조각 하나, 자기 인용 하나, 참여 조건 표지 하나인 후보로 제한한다. 날짜·발행처·장 소유권을 확인하고, 출처 접두사를 제외한 후보가 조각 전체와 정확히 일치해야 한다. 원문의 해당 절만 같거나 `원문대체후보` 표식만 있는 것으로는 충분하지 않다.

이 범위 안에서 반복어가 혜택 수령인의 참여 조건임을 확인한 경우에만 그 자리의 불필요한 반복 결속 요구를 제외한다. 수령인과 혜택 사이에 다른 주체·절이 있거나, 의역·다중 인용·다른 역할·수익 주장이 섞여 있으면 기존 검사를 유지한다. 다른 관계 항목을 지우거나 무시하지 않는다. 도식의 검사는 유지한다.

동시에 원문은 참여 조건인데 후보는 실제 반복 행동·수익이라고 바꾼 경우, 그 조건 구절로는 증명할 수 없도록 `role_binding.py`의 원문·후보 대조 단계에서 막는다. 별도의 원문 구절이 같은 주체의 실제 행동을 명시하면 그 구절로 증명할 수 있다.

메모리 실험의 monkeypatch, 동적 함수 소스 삽입, 전역 상태는 제품 코드로 복사하지 않는다. 명시적인 인자와 반환값을 갖춘 순수 함수로 구현한다. 문법 상수와 테스트는 composer 기능 내부에 둔다.

### 3. 무엇이 실패했는지 기록하고 정상 결과를 본문·목록에 연결한다

검증 항목을 맞추지 못한 경우와 원문·주체·수치·조건이 틀린 경우를 구분할 수 있도록, 기존 후보지문과 사유코드에 실패 검사 단계·요구 유형·제출 유형·규칙 버전을 연결한다. 유형 오류는 뒤쪽 원문 검사보다 먼저 발생할 수 있으므로 그 코드만 보고 ‘단순 형식 오류’라고 확정하지 않는다.

원 AI 응답과 응답지문을 보존한다. 교정·재판정이 있다면 원응답과 구별된 기록을 만들고 실제 사용한 판단을 기존 생성 근거와 검수 영수증에 연결한다. 호출 순번·검수 회차, 후보지문·장·인용, 규칙 버전, 변경 전후 값과 전체 재검증 결과를 함께 기록한다. 교정된 JSON을 원래 AI 응답으로 바꿔 기록하면 안 된다. 최종 검증을 통과한 같은 후보지문·출처만 본문과 뉴스 목록으로 보낸다.

### 보조안: 유일하게 결정되는 분류만 교정

후보·원문·인용·주체·금액·조건을 바꾸지 않고 원 판정이 참이며 잘못된 유형만 유일하게 결정되는 경우에 한해 검토한다. 역할값이 어디에도 해당하지 않거나 두 유형에 걸치면 교정하지 않는다. 누락·애매·거짓 판정이나 다른 관계 항목의 오류를 지우지 않는다. 교정 후 전체 검증에 다른 오류가 있으면 공개하지 않는다.

이 안은 실제 운영 응답을 확보한 뒤 필요성을 판단하는 별도 보조안이다. 응답을 통과할 때까지 반복 요청하거나 뉴스 수집기의 남은 분석 횟수를 본문 검수에 임의로 전용하지 않는다.

## 수락 조건

구현 단계의 정보 전달은 다음 조건을 지킨다. 현재 `role_binding_problem`의 `own_sources`는 인용 ID와 본문 문자열만 있으므로 뉴스 수집 검증·날짜·발행처·장 소유권을 그 함수에서 추정하면 안 된다. `verify.py`에서 실제 문장과 `CollectedFragment`, 기존 소유권 정보를 대조한 후보별 문맥을 만들고 안내 생성과 `_apply_grounding` → `constrain_verdicts` → 역할 검사에 함께 전달한다. 원문 지문·후보지문·인용·장을 결속하고, 문맥 누락이나 불일치에는 적용하지 않는다. 기존 객체로 증명할 수 있는 정보부터 사용하며, 별도 수집 계약을 불필요하게 추가하지 않는다.

단일 자기 인용은 문장의 실제 `citations`로 확인한다. `_grounding_candidate`가 보조 재무표를 `TABLE_SOURCE_ID`로 자동 추가할 수 있으므로 `len(own_sources) == 1`로 판별하지 않는다. 잘못된 인용을 버린 뒤 남은 인용 하나로 자격을 계산해서도 안 된다. 적용 자격을 AI 응답의 표식으로 정하지 않는다.

참여 조건의 요구를 줄여도 제출된 관계 항목은 별도로 검증한다. 같은 `재가입`이라는 역할값이 있다는 이유만으로 항목 전체를 건너뛰면 잘못된 대상·인용이 숨을 수 있다. 요구 표지가 없어졌다는 이유로 이 검사까지 조기 종료하지 않는다. 기존 응답에 다른 오류가 남으면 해당 응답은 계속 탈락하며, 이를 원문 복구 성공으로 계산하지 않는다.

- 정확한 기사와 동일 검사표를 사용한 전후 비교에서 정상 원문은 본문 1건·뉴스 목록 1건으로 이어진다.
- 행사 참여 조건을 실제 행동·반복 수익으로 바꾼 문장은 차단된다.
- 금액 변경, ‘최대’ 삭제, 다른 회사, 다른 지급 대상, 기간 변경, 조건·부정 삭제, 다른 인용과 위조 원문은 계속 차단된다.
- 숫자가 없는 반례도 포함한다. 숫자 검사 실패가 다른 검사의 빈틈을 가리는 시험을 피한다.
- 재가입 증가·재구매 기반 수익·재계약 매출 등 명사형 실제 주장, 다중 주체·절·괄호·선택한 인용 구절을 짝으로 검증한다.
- 같은 원문 절에 거짓 절을 덧붙이거나 다른 지급 주체를 연결한 후보를 차단한다. 한 표지의 면제가 다른 관계 항목의 실패를 덮지 않는다.
- 단일·묶음 검수, 현재 뉴스 소유권·출처·중복 처리, 본문과 목록 및 최종 공개 근거 연결을 확인한다.
- 검사 안내와 실제 판정이 같은 요구사항 계산을 사용한다. 기본 검수 호출 수를 늘리지 않는다.
- 교정 시 원응답 지문은 불변이며 별도 교정 이력과 최종 검수 기록이 연결된다. 같은 입력의 재검증에서 교정이 누적되지 않는다.
- 운영 원응답을 확보하지 못하면 합성 재현의 한계를 명시한다. 이번 PDF에서 누락된 기사 전체가 복구된다고 주장하지 않는다.

## 해결방법 추가 질의 결과

2026-09-13 사용자의 재질의에 따라 Codex와 Claude Code FABLE(`effort=max`, 요청·적용 설정 확인)에 각각 구체적인 수정 처방을 다시 요청했고, 두 답변을 받았다. 새 운영 구현이나 시험은 수행하지 않았다.

- [Codex 실행 처방](../../tmp/kiwoom-news-investigation/followup/codex-solution.md): 같은 요구사항 계산으로 검사 안내를 만들고, 검증된 기사 정보가 후보별로 끝까지 전달되도록 연결한다. 조건을 실제 행동으로 바꾸는 오류 차단과 좁은 원문 조건 처리를 함께 적용하고 검증한다.
- [Claude 실행 처방](../../tmp/kiwoom-news-investigation/followup/claude-solution.md): 같은 수정 순서에 동의하며, `verify.py`에서 원문 보존 자격을 계산해 단일·묶음 검수에 전달하는 구체안을 제시했다. 실제 뉴스 인용과 자동 추가되는 보조 재무표를 구분하자고 했다.

총괄은 두 답변의 공통 방향을 채택한다. 다만 Claude 처방의 ‘면제 낱말과 역할값이 같은 항목을 건너뛴다’는 세부안은 채택하지 않는다. 같은 낱말이 있어도 잘못된 인용·대상일 수 있으므로, 위 수락 조건처럼 제출 항목의 독립 검증을 유지한다. 실제 인용에 없는 조각을 걸러낸 뒤 단일 인용으로 취급하는 방식도 허용하지 않는다. ‘전문 저장 금지’는 공개 진단에 전문을 노출하지 않는 원칙으로만 적용하고, 원응답 보존 참조·지문과 교정 사본의 구분은 유지한다.

두 모델 모두 원응답을 확보하지 못한 상태에서도 규칙 구현과 합성 반례 검증을 진행할 수 있다고 답했다. 따라서 구현 착수의 선행 조건으로 과거 원응답 복구를 요구하지 않는다. 실제 실행의 복구 성공 여부는 수정 후 새 생성 결과로 확인한다.

최종 권고는 검수 안내와 실제 요구사항을 일치시키고, 참여 조건을 실제 행동으로 바꾸는 오류를 막으며, 원문 그대로인 단일 행사 조건에 한해 불필요한 결속 요구를 줄이는 것이다. 다음 구현은 composer 기능 내부에서 이 수락 조건을 충족하는 변경으로 진행할 수 있다.
