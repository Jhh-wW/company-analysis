# 검수 응답 판독과 요약 단계 진단 보완

HYBE 실제 평가에서는 공급자 응답이 정상 종료됐지만 핵심 요약이 2문장이라 출고가 차단됐다. 기존 기록만으로는 검수 응답의 JSON 판독 실패와 문장 판정에 따른 제외를 구분할 수 없었다. 같은 유료 실행을 반복하기 전에 실패 구간을 확인할 관측을 추가한다.

## 변경

실제 JSON 추출기와 평문·묶음 검수 파서가 지나간 분기에 판독 코드, 요청·응답 길이, 행 개수, 빠진 번호 개수와 행 탈락 사유별 개수를 기록한다. 응답 없음, JSON 문법 오류, 객체 아닌 값, 판정 목록 계약 오류, 유효 행 없음은 서로 다른 코드다. `null`은 JSON 문법 오류로 기록하지 않는다. 요청 밖 번호를 세지만 기존 파서의 반환 정책은 바꾸지 않는다. 평문 검수의 1회 재시도와 묶음 검수의 1회 호출을 유지한다.

SHADOW의 기존 요약 경로에는 본문 후보·초안·검수·보충·수치 검사·최종 문장 수와 작성/검수 한도 도달 여부를 기록한다. 실행하지 않은 단계의 개수는 `None`, 실행 후 결과가 없는 경우는 0이다. `도달단계`는 결과를 기록한 마지막 단계다. 작성 도중 치명적 오류가 나면 `시작`, 검수 도중 나면 `작성`까지 남는다. 기존 본문 보충, 수치 검사와 3~5문장 출고 조건은 유지한다.

두 기록은 요청 로컬 목록으로 전달하고 실행 기능의 `finally`에서 닫힌 계약으로 정규화한다. 보고서가 없어도 실행 단계 기록에 남는다. 알 수 없는 필드, 원문·응답·프롬프트·오류문·인용 식별자와 오염된 숫자는 저장하지 않는다. 공개 보고서 필드를 추가하지 않으며 성공, 최종 출고 차단, 공개 근거 계약 오류, 예산 오류와 원인 예외 처리 결과를 유지한다.

## 조직문화 장 보완

우리은행의 주식보상 설명 중 현금결제방식·회계처리·부채 공정가치 재측정·보상원가가 같은 문장에 함께 나오는 회계 측정 설명을 문화 본문에서 제외한다. 기존 `culture_accounting_policy_misplaced` 사유를 쓴다. 실제 검토·승인·감독 절차가 같은 문장에 결속된 경우는 보존하며, 단순한 위원회·감독기관 명사나 부정된 승인을 면제로 삼지 않도록 좁힌다. 기존 손실충당금·재무위험 검사와 도식 경로는 변경하지 않는다.

이 검사는 장 배치를 다룬다. 은행장의 보수를 경영진 전체로 확대하거나 임직원 보상을 경영진으로 좁히는 주체 범위 문제를 해결한 것으로 세지 않는다. 같은 긴 문장에 실제 제도와 회계 설명을 함께 쓰는 경우의 선별 한계도 남아 있다. 문장 전체의 사실성·주체·절차 결속은 기존 의미 검수와 원문 대조가 필요하다.

## 검증 범위

실제 파서 및 생성 경로의 반환값·호출 수 대조, 재시도/판독 코드 구분, 원문 제거, 한도·치명적 오류·출고 차단 뒤 전달과 요약 수치 제거를 확인한다. 수치 제거 시험은 실제 생성 경로처럼 안전한 본문을 제공하고 요약 검수 반환 경계에만 미결속 수치를 주입한다. 실제 수치 검사와 기존 본문 보충을 실행하며 최종 요약에 지운 숫자가 다시 들어오지 않는지 확인한다.

최종 고정 소스 검사는 `.local-artifacts/resume-20260910-composition-diagnostics-final/receipt.json`, 평가 도구 검사는 `resume-20260910-composition-diagnostics-tools-final/receipt.json`에 기록한다. 두 결과의 소스 파일 지문과 HEAD를 대조해 합친 영수증만 다음 평가 서버의 시작 증거로 사용한다. 이전 커밋의 통과 개수를 이번 변경의 검증 결과로 승계하지 않는다.

## 실제 평가 상태

HYBE까지 정산된 캠페인 누적 원가는 14,973.74원, 승인된 20,000원 중 남은 한도는 5,026.26원이다. HYBE는 보고서 JSON/PDF가 없고 고객 청구는 0원이다. 새 변경에서의 기업 평가 성공 여부는 새 실행·정산·품질 검토 기록으로 확인해야 한다. 테스트 통과를 실제 보고서 품질 승인으로 세지 않는다.

## 인계 후 고정 검사

Codex 총괄이 2026-09-10 13:00 KST 사용량 한도로 중단된 뒤 Claude 세션이 인계했다. 인계 시점에 이 문서의 변경(검수 판독·요약 단계 진단, 조직문화 보상 회계 예외 수정)은 미커밋 상태였고, 통합 코드의 최종 고정 검사는 아직 실행되지 않았다.

21경로 선택 검사(`resume-20260910-composition-diagnostics-final/test-selection-flat.json`, `src/features/pipeline/tests` 전체 포함)를 미커밋 트리에서 실행한 첫 결과는 **4,398 통과·12 실패**였다(`.local-artifacts/takeover-20260910-composition-final-claude/receipt.json`). 12건은 모두 `src/features/pipeline/tests`의 세 파일이며, 깨끗한 `4cf29cf2` 분리 워크트리에서도 같은 12건이 실패해 이번 미커밋 변경의 회귀가 아니다. 원인은 `4ac0b03c`의 미래 장 범위 검사(`future_section_no_forward_statement`)가 그 시험들의 공용 작성 대역이 미래 장에도 넣던 완료형 문장 다섯 개를 제외해 장이 비고 ENFORCE 출고가 차단된 것이다. 앞선 27경로 검사에는 이 세 파일이 포함되지 않아 드러나지 않았다.

수정은 시험 자료에 한정했다(`4cf29cf2` 선례와 같은 방식). `test_report_company_id_release_mode.py`와 `test_full_post_output_diagnostics.py`의 미래 장 문장을 회사 주어·대상·활동·양태를 갖춘 계획 문장으로 바꾸고 같은 문장을 원문 조각에 제공했으며, 검수 대역은 후보 문장을 읽어 대응하는 미래 근거를 붙인다. 근거 제거·계획 문장 원복·검수 근거 누락 각각에서 다시 실패함을 음성 대조로 확인했다. `test_full_post_output_diagnostics.py`의 마지막 단정은 이번 변경이 검수·요약 진단을 실행 `finally`에서 단계 목록 뒤에 덧붙이므로 차단 기록을 위치가 아니라 이름으로 찾도록 바꿨다. 제품 코드와 검사 조건은 바꾸지 않았다.

같은 21경로를 다시 실행한 최종 결과는 **4,410 통과·실패 0·경고 39·398.03초**, 소스·시험·템플릿 1,273개 파일과 HEAD가 전후 동일했다(`.local-artifacts/takeover-20260910-composition-final-claude-2/receipt.json`). `app/tools/tests` 전체는 별도 실행에서 182개 통과였다. 유료 평가 관문용 영수증은 이 커밋 뒤 새 HEAD로 `resume-20260910-composition-diagnostics-final/`과 `resume-20260910-composition-diagnostics-tools-final/`에서 다시 만든다.
