# 보고서 입력 비용 절감 변경과 측정 결과

2026-09-13 · 기준 커밋 `eaa20aedd51b7b7c0b5fcc66d79e8842aaaab5ff`

## 결론

작성 입력의 완전 일치 반복을 제거하고 본문·도식 검수 JSON의 구분자 공백을 줄였다. 모델, 근거 원문, 검증 기준, 응답 형식, 호출 수, 출력 한도와 재시도 정책은 보존했다. 관련 시험 2,531건과 독립 교차검토를 통과했다.

확인된 절감 폭은 작다. JYP 시험 자료의 flat 본문 검수와 도식 검수를 합쳐 입력 87토큰을 줄였다. 기존 앱의 Haiku 일반 입력 단가와 고정 환율로 환산하면 약 **0.12원**에 해당한다. 이는 두 시험 요청의 입력 비용 차이이며, 현대글로비스 1건의 전체 비용 절감 실측이 아니다. 이 변경을 큰 비용 절감으로 안내하지 않는다.

## 현대글로비스 비용 기준

사용자가 제공한 검색 스냅샷과 수집·생성 소요 시간이 일치하는 기존 운영 실행의 비용 원장을 읽기 전용으로 확인했다. 신규 보고서 생성 없이 확인한 결과다.

| 단계 | 호출 수 | 앱에 기록된 AI 원가 |
|---|---:|---:|
| 뉴스 본문 분석 | 3 | 84.30원 |
| 본문·요약 작성 | 10 | 429.40원 |
| 본문 검수 | 1 | 160.23원 |
| 도식 검수 | 1 | 47.68원 |
| 합계 | 15 | **721.61원** |

실제 모델은 모든 비용 사건에서 `claude-haiku-4-5-20251001`이었다. 작성 단계에는 캐시 생성 72,086토큰과 읽기 576,688토큰이 기록되어 캐시가 이미 작동했음을 확인했다. 실패 호출 표식은 0이며 사건 합계와 보고서 요약 금액이 일치한다. 고객 청구는 가격 미설정으로 0원이다.

이 금액은 앱의 가격표·고정 환율·호출별 소수 둘째 자리 올림 규칙으로 계산한 내부 AI 원가다. 공급자의 카드 청구 총액, 서버료, 모든 외부 API 요금의 합계와 구분한다. 건별 내역은 기존 실행 번호와 비용 원장을 연결해 조회할 수 있고 사용자가 보고서를 다시 생성할 필요가 없다.

## 변경 범위와 보존 조건

- `composer/logic.py::_render_already_written`: 기존 strip·빈값 제외·80개 상한을 먼저 적용한 뒤, 완전히 같은 문자열을 첫 등장 순서로 한 번만 남긴다. 상한 밖 문장이 새로 유입되지 않는다. 내부 공백·Unicode·다른 표현을 합치지 않으며 캐시 접두부와 장별 근거를 보존한다. 중복이 없거나 앞 장 문장을 전달하지 않는 packet 경로에는 효과가 없다.
- `composer/verify.py`: 출처 메타데이터, 실적표, grouped 도식 칸 JSON의 구분자 공백만 줄인다. 빈 필드, 원값 표, 문서 정보, 장별 출처 경계와 순서를 보존한다.
- `composer/diagram_check.py`: 근거 사전, 도식 칸, 인용 배열에 같은 직렬화 옵션을 적용한다. 서로 다른 근거 ID를 합치거나 문자열 내부 공백을 삭제하지 않는다.

새 시험은 같은 feature의 `tests/`에 둔다. 다른 feature, 가격·예산·예약·정산·운영 설정은 변경하지 않았다. Claude의 `claude/budget-double-review-retry-cap` 변경은 읽기 전용으로 확인했다. 같은 verify.py에서도 Claude 변경은 `_ask_verdicts` 이후 재요청 배선이고, 이번 변경은 그 앞 프롬프트 직렬화 구간이다. 이 확인은 두 변경을 합친 운영 시험을 뜻하지 않는다.

## 무료 토큰 계측

공식 `messages.count_tokens`를 10회 호출했고 텍스트 생성 호출은 0회다. 계측 API는 무료이며 생성 API와 별도 속도 제한을 사용한다. 결과는 공급자의 입력 토큰 추정치라 실제 생성 사용량과 소폭 다를 수 있다. [Anthropic 토큰 계산 문서](https://platform.claude.com/docs/en/build-with-claude/token-counting)

기존 Render Shell의 별도 Python 프로세스에서 공개 시험 자료와 합성 자료만 계측했다. API 키를 읽어 출력하거나 가져오지 않았고 앱 코드·DB·서비스 상태를 바꾸지 않았다. 모델은 기존 실행과 같은 Haiku였다. 원문과 모델 답변이 아닌 입력 해시·글자 수·토큰 수를 [계측 기록](2026-09-13-prompt-token-counts.json)에 남겼다.

| 시험 입력 | 변경 전 토큰 | 변경 후 토큰 | 감소 |
|---|---:|---:|---:|
| JYP 본문 검수 flat | 22,033 | 21,955 | 78 |
| JYP 본문 검수 grouped | 24,153 | 24,062 | 91 |
| JYP 도식 검수 4행 | 8,561 | 8,552 | 9 |
| 합성 작성 입력: 고유 문장 1개 | 2,756 | 2,756 | 0 |
| 합성 작성 입력: 같은 문장 80개 | 4,257 | 2,756 | 1,501 |

JYP 자료는 저장소의 오프라인 시험용 자료이며 현대글로비스 원문이 아니다. flat과 grouped는 대안 경로여서 두 결과를 합쳐 보고서 절감으로 계산하지 않는다. 80회 반복 사례는 경계 시험이며 실제 보고서의 평균 중복률이 아니다.

저장 보고서 5건을 이용한 별도 조건부 재생에서는 4건의 누적 작성 블록이 이전과 바이트까지 같았고, `hive_8d6ae287` 1건에서만 중복 문장 1개가 후속 6개 장에서 각 81글자씩 빠졌다. 이는 렌더 후 저장된 문장으로 재생한 결과다. 생성 당시 중간 입력이나 실제 API 토큰·최종 품질 비교 결과로 해석하지 않는다.

## 품질 검증

전체 composer 시험과 실제 provider 캐시 블록 전달 시험을 함께 실행했다.

```text
python -X utf8 -m pytest src/features/composer/tests src/features/pipeline/tests/test_v2_prompt_cache_blocks.py -q -p no:cacheprovider --tb=short
2531 passed, 11 warnings in 160.19s
```

경고는 기존 Starlette/httpx와 쿠키 사용 방식에 관한 폐기 예정 안내다. 시험 함수명을 프로젝트 규칙에 따라 영문으로 정리한 뒤 전용 시험 58건도 재실행해 통과했다.

검증 범위에는 인용과 장별 근거 경계, 숫자·단위·시점·역할 결속, JSON 문자열 속 가짜 지시, 빈값과 Unicode, 캐시 접두부, 9회 작성 호출, 저장 보고서 회귀, 웹/PDF 전달의 오프라인 E2E가 포함된다. 완전 일치 중복 제거는 별도 작업자가 오류 변형 7종을 주입한 메모리 시험으로 회귀 검출도 확인했다. 본문 JSON은 변경 전 실제 모듈의 AST와 대조해 세 직렬화 옵션 외 변경이 없음을 확인했고 도식 변경도 독립 검토했다.

가짜 provider 기반 시험은 전달 자료와 검증 계약의 보존을 확인한다. 모든 실제 LLM 출력의 동일성을 보장하거나 여러 회사에 대한 유료 품질 비교를 대신하지 않는다. 실제 출력 비용과 운영 보고서 전체 원가 차이는 아직 측정하지 않았다.

## 큰 절감에 대한 판단

이번 변경은 작은 낭비를 줄이는 범위다. 이미 사용 중인 Haiku, 작성 캐시, 인용 원문 중복 제거, 번호만 고르는 요약을 새 절감 수단으로 다시 계산하지 않는다. 출력 한도를 낮추는 것 자체도 실제 사용 토큰 감소와 같지 않다.

더 큰 절감은 생성 문장의 근거 적합성을 높여 폐기·재작성 비용을 줄이는 방향에서 검증해야 한다. 다만 90개 생성 후보 중 50개가 남았다는 로그만으로 비용의 44.4%를 없앨 수 있다고 계산할 수 없다. 원래의 검증 기준과 핵심 사실을 유지한 여러 회사의 비교 평가가 필요하다. 이번 변경은 모델 하향·검수 삭제·근거 축소를 도입하지 않는다.
