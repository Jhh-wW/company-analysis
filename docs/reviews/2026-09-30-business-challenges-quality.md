# 사업 중심의 5장과 보고서 품질 후속 검증

## 현재 상태

PR #106은 배포 완료 상태다. 마지막 직접 운영 조회의 전체 SHA는 `7e9627565b232ec18e3c8540cd3d9e21fa2b4612`이며 `healthz=ok`, `readyz=ready`, 관리자 상태는 `normal`이다. 후속 PR #107의 후보 `817606c1`과 `7542f5f9`는 각각 전체 CI를 통과했지만 실제 유료 내용 검수에서 불합격했다. 10월 1일 두 번째 결과까지 보존하고 공통 결함을 보완 중이며 이번 최종 배포는 아직 하지 않았다.

최초 dirty 변경 12개는 별도 복사·지문 목록으로 보존한 뒤, 코드 트리가 같은 최신 main 기반 브랜치로 옮겼다.

## 바꾸는 동작

- 2장: 고객·제공물·이용 또는 전달·대가가 같은 문장이나 표 행에서 연결되는지 확인한다. 금융부채의 대가, 공정가치, 감사 설명으로 가치 교환 칸을 채우지 않는다. 정상 구독료·이용료·판매대금·개발 대금과 구체적인 서비스 효용은 남긴다.
- 5장: 제품·서비스·사업의 품질, 고객 이용, 기술, 공급, 경쟁, 규제를 중심으로 작성·검수한다. 일반 유동성 관리나 회계 규칙을 회사 고유 문제로 바꾸지 않는다. 혼합 원문은 보존하고 해당 의미칸의 부당한 점수만 막는다.
- 직접 확인한 회사 문제가 부족하면 공식 사업 설명과 실제 산업 기사를 묶은 별도 보충 내용을 제공한다. 국내·세계·해외 특정 지역을 구별하고, 회사 적용은 **해석**으로 표시한다. 회사의 직접 피해와 실제 대응이 확인되지 않았다는 점도 함께 쓴다.
- 회사 기사와 산업 기사, 회사 사실과 산업 해석을 별도로 운반한다. 산업 보충 내용은 회사의 공식자료 준비 상태나 FULL 품질 하한을 올리는 데 사용하지 않는다.
- 기존 검색·본문·AI 호출 상한 안에서 산업 조사에 일부 기회를 배분한다. 회사 검색에 쓸 수 있는 몫이 줄어드는 절충이 있으며 기사 수 증가를 보장하지 않는다. 산업 관계 자체의 의미 판단에는 모델 오류 가능성이 남는다.
- 저장·웹·PDF·Notion이 같은 공개 내용을 사용하며, 산업 보충이 빈 기존 보고서는 기존 정본 형식을 유지한다.
- 산업 출처는 기사와 공식 보도자료를 포함할 수 있어 `산업 자료`로 표시한다. 공개 산업 자료 수는 회사 기사 수와 따로 기록한다.

## 공식 사업 연결의 실제 입력 확인

DART 목록 응답에 있던 법인 코드가 선택 결과에서 사라지는 공통 결함을 고쳤다. 실제 선택한 목록 행의 코드와 요청 회사가 일치할 때만 목록 검증 상태를 부여한다. XML에도 `DOCUMENT` 직속 `COMPANY-NAME`의 `AREGCIK` 회사 코드가 있음을 실제 보존 원문 네 개에서 확인했다. 이 선언을 제한된 머리말에서 읽고, 문서 코드가 다른 회사이면 목록 코드가 맞아도 거절한다. 선언 부재와 깨진 명시 선언을 구별하며, 중복·중첩·외부 엔터티·읽기 상한 초과를 거절한다. 본문의 태그나 계열사 이름은 소유 회사 증거가 아니다.

현재 공시 목록 한 번의 무료 조회와 보존 XML을 생산 수집 경로에 넣어 대상 회사의 실제 사업 앵커 한 개를 확인했다. 원문·위치·문서 지문은 보존했다. 이 재현은 과거 실행 전체나 모든 회사에 대한 성공 증거가 아니다. 목록 응답은 당시 저장된 파싱 결과와 응답 바이트 지문만 있으며, 원래 응답 바이트는 보존되지 않았다는 한계가 있다.

수집기 버전은 원문 법인·표 행의 제약 문맥을 운반하고 회계 문맥의 절 분할 우회를 막는 변경을 포함해 `evidence_collection/2.6`으로 올렸다. 본문 분할 파서 버전 `2.1`은 변경하지 않았다. 원문 조각의 내용·위치·해시와 별도로 법인 표제 또는 표의 전체 행을 붙이며, 이 문맥은 인용에 없는 사실을 추가하는 근거로 사용하지 않는다.

수치는 서로 다른 실행이나 단위를 합치지 않았다. 당시 원문·모델 응답이 없으면 기사 판정의 정오를 확정하지 않는다.

## 회귀에서 바로잡은 점

- 과거 연결 시험이 순수한 수익인식 기준을 `value_exchange`의 양성으로 사용했다. 현재 계약과 맞지 않아 실제 고객의 용역 이용·대금 지급을 합성 원문과 작성 문장에 넣었다. 정확한 진행기준·1년 예외 조건의 의미검수 반례는 유지했다. 가드를 낮춰 회계 문장을 살리지 않았다.
- 이 과정에서 명시적인 개발 대금 지급도 과도하게 제외하던 정상 반례를 찾아 분류기를 고쳤다.
- 옛 인용 객체는 `number` 필드가 없는 경우가 있다. 산업 보충이 빈 기존 보고서는 새 출처 번호 조회를 하지 않도록 호환성을 유지했다.
- UI의 기존 문단 클래스가 번호용 2열 구조여서 새 보충 글이 좁은 칸에 접히는 문제를 실제 렌더에서 확인하고 수정했다.
- 산업 출처가 회사 뉴스 집계에 섞이지 않도록 새 검증 도구는 기사·조각·출처·공개 문장을 따로 센다. 기존 외부 QA의 뉴스 출처 수만으로 회사 뉴스 개선을 주장하지 않는다.
- 정상적으로 수집한 사업 근거가 최종 작성 묶음에서 빠지면 산업 보충만 제외하고 그 이유를 기록한다. 이전 연결은 이를 원문 변조와 똑같이 취급해 전체 보고서를 실패시킬 수 있었다. 원본에 없는 앵커나 같은 인용 번호의 원문 변조는 계속 차단한다.
- 검수 지침 추가로 바뀐 프롬프트 기준값은 이전 문구를 복원했을 때 옛 네 해시가 모두 재현되는지 확인한 뒤 갱신했다. 입력 원문과 인용 직렬화는 같았다. 과제 표 시험은 가짜 작가가 지침 안의 단어를 표 헤더로 잘못 읽는 문제였으며 실제 파서는 바꾸지 않았다.

## 부분 보고서와 표시 검증

현재 신규 실행에 lifecycle·발행 의도·Delivery 기록이 있으면 오래된 보고서의 읽기 전용 HTML 호환 경로로 우회하지 못한다. 과거 Delivery가 없는 PDF를 새로 만들어 덮어쓰지도 않는다. 실제 부분 생성 경로에 원문 없는 금액과 없는 인용을 넣은 무료 반례는 모두 공개에서 제외됐다. 관련 부분·검수·legacy 정책 100건이 통과했다. 이것이 당시 메디라인의 생성·전달 로그를 대신하지는 않는다.

가상 자료로 만든 PDF 세 쪽과 웹의 데스크톱·모바일 화면을 확인했다. 산업 과제의 두 출처와 해석 문구가 PDF·웹·Notion에서 같고, 회사 사실 수와 5장 준비 상태를 올리지 않았다. 실제 유료 PDF 합격과는 별도 증거다.

## 운영 장애와 보존

9월 28일 00:24의 일시 장애는 Render 과거 로그에서 저장소 신원 대조 실패, 서버 종료·재시작, 00:25 정상 회복 순서가 확인됐다. 대조값은 DB 고유 신원과 스키마 버전의 튜플이므로 어느 값이 달랐는지는 당시 값이 없어 확정하지 않는다. 잠금·RAM 부족·데이터 손실로 단정하지 않는다.

이전 배포 전후 보호 37표·1,478행, 보고서 113개·공유 연결 33개·참조 파일 81개와 내용 해시는 같았다. 다만 옛 111개 고정 기준 때문에 `baseline_count_match=false`였으며 검사 전체 성공으로 기록하지 않는다. 다음 배포는 바로 직전의 실제 기준으로 다시 비교한다. 영속 디스크 2GB와 RAM 요금제는 별개이며 이번에 RAM을 증설하지 않았다.

## 남은 관문

### 두 번째 신규 유료 실행과 후속 수정

사용자가 10월 1일 캠페인 예산 제한을 명시적으로 해제했다. 후보 `7542f5f9`의 전체 CI `36735042782` 성공 후 새 표지 `v7run_c07b6b97a297`를 정확히 한 번 실행했다. 실비는 728.91원이며 제공자 시도 17건은 모두 정산됐다. 활성 실행·예약·미확정 부채는 0이고 과거 표지를 다시 실행하지 않았다.

- 결과와 10쪽 PDF는 HTTP 200으로 회수됐다. 등급은 부분 완성, 정책은 `evidence-available-v1`이다. 실제 Delivery 완료·공개 이력과 자동 PDF 공개 기록 1건을 확인했고, 회수 JSON·PDF·저장 스냅샷·등록 파일의 지문이 일치한다. 이 전달 성공이 내용 품질 합격을 뜻하지는 않는다.
- 다른 회사의 기술을 대상 회사 기술로 바꾸던 사례는 이번에 실제 주어를 유지했다. 원 XML 표 행의 행위자·적용 예정 문맥 지문이 작성 입력과 최종 사실 기록까지 일치한다.
- 5장에는 순수 환율 노출, 운송 수익인식, 반품·할인 추정이 사업 과제로 남았다. 쉼표 뒤 회계 처리절이 주어를 잃어 분류를 통과했고, 문장 검수만 하는 경로의 표는 본문과 다른 검사를 받았다. 같은 문장의 회계 맥락을 보존하고 5장 본문·표·장 이동에 같은 사업 범위 검사를 적용한다. 실제 사업 문제와 금융 대응이 연결된 행 및 혼합 원문은 보존한다.
- 독립 반례에서 금융 서비스를 본업으로 하는 회사의 고객 문제와 제조사의 설비 대응이 과도하게 제외되는 문제도 찾아 보완했다. 회계 맥락은 실제 회계 처리로 이어지는 절에만 전달한다. 엔진·앱·5장 직접 작성·다른 장에서의 이동을 대조한 최종 29종 반례와 엔진 전체 767건이 통과했다. 조건부 품질 계획까지 문단 전체로 지우도록 기대한 시험 1개는 원문 보존·5장 채점 0이라는 실제 계약으로 바로잡았으며 이전 실패 결과도 보존했다.
- 표의 법인·예정 상태 검사가 빠진 경로도 독립 재현했다. 문장 검수와 묶음 검수 양쪽에 같은 원문 문맥 제약을 연결하고, 검수 뒤 문맥 변경·삭제·추가 시 기존 표 승인을 재사용하지 못하게 했다. 문맥이 없는 기존 자료의 검수 지문은 유지한다.
- 회사·산업을 합친 검색 220행, 신뢰 후보 58건, 본문 조사 기사 24건·읽기 16건에서 회사 기사 2건이 검증돼 공개 본문 2문장으로 남았다. 기사·조각·문장 수를 합산하지 않는다. 공식 사업 앵커 1개는 실제로 활성화됐지만 산업 보충은 0건이다. 당시 뉴스 모델 입력·응답이 디스크에 남지 않아 정확한 탈락 원인은 확정하지 않는다. 다음 격리 검증에는 입력과 파싱 응답을 구분해 보존한다.
