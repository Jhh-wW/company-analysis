# 뉴스 근거와 회사별 품질 검토

## 목적과 확정된 사용자 기준

- 공시는 가장 신뢰하는 중심 자료로 유지한다. 뉴스는 공시 이후의 변화와 설명의 깊이를 보강한다.
- 공식 발표와 신뢰할 수 있는 언론을 조사하고, 관련 본문의 근거와 뉴스 목록에 함께 반영한다.
- 최근 12개월을 먼저 조사한다. 유효한 자료가 적을 때 24~36개월까지 확장하고 오래된 보도임을 표시한다.
- 기사 개수 할당량을 채우지 않는다. 동일 보도자료 전재와 같은 사건 반복은 독립적인 내용 증가로 세지 않는다.
- 보도된 숫자는 출처와 보도일을 붙여 사용할 수 있다. 공시로 확인한 실적과 외부 보도를 구분한다.
- 자료가 적으면 확인된 내용만 제공한다. 공개 자료 부족과 검색·접속 장애는 별도로 표시한다.
- 회사 규모·산업이 달라도 신원 확인, 수집 범위, 원문 검증, 출처 표기 기준은 같다. 자료 가용성이 비슷한 회사끼리 내용 충실도를 비교한다.
- 유료 실제 실행을 포함한 검증이 허용됐다. 기존 비용 원장·호출 상한·출고 안전 검사를 우회하지 않는다.

## 확인된 구조적 원인

1. `news_intake/select.py`의 뉴스 발동 조건이 공식 자료의 빈 장에 종속돼 있다. 모든 장이 준비됐고 공식 웹 문서가 한 건 이상이면 `pipeline/real.py`는 검색을 하지 않고 `검색호출=0, 실패=null`로 끝낸다.
2. 기사 제목·검색 요약만 분류한 뒤 본문을 읽는다. 대상 회사의 법인 정보가 분류 프롬프트에 없고, 본문에서 대상 회사에 관한 유효한 사실인지 다시 판정하지 않는다.
3. 원문을 처음부터 문장으로 나눈 뒤 숫자가 들어간 문장을 모두 버린다. 그러므로 페이지 제목·일반론·영상 묘사 같은 숫자 없는 앞부분이 중요한 사업 사실보다 먼저 살아남는다.
4. 전체 상한은 기사 수가 아니라 문장 6개다. 기사당 문장 2개와 입력 순서 선별이 결합해 앞쪽 소수 기사에 쏠린다.
5. 장별 뉴스 표는 원문·출처 결속만 확인하고 의미 검수를 하지 않는다. 글자를 그대로 복사했다는 사실은 대상 회사에 맞는 유익한 근거라는 증거가 아니다.
6. 불변 보고서 캐시 재사용 판정은 뉴스 검색보다 먼저 일어나며 뉴스 검색 결과가 생성 신원에 포함되지 않는다. 공식 자료가 같아도 뉴스가 바뀔 수 있다는 입력 조건을 반영해야 한다.

## 검증 계획과 진행 상태

수집·작성·운영의 독립 감사를 마치고 구현·통합 시험 중이다. 아직 수정본의 유료 실제
보고서 비교·최종 전체 시험·배포를 마쳤다고 주장하지 않는다. 아래 항목의 완료 여부는
실제 증거를 확보한 뒤 기록한다.

- 수집·본문 반영·프로젝트 전반의 독립 병렬 감사.
- 회사 신원과 본문 근거 범위를 검증하는 뉴스 수집 경로, 최신성 갱신, 다양성 선별, 원인별 진단 수정.
- 본문 인용·뉴스 목록·출처 부록·웹/PDF/Notion의 일치 검증.
- 제공된 6개 회사와 다른 산업·자료 가용성의 대표 회사로 실제 실행 비교.
- 같은 입력의 반복 실행 및 자료 부족·검색 장애·동명이의어·전재·숫자·원문 잡음 회귀 시험.
- 발견한 별도 결함의 영향·수정 여부·남은 제한을 구분한 전체 프로젝트 검토 결과.

유한한 표본으로 모든 회사의 완벽한 동일 품질을 보장한다고 주장하지 않는다. 대신 같은 검증 계약을 코드로 적용하고, 표본 밖 회귀를 탐지할 재현 가능한 평가를 남긴다.

## 통합 검토에서 추가로 확인한 결함

초기 단위시험 통과만으로 종료하지 않고 작성·검색·실행 경계에 별도 입력을 넣어 재검토했다.

- 작가가 직접 인용한 뉴스가 검수에서 거절된 뒤 뉴스 목록으로 다시 나타났다. 자동 보강뿐 아니라 최초·보충 작성 회차의 전체 뉴스 인용을 추적하도록 수정했다. 거절 뒤 본문과 목록 모두 0건인 회귀를 확인했다.
- 공식 한글 법인명과 영문 이름을 알고 있어도 혼합 표기를 기사에서 찾지 못했다. 공식 한·영 전체 이름이 교차 증명하는 알파벳 독음만 정규화한다. 짧은 영문 접두를 임의 별칭으로 만들지 않으며, 이름 미확인은 실제 자료 부족과 구분한다.
- 공식 사업 본문이 없는 경우 회사 프로필의 필드명·대표자명이 사업 문맥처럼 쓰여 정상 기사를 거절했다. 프로필 신원 필드와 공식 사업 문맥을 분리했다.
- 평가 서버가 정상 응답하더라도 실제 실행 버전이 미확인 상태라 생성이 차단됐다. 실행기는 실제 Git HEAD와 변경 여부를 확인하고, 미커밋 실행 소스를 이전 버전으로 가장한 유료 시험을 차단한다.
- 검색 어댑터의 내부 재시도가 논리 검색 횟수와 같은 것으로 기록됐다. 전송 시도·재시도 복구·실패 원인을 별도로 반환하고 검색 스냅샷과 실제 전송 예산을 연결했다. 기존 어댑터가 실제 전송을 관측하지 못한 경우는 0회가 아닌 미확인으로 남긴다.
- 제목·검색 요약에 회사 이름이 없으면 본문에 정확한 법인이 있어도 읽기 전에 버렸다. 메타 이름 일치는 우선순위로만 사용하고, 비일치 후보도 같은 본문 검증과 예산 안에서 조사한다. 정상 검색에 섞인 무관한 기사 한 건 때문에 전체 조사를 장애로 판정하던 문제도 수정했다.
- 뉴스 분석이 전체 AI 호출 한도를 먼저 소비해 FULL 보충 검수에서 중단될 수 있었다. 전체 18회를 유지하면서 FULL 작성·검수·허용된 보충에 13회를 남기고 뉴스 분석은 남은 예산 안에서 실행한다. 상한 때문에 미분석한 기사는 자료 부재로 표시하지 않는다.
- 평가기의 뉴스 활용 단계명이 실제 생산 단계명과 달라 본문·목록 지표가 미확인으로 기록됐다. 실제 생산 단계명과 구형 호환 이름을 함께 읽고 독립 재현으로 일치를 확인했다.

최신 뉴스 메타·본문 분리 수정은 담당 시험 287개와 연결 시험 224개를 통과했다.
호출 예약과 평가 지표는 별도 작업자가 실제 FULL 보충 분기에 연결해 총 18회로
완주하고 생산·소비 지표가 일치함을 재검증했다. 본문·목록·출력 412개,
NAVER 어댑터 42개도 앞선 표적 시험에서 통과했다. 시험 묶음은 일부 겹치므로
합산한 수치를 서로 다른 시험 총수로 제시하지 않는다.

전체 오프라인 회귀의 첫 실행은 앱 8,398 통과·4 실패·1 건너뜀이었다. 실패 4개는
Windows 임시 실행기의 프로세스 재진입과 긴 경로 문제를 보정한 재실행에서 모두
통과했다. 엔진 492개, 평가 도구 160개, 배포 122개, 운영 도구 119개가 통과했다.
앱 1개·운영 도구 3개의 Windows 심볼릭 링크 권한 관련 건너뜀은 Linux 검증이
남아 있다. 이 전체 회귀 뒤 변경된 뉴스·호출 예약·KPI는 최신 표적 검사를 별도로
실행한다. 한 번의 전체 실행이 실패 없이 끝났다는 뜻은 아니다.

최신 뉴스·작성·파이프라인 통합 검사(14:49~14:50)는 2,091 통과·1 실패·건너뜀
0개였다. 한 실패는 요청별 계량 래퍼의 새 공개 메서드를 저수준 모듈에서만 찾는 정적
시험이었다. 실제 래퍼에 선언된 API도 대조하도록 시험 계약을 고친 뒤 해당 시험의
독립 재실행 1개와 관련 계약·호출 예산 묶음 23개가 통과했다. 관리자·웹·읽기 전용
경계의 최종 별도 회귀는 177 통과·실패 및 건너뜀 0개였다.

수정본의 실제 8개 회사 보고서 비교와 배포는 아직 완료하지 않았다. 자동시험
통과 수는 실제 기사 활용의 유용성·회사별 내용 품질·배포 성공을 대신하지 않는다.

### 실제 HTTP 시험의 첫 진입 — 14:55 KST

커밋 `b4447ce`의 격리 서버는 실제 커밋 신원·ready·운영 관측 스위치 일치를 확인했고,
8사 GET 사전검사를 통과했다. 첫 회사 확인 요청은 본조사 접수 전에 중단됐다.
평가기 HTTP client에 `Origin`이 없었으나, 유료 로컬 서버의 CSRF 경계는 정확한
동일 출처 헤더를 요구한다. 실행기에서 검증한 loopback origin을 항상 전달하도록
수정하고, 응답 후 파싱 실패에서도 HTTP 상태만 안전하게 보존하도록 보완했다.
실제 ASGI 앱 경계를 사용하는 회귀에서 Origin 누락·null·다른 호스트는 403이며,
정확한 Origin은 화면 CSRF를 통과함을 확인했다. 동의는 생략해 다음 경계에서
중단하므로 공급자를 호출하지 않았다. 평가기 전체 23개가 통과했다.

첫 격리 DB의 lifecycle·공급자 attempt·비용 사건·AI 비용 사건·미정산 예약은 모두
0건이었다. 불확실 체크포인트를 초기화하거나 자동 재전송하지 않았고, 서버를 종료해
원본 증빙을 보존했다. 이 결과는 보고서 생성 품질 실패도 유료 생성 성공도 아니다.
수정 후 새 커밋·격리 서버에서 의도적인 새 시험을 시작한다.

## 별도 운영 제한

`EVIDENCE_RECLASSIFY=1`의 공식 근거 재판정은 생성 소유권 확정 전에 계량 모델을
호출하는 기존 경로가 있어, 캐시 미적중 때 실제 호출이 차단될 수 있다. 현재 확인한
운영 설정과 이번 비교 설정은 모두 OFF이므로 이 문제를 검증했다고 보지 않는다.
단순히 소유권·비용 방어를 해제하는 방식으로 우회하지 않는다. 전역 동기 DB 접근과
계측되지 않은 KPI 표시는 별도 [운영 감사](project-runtime-audit-2026-09-08.md)의
수정·보류 구분을 따른다.
