## 결론

사용자가 보낸 PDF와 운영 저장본의 SHA-256이 정확히 일치한다. 해당 실행은 뉴스 기능이 켜져 있었고 검색도 성공했다. 그러나 본문 작성에 넘길 검증된 외부 기사 근거가 0건이어서 최종 보고서에 외부 언론 기사가 실리지 않았다. 기사 검색 결과가 없었던 실행으로 설명하면 잘못이다.

## 어디에서 막혔는가

- **매체 등록 조건:** 확인한 도메인 55개만 허용하는 정책에서 57개 미등록 도메인의 검색 응답 107행이 제외됐다. `ddaily.co.kr` 5행, `platum.kr` 3행 등이 포함된다. 미등록이라는 사실은 해당 기사 자체가 부정확하다는 판정과 다르다. `untrusted_publisher`와 `publisher_verification_required`의 107은 같은 단계의 중복 표기이므로 합산하지 않는다.
- **본문 확보:** 시도한 20개 중 5개에서 본문을 얻지 못했다. 진단은 접근 제한 3개와 빈 본문 2개다. 제한을 우회해서 수집하는 변경은 제안하지 않는다.
- **회사·원문 검증:** `grounded_identity_unverified`가 5회이며, 세부 사유는 회사 확인 증거 문구의 원문 불일치 4회와 이름 누락 1회다. 실질 사건 아님 5회, 주체 누락 3회, 본문 근거가 아닌 항목 2회, 근거 문구 원문 불일치 1회도 기록됐다. 이는 검증 단계별 집계라 서로 배타적인 기사 수로 합산하지 않는다.
- **예산과 미완료:** 분석 호출 상한 3회와 본문 시도 상한 20개에 도달했다. 12개월 창의 후보 52개 중 미시도 32개가 남았다. 최종 상태는 `failed`, `자료부족=false`, `검증미완료`에 본문·회사·주체·원문·매체 확인 미완료가 포함된다. 모든 기사를 확인한 뒤 쓸 자료가 없다고 판정한 결과가 아니다.

짧은 회사명 `뤼튼`을 전체 법인명 `뤼튼테크놀로지스`에 연결하지 못하는 조건은 Astra가 무료 합성 입력으로 재현했다. 다만 저장된 운영 집계에는 개별 기사의 입력과 분석 응답이 없어, 위 5회의 회사 확인 실패가 전부 이 조건 때문이라고 단정할 수 없다. `검증된이름변형`이 빈 배열인 사실과 개별 실패의 원인은 구분한다.

Astra의 배포 버전 대조에서 회사 이름·원문 검증·검색 후보 필터·매체 허용목록은 현재 로컬 코드와 동일했다. 이전 속도 개선의 주요 차이는 본문 동시 수집이다. 이번 기사 채택 문제는 앞선 수정본 배포와 별도로 보완할 항목이다.

## 결과물 피드백

Claude Fable이 PDF 5쪽 전체와 부록을 검수했고, 총괄도 3·4쪽 렌더를 확인했다. 외부 언론 출처는 없지만 회사 공식 웹 자료 2건은 사용됐다. 두 출처는 크랙 보호 정책과 상장 준비 관련 내용이다.

뉴스 누락 외에도 6장 성장 전략은 비었고, 8장은 내용이 다른 장으로 옮겨졌다고 안내하지만 해당 내용이 확인되지 않으며, 9장 차별점은 회계정책 설명 4문장으로 채워졌다. 숫자의 원문 일치와 보고서 전체의 분석 품질은 별도 평가다. 이 PDF를 품질 합격으로 판정하지 않는다. 자세한 쪽별 검수는 [PDF 검수 기록](2026-09-22-wrtn-pdf-review.md)에 있다.

## 비용을 먼저 늘리지 않고 고칠 순서

1. 공식 자료로 입증된 법인명·브랜드명 관계를 기사 검증에 전달한다. 글자가 비슷하다는 이유만으로 별칭을 만들거나 다른 회사를 통과시키지 않는다.
2. 확인 가능한 매체 정보를 검토해 등록 목록의 누락을 보완하고, 현재처럼 검증이 끝나지 않은 상태를 단순한 기사 없음과 구분한다.
3. 같은 분석 호출 예산 안에서 회사 이름·주체·증거 문구를 원문 그대로 선택하도록 입력과 결과 검증을 개선한다. 수집 후보의 우선순위도 점검한 뒤 실제 기사 채택률을 확인한다.

호출 횟수를 늘리는 것만으로 회사·원문 검증 문제가 해결된다고 보장할 수 없다. 위 항목은 이번 조사에서 정한 수정 우선순위이며, 이번 조사로 구현·배포됐다고 주장하지 않는다.
