# ADR 0002 — 검수 응답 판독 내구성과 빈 장 복구 키 해석

> 작성 2026-09-23 · 버전 1.1(구현 대조 반영) · 작성 개발 에이전트, 검토 총괄 · 청중 개발자·검토자
> 200줄 규칙에 따라 이 문서는 인덱스이고, 결정마다 챕터 파일을 따로 둡니다(아래 «결정» 표).

## 상태

- (a) 검수 응답 판독: 승인됨 — 2026-09-23, 총괄 대조 완료.
- (b) 빈 장 복구 키 해석과 주장슬롯 앞부분 복원: 승인됨 — 2026-09-23, 총괄 대조 완료.
- (c) 감사 상용구 조각 차단: 승인됨 — 2026-09-23, 총괄 대조 완료.
- (d) 제외 각주가 있는 법인의 소속·지분 단정: 제안 — 보강 진행 중.

## 변경 요약

- 1.0 → 1.1(2026-09-23): 구현과 문장 단위로 대조해 고쳤습니다.
  - (a) 응답 스키마는 기본 꺼짐 스위치 뒤에 둡니다. FULL 호출 장부 아래에서는 행 단위 구제만
    효과가 있다는 점과 부분보고서의 호출 예산을 적었습니다.
  - (b) 번호만 있는 키의 요청 순번 규칙, 응답 단위 정본 번호 판별, 섞인 번호 답의 본문 칸 교차
    확인, «1.» 미수용·재요청 비보장 한계를 더하고, 모호 규칙 문장을 고쳤습니다.
  - (c) 세 겹 차단, 사유 코드 재사용, 경계와 한계를 적고, 적용 범위를 모든 장으로 고쳤습니다.
  - (d) 절을 새로 만들었습니다.
  - 200줄을 넘어 인덱스와 챕터 네 개로 나눴습니다. 내용은 줄이지 않았습니다.

## 맥락

2026-09-23 유료 실측 1회(외부감사 대상 비상장 회사 1곳)에서 보고서가 9장 중 8장이 빈 채
«부분 완성»으로 끝났고 공개가 차단됐습니다. 실행 기록과 진단으로 확인한 원인은 두 가지입니다.

1. **검수 응답 한 행의 문법 오류가 판정 전체를 지웠습니다.** 본문 검수는 장별 근거
   묶음(packet) 경로를 탔습니다. 운영 FULL과 부분보고서가 함께 쓰는 경로입니다. 이 경로는
   응답 형식 스키마 없이 한 번만 호출했습니다. 응답은 잘리지 않고 정상 종료했고 판정 행
   42개를 담았습니다. 그중 1행에서 배열을 닫는 대괄호가 빠졌습니다. 나머지 41행은 각각
   단독으로 읽히는데도 응답 전체의 JSON 파싱이 실패해, 유효 행 0개·미응답 번호 42개로
   처리됐습니다. 검수를 통과하지 못한 문장은 공개하지 않으므로 본문이 거의 모두 사라졌습니다.
2. **빈 장 복구의 정답이 장 키 모양 때문에 버려졌습니다.** 복구 작가는 두 장을 요청받았습니다.
   첫 답은 장 ID 대신 «1장 <장 제목>» 같은 표시명을 키로 썼습니다. 재요청 답은 «1장»·«2장»을
   키로 쓰고 주장슬롯에서도 «장 ID:» 앞부분을 뗐습니다. 두 답의 인용은 모두 요청에 준
   조각이었고, 의미칸도 앞부분을 붙이면 인용한 조각의 목록 안에 있었습니다. 그런데도 두 번
   모두 «요청장없음»으로 판정돼 «작성형식실패»로 끝났습니다. 지시문은 JSON 예시에
   `<요청 장 ID>` 자리만 두고 실제 ID를 적지 않았고, 근거 묶음의 작성범위 문구에는
   «N장 «제목»»이 먼저 보였습니다.

같은 날 앞선 실측에서는 재무·감사 문서의 상용구가 사업 주장의 근거로 쓰인 결함(9장
「회사가 밝힌 차별점」 전체가 회계정책 상용구)이 기록됐습니다. 외부감사 대상 회사는 공식
문서가 감사보고서 하나뿐인 경우가 있어, 감사인 책임·감사의견 같은 상용구 문단도 근거 후보에
그대로 섞입니다.

이번 실측의 독립 검수에서도 감사인 책임 문단을 회사의 과제·대응으로 옮긴 5장 후보 8건과,
감사의견 문구를 회사 특징으로 쓴 9장 후보 1건이 검수 AI의 «참»을 받았습니다(판독 실패로
공개되지는 않았습니다). 표 행의 각주가 종속기업에서 제외한 법인을 «종속기업 <법인>을 보유»라고
쓴 문장도 «참»을 받았습니다.

네 결정은 모두 «막힌 것을 풀어 채우기»가 아닙니다. «이미 검증할 수 있는 정상 답을 형식
문제로 잃지 않기»((a)·(b)), «근거가 될 수 없는 조각을 앞 단계에서 거르기»((c)), «근거의
조건을 지운 단정을 막기»((d))로 범위를 한정합니다.

## 공통 품질 원칙

- 가드를 통째로 완화하지 않습니다. 구제·해석·복원은 «형식»만 넓히고, 받은 문장은 기존 검수·
  근거 결속·수치 안전 검사를 모두 다시 거칩니다.
- 근거 없이 채우지 않습니다. 판정이 없는 번호를 참으로 보거나, 깨진 행을 추측으로 복원하거나,
  빈 장을 근거 없는 문장으로 채우지 않습니다.
- 관측 기록에는 개수와 닫힌 코드만 남깁니다. 문장·키 원문·회사명은 싣지 않습니다.
- 회사명이나 특정 문장을 코드 분기·목록에 넣지 않습니다. 규칙은 모든 회사와 업종에 같습니다.

## 결과

- 검수 응답 한 행의 형식 오류나 복구 답의 키 모양 때문에 검증 가능한 본문이 사라지는 일을
  줄입니다.
- 호출·출력·비용 상한은 올리지 않습니다. packet 검수의 두 번째 호출은 FULL에서는 호출 장부가
  막고, 부분보고서에서는 이미 예약된 재요청 여유 안에서 쓰입니다((a) 결과).
- 감사 상용구와 제외 각주 법인의 단정은 검수 AI의 «참»과 무관하게 기계 규칙으로 막습니다
  ((c)·(d)). 막힌 만큼 장이 빌 수 있으며, 빈 장은 안내문으로 둡니다.
- 실제 모델에서의 효과는 같은 조건의 유료 실측 1회로 다시 확인합니다. 맥락의 수치는 수정 전
  실행 1회의 관측값이며, 수정 효과로 소급하지 않습니다.
