# ADR 0006: FULL 자기 선언 프로그램의 공식 원문 숫자 대조

상태: 채택 (2026-09-24)

## 문제

FULL 실측에서 공식 자료의 숫자를 그대로 옮긴 자기 선언 사실과 그 사실을 다시 인용한 한계 문장이 수치 이름표·NumericBinding 부재로 차단됐다. 이 두 문장은 계산값이 아니며, 기존 산문 예외는 `verified_prose`만 대상으로 하므로 프로그램 사실에는 적용되지 않는다. 또 숫자 뒤 단독 조사 `에`가 붙은 문장은 원문의 같은 맨 숫자와 서로 다른 토큰으로 읽혔다. 세 사실이 각각 두 안전 문제를 만들어 보고서가 공개 관문에서 중단됐다.

## 결정

- FULL v3에서만 `stated_differentiator` 사실의 숫자를 공식 원문과 대조한다. 확인 상태, 경쟁 장의 두 허용 슬롯, 단일 공식 출처의 종류·문서 신원·회사 발행자·발행일, 원문 SHA-256과 등록 지문, 구조화 수치 입력 부재를 모두 확인한다. 원문에는 실제 회사 주어와 정해진 자기 선언 표지가 있어야 하며, 원본 주장은 생산자와 공유하는 정본 함수로 원문의 회사 주어만 바꾼 문장과 글자 단위로 일치해야 한다. 문장의 모든 숫자 토큰이 그 사실의 정확한 원문에 있을 때만 NumericBinding 두 검사를 생략한다.
- 한계 문장은 같은 출처와 원문을 가진 원본 자기 선언 사실이 최종 공개 집합에 남아 있고, 생산자와 안전 평가기가 공유하는 고정 문장 형식에 정확히 맞아야 한다. 임의로 추가한 설명이나 숫자는 예외를 받지 않는다.
- 숫자에 바로 붙은 단독 위치 조사 `에`만 제거한다. `년`, `개`, `가`, `도`, `과`, 부호, 크기 단위는 그대로 구별한다.

## 검증과 한계

실측 저장 원문·문장을 외부 호출 없이 대입하면 앞서 확인된 숫자 안전 문제 세 사실이 통과한다. 일반 URL·뉴스·다중 출처·누락된 발행일·해시 불일치·원문에 없는 값·원본 주장의 동사·조건·부정 변조·형식이 바뀐 한계 문장은 계속 차단한다. 안전 평가에 별칭 목록이 운반되지 않으므로 별칭만으로 주어가 쓰인 수치 자기 선언은 보수적으로 차단한다. 저장 자료 재현에서 URL과 Source ID는 합성했으므로 실제 FULL 출고와 PDF 품질은 별도 실측으로 확인해야 한다.

이 결정은 [ADR 0005](0005-full-safety-verbatim-numeric-official-prose.md)의 공식 산문 예외를 프로그램 사실 한 종류에 한정해 확장한다. 안전 평가의 다른 모드, 계산 수치의 NumericBinding, 장별 품질 하한은 바꾸지 않는다.
