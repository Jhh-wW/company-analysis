# 9. 경쟁사 대비 핵심 경쟁력

## 이 장의 목적

앞 장에서 확인한 회사 사실을 동일한 조건의 경쟁사·대체재와 비교해, 객관적으로 확인되는 경쟁우위와 운영 특성을 최대 3개까지 구분해 보여준다.

50개 기준 문서 모두 경쟁력 내용을 담았지만 독립 제목으로 둔 문서는 절반이었다. 이 장은 새로운 홍보 문구를 만드는 곳이 아니다. 1~8장의 확정 사실과, 1~8장 의미 분류와 독립적으로 봉인한 자사 공식 후보 원문을 공정한 비교 조건으로 종합한다.

## 이 장이 답해야 하는 질문

1. 이 회사를 비교하기에 적절한 경쟁사·대체재는 누구이며 왜 선정했는가?
2. 양쪽 자료가 같은 기간·정의·사업 범위·회계 기준을 사용하는가?
3. 양쪽에서 각각 확인되는 근거는 무엇인가?
4. 확인된 차이는 성과 우위인가, 단순한 운영 방식의 차이인가?
5. 그 차이가 사업에 주는 의미와 해석 한계는 무엇인가?

## 자료 우선순위

1. 자사와 비교사의 사업보고서·감사보고서·규제기관 공시
2. 자사와 비교사의 공식 IR·연차보고서·공식 제품·사업·보도자료 페이지
3. 정부·규제기관이 양사를 같은 정의로 수록한 공식 원문(양사의 공식 원문을 대체하지 않는 보조 확인)
4. 비교사 공식 보도자료와 공식 채널
5. 외부 분석 보고서는 비교축 후보·위험·가설을 찾는 내부 용도로만 사용하고, 핵심 수치는 양사 공식 원문으로 재검증
6. 언론 보도는 양사 공식 원문을 찾기 위한 내부 탐색 단서로만 사용하며 공개 `FactRecord`·출처로 승격하지 않음

비교사 **후보 선정 근거**는 자사가 발행한 DART 공시, 자사 공식 HTML IR, 자사 공식 웹 원문만 허용한다. 공식 웹·HTML IR은 DART 기업개황에 결속된 정확한 HTTPS host와 수집 `provenance_seal`을 통과해야 한다. 안정적인 `corporate/about/product` 페이지는 봉인된 최신 수집일을 쓸 수 있지만, 보도·공지·archive·blog·문서형 URL은 봉인된 machine-readable 문서일이 필요하고 검색 결과는 날짜와 무관하게 제외한다. 현재성은 `Report.as_of_date` 기준 0~400일만 허용한다. 공식 IR PDF는 안전하게 제한 수집하고 일반 인용으로 보존할 수 있지만 현재 수집 경로에는 신뢰 가능한 문서 발행일·보고기간 결속이 없으므로 raw preflight·후보 선정·1~8장 직접 사실에 쓰지 않는다. PDF 수집일을 문서의 발행일·사실 기준일로 대신 쓰지 않는다. 실제 재무 수치 비교는 공식 IR·웹 수치로 대체하지 않고 양사의 DART 완료 사업연도 자료를 사용한다. 한쪽 회사의 자료만 있거나 출처 정의가 불명확한 순위·외부 뉴스·블로그·검색 결과 snippet·홍보성 비교표는 근거로 사용하지 않는다.

## 조사·검증 절차

### 1단계. 비교 질문 정의

먼저 1~8장에서 회사가 실제로 중요하게 운영하는 축을 찾는다.

- 수익성·성장성·시장 성과
- 제품 성능·품질·가격·공급 능력
- 고객·지역·채널 접근성
- 기술·데이터·생산·유통 기반
- 사업 포트폴리오·운영 모델

지원자가 회사의 사업을 이해하는 데 중요하지 않은 주가·목표주가·밸류에이션은 비교축으로 쓰지 않는다.

### 2단계. 비교대상 선정

내부 후보 탐색 단계에서는 다음 조건 중 두 가지 이상이 겹쳐야 한다.

`핵심 고객 | 주요 제품·서비스 | 수익 모델 | 우선시장 | 사업 규모·단계`

- 단순히 같은 거래소·같은 업종 코드라는 이유만으로 고르지 않는다.
- 종합기업은 비교축별로 다른 전문 경쟁사를 쓸 수 있다. 이 경우 행마다 선정 이유를 밝힌다.
- 비교군은 일반적으로 1~3개사다. 많은 회사를 나열해 핵심이 흐려지지 않게 한다.
- 공개 비교 행으로 채택할 때는 해당 축의 고객·제품/서비스·시장 범위가 자사와 실제로 같다는 양사 공식 근거를 추가로 확보해야 한다. 후보 탐색 조건만 통과한 회사는 공개 비교사가 아니다.
- 자사 공식 원문이 현재형의 명시적 `경쟁사·경쟁업체·동종업체·경합·경쟁 관계` 문법에서 비교사 법인명을 실제 경쟁 술어의 target/list slot에 적으면 **경쟁 관계 명시**까지만 증명한다. 단순히 법인명과 표지가 같은 문장에 있다는 이유만으로는 부족하며, v2에서 `시장점유율`은 경쟁 표지가 아니다. 그 문장에 고객·제품·시장 범위가 실제로 적혀 있지 않으면 겹침 범위를 추정하지 않는다.
- 현재 문법은 자사 또는 자사 대명사가 후보와 현재 `경쟁한다/경쟁 중이다/경쟁 관계에 있다`, 후보가 자사의 현재 경쟁사다, 자사의 현재 경쟁사 목록에 후보가 들어가는 구조처럼 닫힌 argument/list 관계만 허용한다. 영문도 `compete/competes/are competing with|against`, `is/are/remains our competitor`, `our competitors include/are/remain/consist of`의 현재형 slot만 허용한다.
- 과거형·`former/potential/possible` 후보, 부정·제외, 인용·제3자 귀속, 협력·지원 문맥, 자사의 고객·공급사·파트너가 경쟁하는 문장, 모호한 별칭, `or/또는` 선택지는 거부한다. 오탐을 피하는 엄격한 문법이므로 실제 경쟁 관계를 놓치는 false-negative는 허용한다.
- `경쟁 관계 명시` 후보를 공개 비교사로 채택하려면 양사의 별도 공식 원문에서 같은 고객·제품/서비스·시장 범위를 다시 증명한다.

### 3단계. 비교 조건 정규화

양쪽 자료에서 아래 항목을 모두 맞춘다.

`고객 범위 | 제품·서비스 범위 | 시장 범위 | 기간 | 지표 정의 | 연결·별도 범위 | 사업 범위 | 통화·단위 | 실제·잠정·추정 상태`

- 회계연도가 다르면 같은 달 수를 임의로 합치지 않는다.
- 연결 실적과 별도 실적을 섞지 않는다.
- 제품군 전체와 단일 제품을 비교하지 않는다.
- 환율 환산이 필요하면 환율·기준일·계산식을 기록한다.
- 정부·규제기관 공식 차트는 양사 공식 원문을 각각 확보한 뒤 보조 확인에만 쓰며, 같은 차트·같은 집계 방식에 포함된 대상만 비교한다.
- 재무 비교값은 양사 DART의 같은 완료 사업연도, 같은 `account_id + account_nm + sj_div + fs_div`, 같은 시작일·종료일, 같은 통화·단위를 사용한다. 공식 HTML IR·웹은 후보 선정과 범위 확인에는 쓸 수 있지만 이 수치 원장을 대신하지 않는다. 문서일을 결속하지 못한 공식 IR PDF는 후보 선정에는 쓸 수 없다.

### 4단계. 양사 근거 확보

각 비교 행에는 다음이 모두 있어야 한다.

- 자사 근거와 출처
- 비교대상 근거와 출처
- 같은 조건임을 보여주는 기간·정의·범위
- 선정 이유

자사 수치가 1~8장에 이미 있으면 값을 다시 적지 않고 `4장 참조[n]`처럼 장과 출처를 연결한다. 비교에 필요한 타사 값과 비교 결과는 9장이 소유한다.

### 5단계. 판정

- `경쟁우위`: 동일 조건의 성과 결과에서 우위가 확인됨
- `운영 특성`: 사업 구조·파트너 방식·조직 모델이 다르지만 우열은 확인되지 않음
- `비교 근거 부족`: 조건이 다르거나 양쪽 원문을 확보하지 못한 내부 탈락 상태. 공개 행이 아님

운영 방식이 다르다는 이유만으로 `강점`, `우위`, `경쟁력`이라고 부르지 않는다. `경쟁우위` 판정에는 결과 근거가 반드시 있어야 한다.

비교사에 동일 정의의 지표가 없으면 자사의 운영 특성만 확인된 것이다. 이 경우 내부적으로 `비교 근거 부족`으로 탈락시키며, 공개 9장·핵심 요약·종합 판단에서 `차이·차별점·경쟁력`으로 승격하지 않는다. 다른 유효 축도 하나도 없으면 보고서 전체를 `GATE_STOPPED`로 끝낸다.

### 6단계. 의미와 한계 작성

- 의미는 고객 가치·수익성·확장성·안정성 중 직접 연결되는 것만 쓴다.
- 인과관계가 양사의 공식 원문으로 직접 입증되지 않았으면 관찰된 차이와 한계만 쓰고 사업 효과를 연결하지 않는다. 외부 분석은 과장 여부의 내부 교차검증에만 사용하며 공개 비교 `FactRecord`·출처가 될 수 없다.
- 연결 범위, 일회성 요인, 특정 제품 집중, 표본 수, 비공개 계약 등 비교 한계를 같은 행에 쓴다.

## 포함할 내용

- 비교대상과 선정 이유
- 동일한 비교축·기간·범위
- 자사와 비교사 양쪽의 공식 근거
- 공개 가능한 `경쟁우위·운영 특성` 판정. `비교 근거 부족`은 내부 실패 기록에만 보존
- 사업상 의미와 비교 한계
- 검증 가능한 차이 최대 3개

## 제외할 내용

- `브랜드가 강하다`, `기술력이 뛰어나다`, `팬덤이 탄탄하다` 같은 결과 없는 일반명사
- 한쪽 회사 자료만으로 만든 비교
- 기간·정의·범위가 다른 수치의 단순 나열
- 공식 근거 없이 만든 시장점유율·순위·고객 평가
- 회사 규모가 다른 것을 곧바로 효율성 우위로 해석한 문장
- 운영 방식의 차이를 성과 우위로 부른 문장
- 목표주가·주가 상승 여력·투자 의견
- 숫자만 바꿔 다른 회사에도 적용되는 홍보 문장
- 3개를 채우기 위한 약한 차별점

## 출력 형식

### 1. 비교군 안내

표 위에 비교대상과 선정 이유를 한 문장으로 밝힌다.

`비교군은 [고객·제품·시장]이 겹치는 [회사 A·회사 B]이며, [기간·범위]가 같은 공식 자료가 있는 축만 비교했다.`

### 2. 비교표

| 차이·판정 | 비교대상·선정 이유 | 동일 비교 조건 | 양사 근거 | 직접 확인된 의미·한계 |
|---|---|---|---|---|
| 확인된 차이·경쟁우위/운영 특성 | 고객·제품·시장 겹침 | 고객·제품/서비스·시장·기간·정의·연결/별도 범위 | 자사: 관련 장 참조[n] / 비교사: 공식 근거[m] | 의미와 제한 |

- `양사 근거`에는 각 근거 앞에 반드시 `자사:`와 `비교사:`를 붙인다.
- `동일 비교 조건`에는 고객·제품/서비스·시장·기간·지표 정의·연결/별도 범위를 모두 쓴다.
- 판정은 눈에 띄게 쓰되 여러 색의 배지를 사용하지 않는다.
- 같은 기준일을 모든 행에 반복하지 않는다. 표 전체 기준일은 캡션에 한 번만 쓰고, 행별로 다른 기간만 해당 행에 적는다.

## 중복 방지

- 9장은 `비교 결과·타사 근거·비교 한계`만 소유한다.
- 자사 실적·제품·파트너 사실은 1~8장의 장 번호로 연결하고 숫자를 복사하지 않는다.
- 핵심 요약에는 경쟁력의 결론만 쓰고 비교 수치·사례는 다시 적지 않는다.
- 같은 비교 결과를 표와 그래프에 동시에 넣지 않는다.
- 세 행에서 동일한 비교대상 설명을 반복하지 않고 표 위에서 한 번 설명한다.

## 시각화 조건

기본 형식은 비교표다. 그래프는 아래 조건을 모두 만족할 때만 표 대신 사용한다.

- 같은 지표·기간·범위의 기업이 3곳 이상이다.
- 순위나 격차가 문장보다 즉시 이해된다.
- 계열은 4개 이하이고 모든 수치의 공식 원문이 있다.
- 축·단위·기간·자료 범위를 그래프 안에서 확인할 수 있다.

그래프를 사용하면 같은 수치를 표에 반복하지 않는다. 운영 모델 비교는 우열을 암시하는 막대그래프 대신 짧은 구조 비교표를 사용한다. 장식용 레이더차트·3D 차트·근거 없는 점수화는 금지한다.

| 소비재·유통 | 점포·채널·재구매·제품 믹스·지역 | 출점 수만으로 성장 우위 단정 |
| 콘텐츠·IP | IP 성과·투어·유통·지역 포트폴리오 | 단일 작품 성과를 회사 전체로 확대 |
| 금융 | 고객·자산·수수료·건전성·자본비율 | 상품·규제·회계 기준이 다른 값 혼용 |
| 바이오·헬스케어 | 임상 단계·적응증·허가·파트너 범위 | 서로 다른 임상 단계의 성공 가능성 비교 |

업종마다 비교축은 달라도 `같은 기간·정의·사업 범위`와 양쪽 원문 확보 조건은 바꾸지 않는다.

## 근거가 부족할 때

- 검증 가능한 차이가 1개면 1개만 출력한다.
- 구조 차이만 확인되면 `운영 특성`으로 표시하고 경쟁우위 개수에 포함하지 않는다.
- 양쪽 원문을 구하지 못하면 해당 비교를 공개 행에서 삭제하고 내부 실패 이유에 `비교 근거 부족`으로 기록한다.
- 비교 기간이 다르면 최신 수치로 임의 보정하지 않는다.
- 직접 경쟁사가 없는 경우 고객이 선택할 수 있는 대체재를 사용하되 선정 이유를 밝힌다.
- 적절한 대체재도 없으면 일반론이나 근거 부족 장을 만들지 않고 전체를 `GATE_STOPPED`로 끝낸다.

실서비스 출고에서 9장은 필수다. 따라서 `비교 근거 부족`은 빈 장이나
일반론으로 렌더링하는 상태가 아니라 **보고서 전체 GATE_STOPPED**다.
수집기는 실패 사유를 남기고, 다음 조사에서 자료를 새로 받기 전에는 결과물을
캐시하거나 외부로 내보내지 않는다.

## 실서비스 수집 계약

1. 1~8장의 원자 사실을 먼저 잠그고 아직 출고하지 않는다.
2. 비교사 후보 원문은 다음 두 계약 중 하나로만 잠근다.
   - **v1 읽기 호환 계약**: 실제 1~8장 `fact_ids`에 포함된 `verified` FactRecord의
     단일 `state_evidence` 문장을 `fact_id·source_id·DART corp_code·document_id·
     SHA-256`으로 역참조한다. 저장 JSON과 기존 HMAC payload 형식은 읽지만 재출고할
     때 현재의 엄격한 경쟁 관계 문법으로 다시 검사한다. 따라서 과거에 저장된 v1도
     현재 문법을 통과하지 못하면 `GATE_STOPPED`된다.
   - **v2 독립 계약**: 자사 DART 공시·공식 HTML IR·공식 웹의 봉인된 Source에서 후보
     법인명이 현재형의 명시적 경쟁 술어 target/list slot에 있는 정확한 한 문장을 별도
     후보 원장에 보존한다.
     `source kind/type·publisher·host·HTTPS URL·document_id·location·source_date·
     evidence_text·evidence_sha256·evidence_exact_sha256·self corp_code·attester`를
     닫힌 JSON으로 결속한다. `evidence_sha256`은 문장 공백을 정규화하고 casefold한
     UTF-8 문자열의 해시이고, `evidence_exact_sha256`은 문장 추출 뒤 `strip`된 저장
     문장 문자열 그대로의 UTF-8 해시다. 후자는 원 HTTP 응답이나 PDF 파일 바이트의
     해시가 아니다. 두 값은 각각 `Source.evidence_hashes`와
     `Source.exact_evidence_hashes`에 들어가며 두 목록 모두 Source HMAC seal에 결속한다.
3. 순수 경쟁 관계 문장은 1~8장 `customer_market` 등 다른 `claim_type`으로 위장하지
   않는다. 1~8장의 의미 계약도 실제로 충족할 때만 v1을 사용하고, 그렇지 않으면 v2를
   사용한다. v2 후보 원문은 9장 후보 선정 증거일 뿐 공개 사업 사실이나 비교 결과가 아니다.
4. 두 버전 모두 자사가 발행 주체인 **self-subject** 원문이어야 한다. 후보 법인명은
   현재형의 명시적 경쟁 술어가 차지하는 실제 target/list slot에 있어야 하고, 그 문장은
   수집한 한 원문 블록의 연속 부분이어야 한다. `시장점유율`만 있는 문장, 과거·잠재 관계,
   부정·제외·인용·제3자 귀속·협력·지원, 고객/공급사/파트너 경쟁, 모호한 별칭과
   `or/또는`는 거부한다. 엄격한 문법 때문에 false-negative가 생길 수 있다.
5. 공식 웹·HTML IR 후보는 DART 기업개황의 `corp_code·corp_name·hm_url`을 봉인한 별도
   attester와 정확한 host로 결속한다. attester는 사업 사실이나 비교 수치가 아닌
   **내부 provenance dependency**이며, 직접 `FactRecord`가 없어도 조립·출고 Source
   등록부에서 의존 Source와 함께 보존돼야 한다. `attestation_only` Source는 내부 Report
   JSON·저장·감사 등록부에만 남기고 공개 웹·PDF·Notion·Markdown 부록에는 절대 표시하지
   않는다. 공개 부록에는 실제 후보 원문 citation만 표시한다.
6. 후보용 공식 웹·HTML IR은 처음부터 끝까지 같은 정확한 host의 HTTPS만 허용한다. HTTP
   fallback, 인증서 이름 대체 host, 인증서 검증 실패, cross-host redirect로 읽은 조각은
   일반 내부 조사 재료로 남을 수 있어도 후보 원문으로 승격하지 않는다.
7. `corporate/about/product` 같은 안정 회사 페이지는 명시 문서일이 없으면 봉인된 최신
   `collected_at`을 쓸 수 있다. host·path·query의 `news/newsroom/press/media/notice/
   release/archive/blog`, 연도·`article/post/board/bbs/view` 문서 segment, `id/idx/seq/no/
   article/post/board/bbs/view` query key는 봉인된 machine-readable `published_at` 또는
   `disclosed_at`이 필수다. `search/results/find` host·path와 `q/s/query/keyword/keywords/
   search/term` query key는 검색 결과로 보고 최근 문서일이 있어도 후보·canonical 사실에서
   항상 제외한다. 날짜가 잘못됐거나 미래이거나 `Report.as_of_date`보다 400일을 초과해도
   제외한다. 캐시 복원에서는 조회 당일을 기준으로 다시 검사해 오래된 보고서를 cache miss로
   처리한다.
8. 공식 IR PDF는 DART가 확인한 정확한 HTTPS host에서만 제한 수집한다. robots.txt를
   따르고 HTML 탐색 5쪽·링크 60개·PDF 최대 2개, 파일당 12 MiB·80쪽·추출 12,000자·
   160조각, 사이트 전체 PDF 20 MiB·보존 12,000자 상한을 적용한다. MIME
   `application/pdf`, `%PDF-` magic, 비암호화 문서를 확인하고 `pypdf 6.16.1`을 별도
   프로세스에서 실행한다. wall 10초·CPU 8초·256 MiB 프로세스 메모리 hard limit(단순
   RSS 측정값이 아니라 POSIX `RLIMIT_AS` 주소공간 또는 Windows Job Object process/job
   memory)·압축 해제 스트림 12 MiB·동시 워커 1의 OS/프로세스
   상한을 적용한다. 앞 2쪽에서 대상 법인명·별칭을 확인하고 OCR 없이 추출 가능한 글자가
   없으면 거부한다. production에서 OS 자원 상한 설정 자체가 실패해도 거부한다.
   수집된 citation에는 페이지·문단 위치와 PDF 내용 SHA-256 문서 ID를 보존하지만, 현재
    수집 경로는 신뢰 가능한 문서 발행일·보고기간을 provenance에 결속하지 않으므로 raw
    preflight·후보 선정·1~8장 canonical 선택과 직접 사실에는 사용하지 않는다. 향후 신뢰
    가능한 `published_at/disclosed_at`을 결속하더라도 보고서 `as_of_date`와의 차이가
    0~400일인 경우에만 현재성 검사를 통과한다.
9. 단순 고객·파트너 언급, 동일 업종 코드, 뉴스·애널리스트 추정만으로는 비교사를
   고르지 않는다. 관계만 직접 적힌 문장은 `경쟁 관계 명시`로 보존하고 고객·제품·시장
   겹침은 양사의 별도 공식 근거로 증명한다.
10. 후보는 1~3개사로 제한하고, 각 후보의 DART 기업개황·연간 공시
    원문·단일회사 주요계정을 **자사 자료와 다른 요청으로** 수집한다.
11. `account_id + account_nm + sj_div + fs_div + 시작일·종료일`이 모두
    같은 행만 비교한다. 연결(CFS)과 별도(OFS), 서로 다른 회계연도는
    변환하거나 추정해 합치지 않는다.
12. 각 `FactRecord`에 비교사·지표·정의·기간·범위·자사 출처·비교사
    출처·원문 지문·비교 한계를 각각 저장한다.
    출고 게이트는 v1 또는 v2의 Source·문장·해시·seal·attester를 역참조한다. 후보 선정
    원문 citation 번호는 9장 공개 블록과 출처 부록에 표시하되, `attestation_only` Source와
    후보 수집 실행 상태는 공개하지 않고 내부 Report JSON·저장·감사 등록부에만 보존한다.
13. 실서비스의 최소 비교축은 양사 DART의 같은 완료 사업연도·연결(CFS) 범위의
    `매출액 + 영업이익`으로 직접 계산한 영업이익률 차이다. 계산식과 양사
    원값을 결속하고, 한 사업연도 차이를 지속적 경쟁우위로 승격하지 않는다.
14. 규모 비교는 `매출 규모 차이·운영 특성` 한 축만 허용한다. 매출·영업이익·
    순이익 배수를 각각 세어 3개를 채우거나 규모를 경쟁우위로 표현하지 않는다.
15. 서로 다른 공식 비교축이 추가로 성립할 때만 최대 3개까지 늘린다. 같은 축을
    다른 계정명이나 비교사로 반복하지 않는다.

유료 사실 선택 전에는 뉴스가 아닌 자사 DART·봉인된 공식 HTML IR·공식 웹 원문 상위집합을
훑는다. 허용 범위를 끝까지 읽었고 상한에도 걸리지 않은 정상 수집에서 현재의 엄격 문법상
경쟁 target/list slot에 들어간 고유 DART 법인명이 한 건도 없을 때만 `후보 없음`으로 조기 `GATE_STOPPED`할
수 있다. 실제 수집 `state`는 `failed·none·ok`뿐이다. 접속·TLS·MIME·파서·카탈로그
실패는 `failed`로, 페이지·문서·바이트·글자 상한 잘림은 별도 `truncated` state가 아니라
`candidate_scope_complete=False`와 상세 사유로 남긴다. 범위가 불완전한 `failed` 또는
`ok`는 `후보 없음`이 아닌 `unknown`이다. `unknown`을 음성 증거로 쓰지 않고,
상위집합에서 문장을 발견했다는 사실만으로 후보를 확정하지 않는다.

## 출력 전 체크리스트

- [ ] 모든 비교대상의 선정 이유가 있다.
- [ ] 후보 선정 원문이 자사 DART 또는 DART 도메인 증명에 결속된 자사 공식 HTML IR·공식 웹인가? 발행일·보고기간을 결속하지 못한 공식 IR PDF를 후보로 승격하지 않았는가?
- [ ] v1은 저장 형식 읽기 호환 뒤 현재 엄격 문법으로 재검증하고, 순수 경쟁 문장은 1~8장으로 위장하지 않고 v2 독립 원장에 보존했는가?
- [ ] v2 후보가 현재형의 명시적 경쟁 관계 target/list slot이며 `시장점유율`, 과거·잠재·부정·제외·인용·제3자·협력·지원·관계사 경쟁·모호 별칭·`or/또는`를 거부하는가?
- [ ] v2의 `evidence_sha256`과 `evidence_exact_sha256`이 각각 Source의 두 해시 목록 및 HMAC seal에 결속되고, exact 해시를 원 HTTP/PDF 바이트 해시로 오해하지 않았는가?
- [ ] `attestation_only`는 내부 Report JSON·저장·감사 등록부에만 있고 공개 웹·PDF·Notion·Markdown에는 후보 원문 citation만 보이는가?
- [ ] HTTP·인증서 fallback·외부 뉴스·블로그·검색 snippet이 후보 원문으로 승격되지 않았는가?
- [ ] 공식 IR PDF가 최대 2개·문서/사이트 추출 12,000자·사이트 전체 20 MiB 등 고정 상한과 격리 파서 검사를 통과했고, 발행일·보고기간 없는 PDF를 후보로 쓰지 않았는가?
- [ ] 수집 상태는 `failed·none·ok`만 쓰고 잘림은 `candidate_scope_complete=False`와 상세 사유로 기록해 후보 없음으로 오판하지 않았는가?
- [ ] 관계만 명시된 후보의 고객·제품/서비스·시장 공통 범위를 양사의 별도 공식 근거로 증명했는가?
- [ ] 양쪽 자료가 같은 고객·제품/서비스·시장·기간·정의·회계/사업 범위다.
- [ ] 자사와 비교사의 **공식 자료**가 각각 별도 출처로 연결돼 있는가?
- [ ] 자사와 비교사 근거가 각각 연결돼 있다.
- [ ] 연결/별도, 실제/잠정/추정 상태를 섞지 않았다.
- [ ] 운영 특성을 경쟁우위라고 부르지 않았다.
- [ ] 단순 재무 규모를 여러 계정으로 반복하거나 우위로 승격하지 않았는가?
- [ ] 영업이익률 등 유효 비교축의 원수치·산식·`ROUND_HALF_UP` 표시값이 재현되는가?
- [ ] 실제 재무 비교값이 양사 DART의 같은 완료 사업연도·같은 회계 범위인가?
- [ ] 비교 근거 부족 항목을 요약에서 차이·차별점으로 승격하지 않았는가?
- [ ] 경쟁우위에는 성과 결과 근거가 있다.
- [ ] 사업상 의미와 비교 한계를 같은 행에 썼다.
- [ ] 차이가 3개를 넘지 않는다.
- [ ] 자사 수치가 앞 장과 반복되지 않는다.
- [ ] 표와 그래프가 같은 사실을 중복하지 않는다.
- [ ] 가치평가·투자 의견이 없다.

## 범용 예시

> 아래 문장은 구조 예시이며 실제 회사·수치·출처로 교체한다.

`[회사]는 [비교사]와 같은 [기간·연결 범위]의 [지표]에서 [객관적 차이]를 보인다. 양사 자료로 직접 확인되는 사실은 [측정된 차이]까지다. [사업 구성·일회성 비용·표본 범위]가 달라 사업 효과나 장기적인 구조 우위는 확인되지 않았다.[n][m]`
