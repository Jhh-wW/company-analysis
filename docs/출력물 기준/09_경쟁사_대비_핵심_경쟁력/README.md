# 9. 회사가 밝힌 차별점

## 이 장의 목적

회사가 공식 자료에서 자기 자신을 주어로 직접 밝힌 차별화 표현을 원문에 충실하게 보여준다. 작성자는 선언의 사실 여부나 타사 대비 우열을 판정하지 않는다. 동일 조건의 양사 비교는 검증 자료가 있을 때만 선택적으로 덧붙인다.

출시 모드(`REPORT_RELEASE_MODE=FULL`)에서는 이 장도 필수다. 회사가 밝힌 차별점 근거가 없으면 빈 장이나 일반론을 만들지 않고 보고서 생성을 멈춘다. 이는 차별점이 없다는 판정이 아니라 현재 공식 공개 근거로 확인하지 못했다는 뜻이다.

## 필수 의미 칸

1. `competitive_position:self_context`: 회사가 설명한 사업·제품·기술 맥락
2. `competitive_position:stated_differentiator`: 회사 주어와 선언 표지가 있는 공식 원문
3. `competitive_position:limitation`: 회사 발표 표현을 옮긴 것이며 진위·우열을 별도로 판정하지 않았다는 한계

다음 비교 칸은 선택 사항이다.

- `competitive_position:comparison_target`
- `competitive_position:comparison_metric`
- `competitive_position:comparison_basis`
- `competitive_position:comparison_judgment`

## 허용하는 자기 선언

공식 DART 공시, 회사 공식 웹, 회사 공식 IR에서 다음 조건을 모두 만족한 문장만 사용한다.

- 주어가 정확한 회사명, `당사`, `우리`, `우리 회사` 중 하나다.
- 문장에 `최초`, `유일`, `최다`, `1위`, `최대`, `독자 개발`, `특허` 중 하나가 직접 적혀 있다.
- 원문 문장, 문서 ID, 위치, 발표일, 출처, exact SHA-256이 함께 결속돼 있다.
- 공식 웹·IR은 DART 기업개황 또는 승인된 회사 신원 계약을 통과한다.

제3자 평가, 뉴스·검색 결과, 외부 분석, 주어가 업계·제품·기술인 문장, 선언 표지가 없는 일반 홍보 문장은 제외한다. `우위`, `열위`, `더 낫다`처럼 작성자가 우열을 추가한 문장도 제외한다.

## 출력 형식

비교 자료가 없으면 회사가 밝힌 차별점을 1~4개 목록으로 쓴다.

| 항목 | 내용 |
|---|---|
| 발표 내용 | 회사 법인명을 주어로 정규화한 공식 원문 표현 |
| 발표일·출처 | 문서 발행일과 공식 문서명·인용 번호 |
| 확인 범위 | 회사 발표 표현 자체이며 진위·타사 비교를 판정하지 않았다는 한계 |

여러 항목은 각각 다른 공식 Source에 결속한다. 개수를 맞추기 위해 한 문장을 잘게 나누거나 비슷한 표현을 반복하지 않는다.

## 선택적 동일 조건 비교

자사와 비교사의 공식 자료가 모두 있고 고객·제품/서비스·시장·기간·지표 정의·회계 범위가 같을 때만 기존 비교 블록을 차별점 목록 뒤 별도 문단에 붙일 수 있다.

- 비교사 후보는 자사 공식 원문이 현재 경쟁 관계의 실제 대상으로 지목한 법인이어야 한다.
- 재무 비교는 양사의 DART 완료 사업연도 자료에서 같은 계정·기간·연결/별도 범위·통화를 사용한다.
- 비교 블록이 있으면 비교 대상, 지표, 기준, 판정, 양사 출처, 한계를 모두 보존한다.
- 비교가 실패해도 적격 회사 자기 선언이 있으면 9장을 생략하거나 차단하지 않는다.

구조 차이는 `운영 특성`으로만 쓴다. 같은 조건의 결과 차이가 검증된 경우에만 기존 `경쟁우위` 판정을 사용할 수 있으며, 이 판정을 회사 자기 선언 문장에 섞지 않는다.

## 수집·검증 절차

1. 공식 수집기가 9장의 `self_context`와 `stated_differentiator` 슬롯을 수집 대상으로 선언한다.
2. 유료 AI 호출 전에 결정론 모듈이 모든 공식 조각에서 회사 주어와 닫힌 선언 표지를 검사한다.
3. 적격 조각은 원문·해시·문서 ID·위치를 유지한 채 `competitive_position:stated_differentiator` typed 조각으로 9장에 추가한다.
4. 사전검사는 `self_context`와 `stated_differentiator`가 모두 있어야 9장을 `READY`로 판정한다. `limitation`은 검증된 프로그램 사실로 주입한다.
5. 작성·출고 단계는 회사 법인명 주어, 발표일·출처, 공식 Source, 원문 해시, 최소 두 개 근거어를 다시 검사한다.
6. 선택적 비교가 있으면 기존 동일 조건 검사를 비교 사실에만 적용한다.

결정론 분류는 기능 스위치나 AI 재판정 여부와 무관하게 항상 실행한다.

## 제외할 내용

- 회사가 말하지 않은 강점·선도성·시장 평가
- 제3자가 회사를 주어로 평가한 문장
- `업계 최초`처럼 회사 주어가 없는 문장
- 한쪽 회사 자료만으로 만든 타사 비교
- 기간·정의·범위가 다른 수치의 나열
- 공식 근거 없는 순위·점유율·고객 평가
- 목표주가·주가 상승 여력·투자 의견
- 회사 선언을 사실 검증이나 우열 판정으로 바꾼 문장

## 근거가 부족할 때

- 적격 선언이 1개면 1개만 출력한다.
- 적격 선언이 없으면 비교 사실만으로 자기 선언 슬롯을 대신하지 않는다.
- 회사 자기 선언과 선택적 비교가 모두 없으면 `INSUFFICIENT_EVIDENCE` 경로로 멈춘다.
- 선택적 비교만 실패한 경우에는 적격 자기 선언과 발표일·출처·한계를 포함한 9장을 계속 제공한다.
- 연습 모드에서 9장을 생략할 때는 정해진 부족 사유만 표시하고 차별점 부재로 단정하지 않는다.

## 중복 방지

- 9장은 회사가 밝힌 차별점과 선택적 비교 결과만 소유한다.
- 자사 실적·제품·파트너 사실은 1~8장의 값을 다시 복사하지 않는다.
- 핵심 요약은 검증된 9장 `FactRecord.claim`을 글자 변경 없이 재사용한다.
- 같은 선언을 목록·표·그래프에 반복하지 않는다.
