# 5. 당면 과제와 대응 `#현재`

## 목적

회사의 현재 우선순위를 보여 주는 **아직 해결되지 않은 사업 문제와 진행 중인 대응**을 연결한다. 위험 목록을 옮겨 적는 장이 아니라, 현재 실적·운영·고객 지표에서 문제가 나타나고 회사가 이에 대응하고 있는 항목만 다룬다.

- 핵심 과제는 최대 3개다.
- 현재 문제의 증거로 사용한 최신 수치는 이 장이 소유한다.
- 직무별 맞춤 정보와 지원자 행동 지침은 범위 밖이다.

## 답할 질문

1. 현재 사업 성과를 제약하는 미해결 문제는 무엇인가?
2. 문제가 실제로 나타났다고 볼 최신 증거는 무엇인가?
3. 회사는 지금 무엇을 하고 있는가?
4. 대응의 초기 효과는 어디까지 확인됐고, 무엇이 아직 남았는가?
5. 해결 여부를 다음에 판단할 객관적 신호는 무엇인가?

## 사실의 시간 상태 정의

### 이 장에 넣는 `#현재`

다음 네 조건을 모두 만족해야 한다.

1. 문제가 보고서 기준일에도 해결되지 않았다.
2. 최신 실적·운영·고객·시장 지표 또는 경영진의 공식 발언으로 현재성이 확인된다.
3. 회사가 실제 대응을 시작했거나 현재 진행 중이다.
4. 대응 완료와 결과가 아직 확정되지 않았다.

단순한 `현재 운영 상태`는 7장이고, `현재 미해결 문제`만 5장이다.

### 시간 상태 전환

- 대응이 완료되고 결과가 확인되면 다음 보고서에서 `4장 #과거`로 옮긴다.
- 아직 대응을 시작하지 않았고 향후 계획만 발표됐다면 `6장 #미래`로 보낸다.
- 구조적 운영 방식이나 지속적 파트너 관계는 `7장`으로 보낸다.

## 입력자료 우선순위

1. 가장 최신의 공식 분기·반기·연간 실적발표서
2. 실적발표 설명회·주주서한·CEO 메시지·사업보고서의 현재 과제 설명
3. 공식 대응을 확인할 수 있는 출시·가격·증설·구조 개편·협업 발표
4. 규제기관·자회사·핵심 파트너의 공식 자료
5. 동일 기간·사업 범위를 분석한 외부 보고서

외부 분석은 문제의 규모와 대응의 실효성을 내부에서 점검하는 보조자료다. 공개 `FactRecord`·출처로 승격하지 않으며, 회사 공식 원문으로 현재 문제와 착수 대응이 결속되지 않으면 `회사의 현재 핵심 과제`로 올리지 않는다.

## 독립 조사 절차

1. **최신성 고정:** 가장 최신 공식 실적 기간을 기준으로 잠그고, 이후 발표된 중요 업데이트를 반영한다.
2. **문제 후보 수집:** 수익성 저하, 성장 둔화, 원가·재고·가동률, 고객·IP 집중, 규제·인허, 신제품 전환, 투자·재무 부담을 검색한다.
3. **현재성 확인:** 문제가 최신 수치나 경영진 발언에서 계속 남아 있는지 확인한다.
4. **대응 확인:** 회사가 이미 시작한 대응만 매칭한다. 아직 미실행인 계획은 6장으로 보낸다.
5. **문제–대응 결속:** 각 미해결 문제를 고유 `fact_id`로 만들고, 실제 대응의 `response_to_fact_id`가 같은 장의 해당 문제를 정확히 가리키게 한다. 어떤 문제에 대한 대응인지 원문으로 확인되지 않으면 추정해 연결하지 않는다.
6. **동시 지표 검토:** 대응 착수 뒤 같은 범위의 지표 변화가 관찰되는지 보되, 직접 인과 근거가 없으면 대응 효과나 전사 해결로 표현하지 않는다.
7. **핵심 과제 선정:** 근거가 확인된 과제를 1~3개만 남긴다. 한 개만 확인되면 억지로 둘 이상을 채우지 않는다.
8. **해결 조건 설정:** 향후 어떤 지표가 어느 방향으로 움직여야 해결로 볼 수 있는지 정한다. 임의의 목표값은 만들지 않는다.
9. **시간 상태·중복 검사:** 4·6·7장과 중복되는 수치·사건·파트너 역할을 제거한다.

## 포함 기준

- 최신 공식 지표에서 확인되는 수익성·성장·운영 문제
- 경영진이 현재 중요 과제로 지목하고 실제 대응을 진행 중인 항목
- 고객·제품·지역·채널·핵심 자산에 대한 과도한 집중이 실제 성과 변동으로 이어진 경우
- 원가·공급망·규제·인허·보안·재무 문제가 현재 사업 실행을 제약하는 경우
- 회사가 시작한 대응과 그 초기 신호가 확인되는 경우
- 각 대응이 직접 연결되는 미해결 문제의 `response_to_fact_id`

## 제외 기준

- 법정 보고서의 범용 위험 목록을 그대로 옮긴 내용
- 현재 증거가 없는 가상의 위험과 일반적 업종 위험
- 회사가 하지 않은 대응을 필자가 제안하는 내용
- 이미 해결됐고 결과가 확인된 과거 문제
- 아직 시작되지 않은 향후 계획과 일정
- 직무별 `지원자가 보여 줄 행동`과 근거 없는 포괄적 조언
- 목표주가·적정가치·주가 상승여력·투자의견

## 출력 필드와 표 형식

장 상단에 `현재 판단 기준: 최신 공식 실적 기간 / 보고서 기준일`을 한 번만 적는다. 모든 행에 같은 기준일을 반복하지 않는다.

### 1. 핵심 결론

회사가 기준일 현재 대응 중인 문제 1~2개를 숫자 없는 한 문장으로 요약한다.

### 2. 과제–대응 표

| 당면 과제·현재 증거 | 진행 중인 대응 | 초기 신호·남은 문제 | 향후 확인 신호 | 근거 |
|---|---|---|---|---|
| 해결할 문제와 최신 수치·사건 | 이미 시작한 회사 행동 | 확인된 진척과 미해결 부분 | 다음 공식 실적에서 볼 지표 | [n] |

- 행은 근거가 확인된 1~3개로 제한한다.
- `향후 확인 신호`는 임의의 목표값이 아니라 다음 공식 실적에서 확인할 지표명만 적는다.
- 최신 수치는 이 표에서 한 번만 쓴다. 서론과 평가 셀에서 다시 쓰지 않는다.
- 대응 자체가 예정 상태라면 이 표에서 빼고 6장에 배정한다.

## 원인·결과 연결 규칙

기본 구조는 `현재 증거 → 사업상 문제 → 진행 중인 대응 → 초기 신호 → 남은 문제`다.

- 문제는 수치 자체가 아니라 그 수치가 나타내는 사업 제약으로 적는다.
- 수익성 저하가 원가·판매 구성·일회성 비용 중 무엇 때문인지 구분한다.
- 대응과 지표 변화의 인과가 확인되지 않으면 `같은 기간 관찰된 지표 변화·효과 미확인`이라고 쓰고 `개선 효과·기여·영향·해결`이라고 쓰지 않는다.
- 자회사·일부 제품의 개선을 전사 개선으로 확대하지 않는다.
- 하락한 지표와 회사 대응이 서로 다른 범위면 한 행에 연결하지 않는다.

## 다른 장과 중복 방지

- 4장의 3개년 수치를 복사하지 않고, 현재 과제를 증명하는 **최신 수치**만 5장에 둔다.
- 6장에서 계획의 전체 일정을 다루면, 5장은 이미 시작한 대응의 현재 범위만 소유한다.
- 7장의 파트너 역할을 반복하지 않고 `현재 운영 기반을 활용해 대응 중(7장)`처럼 연결한다.
- 9장은 자사 수치를 다시 쓰지 않고 `자사 현황은 5장 참조`로 연결한다. 비교사 수치만 같은 비교표 안에서 한 번 제시한다.
- 핵심 요약은 5장의 Writer 검수 완료 문장을 글자 변경 없이 재사용한다. 같은 장에 숫자 없는 문장이 있으면 우선하지만, 검증 문장이 숫자를 포함한 것뿐이면 그 문장을 그대로 허용한다.

## 시각화 사용 조건

기본 출력은 과제–대응 표다. 다음 경우에만 추가 시각화를 쓴다.

- 한 과제의 `문제 → 대응 → 초기 신호`가 3단계 이상이고 순서를 잃기 쉬울 때: 작은 흐름도
- 같은 정의의 최신 분기 지표 4개 이상이 문제의 변동성을 보여 줄 때: 최소한의 추세선
- 복수의 과제가 하나의 대응 체계로 연결될 때: 간단한 관계도

표만으로 이해되거나 시각화가 같은 수치를 반복하면 사용하지 않는다. 빨간색·경고 아이콘을 남용해 위험을 과장하지 않는다.

## 근거 부족 시 처리

- 회사가 과제를 직접 명시하지 않아도 최신 공식 지표와 실제 대응이 같은 범위로 연결되면 `확인되는 과제`로 쓸 수 있다. 이때 회사의 직접 표현처럼 인용하지 않는다.
- 문제는 확인되지만 회사가 시작한 대응을 확인할 수 없으면 공개 `current_issue`와 본문에서 모두 제외하고 내부 실패 기록에만 남긴다. 공개한 모든 문제는 같은 장의 실제 대응 `response_to_fact_id`와 결속돼야 한다.
- 대응은 있지만 초기 결과가 없으면 `대응 진행 중·효과 미확인`으로 남긴다.
- 일반적 업종 위험만 있고 회사별 증거가 없으면 해당 행을 생략한다.
- 핵심 과제가 1개면 1개만 보여 주고 억지로 3개를 채우지 않는다.
- 미해결 문제와 실제 대응의 결속 쌍을 하나도 확보하지 못하면 5장 필수 계약이 성립하지 않으므로 보고서 전체를 `GATE_STOPPED`로 끝낸다.

## 짧은 범용 예시

> 현재 핵심 과제는 `[공식 자료로 확인된 미해결 문제]`다. `[최신 지표·사건]`은 이 문제가 기준일 현재 남아 있음을 보여 준다. 회사는 `[실제로 착수한 대응]`을 진행 중이다. 대응 효과는 아직 확인되지 않았으며, 공개 자료로 확인되는 범위는 `[한계]`까지다.[n]
