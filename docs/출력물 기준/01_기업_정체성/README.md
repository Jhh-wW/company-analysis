# 1. 기업 정체성 출력 기준

## 목적

회사가 스스로 정의한 존재 목적과 산업 내 역할을 지원자가 정확히 이해하게 한다. 제품 목록이나 홍보 슬로건을 모으는 장이 아니라, 뒤의 모든 사업 설명을 읽는 기준점을 만든다.

> 내부 설계 근거: 기업 정체성은 50개 중 25개에 실질적으로 등장했고 공식 문서가 외부 문서보다 압도적으로 강했다. 따라서 이 장은 공식 자기정의를 우선하며, 외부 분석가의 별칭을 회사 정체성으로 대신하지 않는다. 이 설명은 완성 보고서에 출력하지 않는다.

## 이 장이 답할 질문

- 회사는 자신을 어떤 기업이라고 공식적으로 정의하는가?
- 회사가 해결하려는 고객·산업의 문제는 무엇인가?
- 제품을 넘어 산업에서 맡는 역할은 무엇인가?
- 사업 범위 중 회사의 정체성을 가장 잘 설명하는 경계는 어디까지인가?

## 필수 입력자료 우선순위

1. 공식 회사 소개·미션·비전·경영철학·CEO 메시지
2. 최신 사업보고서·연차보고서의 회사 개요와 사업의 내용
3. 공식 IR의 전사 전략·사업 정의
4. 공식 제품·서비스·채용 페이지 중 회사 전체를 설명하는 부분
5. 외부 분석은 공식 자기정의가 실제 사업과 맞는지 내부에서 점검할 때만 사용하며 공개 `FactRecord`·출처로 승격하지 않음

오래된 창업 문구보다 최신 공식 정의를 우선한다. 공식 문구의 적용 시점이 다르면 최신 정의와 과거 정의를 섞지 않는다.

## 조사 절차

1. 기준일 현재 회사가 사용하는 공식 자기정의·미션·비전 문구를 원문과 함께 수집한다.
2. 사업보고서에서 실제 영위 사업과 주요 고객 가치를 확인한다.
3. 슬로건과 사업 실체가 연결되는 핵심 동사와 대상을 찾는다.
4. 공식 표현은 `공식 자기정의`, 조사자가 합성한 문장은 `정체성 요약`으로 분리한다.
5. 공식 문구가 현재 사업과 맞지 않거나 지나치게 추상적이면 실제 사업 범위를 근거로 한 문장으로 다시 쓴다.
6. 제품·수익·조직의 세부 내용은 2·3·7장으로 넘기고 정체성을 설명하는 데 꼭 필요한 범위만 남긴다.

## 포함 기준

- 현재 공식 문서에서 반복되거나 전사 수준으로 제시된 존재 목적·산업 역할
- 고객에게 만드는 핵심 가치와 회사가 담당하는 가치사슬의 위치
- 복수 사업을 하나로 이해하게 만드는 연결 원리
- 회사 정체성을 구체화하는 공식 운영 구조의 특징 1개 이내

## 제외 기준

- 근거 없이 만든 인상 비평 또는 외부 분석가의 별칭
- 사업부·제품·국가·파트너의 긴 목록
- `글로벌·혁신·선도·최고`처럼 구체적 역할이 없는 수식어
- 연혁 나열, 설립자 일화, 사훈 전문
- 공식 인용처럼 보이도록 조사자 문장을 따옴표로 감싸는 표현
- 직무별 업무·KPI·조직별 맞춤 지원전략. 이는 서비스 범위 밖이다.

## 출력 필드/형식

공식 근거가 있는 짧은 텍스트 블록 1~3개만 사용하며, 각 블록은 1~2문장으로 제한한다.

1. `정체성 요약`: 회사의 실체를 쉬운 말로 쓴 한 문장
2. `공식 자기정의`: 현재 공식 표현 1개와 출처
3. `산업 내 역할`: 고객·산업에서 회사가 맡는 역할과 사업 범위

공식 자료로 확인되는 경우에만 `운영 정체성`을 전체 1~3개 블록 안의 선택 항목으로 둘 수 있다. 예: 아티스트별 레이블, 통합 SaaS 플랫폼, 제조·설계 분업 구조. 세부 조직 설명은 넣지 않는다.

## 문장 작성법

- 정체성 요약은 `무엇을 만들거나 연결하는가 + 누구에게 어떤 가치를 주는가 + 어떤 종류의 기업인가`로 쓴다.
- 공식 표현을 그대로 쓸 때는 짧은 핵심 구절만 인용하고 곧바로 쉬운 뜻을 설명한다.
- 조사자 합성 문장에는 따옴표를 쓰지 않는다.
- `A를 넘어 B`는 실제 사업 전환 근거가 있을 때만 쓴다.
- 정체성 자체를 경쟁우위로 평가하지 않는다. 비교 평가는 9장이 소유한다.
- 권장형: `[회사는] [핵심 자산/역량]을 [고객·시장]의 [가치/문제]와 연결하는 [산업 역할] 기업이다.`

## 시각화 사용 조건

- 기본은 시각화 없이 텍스트 블록만 사용한다.
- 복수 사업이 하나의 정체성으로 연결되는 과정이 문장만으로 오해될 때만 `핵심 자산 → 제공 가치 → 산업 역할` 3단 흐름도를 쓴다.
- 흐름도에 실적 수치·제품 목록·파트너 관계를 넣지 않는다.
- 한 문장으로 충분하면 도표를 만들지 않는다.

## 업종별 변형

- 제조: 설계·제조·검사·서비스 중 가치사슬에서 맡는 핵심 위치
- 플랫폼: 연결하는 참여자와 거래·정보·콘텐츠의 종류
- SaaS: 해결하는 기업 업무와 통합 범위
- 금융: 자금을 중개·운용·보호하는 대상과 방식
- 바이오: 발견·진단·치료 중 담당 단계와 기술의 용도
- 콘텐츠·IP: IP를 만들고 팬·유통·상품으로 확장하는 역할
- 유통: 상품·점포·물류·고객 경험을 연결하는 역할

## 실패 시 처리

- 공식 미션이 없으면 사업보고서의 사업 개요와 공식 제품 설명을 합성해 `정체성 요약`만 쓴다. 이를 공식 인용으로 표시하지 않는다.
- 공식 문구가 여러 개 충돌하면 기준일 현재 사용되는 최상위 문구를 우선하고, 필요할 때만 변화 사실을 4장으로 넘긴다.
- 외부 분석에만 정체성 표현이 있으면 회사 정체성으로 채택하지 않는다.
- 검증 가능한 산업 역할이 없으면 추상적 문구로 채우지 말고 확인된 사업 범위까지만 쓴다.

- [ ] 고객 가치와 산업 역할이 한눈에 드러나는가?
- [ ] 제품·실적·파트너의 세부 정보를 다른 장과 중복하지 않았는가?
- [ ] 근거 없는 `글로벌·혁신·선도` 표현을 제거했는가?
- [ ] 조사자 문장을 공식 인용처럼 표시하지 않았는가?
- [ ] 직무별 업무·KPI·맞춤 지원전략을 넣지 않았는가?

## 짧은 범용 예시

> **정체성 요약**  기업의 업무 데이터를 하나의 클라우드 환경에서 연결해 경영 의사결정을 돕는 소프트웨어 기업이다.

회사명과 제품명만 바꾼 일반 문장이 되지 않도록, 실제 고객 문제와 가치사슬 역할을 공식 근거로 채운다.
