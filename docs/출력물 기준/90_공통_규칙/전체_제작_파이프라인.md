# 전체 제작 파이프라인

이 파이프라인의 프로그램 계약은 [`런타임 출고 계약`](./런타임_출고_계약.md)이다. 신규 보고서는 `Report.schema_version=company-report-v4-canonical`을 사용하고 캐시는 `product:company-analysis`과 `schema:company-report-v4-canonical` 토큰을 함께 사용한다. v3 이하 자료는 새 캐시 적중으로 인정하지 않는다.

## 1. 역할 순서

역할은 독립 에이전트나 하나의 프로그램 단계로 구현할 수 있다. 중요한 것은 순서와 입력·출력 계약이다.

1. **범위 설정자**: 회사명·법인·연결 범위·기준일을 확정한다.
2. **자료 수집자**: 자사 DART·공식 HTML IR·공식 웹 원문을 모은다. canonical 보고서의 공개 사실·교차검증에 실제 쓰이지 않는 뉴스 검색·AI 선별은 생략한다. 공식 IR PDF는 제한 수집·인용하되 신뢰 가능한 문서 발행일 또는 보고기간을 결속하기 전에는 후보 원장에 넣지 않는다.
3. **섹션 조사자·사실 선택자**: 1~8장을 서로 독립적으로 조사해 구조화된 사실 묶음을 만든다. 선택 AI는 최대 2회이며 완결된 한 회차 결과만 채택한다.
4. **작가**: 한 문장에 하나의 원문 근거만 사용해 보고서 문체와 정보 순서를 정리한다.
5. **독립 Reviewer**: 원문과 앞뒤 공백 제외 완전일치하지 않는 새 문장을 작가와 대화·지시문을 공유하지 않고 대조한다. 명시적 실패 문장만 한 번 재작성하며, 재작성 완전일치는 코드로 확정하고 나머지만 새 Reviewer 재검사를 허용한다.
6. **총괄 분석자**: 검증된 1~8장을 공개 불가 내부 초안으로 조립하고, 양사 공식자료의 동일 조건이 맞을 때만 9장을 결합한다. 검증된 본문에서 핵심 요약을 결정론적으로 고른 뒤 최종 출고 게이트를 정확히 한 번 실행한다.
7. **중복 검토자**: 조판 전 원고에서 사실 소유권 위반과 같은 수치·사건의 재등장을 검사한다.
8. **레이아웃 작성자**: 정해진 UI 토큰으로 PDF를 만든다.
9. **사실·편집 자동검사**: 최종 객체의 모든 주장과 전체 `fact_id`를 잠긴 원장에 대조하고 인용·수치·중복·일반론·범위 밖 문구를 판정한다.
10. **PDF 전 페이지 자동검사**: 같은 PDF를 모든 페이지 PNG로 렌더해 구조·텍스트·glyph 가시성·페이지 해시를 판정한다.
11. **채널·해시 자동검사**: 웹·PDF·Notion이 같은 정본과 출고 레코드를 쓰는지 확인하고 검사 전후 보고서/PDF/페이지 지문을 다시 대조한다.

총괄 분석자는 앞 단계의 근거가 없는 내용을 새로 만들 수 없다. 작가와 레이아웃 작성자는 사실을 추가하거나 의미를 바꿀 수 없다. Reviewer 판정 누락·형식 파손과 두 번째 실패는 재시도하지 않고 해당 문장을 삭제한다.

검사 뒤 수정이 발생하면 새 작업 ID로 조립·PDF 렌더·자동검사를 다시 수행한다. 같은 작업 ID의 바뀐 hash를 조용히 재승인하지 않으며 조사·작성 기능이나 출력 채널은 어떤 이유로도 이 순서를 우회할 수 없다.

## 2. 회사 범위 확정

조사 전에 다음 값을 고정한다.

| 필드 | 기준 |
|---|---|
| 회사명 | 보고서 제목에 사용할 공식 명칭 |
| 분석 법인 | 본사·연결그룹·특정 자회사 중 하나 |
| 기준일 | 독자가 보고서를 읽는 정보 시점 |
| 실적 범위 | 연결/별도, 회계연도, 잠정/감사 완료 |
| 완료 재무 범위 | 회사의 실제 결산월에 따른 비교 가능한 최근 완료 사업연도 3개 |
| 완료 실행 범위 | 보고서 기준일 이전 36개월 |
| 비교군 | 내부 후보는 자사 DART 또는 DART 도메인 증명을 통과한 자사 공식 HTML IR·공식 웹이 현재형의 명시적 경쟁 관계 target/list slot에서 직접 지목한 1~3개사 또는 대체재. 발행일·보고기간을 결속하지 못한 공식 IR PDF는 후보에서 제외. 관계만 명시되면 고객·제품·시장 겹침은 별도 증명. 공개 비교 행은 공통 범위와 양사 DART 완료 사업연도 수치의 기간·정의·회계 범위가 모두 맞을 때만 채택 |

범위가 섞이면 수치 비교를 중단하고 먼저 법인·회계 기준을 통일한다.

## 3. 구조화 사실 레코드

모든 조사 결과는 아래 필드를 갖는다.

```text
fact_id: 회사·대상 + 지표 또는 사건 + 기간·시점 + 값 또는 상태
legal_entity: 사실이 적용되는 정확한 법인
subject_scope: 제품·모델·지역·관계의 원문 범위
relationship_or_action: 확인된 행동 또는 관계
claim: 보고서에 쓸 수 있는 사실 문장
claim_type: 장별 닫힌 영문 열거값(런타임 출고 계약의 허용표 참조)
section_owner: identity | business_model | portfolio | past_changes | current_challenges | future_strategy | operations_partners | culture | competitive_position
time_state: completed | current_issue | current_response | future_plan | standing
as_of: 기준일 또는 측정 기간
source_id: 원문 식별자
source_type: 공식 공시 | 공식 재무 API | 회사 공식 IR | 회사 공식 웹 | 공식 파트너 자료 | 규제기관 공식 자료 | 비교사 공식 공시
source_title: 원문 표지의 문서명
source_publisher: 원문 표지·머리글·판권의 실제 발행처
location: 페이지·표·문단
fact_status: actual | provisional | planned | estimated | scope_undisclosed
verification_status: verified | partial | insufficient
state_evidence: 해당 상태를 직접 확인하는 원문
source_date: 원문 발행·공시·확인일
evidence_support_terms: claim과 원문 근거 양쪽에 실제로 나타나는 핵심어
evidence_binding: claim·state_evidence·source_id·location·시점을 잠근 SHA-256
raw_value: 원수치와 원단위
calculation: 단위 변환·산식
display_value: 최종 표시값
rounding_rule: ROUND_HALF_UP 또는 해당 없음
numeric_checks: 원수치|나눗수|표시 자릿수|표시값
fiscal_year: 4장 완료 사업연도
event_date: 4장 completed_execution의 실제 사건 연도·날짜
product_role: 3장 제품·서비스의 사업 역할
priority_signals: 3장 원문에서 각각 확인된 서로 다른 실제 우선 신호 2개 이상
basis_fact_ids: 4장 변화 해석을 뒷받침하는 완료 실행·실적 ID
response_to_fact_id: 5장 대응이 직접 연결되는 미해결 문제 ID
limitations: 재분류·일회성·비교 한계 등(`limitation`은 구형 저장 호환용 별칭)
supports_causality: 직접 인과 근거가 있을 때만 true
causal_subject | causal_mechanism | causal_outcome | causal_evidence: 직접 인과의 주체·기제·결과·결속 원문
comparison_target | comparison_metric | comparison_definition | comparison_basis | comparison_period | comparison_scope: 9장 고객·제품/서비스·시장·기간·정의·회계 범위를 잠근 동일 조건 비교축
comparator_source_id | comparator_state_evidence | comparator_evidence_support_terms: 비교사 공식 원문 결속
```

실서비스 `comparison_basis`는 v1과 v2의 닫힌 JSON을 함께 읽는다.

- **v1 읽기 호환**은 실제 1~8장에 포함된 `verified` 후보 사실의 `fact_id·source_id`,
  DART `corp_code`, 공식 문서 ID, 단일 `state_evidence` 문장 정규화 SHA-256과 겹침 축을
  역참조한다. 저장 JSON/HMAC 형식만 호환하고 재출고할 때 현재의 엄격한 경쟁 관계 문법을
  다시 적용하므로 과거 v1도 `GATE_STOPPED`될 수 있다.
- **v2 독립 후보 원장**은 1~8장 의미 분류와 무관하게 자사 DART·공식 HTML IR·공식 웹
  Source의 정확한 한 문장을 보존한다. Source 종류·발행 주체·HTTPS host/URL·문서 ID·
  위치·날짜·문장·`evidence_sha256`·`evidence_exact_sha256`, 자사 DART 고유번호와
  attester를 함께 결속한다. 첫 해시는 공백 정규화+casefold 문자열, 둘째는 문장 추출 뒤
  `strip`된 저장 문장 문자열 그대로의 UTF-8 SHA-256이며 원 HTTP 응답·PDF 파일 바이트
  해시가 아니다. 두 값은 각각 `Source.evidence_hashes`와
  `Source.exact_evidence_hashes`에 있고 두 목록 모두 Source HMAC seal에 결속한다.

출고 게이트는 두 버전 모두에서 Source 등록부, 발행 법인(self-subject), 문서 ID·위치·
해시·seal을 다시 계산하고 후보 법인명이 현재형의 명시적 경쟁 술어의 실제 target/list
slot인지 검사한다. v2에서 `시장점유율`은 경쟁 표지가 아니며 과거·former·potential,
부정·제외, 인용·제3자 귀속, 협력·지원, 고객·공급사·파트너 경쟁, 모호한 별칭과
`or/또는`는 거부한다. 같은 문장+표지 조건만으로는 부족하고 엄격 문법의 false-negative를
허용한다. 순수 경쟁 문장을 1~8장 `claim_type`으로 위장하지 않는다. 일반
`FactRecord.state_evidence` 해시 계약은 v2 이중 해시 때문에 바뀌지 않는다.
`attestation_only` Source는 내부 Report JSON·저장·감사 등록부에만 보존하고 공개
웹·PDF·Notion·Markdown에는 실제 후보 원문 citation만 내보낸다.

시간 상태와 검증 상태는 위 영문 열거값으로 저장하고 표시용 한글은 렌더링 단계에서 붙인다.

출처 등록부의 각 `Source`는 실제로 수집한 원문 조각의 SHA-256 목록
`evidence_hashes`를 가진다. `state_evidence`의 해시가 이 목록에 포함되지 않으면 사실을
출처에 결속한 것으로 보지 않는다. 3장 후보의 `subject_label`은 원문에 실제로 적힌
정확한 대상명이어야 하며 최종 `subject_scope`와 의미가 달라지면 탈락한다.

필수 필드가 비어 있으면 본문 후보가 아니다. 같은 문장에 여러 법인·제품·상태가 들어가면 각 대상을 별도 `fact_id`로 나누고, 모든 상태와 근거가 같을 때만 출력 단계에서 묶는다.
모든 공개 `FactRecord`는 닫힌 공식 자료 허용 목록을 통과해야 한다. 현재 canonical 런타임은
보고서 결과에 사용되지 않는 외부 뉴스 검색·AI 선별을 생략하며 핵심 사실은 공식 공시·IR·
회사 공식 홈페이지 근거로만 만든다. `newspick` 기능 파일은 기존 호출 호환용으로만 남긴다.

## 4. 섹션 조사 계약

각 섹션 조사자는 다음만 전달한다.

- 채택 후보 사실
- 제외한 사실과 제외 이유
- 사실별 원문 위치
- 시간 상태와 기준일
- 해석 한계
- 권장 출력 형식

완성 문체나 페이지 디자인은 만들지 않는다. 동일 사실이 여러 섹션 후보가 되면 가장 직접적인 한 장만 소유자로 정한다.

## 5. 작성 순서

1. 사실 선택 전 자사 DART와 DART 기업개황 attestation을 통과한 자사 공식 HTML IR·공식 웹
   원문 상위집합을 검사한다. 후보용 웹·HTML IR은 정확한 같은 host의 HTTPS만 허용하고 HTTP·
   인증서 fallback·cross-host redirect를 허용하지 않는다. `corporate/about/product` 같은
   안정 회사 페이지는 별도 문서일이 없으면 봉인된 최신 수집일을 허용한다. host·path·query의
   `news/newsroom/press/media/notice/release/archive/blog`와 문서형 경로·키는 봉인된
   machine-readable 문서일이 필수다. `search/results/find` 경로와 `q/s/query/keyword(s)/
   search/term` key의 검색 결과는 최근 문서일이 있어도 항상 제외한다. 날짜가 무효·미래이거나
   `Report.as_of_date` 기준 400일을 초과하면 raw preflight·후보·canonical 직접 사실에서 뺀다.
   공식 IR PDF는 robots.txt, HTML 탐색 5쪽·링크 60개·PDF 최대 2개, 파일당 12 MiB·
   80쪽·추출 12,000자·160조각, 사이트 전체 PDF 20 MiB·보존 12,000자 상한을 적용한다.
   MIME `application/pdf`, `%PDF-` magic과 비암호화 문서를 확인하고 `pypdf 6.16.1`을
   별도 프로세스에서 wall 10초·CPU 8초·메모리/주소공간 256 MiB(POSIX `RLIMIT_AS`,
   Windows Job Object)·압축 해제 스트림 12 MiB·동시 워커 1로 실행한다. 앞 2쪽에서
   법인명·별칭을 확인하며 OCR-only 문서와 production OS 자원 상한 설정 실패를 거부한다.
   페이지·문단·문서 SHA-256은 보존하지만 현재 수집 경로는 신뢰 가능한 문서 발행일·보고기간을
   결속하지 않으므로 PDF를 raw preflight·후보·1~8장 canonical 선택과 직접 사실에 쓰지 않고,
   수집일을 문서 사실 기준일로 대신 쓰지 않는다. 선택 가능한 공식 후보가 없거나 연속 3개
   완료 회계연도 실적표가 없으면 사실 선택 AI를 호출하지 않고 중단한다.
2. 입력이 갖춰지면 사실 선택 AI를 실행하고, 장별 상한 안에서 필요한 `claim_type`과 모든 내부
   SID 참조가 함께 들어 있는 완결 부분집합만 Writer에 전달한다.
3. 1~8장 사실을 요약 없는 내부 초안으로 조립(`publish=False`; 저장·캐시·렌더링 금지)
4. 4·5·6장의 시간 상태 충돌 제거
5. 2·3·7장의 고객·제품·파트너 중복 제거
6. v1은 실제 1~8장 `fact_ids`에 포함되고 binding·공식 Source가 잠긴 단일 원문
   문장을, v2는 별도 봉인된 공식 후보 원문의 단일 문장을 DART 법인 후보로 연결한다.
   관계만 명시한 문장은 겹침 축으로 확대하지 않고 양사의 별도 공식 원문에서 같은 고객·
   제품/서비스·시장 범위를 확인한다. 실제 재무 비교 후보는 양사 DART의 같은 완료 사업연도·
   계정·기간·연결/별도 범위만으로 준비한다.
7. 동일 조건 비교가 성립하면 9장을 결합하고, 성립하지 않으면 빈 장·추정 비교를 만들지 않고 1~8장 기본 보고서 상태를 유지한다.
8. Writer 검수를 통과한 실제 본문 `FactRecord` 문장 중 3~5개를 프로그램이 글자 변경 없이 골라 해당 `fact_ids`의 최소 부분집합과 `verified_fact_reuse` 상태에 결속한다. 같은 장에서는 숫자 없는 문장을 우선하되 숫자 포함 문장뿐이면 그대로 허용한다. 요약 전용 AI·Reviewer는 호출하지 않는다.
9. 출처 부록을 연결하고 `build_published_report` 최종 게이트를 정확히 한 번 실행한다. 9장이 생략된 정본은 `Grade.PARTIAL`과 표준 비교 부족 사유를 가진다.
10. 캐시 후보는 저장 당시 날짜를 그대로 신뢰하지 않고 조회 당일 기준으로 공식 웹 현재성을
   다시 검사한다. 안정 페이지의 봉인 수집일 또는 문서형 페이지의 봉인 문서일이 미래·무효이거나
   400일을 초과하면 cache miss로 처리하고 새로 조사한다.
11. 최종 게이트에서 숫자·사건 중복과 모든 장별 계약 검사
12. 통과한 공개 객체만 저장·웹·PDF·Notion으로 렌더링하고 PDF 조판·시각 QA 수행

사실 선택 AI는 사전 조건을 통과한 경우에만 1차를 실행한다. 1차 결과가 필수 1~8장의 `claim_type`·내부 SID 링크를
한 회차 안에서 완결하고 파싱·출력 상한 이상이 없으면 즉시 확정한다. 불완전하거나 이상일
때만 2차를 호출한다. 2차 단독 결과가 완결되면 2차를 채택하고, 두 불완전 결과의 합집합을
만들거나 세 번째 호출·3회 다수결을 실행하지 않는다.

Writer 문장이 원문과 앞뒤 공백 제외 완전일치하면 프로그램이 확정하고 Reviewer를 부르지
않는다. 공백 정규화·부분 일치·의미 유사성은 이 예외가 아니다. 나머지 중 첫 Reviewer가 정상 boolean `False`로 판정한 문장만 한 배치에서 한 번 고쳐 쓸
수 있다. 재작성문도 원문 완전일치는 코드가 확정하고, 나머지만 별도·무문맥 Reviewer가 다시 검사한다. 첫 검수 통과 문장은 다시
AI에 보내지 않으며, 재작성 대상이 없으면 추가 Writer/Reviewer 호출도 하지 않는다.

## 6. 근거 부족 처리

- 근거가 없는 카드는 만들지 않는다.
- 빈 박스나 “자료가 없습니다” 상자를 본문에 반복하지 않는다.
- 선택 하위 사실의 근거가 부족하면 해당 사실을 빼고 장의 필수 계약을 다시 검사한다.
- 1~8장은 모두 필수다. 하나라도 최소 내용 계약을 충족하지 못하면 빈 장·구형 보고서를 내보내지 않고 전체를 `GATE_STOPPED`로 종료한다.
- 9장은 조건부다. 양사 공식자료의 동일 고객·제품/서비스·시장·기간·정의·회계/사업 범위 비교가 성립하지 않으면 비교 행·우위 문장·빈 장을 만들지 않고, 검증된 1~8장을 `Grade.PARTIAL` 기본 보고서로 출고한다. 표준 부족 사유는 경쟁우위 부재 판정이 아님을 명시한다.
- 후보 탐색의 실제 `state`는 `failed·none·ok`뿐이다. 허용 범위를 끝까지 읽고 후보가
  없는 정상 완전 탐색의 `none`만 음성 판정으로 사용한다. 네트워크·TLS·MIME·파서·
  카탈로그 실패는 `failed`, 페이지·문서·바이트·글자 상한 잘림은 별도 `truncated`
  state가 아니라 `candidate_scope_complete=False`와 상세 사유로 기록한다. 불완전한
  `failed` 또는 `ok`는 `unknown`이며 `후보 없음`으로 바꾸지 않는다.

## 7. 최종 자동검사·자동출고

사실·인용·수치·목차·금지 문구·장별 의미·PDF 전 페이지 렌더·채널 동등성 검사를 모두
통과한 경우에만 자동출고한다. 결과 레코드는 같은 보고서/PDF/모든 페이지 PNG 해시,
전체 `fact_id`, 검사 버전에 결속한다. 9장 조건부 생략은 허용된 v4 기본 보고서 상태다.
그 밖의 검사 하나라도 실패하거나 검사 뒤 어느 해시라도 바뀌면 웹·PDF·Notion 전체를
`GATE_STOPPED`하며 미검증 결과를 보여 주지 않는다.

공개 웹·PDF·Notion·Markdown은 같은 자동출고 레코드를 확인하고 같은 보고서 객체를 사용한다.
구형 DOCX와 수동 `/review/pdf/*` 경로는 이 파이프라인의 활성 출력·승인 경로가 아니다.
기존 수동 승인 테이블과 행은 감사자료로 보존하지만 출고 권한으로 읽지 않는다.

파일럿 후보 원장은 P01~P25 25건이다. 현재 실제 유료 실행과 사용자가 자동판정 옆에
품질을 기록하는 완전검수 범위는 P01~P10이며, P11~P25는 이번 재시험 결과와 후속 범위
결정에 따라 평가한다. 이는 자동검사를 보정하는 평가자료이며 이후 실제 서비스의
보고서별 승인 조건이 아니다. 유료 실행 범위와 비용 경계는 실행 전에 사용자의 최신
결정과 provider 선불 잔액을 확인한다.
