# 디자인과 PDF QA

## 목표

모든 회사 보고서를 같은 제품이 만든 공식 문서처럼 보이게 한다. 디자인은 정보를 돋보이게 해야 하며, 장식·색상·복잡한 도표 때문에 조사 품질이나 제작 시간이 흔들리면 안 된다.

기준은 현재 제품 결과 화면의 `흑백 팔레트·Freesentation·큰 여백·가는 선·간결한 표`와 기준 산출물의 A4 편집 방식을 따른다. 특정 회사의 브랜드 색이나 예외 레이아웃을 공통 규칙으로 하드코딩하지 않는다.

PDF는 사용자 다운로드 정본이다. 구조화된 내용은 공개 웹·Notion과 같아야 하며, 어느 출력도 별도의 활용 질문·지원 조언·구형 섹션을 추가할 수 없다. 필수 자동검사 전 항목 통과 전에는 어느 채널도 공개 정본이 아니다. 세부 런타임 조건은 [`런타임 출고 계약`](./런타임_출고_계약.md)을 따른다.

## 1. 문서 규격

- 용지: A4 세로, 210 × 297mm
- 기본 여백: 왼쪽 17mm, 오른쪽 17mm, 위 18mm, 아래 16mm
- 본문 폭: 약 176mm
- 표지 제목: `[회사명]` 줄바꿈 후 `분석 보고서`. 제목에 `기업`을 넣지 않는다.
- 표지 제목 블록은 첫 장의 세로 중앙보다 약간 위인 `상단에서 72~118mm` 영역에 둔다. 좌우 기본 여백 안에서 왼쪽 정렬하며, 페이지 맨 위에 붙이지 않는다.
- 표지 메타정보는 제목 바로 아래에 한 줄로 둔다. 회사 로고·영문 회사명·설명용 부제는 별도로 반복하지 않는다.
- 표지 `핵심 요약`은 첫 장 하단의 `상단에서 190~262mm` 영역에 고정한다.
- 표지 `최신 사업연도 실적` 띠는 제목 블록과 핵심 요약 사이의 `상단에서 138~166mm` 영역에 둔다. 띠를 낼 값이 없는 보고서에서는 같은 자리를 예전처럼 의도된 표지 여백으로 유지한다(빈 제목·빈 칸을 남기지 않는다).
- 2쪽 이후 상단: `[회사명] 분석 보고서` / 오른쪽 `기준일 YYYY.MM.DD`
- 2쪽 이후 하단: 왼쪽 회사명 / 오른쪽 페이지 번호
- 페이지 번호는 표지를 1쪽으로 계산하되 표지에는 표시하지 않는다.
- 모든 페이지의 제목·작성자·주제 PDF 메타데이터를 채운다.
- 최종 파일명은 회사가 바뀌어도 동일한 규칙을 쓴다. 예: `<company-slug>-company-analysis.pdf`.

## 2. 색상

### 기본 팔레트

| 용도 | 색상 |
|---|---|
| 가장 진한 글자·제목 | `#0A0A0A` 또는 `#171717` |
| 본문 | `#171717` |
| 보조 글자 | `#5F5F5F` |
| 약한 보조 글자 | `#737373`~`#8A8A8A` |
| 배경 | `#FFFFFF` |
| 옅은 구분 배경 | `#F5F5F5`, `#FAFAFA` |
| 선 | `#E5E5E5` |
| 그래프 계열 | `#0A0A0A`, `#5F5F5F`, `#A3A3A3`, `#D4D4D4` |
| 예외 경고 | `#E7000B` |

- 기본은 검정·회색·흰색만 사용한다.
- 빨간색은 손실·하락·오류처럼 의미가 명확한 예외에만 쓴다.
- 장마다 다른 강조색을 배정하지 않는다.
- 상태를 색만으로 구분하지 않고 텍스트를 함께 쓴다.
- 표 머리글은 검은 바보다 옅은 회색 배경을 기본으로 한다. 검은 면은 표지 요약 번호 등 아주 작은 강조에만 허용한다.
- 회사 로고 색·브랜드 색을 보고서 전체 테마로 사용하지 않는다.

## 3. 서체와 글자 크기

### 서체

- 기본: Freesentation Regular
- 강조: Freesentation SemiBold
- PDF에는 사용 글꼴을 임베드한다.
- 한글·영문·숫자에 같은 계열을 사용한다.
- 회사 로고 서체·장식용 영문 세리프를 본문에 섞지 않는다.
- 대체 글꼴이 필요하면 `맑은 고딕`을 사용하되 최종 출력 전 줄바꿈을 다시 검수한다.

### 권장 크기

| 요소 | 크기·행간 |
|---|---|
| 표지 회사명·보고서명 | 30~31pt / 34~36pt |
| 장 제목 | 17pt / 21pt |
| 소제목 | 11pt / 14pt |
| 강조 결론 | 13~14pt / 18~20pt |
| 본문 | 9.2~9.6pt / 13.8~14.4pt |
| 카드 본문 | 8.2~8.6pt / 11.5~12pt |
| 표 머리글·셀 | 7.5~7.8pt / 9.5~10.2pt |
| 주석·출처 보조문 | 6.9~7.7pt / 9.2~10.8pt |
| 상·하단 메타정보 | 6.6~6.8pt |

- 본문을 페이지에 맞추기 위해 9pt 아래로 줄이지 않는다.
- 일반 표를 7.4pt 아래로 줄이지 않는다. 출처표도 6.9pt 아래로 줄이지 않는다.
- 6.5pt 미만 글자는 어떤 경우에도 허용하지 않는다.
- 글자가 넘치면 폰트를 줄이기보다 문장을 줄이고 표를 나누거나 다음 페이지로 보낸다.
- 숫자는 가능한 한 tabular 숫자 정렬을 사용한다.

## 4. 제목과 정보 위계

- 표지는 `[회사명]`을 먼저 쓰고 다음 줄에 `분석 보고서`를 쓴다. `기업분석 보고서`, `회사 분석 보고서`처럼 중간에 다른 말을 더하지 않는다.
- `취업 준비를 위한`, `회사 공식 자료 우선` 같은 설명 문구는 표지에서 제거한다.
- 장 제목은 `번호. 제목` 형식이며 아래에 1pt 안팎의 검은 선을 둔다.
- `#과거`, `#현재`, `#미래` 태그는 4·5·6장 제목 옆에만 회색 작은 글자로 쓴다.
- 다른 장에는 상태 배지나 `운영 중` 같은 장식 태그를 붙이지 않는다.
- 소제목은 `무엇을 파나` 같은 구어체 대신 `주요 제품·서비스`, `최근 실행 근거`, `수익 창출 구조`, `포트폴리오 역할`처럼 공식 문서형 명칭을 쓴다.
- 소제목은 SemiBold로 본문과 명확히 구분한다.
- 장 도입문은 핵심 결론 한두 문장으로 시작한다. `이 장에서는 …을 정리했다` 같은 제작 설명은 쓰지 않는다.

## 5. 여백과 간격

- 큰 제목 뒤: 7~10pt + 구분선 + 9~12pt
- 문단 사이: 4~8pt
- 소제목 위: 12~16pt, 아래: 4~7pt
- 표·그래프 위아래: 10~16pt
- 카드 사이: 4~6mm
- 표 셀 안쪽: 좌우 4~7pt, 위아래 4~7pt
- 한 페이지 안에서 같은 계층은 같은 간격을 유지한다.
- 빽빽함을 해결하기 위해 임의로 자간·장평을 줄이지 않는다.
- 장 제목이 페이지 하단 25mm 이내에서 혼자 시작하지 않게 한다.

## 6. 표지와 핵심 요약

- 표지와 핵심 요약은 한 페이지에 배치한다.
- 제목은 상단에서 72~118mm 안에 놓고, 핵심 요약은 상단에서 190~262mm 안에 놓는다. 두 영역의 위치를 회사별 내용량에 따라 서로 바꾸지 않는다.
- 핵심 요약은 회사 고유 결론 3~5개다.
- 요약은 Writer 검수를 통과한 본문 문장을 글자 변경 없이 재사용하고 `[n장]`으로 연결한다. 같은 장에서는 숫자 없는 문장을 우선하되 숫자 포함 검증 문장뿐이면 그대로 허용한다.
- 요약 행은 `번호 | 짧은 주제 | 한 문장 결론` 구조를 권장한다.
- 제목과 핵심 요약 사이는 아래 `6-1. 표지 최신 사업연도 실적 띠`가 있으면 띠가, 없으면 빈 공간이 차지한다. 어느 쪽이든 제목·메타정보·띠·요약의 왼쪽 정렬축이 정확해야 한다.
- 로고·회사 사진·그라데이션·장식 이미지는 사용하지 않는다.

## 6-1. 표지 최신 사업연도 실적 띠

### 왜 여백 규칙을 바꿨나

표지 중간의 넓은 여백은 원래 「제목과 요약의 위치를 회사별 내용량에 흔들리지 않게 고정한다」는 목적에서 나왔다. 그 목적은 위치를 **고정**하는 데 있지 그 자리를 **비워 두는** 데 있지 않다. 실제로 표지 첫 화면에는 회사를 규모로 가늠할 숫자가 하나도 없어, 독자가 4장까지 넘겨야 매출 규모를 알 수 있었다.

그래서 여백의 일부(`상단에서 138~166mm`, 최대 28mm)만 **고정 위치의 띠**로 대체한다. 제목 블록(`72~118mm`)과 핵심 요약(`190~262mm`)의 영역은 그대로다. 띠가 없어도 두 영역은 움직이지 않으므로, 이 개정은 위치 고정이라는 원래 목적을 깨지 않는다.

### 무엇을 실을 수 있나 (닫힌 목록)

- 4장 실적표(`build_three_year_table`가 전자공시 API 원수치로 만든 표)의 **최신 사업연도 행** 하나만 싣는다.
- 실을 수 있는 값: `사업연도`, `매출액`, `영업이익`, 그리고 표의 단위(`억원`)와 표와 **같은** 출처 번호.
- 값은 표 셀의 **글자 그대로** 재사용한다. 표지에서 반올림·단위 변경·자릿수 조정을 하지 않는다.

### 금지 (MUST NOT)

- **새로 계산한 숫자 금지** — 증감률·성장률·비율·순위·합계·평균 등 표에 인쇄되지 않은 값은 어떤 것도 표지에 올리지 않는다. 이 값들은 재검산할 사실 장부가 없어 검증 불가 주장이 된다.
- **AI 문장에서 뽑은 숫자 금지** — 띠의 값은 프로그램이 만든 표에서만 온다.
- **영문 라벨 금지** — `KPI` 등 영문 약어를 라벨로 쓰지 않는다. 출고 게이트가 `KPI`를 지원자 직무 소재로 간주해 차단한다(`report_standard/publish.py`의 `_FORBIDDEN_JOB_TOPIC`). 라벨은 표의 한국어 열 이름을 그대로 쓴다.
- **빈 자리 금지** — 실적표가 없는 회사(비상장·수치 불충분·기간 불연속 등)에서는 띠 전체를 그리지 않는다. 제목만 남기거나 `—`로 채우지 않는다.

### 모양

- 웹: 결과 화면 토큰(`--ink`/`--paper`/`--line`, 카드 모서리 24px)만 쓴다. 새 색을 만들지 않는다.
- PDF: 흰 배경 + `#E5E5E5` 0.55pt 선. 값은 SemiBold, 라벨과 단위는 보조 글자색.
- 값 글자 크기는 표지 제목보다 작고 장 제목보다 크지 않게 한다(PDF 기준 15~18pt).
- 웹과 PDF는 **같은 순수 함수**(`report_standard/cover_metrics.py`)가 고른 값을 쓴다. 두 곳에서 따로 고르면 화면과 인쇄물이 조용히 갈라진다.
- 출처 번호는 띠 제목 옆에 붙이며 **4장 실적표와 같은 번호**다. 표지가 새 출처를 만들지 않으므로 부록과의 1:1이 유지된다. 표기 모양만 채널을 따른다 — 웹은 눌러서 원문으로 가는 위첨자 링크, PDF는 본문과 같은 `〔n〕` 표기다. **값과 번호는 두 채널이 언제나 같아야 한다.**

## 7. 카드

- 카드가 정보 묶음을 빠르게 구분할 때만 사용한다.
- 동일 수준의 카드가 3개면 너비·높이·제목 위치를 맞춘다.
- 카드마다 다른 배경색을 넣지 않는다.
- PDF에서는 흰 배경·옅은 회색 0.5~0.7pt 테두리를 사용한다.
- 웹 UI의 24px 둥근 모서리를 PDF에 그대로 확대 적용하지 않는다. 공식 문서 톤을 위해 PDF 모서리는 0~2mm 수준으로 절제한다.
- 카드 안 소제목은 굵게 표시하고, 소제목과 내용의 간격을 일정하게 유지한다.
- 한 카드에 소제목은 최대 4개, 본문은 가능한 7~10줄 이내로 제한한다.
- 내용이 길면 카드를 늘리기보다 표나 다음 페이지로 분리한다.

## 8. 표

### 기본 형식

- 표 머리글: `#FAFAFA`, SemiBold, 가운데 또는 의미에 맞는 정렬
- 표 본문: 흰색과 아주 옅은 회색을 교대로 사용 가능
- 테두리: `#E5E5E5`, 0.4~0.7pt
- 텍스트: 왼쪽·위 정렬
- 숫자: 오른쪽 정렬, 단위 통일
- 행 머리글이 반복되면 첫 열을 짧고 굵게 쓴다.
- 페이지가 나뉘면 머리글을 반복한다.

### 폭과 밀도

- A4 세로 기준 일반 표는 3~5열을 사용한다. 출처 부록만 6열까지 허용한다.
- 6열 이상 일반 표는 결합 가능한 열을 먼저 검토하고, 의미가 손상되면 페이지를 가로로 돌리지 말고 5열 이하의 표 둘로 나눈다.
- 한 셀은 핵심 사실 1개 또는 2문장 이하를 원칙으로 한다.
- 열 제목은 1~2줄 안에 끝나게 한다.
- 긴 URL을 셀에 노출하지 않고 자료명에 링크한다.
- 행 하나가 페이지를 넘어 쪼개지지 않게 한다.

### 반복 금지

- 표 위 캡션에서 이미 밝힌 기간·단위·범위는 모든 셀에 반복하지 않는다.
- 특히 포트폴리오 표의 `기준일`은 표 전체 캡션 또는 부록 출처에서 한 번만 밝힌다. 각 행에는 그 자산에만 다른 시점·상태가 있을 때만 날짜를 적는다.
- 동일한 `2026년 2분기 기준`, `공식 활동표 기준`을 모든 행에 반복하지 않는다.
- 같은 사실을 표·카드·본문에서 다시 쓰지 않는다.
- 표 제목은 `선정 기준`처럼 대상이 불명확하면 안 된다. `핵심 사업 포트폴리오의 역할`, `경쟁사 비교 조건`처럼 무엇을 설명하는지 명시한다.

## 9. 그래프와 도표

### 사용 판단

아래 질문에 모두 `예`일 때만 넣는다.

1. 문장이나 작은 표보다 관계를 훨씬 빨리 이해하게 하는가?
2. 최소 3개 시점·3개 대상·3단계 흐름 중 하나가 있는가?
3. 정확한 값·단위·기간·출처를 표시할 수 있는가?
4. 같은 사실을 다른 형식에서 반복하지 않을 수 있는가?

하나라도 `아니오`면 문장이나 표를 사용한다.

### 그래프 선택

- 3개년 추세: 막대 또는 선 그래프
- 매출 구성: 범주 5개 이하일 때 누적 막대
- 같은 지표의 기업 비교: 그룹 막대
- 3단계 이상 사업 흐름·파트너 분기: 플로우차트
- 두 대상의 정성 비교: 표

### 그래프 작성 규칙

- 계열은 최대 4개다.
- 흑백 명도 차이가 충분해야 한다.
- 범례 대신 직접 라벨을 우선한다.
- 제목에 무엇·기간·단위를 적는다.
- 축을 임의로 잘라 격차를 과장하지 않는다.
- 막대는 0에서 시작한다.
- 수치 라벨과 범례는 7.5pt 이상을 권장한다.
- 자료 출처와 계산 여부를 그래프 아래 한 줄로 적는다.
- 3D, 그림자, 그라데이션, 레이더차트, 장식용 아이콘은 사용하지 않는다.
- 같은 수치를 그래프 옆 카드나 표에서 다시 보여주지 않는다.

## 10. 페이지 균형

- 일반 본문 페이지는 사용 가능한 세로 공간의 약 50~85%를 정보로 채우는 것을 목표로 한다.
- 45% 미만은 표지·부록 종료·의도적인 장 전환일 때만 허용한다.
- 88% 이상 채워 글자와 표가 붙어 보이면 다음 페이지로 분리한다.
- 장 하나를 반드시 한 페이지에 넣기 위해 글자 크기·행간을 줄이지 않는다.
- 제목·도입문·첫 표 머리글은 가능한 한 함께 둔다.
- 표 한 행 또는 카드 한 개가 페이지 하단에 고립되지 않게 한다.
- 표·그래프 하단과 바닥글 사이에 최소 8mm의 시각 여백을 둔다.
- 빈 공간이 생겨도 억지 사진·아이콘·설명 문장을 추가하지 않는다.

## 11. 출처 표시와 링크

- 본문 사실 끝에는 `[n]` 형식의 작은 출처 번호를 둔다.
- 번호는 부록의 동일 번호와 정확히 일치해야 한다. PDF 내부 이동 링크는 구현 가능한 경우 권장하지만 필수 출고 조건은 아니다.
- 부록의 자료명은 클릭하면 원문으로 이동한다.
- 출처 번호는 본문 색보다 한 단계 연한 회색을 사용하되 읽을 수 있어야 한다.
- 잠정·계획·재분류·일회성 영향은 해당 주장 가까이에 남긴다.
- 링크 밑줄·색은 인쇄해도 본문과 구분되게 한다.
- 내부 파일 경로·도구 토큰·HTML 태그·플레이스홀더를 노출하지 않는다.

### 파일과 페이지

### 링크와 출처

- [ ] 본문의 모든 `[n]`에 같은 번호의 부록 행이 존재한다.
- [ ] 부록의 모든 자료 링크가 올바른 원문을 연다.

- [ ] PDF 페이지 또는 웹 섹션 위치가 출처표에 있다.

### 내용 구조

- [ ] 핵심 요약이 결속된 본문 문장과 글자 단위로 같고 `verified_fact_reuse` 상태인가?

## 13. PDF 시각 QA 게이트

### 렌더 절차

1. 검수 후보 PDF의 SHA-256을 소문자 16진수 64자리(`[0-9a-f]{64}`)로 계산한다.
2. 그 PDF의 모든 페이지를 PNG로 렌더링하고 페이지별 PNG SHA-256을 같은 형식으로 기록한다.
3. 전체 페이지 축소 보기로 정렬·페이지 균형·일관성을 확인한다.
4. 표·그래프·출처표가 있는 페이지를 확대해 글자와 선을 확인한다.
5. 수정 후 PDF 전체를 다시 렌더링하고 PDF·모든 PNG 해시를 새로 계산한다. 수정한 페이지만 보지 않는다.

### 페이지별 검사

- [ ] 글자·표·그래프·선이 페이지 밖으로 잘리지 않는다.
- [ ] 요소가 겹치거나 셀 안 텍스트가 가려지지 않는다.
- [ ] 제목·도입문·표의 정렬축이 같다.
- [ ] 표 머리글과 행이 페이지 전환에서 분리되지 않는다.
- [ ] 카드 높이와 내부 여백이 같은 수준끼리 일치한다.
- [ ] 그래프 축·단위·수치·범례가 실제 크기에서 읽힌다.
- [ ] 회색 단계가 인쇄·축소 화면에서도 구분된다.
- [ ] 상단·하단 선과 페이지 번호 위치가 모든 페이지에서 같다.
- [ ] 과도하게 빽빽하거나 비어 보이는 페이지가 없다.
- [ ] PDF text glyph의 본문 좌표를 실제 렌더 PNG와 대조했을 때 본문 글자가 보인다. 헤더·쪽번호의 잉크만으로 흰색·미렌더 본문을 통과시키지 않는다.
- [ ] 한 줄만 다음 페이지로 넘어간 고아 문단이 없다.
- [ ] 잘못된 줄바꿈으로 회사명·제품명·숫자 단위가 분리되지 않는다.
- [ ] 출처표 링크 밑줄과 글자가 셀 경계를 침범하지 않는다.
- [ ] 표지 실적 띠가 상단 138~166mm 안에 있고 제목 블록·핵심 요약과 겹치지 않는다.

### 실패 조건

다음 중 하나라도 있으면 배포하지 않는다.

- 잘림·겹침·깨진 글꼴·검은 네모
- 표의 열 의미를 읽기 어려운 지나친 압축
- 같은 사실의 표·그래프·카드 반복
- 근거 없는 장식 그래프
- 6.5pt 미만 글자
- 표지·헤더의 회사명 불일치
- 끊어진 출처 링크 또는 출처 번호
- 페이지 하단을 침범한 내용
- 표지 실적 띠에 4장 실적표에 없는 숫자(증감률·비율 등)가 인쇄된 경우
- 본문 glyph 영역이 흰색·미렌더 상태인데 헤더·쪽번호만 보이는 페이지

## 14. 최종 자동검사·자동출고 순서

1. 내용·출처 검증
2. 중복 사실 검사
3. PDF 구조 검사
4. 후보 PDF SHA-256 계산과 전체 페이지 PNG 렌더링·페이지별 해시 기록
5. 모든 페이지의 글자·glyph 가시성·빈 페이지·크기·페이지 수 자동검사
6. 웹·PDF·Notion이 같은 정본과 사실 장부를 쓰는지 자동검사
7. 검사 전후 보고서·PDF·모든 페이지 PNG 해시 재대조
8. 전 항목 통과 시 같은 검사 버전과 해시의 자동출고 레코드 확정
9. 하나라도 실패하거나 해시가 바뀌면 전체 `GATE_STOPPED`

디자인 수정은 사실 내용·출처 연결을 바꾸지 않는 범위에서만 한다. 내용을 줄여야 할 때는 임의 삭제하지 않고 해당 장의 필수 필드와 우선순위에 따라 줄인다.

- 자동검사는 최종 후보의 전체 `fact_id`, 인용·수치·중복·일반론·구형 목차를 전수 확인한다.
- 모든 페이지를 실제 PNG로 렌더하고 PDFium glyph 좌표와 픽셀을 대조한다. 텍스트 추출 성공만으로 시각 통과로 보지 않는다.
- 자동출고 레코드에는 보고서·PDF·모든 페이지 PNG·사실 장부 해시와 검사 버전을 결속한다. 검사 뒤 하나라도 달라지면 새 해시로 조용히 재승인하지 않는다.
- 공개 웹·PDF 다운로드·Notion 전송은 같은 자동출고 레코드가 있을 때만 허용한다. 수동 승인 URL은 410이며 구형 승인 DB는 감사자료일 뿐 권한이 아니다.
- 후보 원장은 P01~P25 25건이지만 현재 실제 유료 실행·사용자 시각·품질 완전검수는
  P01~P10이다. P11~P25는 이번 재시험 결과와 후속 범위 결정에 따라 평가하며, 파일럿
  기록은 실제 서비스의 건별 출고 조건이 아니다.
- DOCX는 활성 출력 채널이 아니며 이 자동출고 흐름을 우회할 수 없다.
