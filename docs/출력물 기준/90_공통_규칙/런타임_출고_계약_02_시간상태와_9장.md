> 챕터: 02. 시간 상태·섹션 라우팅과 9장 계약 (본문 §4~§5)

## 4. 시간 상태와 섹션 라우팅

| 상태 | 소유 섹션 | 출고 조건 |
|---|---|---|
| 최근 3년 내 완료된 실행과 확인된 결과 | 4장 `#과거` | 실행 시점과 결과 근거가 모두 있음 |
| 아직 해결되지 않은 문제 | 5장 `#현재` | 문제가 현재도 남았다는 최신 근거가 있음 |
| 현재 진행 중인 대응 | 5장 `#현재` | 회사가 실제로 착수했다는 근거가 있음 |
| 발표됐지만 아직 결과가 없는 계획 | 6장 `#미래` | 공식 계획·목표·예정 표현과 기준일이 있음 |
| 지속 중인 운영 기반·계약 관계 | 7장 | 관계 당사자·역할·유효 시점이 확인됨 |

- 계획을 완료 사실로, 오래된 사건을 현재 대응으로, 잠정치를 확정치로 바꾸면 출고를 중단한다.
- `가능하다`, `이어질 수 있다`, `영향을 준다` 같은 완곡 표현도 직접 인과 근거를 대신할 수 없다.
- 4장은 회사의 실제 결산월에 따른 비교 가능한 완료 `fiscal_year` 3개와, 기준일 이전 36개월의 `completed_execution`·`event_date`를 모두 가져야 한다. 모든 회사를 달력연도 12월 31일 결산으로 고정하지 않는다.
- 4장의 `change_interpretation`은 같은 장의 완료 실행·완료 실적 `basis_fact_ids`에 결속돼야 한다.
- 5장의 모든 `current_issue`에는 실제 `current_response`가 있어야 하고, 대응의 `response_to_fact_id`가 그 문제를 직접 가리켜야 한다.
- 4장의 공개 3개년 실적표는 행을 완료 사업연도, 열을 지표로 구성하고 표 위에 `단위: 억원`을 한 번만 표시한다. 셀에는 억원 표시값만 두며 원 단위 원값은 `FactRecord.raw_value`와 `numeric_checks`에만 보존한다.
- 제품·지역별 매출 구성 **변화** 표(최대 3개 사업연도)는 4장 `past_changes`가 소유한다. 같은 파서가 만든 **단년** 구성표는 제품축이 3장 `portfolio`, 지역축이 2장 `business_model` 소유다. 캡션이 `제품·서비스별 매출 비중 변화` 또는 `지역별 매출 비중 변화`로 시작하면 변화 표이며, 단계 이름은 `7_구성변화표`다.

## 5. 회사가 밝힌 차별점과 선택적 비교 계약

- 9장의 필수 슬롯은 `self_context`, `stated_differentiator`, `limitation`이다. 공식 DART·회사 웹·IR에서 회사명·`당사`·`우리`가 주어이고 `최초·유일·최다·1위·최대·독자 개발·특허` 중 하나가 직접 적힌 문장을 결정론적으로 선별한다.
- 자기 선언 승격은 **공식 원문 조각만** 대상으로 한다. 한 보고서에서 최대 4건이며, 공식 근거 사전검사 앞·AI 재판정 앞에서 실행한다. 언론 보조 조각은 이 승격의 입력이 아니다.
- 자기 선언 Fact는 회사 법인명을 주어로 유지하고 발표일·공식 출처·exact 원문 해시에 결속한다. 진위나 타사 우열을 판정하지 않았다는 한계를 함께 두며 `우위·열위·더 낫다` 같은 작성자 평가를 섞지 않는다.
- 아래 비교 계약은 검증 가능한 양사 자료가 있을 때만 선택적으로 적용한다. 비교가 성립하지 않아도 적격 자기 선언이 있으면 9장과 전체 출고를 막지 않는다.
- 선택적 비교 사실마다 비교 대상과 선정 이유, 동일 비교축, 같은 고객·제품/서비스·시장·기간·정의·회계/사업 범위, 양사 근거, 확인된 차이, 비교 한계를 저장한다.
- 비교사 후보 선정 근거는 자사가 발행한 DART 공시, DART 기업개황 attestation을 통과한 자사 공식 HTML IR·공식 웹만 허용한다. 안정 회사 페이지는 봉인 수집일, 보도·공지·archive·blog·문서형 URL은 봉인 machine-readable 문서일을 사용하며 `Report.as_of_date` 기준 0~400일만 허용한다. 검색 결과는 날짜와 무관하게 허용하지 않는다. 공식 IR PDF는 현재 문서일 결속이 없어 후보 선정 근거와 직접 사실이 아니다.
- `comparison_basis` v1은 실제 1~8장 `verified` FactRecord의 한 문장을 ID와 정규화 SHA-256으로 역참조하는 저장 JSON/HMAC 형식의 읽기 호환 계약이다. 재출고 시 현재의 엄격한 경쟁 관계 문법을 다시 적용하므로 과거 v1도 실패할 수 있다. v2는 1~8장 의미 분류와 독립된 자사 공식 Source의 정확한 한 문장, Source identity·위치·날짜·두 해시·seal·self corp_code·attester를 닫힌 JSON으로 결속한다.
- v2 `evidence_sha256`은 공백 정규화+casefold한 문장의 UTF-8 SHA-256이고, `evidence_exact_sha256`은 문장 추출 뒤 `strip`된 저장 문장 문자열 그대로의 UTF-8 SHA-256이다. exact 해시는 원 HTTP 응답이나 PDF 파일 바이트 해시가 아니다. 두 값은 각각 `Source.evidence_hashes`와 `Source.exact_evidence_hashes`에 있어야 하며 두 목록 모두 `provenance_seal`의 HMAC payload에 결속한다. 이 이중 해시는 v2 후보 문장 전용이며 일반 `FactRecord.state_evidence` 계약을 바꾸지 않는다.
- v2는 단순한 같은 문장+표지 검사가 아니다. 후보 법인명이 자사 발행 주체(self-subject)의 현재형 명시적 경쟁 술어가 요구하는 실제 target/list slot에 있고, 문장이 수집한 한 원문 블록의 연속 부분일 때만 허용한다. `시장점유율`은 v2 경쟁 표지에서 제외한다. 과거·`former/potential/possible`, 부정·제외, 인용·제3자 귀속, 협력·지원, 고객·공급사·파트너 경쟁, 모호한 별칭과 `or/또는` 선택지는 거부한다. 오탐 방지를 우선하는 닫힌 문법이므로 false-negative를 허용한다. 순수 경쟁 문장을 1~8장 `customer_market` 등으로 위장하지 않으며, 그 문장은 v2 후보 원장 외의 공개 사업 사실로 승격하지 않는다.
- 원문이 경쟁 관계만 직접 명시하면 `경쟁 관계 명시`까지만 저장한다. 고객·제품/서비스·시장 겹침을 추정하지 않고, 공개 비교 행에는 양사의 별도 공식 원문으로 공통 범위를 증명한다.
- 실제 재무 비교값은 양사 DART의 같은 완료 사업연도, 같은 계정·재무제표 종류·연결/별도 범위·기간·통화 자료만 사용한다. 공식 HTML IR·웹은 후보와 공통 범위 근거가 될 수 있지만 재무 수치 원장을 대신하지 않는다. 문서일을 결속하지 못한 공식 IR PDF는 후보 근거가 아니다.
- 자사와 비교사 중 한쪽 공식 근거라도 없거나 고객·제품/서비스·시장·정의·기간·회계 범위가 다르면 공개 비교 행이나 순위·우위 문장을 만들지 않는다.
- 구조 차이만 확인되면 `운영 특성`으로 쓰고, 결과 우위까지 같은 조건으로 확인될 때만 `경쟁우위`로 쓴다.
- 기술력·브랜드·네트워크 같은 일반명사와 원문이 직접 뒷받침하지 않는 인과·수익성·고마진 표현은 금지한다.
- 검증 가능한 항목이 3개보다 적으면 개수를 억지로 맞추지 않는다.
- 유효 비교축은 단순한 매출·자산 규모 반복이 아니라 같은 기간·정의·연결/별도 범위에서 재현되는 영업이익률 등 사업 해석에 유효한 지표여야 한다. 규모 차이를 여러 계정으로 쪼개 차별점 수를 채우거나 규모 자체를 우위로 승격하지 않는다.
- 후보 수집의 실제 `state`는 `failed·none·ok`뿐이다. 허용 범위를 끝까지 확인한 정상 완전 탐색의 `none`만 `후보 없음`으로 판정한다. 접속·TLS·MIME·파서·카탈로그 실패는 `failed`, 페이지·문서·바이트·글자 상한 잘림은 별도 `truncated` state가 아니라 `candidate_scope_complete=False`와 상세 사유로 표현한다. 범위가 불완전한 `failed` 또는 `ok`는 `unknown`이며 음성 증거로 사용하지 않는다.
- 선택적 비교가 성립하지 않으면 비교 행·판정만 만들지 않는다. 적격 자기 선언이 있으면 9장을 계속 제공하고, 자기 선언도 없을 때만 출시 모드를 `OFFICIAL_EVIDENCE_INSUFFICIENT`로 멈춘다. 연습 모드에서는 검증된 1~8장을 `Grade.PARTIAL`로 출고하고 정해진 부족 사유만 표시한다.
