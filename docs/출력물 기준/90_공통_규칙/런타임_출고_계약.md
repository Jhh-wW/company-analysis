# 런타임 출고 계약

- 상태: **현재 정본(Canonical)**
- 제품 키: `product:company-analysis`
- `Report.schema_version`: `company-report-v4-canonical`
- 캐시 스키마 토큰: `schema:company-report-v4-canonical`
- 적용 범위: 신규 조사, 데모 재생, 캐시 조회, 웹 표시, PDF·Notion·Markdown 변환

이 문서는 출력 원칙을 프로그램이 매번 같은 방식으로 집행하기 위한 최소 계약이다. 프롬프트에 원칙을 적는 것만으로는 준수로 보지 않는다. 조사 결과와 최종 PDF가 해시에 결속된 필수 자동검사를 모두 통과해야 자동출고할 수 있다.

## 1. 입력과 서비스 경계

- 신규 분석 입력은 `회사명`과 선택적인 `주소 힌트`뿐이다.
- 지원 직무, 채용공고, 공고 이미지·OCR, 지원자 경험은 신규 조사 입력으로 받지 않는다.
- 직무별 업무·KPI·필수역량, 자기소개서·지원동기·면접 답안, 일반 준비 질문은 보고서에 만들지 않는다.
- `Report.job`, `requirements`, `guidance_lines`와 채용 결합 데이터는 구형 저장자료를 읽기 위한 호환 필드일 수 있으나 신규 보고서의 내용이나 화면을 구성할 수 없다.
- 회사 사실을 바탕으로 지원동기와 면접 답안을 구성하는 일은 독자가 직접 한다.

## 2. 고정 출력 구조

신규 보고서는 다음 순서를 한 번씩만 사용한다.

`핵심 요약 → 1 기업 정체성 → 2 사업 구조와 수익 모델 → 3 핵심 제품·서비스와 포트폴리오 역할 → 4 3개년 주요 변화와 실행 #과거 → 5 당면 과제와 대응 #현재 → 6 성장 전략 #미래 → 7 사업 운영과 파트너 구조 → 8 인재상과 일하는 방식 → 9 동종업계 비교 결과(출시 모드 필수 / 연습 모드 조건부) → 부록 출처와 검증 상태`

- 출시 모드(`REPORT_RELEASE_MODE=FULL`)에서는 1~9장이 모두 기본 보고서의 필수 장이다. 9장을 조건부로 두는 것은 연습 모드(`REPORT_RELEASE_MODE=SHADOW`)뿐이다. 핵심 요약은 검증된 필수 장에서 결정론적으로 고른 뒤 전체 객체가 최종 게이트를 통과한 경우에만 첫 장에 표시한다.
- 10장은 없다. 9장 뒤에는 번호 없는 `부록. 출처와 검증 상태`만 둔다.
- 구형 키 `4-1`, `4-2`, `4-3`, `참고`, `附`, `활용`은 신규 출력 섹션으로 사용할 수 없다.
- 근거가 부족한 선택 하위 사실은 일반론으로 채우지 않는다. 출시 모드에서는 필수 1~9장이나 장별 최소 내용 계약이 하나라도 부족하면 빈 장·구형 출력으로 대체하지 않고 보고서 전체를 `GATE_STOPPED`로 끝낸다. 9장도 예외가 아니어서, 근거가 얇으면 한 번만 보충하고 그래도 미달이면 9장을 뺀 보고서를 내는 대신 전체를 멈추며 이용 건수도 차감하지 않는다. 9장을 뺀 `Grade.PARTIAL` 기본 보고서는 연습 모드에서만 만든다.
- 공개 웹·PDF·Notion·Markdown은 같은 자동출고 레코드에 결속된 정본을 표현만 바꿔 렌더링한다. 출력 채널별로 질문·조언·추가 사실을 덧붙이지 않는다. 연습 모드의 9장 생략은 허용된 v4 정본 상태이며, 그 밖의 자동검사 하나라도 실패하면 관리자 미리보기를 포함해 결과를 공개하지 않고 전체를 `GATE_STOPPED`한다.
- 사용자 다운로드 정본은 PDF다. 구형 DOCX 다운로드는 활성 출력 계약에 포함하지 않는다.

내부 저장과 장 결합에는 아래 `section_id`만 이 순서로 사용한다. 부록과 핵심 요약은
`FactRecord.section_owner`가 아니며 숫자 장 번호도 내부 ID로 저장하지 않는다.

`identity → business_model → portfolio → past_changes → current_challenges → future_strategy → operations_partners → culture → competitive_position`

## 3. 구조화된 사실 원장

작성 전에 모든 후보 사실을 원장에 저장한다. 최소 필드는 다음과 같다.

| 필드 | 의미 |
|---|---|
| `fact_id` | 회사·대상·지표/사건·시점·값/상태를 정규화한 고유 ID |
| `claim` | 원문 범위를 넘지 않는 하나의 사실 주장 |
| `claim_type` | 장별 의미 역할을 나타내는 닫힌 영문 열거값 |
| `legal_entity` | 사실이 속한 정확한 법인 |
| `subject_scope` | 브랜드·제품·지역·관계의 원문 적용 범위 |
| `source_id` | 원문 출처 식별자 |
| `location` | 주장을 직접 뒷받침하는 원문 페이지·표·문단 |
| `as_of` | 기준일 또는 기간 |
| `time_state` | `completed`, `current_issue`, `current_response`, `future_plan`, `standing` 중 하나 |
| `section_owner` | 사실을 본문에서 한 번만 표시할 소유 섹션 |
| `fact_status` | `actual`, `provisional`, `planned`, `estimated`, `scope_undisclosed` |
| `verification_status` | `verified`, `partial`, `insufficient` |
| `state_evidence` | 수집 단계에서 원문 해시 등록부에 잠근 직접 근거 조각 |
| `source_date` | 원문 발행·공시·확인일. 사실 기준시점과 분리 |
| `evidence_support_terms` | 주장과 직접 근거 양쪽에 실제로 나타나는 핵심 근거어 |
| `evidence_binding` | 주장·근거·출처·위치·시점·구조 필드의 SHA-256 결속 |
| `raw_value` | 원문 원수치와 원단위. 공개 표시용 값으로 덮어쓰지 않음 |
| `calculation` | 단위 변환·비율 등 재현 가능한 산식 |
| `display_value` | 최종 공개 표시값 |
| `rounding_rule` | `ROUND_HALF_UP` 또는 수치가 아닐 때 `해당 없음` |
| `numeric_checks` | `원수치|나눗수|표시 자릿수|표시값`; `ROUND_HALF_UP` 결정론적 검산 |
| `fiscal_year` | 4장 완료 사업연도 실적의 실제 회계연도 |
| `event_date` | 4장 완료 실행이 실제 일어난 연도 또는 날짜 |
| `product_role`, `priority_signals` | 3장 대상의 사업 역할과 서로 다른 실제 우선 신호 |
| `basis_fact_ids` | 4장 변화 해석을 뒷받침하는 완료 실행·실적 사실 ID |
| `response_to_fact_id` | 5장 실제 대응이 직접 연결되는 미해결 문제 사실 ID |
| `limitations` | 잠정치·재분류·비공개·비교 한계 |
| `supports_causality`, `causal_subject`, `causal_mechanism`, `causal_outcome`, `causal_evidence` | 직접 인과를 쓸 때 필요한 허용 플래그와 주체·기제·결과·원문 근거 |
| `comparison_target`, `comparison_metric`, `comparison_definition`, `comparison_basis`, `comparison_period`, `comparison_scope` | 9장의 비교사·지표·정의/근거·기간·고객/제품/시장/회계 범위. `comparison_basis`는 v1 검증 사실 역참조 또는 v2 독립 공식 후보 원문 결속 |
| `comparator_source_id`, `comparator_state_evidence`, `comparator_evidence_support_terms` | 9장의 별도 비교사 공식 원문과 직접 근거 결속 |

- 일반 `FactRecord.state_evidence` 계약은 공백 정규화+casefold한 직접 근거 조각의 SHA-256을 `Source.evidence_hashes`에서 찾는 기존 방식 그대로다. 이 해시가 목록에 없으면 해당 사실은 출처에 결속되지 않은 것이다.
- 수집 경계는 `Source`의 원문 URL·host·문서 ID·발행 주체·날짜·원문 해시·공식 도메인 증명을 서버 비밀키의 `provenance_seal`에 함께 결속한다. 보고서 조립·역직렬화·출고 검증 단계에서 입력값을 다시 seal해 주어서는 안 된다. seal이 없거나 한 필드라도 바뀌면 공식 원문으로 인정하지 않고 `GATE_STOPPED`한다.
- `기타` 종류의 회사 공식 웹·IR·파트너·규제기관 자료는 자기 선언만으로 공식 도메인이 되지 않는다. 같은 법인의 별도 DART·KIND 공식 공시 원문에 해당 host의 정확한 URL이 있고, 그 공시 Source 자체의 `provenance_seal`까지 유효할 때만 허용한다.
- 9장 후보용 회사 공식 웹·HTML IR은 더 좁은 계약을 쓴다. DART 기업개황의 `corp_code·corp_name·hm_url`을 봉인한 attester와 정확한 host가 맞고, 처음부터 끝까지 HTTPS이며 cross-host redirect가 없어야 한다. HTTP fallback·인증서 이름 대체 host·인증서 검증 실패 조각은 후보로 허용하지 않는다.
- 위 `attestation_only` Source는 공개 사업 사실이나 비교 수치가 아닌 내부 provenance dependency다. 직접 `FactRecord`가 없어도 의존하는 공식 웹·HTML IR Source와 함께 내부 Report JSON·저장·감사 등록부에 보존하고 `used_in`을 전파한다. 공개 웹·PDF·Notion·Markdown 출처 부록에는 절대 포함하지 않고 실제 후보 원문 citation만 공개한다.
- 공식 HTML 현재성은 `Report.as_of_date`를 기준으로 검증한다. `corporate/about/product` 같은 안정 페이지는 명시 문서일이 없을 때 봉인된 최신 `collected_at`을 사용할 수 있다. host·path·query의 `news/newsroom/press/media/notice/release/archive/blog`, 연도 또는 `article/post/board/bbs/view` 문서 segment, `id/idx/seq/no/article/post/board/bbs/view` query key에는 봉인된 machine-readable `published_at/disclosed_at`이 필수다. `search/results/find` host·path와 `q/s/query/keyword/keywords/search/term` query key는 검색 결과이므로 날짜와 무관하게 제외한다. 기준 날짜가 잘못됐거나 미래이거나 보고서 기준일보다 400일을 초과해도 후보와 canonical 직접 사실에서 제외한다.
- 공식 IR PDF 수집은 정확한 같은 HTTPS host와 robots.txt를 요구한다. HTML 탐색 5쪽·링크 60개·PDF 최대 2개, 파일당 12 MiB·80쪽·추출 12,000자·160조각, 사이트 전체 PDF 20 MiB·보존 12,000자 상한을 적용한다. MIME `application/pdf`, `%PDF-` magic, 비암호화 문서를 확인하고, `pypdf 6.16.1`을 별도 프로세스에서 wall 10초·CPU 8초·256 MiB 프로세스 메모리 hard limit(단순 RSS 측정값이 아니라 POSIX `RLIMIT_AS` 주소공간 또는 Windows Job Object process/job memory)·압축 해제 스트림 12 MiB·동시 워커 1로 실행한다. 앞 2쪽에서 대상 법인명·별칭을 확인하며 OCR 없이 추출 가능한 글자가 없거나 production에서 OS 자원 상한 설정이 실패하면 거부한다. 페이지·문단 위치와 PDF 내용 SHA-256 문서 ID는 보존하지만 현재 PDF 수집 경로는 신뢰 가능한 문서 발행일·보고기간을 provenance에 결속하지 않으므로 raw preflight·비교사 후보·1~8장 canonical 선택 및 직접 사실에서 제외한다. 수집일은 문서 사실 기준일이 아니다. 향후 신뢰 가능한 `published_at/disclosed_at`을 결속하더라도 `Report.as_of_date`와의 차이가 0~400일인 경우에만 현재성 검사를 통과한다.
- 실제 배포는 32바이트 이상의 고정 `PROVENANCE_SEAL_SECRET`을 비밀 저장소에서 모든 worker에 동일하게 제공한다. 값이 없으면 프로세스 임시키를 사용하므로 재시작 뒤 기존 보고서는 안전하게 출고 차단된다.
- 3장 후보의 `subject_label`은 원문에 실제로 적힌 정확한 제품·서비스명이어야 하며 최종 사실의 대상 범위로 그대로 이어져야 한다.
- `fact_id`가 같은 사실은 본문 전체에서 한 번만 표현한다.
- 한 문장·표 행·도식 노드에는 같은 대상·시점·상태의 사실만 둔다.
- `verified`가 아니면 확정 문장으로 쓰지 않는다.
- 외부 분석의 해석은 회사의 공식 판단처럼 표시하지 않는다.
- 현재 단일-source 원장은 외부 보조근거의 역할을 별도로 표현하지 못하므로 모든 공개 `FactRecord`의 `Source.is_canonical_official`이 참이어야 한다. canonical 런타임은 공개 사실이나 교차검증에 실제 쓰이지 않는 뉴스 검색·AI 선별을 실행하지 않으며, 뉴스·증권사·외부 분석은 메타데이터가 완전해도 공개 `FactRecord`·출처로 승격하지 않는다. `newspick` 기능 파일은 기존 호출 호환용으로만 남긴다.

`Source.is_canonical_official`은 공백과 대소문자를 정규화한 뒤 아래
`SourceKind`·`source_type` 조합만 허용한다.

| `SourceKind` 값 | 허용 `source_type` |
|---|---|
| `공시` | `공식 공시`, `공식 재무 API`, `공식 공시·재무 API`, `공식 계획`, `규제기관 공식 자료`, `공식 규제기관 자료`, `비교사 공식 공시`, `비교사 공식 재무 API` |
| `기타` | `회사 공식 IR`, `공식 IR`, `회사 공식 웹`, `공식 웹`, `회사 공식 자료`, `공식 파트너 자료`, `파트너 공식 자료`, `규제기관 공식 자료`, `공식 규제기관 자료` |
| `뉴스` | 없음. canonical 런타임 입력에서 제외 |

장별 허용 `claim_type`은 다음과 같다.

| 장 | 허용값 |
|---|---|
| `identity` | `official_identity`, `operating_scope` |
| `business_model` | `revenue_model`, `customer_market`, `revenue_mix` |
| `portfolio` | `priority_product` |
| `past_changes` | `completed_execution`, `change_interpretation`, `historical_performance` |
| `current_challenges` | `current_issue`, `current_response` |
| `future_strategy` | `future_plan` |
| `operations_partners` | `operating_core`, `partner_role` |
| `culture` | `official_value`, `work_example` |
| `competitive_position` | `competitive_comparison`, `comparison_limitation` |

- 2장은 `revenue_model`과 `customer_market`을 모두 가져야 하며 각 고객·시장 사실의 `market_priority`가 비어 있으면 안 된다.
- 3장은 서로 다른 정확한 대상을 가진 `priority_product` 1~3개만 가져야 한다. 각 대상은 비어 있지 않은 `product_role`과 원문에서 각각 확인된 서로 다른 실제 `priority_signals` 2개 이상을 가져야 한다.
- 직접 인과 표현이 있거나 `supports_causality=true`이면 네 `causal_*` 필드가 모두 필요하고 `causal_evidence`가 결속된 `state_evidence` 안에 실제로 있어야 한다. 이 계약을 완곡한 표현으로 우회할 수 없다.

공식 자료 판정은 `source_type`에 `공식`이라는 글자가 있는지만 보지 않는다. 런타임의
닫힌 허용 목록과 `SourceKind` 조합이 맞아야 하며 `NEWS`는 항상 보조자료다.

장별 허용 `time_state`와 공개 가능한 `fact_status` 조합은 다음과 같다.

| 장 | `time_state` | 허용 `fact_status` |
|---|---|---|
| `identity`, `business_model`, `portfolio`, `operations_partners`, `culture`, `competitive_position` | `standing` | `actual`, `scope_undisclosed` |
| `past_changes` | `completed` | `actual`, `provisional` |
| `current_challenges` | `current_issue`, `current_response` | `actual`, `provisional` |
| `future_strategy` | `future_plan` | `planned` |

`estimated`는 닫힌 `fact_status` 열거값이지만 현재 공개 시간 상태와 결합할 수 없으므로
내부 조사·교차검증에만 남긴다. 공개 사실은 위 조합을 만족하면서
`verification_status=verified`여야 한다.

## 4. 시간 상태와 섹션 라우팅

| 상태 | 소유 섹션 | 출고 조건 |
|---|---|---|
| 최근 3년 내 완료된 실행과 확인된 결과 | 4장 `#과거` | 실행 시점과 결과 근거가 모두 있음 |
| 아직 해결되지 않은 문제 | 5장 `#현재` | 문제가 현재도 남았다는 최신 근거가 있음 |
| 현재 진행 중인 대응 | 5장 `#현재` | 회사가 실제로 착수했다는 근거가 있음 |
| 발표됐지만 아직 결과가 없는 계획 | 6장 `#미래` | 공식 계획·목표·예정 표현과 기준일이 있음 |
| 지속 중인 운영 기반·계약 관계 | 7장 | 관계 당사자·역할·유효 시점이 확인됨 |

- 계획을 완료 사실로, 오래된 사건을 현재 대응으로, 잠정치를 확정치로 바꾸면 출고를 중단한다.
- `가능하다`, `이어질 수 있다`, `영향을 준다` 같은 완곡 표현도 직접 인과 근거를 대신할 수 없다.
- 4장은 회사의 실제 결산월에 따른 비교 가능한 완료 `fiscal_year` 3개와, 기준일 이전 36개월의 `completed_execution`·`event_date`를 모두 가져야 한다. 모든 회사를 달력연도 12월 31일 결산으로 고정하지 않는다.
- 4장의 `change_interpretation`은 같은 장의 완료 실행·완료 실적 `basis_fact_ids`에 결속돼야 한다.
- 5장의 모든 `current_issue`에는 실제 `current_response`가 있어야 하고, 대응의 `response_to_fact_id`가 그 문제를 직접 가리켜야 한다.
- 4장의 공개 3개년 실적표는 행을 완료 사업연도, 열을 지표로 구성하고 표 위에 `단위: 억원`을 한 번만 표시한다. 셀에는 억원 표시값만 두며 원 단위 원값은 `FactRecord.raw_value`와 `numeric_checks`에만 보존한다.

## 5. 경쟁사 비교 계약

- 차별점마다 비교 대상과 선정 이유, 동일 비교축, 같은 고객·제품/서비스·시장·기간·정의·회계/사업 범위, 양사 근거, 확인된 차이, 비교 한계를 저장한다.
- 비교사 후보 선정 근거는 자사가 발행한 DART 공시, DART 기업개황 attestation을 통과한 자사 공식 HTML IR·공식 웹만 허용한다. 안정 회사 페이지는 봉인 수집일, 보도·공지·archive·blog·문서형 URL은 봉인 machine-readable 문서일을 사용하며 `Report.as_of_date` 기준 0~400일만 허용한다. 검색 결과는 날짜와 무관하게 허용하지 않는다. 공식 IR PDF는 현재 문서일 결속이 없어 후보 선정 근거와 직접 사실이 아니다.
- `comparison_basis` v1은 실제 1~8장 `verified` FactRecord의 한 문장을 ID와 정규화 SHA-256으로 역참조하는 저장 JSON/HMAC 형식의 읽기 호환 계약이다. 재출고 시 현재의 엄격한 경쟁 관계 문법을 다시 적용하므로 과거 v1도 실패할 수 있다. v2는 1~8장 의미 분류와 독립된 자사 공식 Source의 정확한 한 문장, Source identity·위치·날짜·두 해시·seal·self corp_code·attester를 닫힌 JSON으로 결속한다.
- v2 `evidence_sha256`은 공백 정규화+casefold한 문장의 UTF-8 SHA-256이고, `evidence_exact_sha256`은 문장 추출 뒤 `strip`된 저장 문장 문자열 그대로의 UTF-8 SHA-256이다. exact 해시는 원 HTTP 응답이나 PDF 파일 바이트 해시가 아니다. 두 값은 각각 `Source.evidence_hashes`와 `Source.exact_evidence_hashes`에 있어야 하며 두 목록 모두 `provenance_seal`의 HMAC payload에 결속한다. 이 이중 해시는 v2 후보 문장 전용이며 일반 `FactRecord.state_evidence` 계약을 바꾸지 않는다.
- v2는 단순한 같은 문장+표지 검사가 아니다. 후보 법인명이 자사 발행 주체(self-subject)의 현재형 명시적 경쟁 술어가 요구하는 실제 target/list slot에 있고, 문장이 수집한 한 원문 블록의 연속 부분일 때만 허용한다. `시장점유율`은 v2 경쟁 표지에서 제외한다. 과거·`former/potential/possible`, 부정·제외, 인용·제3자 귀속, 협력·지원, 고객·공급사·파트너 경쟁, 모호한 별칭과 `or/또는` 선택지는 거부한다. 오탐 방지를 우선하는 닫힌 문법이므로 false-negative를 허용한다. 순수 경쟁 문장을 1~8장 `customer_market` 등으로 위장하지 않으며, 그 문장은 v2 후보 원장 외의 공개 사업 사실로 승격하지 않는다.
- 원문이 경쟁 관계만 직접 명시하면 `경쟁 관계 명시`까지만 저장한다. 고객·제품/서비스·시장 겹침을 추정하지 않고, 공개 비교 행에는 양사의 별도 공식 원문으로 공통 범위를 증명한다.
- 실제 재무 비교값은 양사 DART의 같은 완료 사업연도, 같은 계정·재무제표 종류·연결/별도 범위·기간·통화 자료만 사용한다. 공식 HTML IR·웹은 후보와 공통 범위 근거가 될 수 있지만 재무 수치 원장을 대신하지 않는다. 문서일을 결속하지 못한 공식 IR PDF는 후보 근거가 아니다.
- 자사와 비교사 중 한쪽 공식 근거라도 없거나 고객·제품/서비스·시장·정의·기간·회계 범위가 다르면 공개 비교 행이나 순위·우위 문장을 만들지 않는다.
- 구조 차이만 확인되면 `운영 특성`으로 쓰고, 결과 우위까지 같은 조건으로 확인될 때만 `경쟁우위`로 쓴다.
- 기술력·브랜드·네트워크 같은 일반명사와 원문이 직접 뒷받침하지 않는 인과·수익성·고마진 표현은 금지한다.
- 검증 가능한 항목이 3개보다 적으면 개수를 억지로 맞추지 않는다.
- 유효 비교축은 단순한 매출·자산 규모 반복이 아니라 같은 기간·정의·연결/별도 범위에서 재현되는 영업이익률 등 사업 해석에 유효한 지표여야 한다. 규모 차이를 여러 계정으로 쪼개 차별점 수를 채우거나 규모 자체를 우위로 승격하지 않는다.
- 후보 수집의 실제 `state`는 `failed·none·ok`뿐이다. 허용 범위를 끝까지 확인한 정상 완전 탐색의 `none`만 `후보 없음`으로 판정한다. 접속·TLS·MIME·파서·카탈로그 실패는 `failed`, 페이지·문서·바이트·글자 상한 잘림은 별도 `truncated` state가 아니라 `candidate_scope_complete=False`와 상세 사유로 표현한다. 범위가 불완전한 `failed` 또는 `ok`는 `unknown`이며 음성 증거로 사용하지 않는다.
- 양사 공식자료의 동일 고객·제품/서비스·시장·기간·정의·회계/사업 범위 비교가 하나도 성립하지 않으면 비교 행·우위 문장·빈 장을 만들지 않는다. 출시 모드는 이때 한 번만 보충하고, 그래도 미달이면 보고서를 내지 않고 이용 건수도 차감하지 않는다. 연습 모드에서만 검증된 1~8장을 `Grade.PARTIAL`로 출고하고 정해진 `COMPARISON_SHORTFALL_REASON`만 표시한다. 이는 경쟁우위가 없다는 판정이 아니다.

## 6. 출고 게이트

실제 조립 순서는 `1~8장 내부 초안 → 9장 결합 → 검증된 본문에서
핵심 요약 결정론 선택 → 최종 build_published_report 게이트 1회`다. 출시 모드는 9장까지
갖춰야 이 순서를 통과하고, 9장 없이 끝나는 것은 연습 모드뿐이다. 내부 초안과 9장
결합 직후 객체는 저장·캐시·공개 렌더링할 수 없다. 다음 검사를 포함한 최종 게이트를
모두 통과해야 PDF를 생성·제공할 수 있다.

### 생성·검수 호출 경계

- 사실 선택 AI 전에 선택 가능한 공식 공시·IR·홈페이지 후보와 연속 3개 완료 회계연도 실적표를 검사한다. 둘 중 하나라도 없으면 선택 AI를 한 번도 호출하지 않고 중단한다.
- 입력이 갖춰지면 사실 선택 AI는 최대 2회다. 1차 결과가 필수 1~8장의 `claim_type`·내부 SID 링크를 한 회차 안에서 완결하고 진단에 파싱·출력 상한 이상이 없으면 즉시 확정해 2차를 호출하지 않는다.
- 1차가 불완전하거나 이상일 때만 2차를 호출한다. 2차 단독 결과가 완결되면 2차를 채택하고, 두 불완전 결과를 합쳐 새로운 완결 결과로 만들지 않는다. 두 번 모두 불완전하면 중단하며 세 번째 호출과 3회 다수결은 금지한다.
- Writer에는 채택 회차 전체가 아니라 장별 출력 상한 안에서 필요한 `claim_type`과 모든 내부 SID 참조가 함께 포함된 완결 부분집합만 전달한다. 상한 밖에 있는 참조 대상을 누락한 채 완결로 판정하지 않는다.
- 작가 AI는 한 문장에 원문 근거 하나만 연결한다. 문장이 원문과 앞뒤 공백 제외 완전일치할 때만 프로그램이 확정해 Reviewer 호출을 생략한다. 공백 정규화·부분 일치·의미 유사성은 이 예외가 아니다. 나머지 새 문장은 별도 대화·별도 지시문의 Reviewer가 원문과 대조하며 Reviewer를 통과하지 못한 문장은 공개할 수 없다.
- Reviewer가 정상 boolean `False`로 판정한 문장만 한 배치에서 한 번 재작성할 수 있다. 재작성문이 원문과 앞뒤 공백 제외 완전일치하면 프로그램이 확정하고, 나머지만 첫 Reviewer와 대화를 공유하지 않는 새로운 Reviewer가 다시 검사한다. 판정 누락·중복·형식 파손과 두 번째 실패는 재시도 없이 삭제한다.
- 핵심 요약 전용 AI·Reviewer는 호출하지 않는다. Writer 검수를 통과하고 사실 원장에 결속된 본문 `FactRecord` 문장 중 3~5개를 프로그램이 글자 변경 없이 고른다. 같은 장에서는 숫자 없는 문장을 우선하되 그 장의 검증 문장이 숫자를 포함한 것뿐이면 그 문장을 그대로 허용한다. 각 요약 항목의 상태는 `verified_fact_reuse`이며 새 문장·새 사실·새 인과를 만들지 않는다.

1. **범위 게이트**: 회사 중심 정보인지, 직무·개인 맞춤·투자 조언이 없는지 검사
2. **근거 게이트**: 모든 사실이 허용된 공식 원문과 연결되고 대상·시점·상태가 일치하는지 검사
3. **원자화 게이트**: 한 문장·표 행·도식 노드에 다른 상태의 사실이 섞이지 않았는지 검사
4. **소유권 게이트**: `fact_id` 중복과 같은 수치·사건·파트너 역할의 재서술 검사
5. **시간 게이트**: 4·5·6장의 `#과거·#현재·#미래` 라우팅 검사
6. **동종업계 비교 게이트**: 9장이 있을 때 양사 근거, 비교 가능성, 차이와 한계 표시 검사. 연습 모드에서 비교가 성립하지 않아 9장을 생략한 기본 보고서는 표준 부족 사유와 9장 사실 부재를 검사
7. **편집 게이트**: 회사명만 바꿔도 성립하는 일반론, 제작 메타정보, 독자 행동 지침 검사
8. **장별 의미 게이트**: 출시 모드의 1~9장 필수(9장 조건부는 연습 모드뿐), 3장 제품 계약, 4장 회계연도·실행·해석 결속, 5장 문제–대응 결속 검사
9. **수치 게이트**: 원수치·산식·표시값과 `ROUND_HALF_UP` 재현 검사
10. **요약 게이트**: 요약이 Writer 검수를 통과한 실제 본문 `FactRecord` 문장과 글자 단위로 같고 그 `fact_ids` 부분집합 및 `verified_fact_reuse` 상태에 결정론적으로 결속됐는지 검사
11. **구조 게이트**: 고정 목차·순서, 표지, 핵심 요약, 출처 연결 검사
12. **PDF 렌더·채널·해시 게이트**: 같은 보고서/PDF/전 페이지 PNG 해시에 사실 장부, 전 페이지 렌더, 웹·PDF·Notion 동등성, 검사 버전을 결속하고 검사 후 변경 여부 확인

자동출고 레코드는 `report_sha256`, `pdf_sha256`, 전 페이지 `page_png_sha256s`, 전체
`expected_fact_ids`, 필수 검사 결과와 검사 버전을 함께 가진다. 모든 해시는 소문자
16진수 64자리여야 한다. PDF는 텍스트 추출만 믿지 않고 PDFium glyph 좌표의 중앙 본문
영역을 실제 PNG 픽셀과 대조한다. 헤더·쪽번호만 보이고 본문 glyph가 흰색·미렌더이면
출고를 차단하되, 중앙 제목이 실제로 보이는 성긴 표지는 허용한다.

필수 검사 하나라도 실패하거나 검사 뒤 보고서·PDF·페이지 이미지·사실 장부 해시가
바뀌면 자동출고 레코드를 만들거나 새 해시로 조용히 재승인하지 않고 전체를
`GATE_STOPPED`한다. 웹·PDF·Notion은 이 하나의 자동출고 레코드를 서버에서 확인하므로
채널별 우회 경로가 없다. 과거 `pdf_release_records`, 역할 결정, 참여자 원장은 삭제하지
않고 감사자료로 보존하지만 신규 출고 권한으로 읽지 않는다. `/review/pdf/*` GET/POST는
`410 Gone`이며 기존 링크로 자동출고를 우회할 수 없다.

파일럿 후보 원장은 P01~P25 25건이다. 현재 실제 유료 실행과 사용자 완전검수는
P01~P10에 한정하고, P11~P25는 이번 재시험 결과와 후속 범위 결정에 따라 평가한다.
그 결과는 자동검사 보정용 평가자료일 뿐 런타임 출고 입력이 아니며, 실제 서비스의
보고서별 사람 승인·대기 시간을 만들지 않는다.

## 7. 캐시와 구형 자료

- 캐시는 `product:company-analysis`와 `schema:company-report-v4-canonical`이 모두 맞고, 복원된 `Report.schema_version`도 `company-report-v4-canonical`일 때만 재사용한다.
- 캐시된 보고서의 공식 웹 현재성은 저장 당시 기준일로 고정하지 않고 조회 당일(`today`)을 기준으로 다시 검사한다. 안정 페이지의 봉인 수집일 또는 문서형 페이지의 봉인 문서일이 미래·무효이거나 조회일보다 400일을 초과하면 전체 캐시 항목을 miss로 처리하고 새로 조사한다.
- `schema:company-report-v3-canonical` 이하 자료는 신규 보고서 캐시 적중으로 인정하지 않는다.
- 구형 데모·저장 보고서는 마이그레이션하거나 새로 생성한다. 구형 섹션을 화면에서 새 목차처럼 이름만 바꾸는 방식은 허용하지 않는다.
- 캐시에서 읽은 보고서도 현재 출고 게이트를 다시 통과해야 한다.

## 8. 완료 판정

문서, 프롬프트, 코드, 데모 데이터, 캐시, 웹, PDF와 자동화 시험이 이 계약에 맞을 때만 “항상 이 원칙에 따라 출력한다”고 말할 수 있다. 한 경로라도 구형 구조를 출력하거나 게이트를 우회하면 전환은 미완료다.

구현 상태를 설명할 때는 `출고 계약`, `현재 코드로 확인된 구현`, `아직 시험하거나
구현하지 못한 제한`을 구분한다. 계약 문서에 적혀 있다는 이유만으로 실행 경로가
완료됐다고 보고하지 않는다.

## 9. 원가와 고객 청구

- `cost_krw`와 단계별 비용 이벤트는 성공·실패와 무관하게 실제 provider 사용으로 생긴 내부 AI 변동원가다. `GATE_STOPPED`나 생성 실패를 0원으로 덮어쓰지 않는다.
- 고객 청구액은 완성 보고서가 위 자동출고 레코드에 결속된 뒤에만 별도 결정한다. 생성 실패·검사 중단·출고 실패의 고객 청구액은 0원이다.
- 공개 판매가는 아직 확정하지 않았으므로 코드와 공개 UI에 후보 가격을 청구액으로 넣지 않는다.
- 서버비는 월 고정 운영비로 별도 기록하며 보고서 AI 변동원가에 합산하지 않는다.
- 평균 300원/P90 500원은 측정 KPI이지 요청별 강제 중단 한도가 아니다. 품질 게이트·출시 모드 필수 1~9장·공식 근거·Writer 독립검수를 낮춰 맞추지 않는다. 대신 중복 전체 선택 호출과 요약 전용 AI 호출을 제거해 비용을 줄인다.
