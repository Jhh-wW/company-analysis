# 자료 수집과 근거 공통 규칙

## 1. 조사 목적과 서비스 범위

이 보고서는 기업이 취업준비생에게 자사에 관해 반드시 알리고 싶어 할 사업 정보를 설명한다. 투자 추천서, 복지 정보집, 직무별 취업 코칭 문서를 만들지 않는다.

### 포함 범위

- 기업 정체성, 고객·수익 구조, 핵심 제품·서비스
- 최근 3년의 실행과 변화, 현재 과제, 공식 미래 전략
- 운영·파트너 구조, 공식 인재상과 전사 공통 문화
- 같은 조건에서 검증되는 경쟁 차이

### 서비스 범위 밖

- 직무별 업무·KPI·필요 역량·조직별 세부 프로세스
- 공고별 맞춤 지원전략, 자기소개서·면접 답변, 개인화 여부와 관계없는 일반 준비 질문·행동 지침 작성
- 개인별 합격 가능성 판단
- 평균급여·근속연수·복지 목록 등 회사 사업 이해와 직접 연결되지 않는 구직 정보
- 주가 목표·밸류에이션·매수·매도 의견

서비스 범위 밖의 내용을 억지로 추가하면 회사·직무·시점별 변수가 크게 늘어 근거 밀도와 일관성이 낮아진다. 해당 정보가 원문에 있더라도 본문 자동 포함 대상으로 삼지 않는다.

## 2. 자료 우선순위

같은 주장에 여러 자료가 있으면 아래 순서를 따른다.

| 순위 | 자료 | 주 용도 | 주의사항 |
|---|---|---|---|
| 1 | 법정 공시·감사보고서·연차보고서 | 사업 범위, 재무, 위험, 조직, 계약 | 표준 문구와 자발적 강조를 구분 |
| 2 | 회사 공식 IR·실적발표·CEO 전략 발표 | 최신 성과 원인, 전략, 계획, 제품 우선순위 | 잠정치·조정치·계획을 실제와 구분 |
| 3 | 공식 회사·제품·채용·파트너 페이지 | 정체성, 제품, 문화, 현재 관계 | 게시·확인일과 현재 유효성 확인 |
| 4 | 정부·규제기관 공식 원문 | 시장·허가·점유·동일 기준 비교 | 정의·기간·표본 범위와 런타임 허용 `source_type` 확인 |
| 5 | 신뢰할 수 있는 외부 기업분석 | 비활성 참고 범위 | 현재 canonical 런타임에서 검색·입력하지 않음 |
| 6 | 주요 언론의 원문 인터뷰·보도 | 비활성 참고 범위 | 현재 canonical 런타임에서 검색·AI 선별하지 않음 |

커뮤니티·블로그·요약형 재가공 글·출처 없는 검색 결과·생성형 답변은 사실 근거로 사용하지 않는다.

### 9장 후보 원문의 추가 경계

- 비교사 후보 선정에는 자사가 발행한 DART 공시와 DART 기업개황의 정확한 홈페이지 host에 결속된 자사 공식 HTML IR·공식 웹만 쓴다. 공식 IR PDF는 안전하게 제한 수집·인용할 수 있지만 신뢰 가능한 문서 발행일 또는 보고기간을 결속하기 전에는 후보 근거로 승격하지 않는다. 수집일을 문서의 발행일·사실 기준일로 대신 쓰지 않는다. 실제 재무 수치 비교는 양사의 DART 완료 사업연도 원문으로만 수행한다.
- 후보용 공식 웹·HTML IR은 정확한 같은 host의 HTTPS만 허용한다. HTTP fallback, 인증서 이름 대체 host, 인증서 검증 실패, cross-host redirect 조각은 후보 근거가 아니다.
- `corporate/about/product` 같은 안정 페이지는 명시 문서일이 없으면 봉인된 최신 수집일을 허용한다. host·path·query에 `news/newsroom/press/media/notice/release/archive/blog` 또는 문서형 경로·키가 있으면 봉인된 machine-readable 문서일이 필수다. `search/results/find` 경로와 `q/s/query/keyword(s)/search/term` key의 검색 결과는 문서일이 있어도 제외한다. 날짜가 무효·미래이거나 `Report.as_of_date` 기준 400일을 초과해도 후보와 canonical 직접 사실에서 제외한다.
- 공식 IR PDF는 DART 홈페이지 host에서 robots.txt를 지키며 제한 수집한다. HTML 탐색 5쪽·링크 60개·PDF 최대 2개, 파일당 12 MiB·80쪽·추출 12,000자·160조각, 사이트 전체 PDF 20 MiB·보존 12,000자 상한을 적용한다. MIME `application/pdf`, `%PDF-` magic, 비암호화 문서를 확인하고 `pypdf 6.16.1`을 별도 프로세스에서 wall 10초·CPU 8초·메모리/주소공간 256 MiB(POSIX `RLIMIT_AS`, Windows Job Object)·압축 해제 스트림 12 MiB·동시 워커 1로 실행한다. 앞 2쪽에서 법인명·별칭을 확인하며 OCR 없이 추출 가능한 글자가 없거나 production에서 OS 자원 상한 설정이 실패하면 거부한다. 현재 수집 경로에는 문서일 결속이 없으므로 raw preflight·9장 후보·1~8장 canonical 선택과 직접 사실에서 제외한다.
- 캐시 복원 때는 공식 웹 날짜를 조회 당일 기준으로 다시 검사한다. 안정 페이지의 봉인 수집일 또는 문서형 페이지의 봉인 문서일이 400일을 초과한 오래된 보고서는 cache miss로 처리한다.
- v2 후보 법인명은 자사 발행 주체(self-subject)의 현재형 명시적 경쟁 술어가 요구하는 실제 target/list slot, 수집한 한 원문 블록의 정확한 한 문장, 봉인 Source에 함께 있어야 한다. `시장점유율`은 v2 경쟁 표지가 아니다. 과거·`former/potential`, 부정·제외, 인용·제3자 귀속, 협력·지원, 고객·공급사·파트너 경쟁, 모호한 별칭과 `or/또는`는 거부한다. 같은 문장에 법인명과 표지가 있다는 조건만으로는 부족하며, 엄격한 문법으로 인한 false-negative를 허용한다. 순수 경쟁 문장은 1~8장 `claim_type`으로 분류하지 않는다.
- DART 기업개황의 `corp_code·corp_name·hm_url`을 봉인한 `attestation_only` Source는 후보 웹·HTML IR의 공식성을 증명하는 내부 provenance dependency다. 직접 공개 사업 사실이 없어도 내부 Report JSON·저장·감사 등록부에서 의존 Source와 함께 보존한다. 공개 웹·PDF·Notion·Markdown에는 후보 원문 citation만 내보내고 attester는 절대 표시하지 않는다.

## 3. 기준일과 조사 기간

- 보고서 전체 기준일을 먼저 확정한다.
- 실적은 기준일 현재 공개된 최신 공식 실제 또는 잠정 실적을 사용한다.
- `#과거`의 재무는 회사 결산월에 따른 최근 완료 사업연도 3개, 완료 실행 사건은 기준일 이전 36개월만 다룬다. 모든 회사를 12월 31일 결산으로 가정하지 않는다.
- `#현재`는 기준일 현재 해결되지 않았고 대응 중인 과제만 다룬다.
- `#미래`는 기준일 이후의 공식 계획·목표·예정만 다룬다.
- 오래된 자료를 쓸 때는 현재도 유효한지 최신 자료로 확인한다.
- 모든 행의 기준일이 같으면 장 또는 표 위에 한 번만 표시하고 행마다 반복하지 않는다.

## 4. 조사 절차

1. `회사명·법인 범위·연결/별도·보고서 기준일`을 확정한다.
2. 자료 등록부를 만든다: `문서명 | 저자·애널리스트 | 실제 발행처 | 호스팅 기관 | 발행·확인일 | URL/파일 | 원문 위치 | 사용 장 | 자료 상태 | Source.evidence_hashes | Source.exact_evidence_hashes | provenance_seal`. 일반 사실은 정규화 `evidence_hashes`만 쓰고, `exact_evidence_hashes`는 v2 후보 문장이 실제로 있을 때만 쓴다. 발행처는 원문 표지·머리글·판권으로 확정한다. `provenance_seal`은 수집기가 원문 identity와 두 해시 등록부를 확정한 뒤 서버 비밀키로 한 번만 만들며, 보고서 조립·저장 복원·검증 단계에서는 새로 만들지 않는다.
3. 1~8장의 핵심 `FactRecord`는 자사 공시·IR·회사 공식 웹·공식 파트너·규제기관 원문만으로 만든다.
4. 원문에서 쓸 문장·표·페이지를 주장 단위로 기록한다.
5. 현재 canonical 런타임은 결과에 실제 쓰이지 않는 외부 뉴스 검색·AI 선별을 생략하고 공식 공시·IR·회사 공식 홈페이지 근거만 다음 단계에 전달한다.
6. 9장 후보는 v1 검증 사실 역참조 또는 v2 독립 공식 후보 원문으로 잠근다. 후보 관계만 명시됐으면 고객·제품/서비스·시장 공통 범위는 양사의 별도 공식 원문으로 증명하고, 실제 수치는 양사 DART의 같은 완료 사업연도 자료를 추가 수집한다.
7. 모든 주장에 `대상·지표/사건·기간·값·fact_status·verification_status·출처 페이지·evidence_binding`을 붙인다.
8. `fact_status(actual/provisional/planned/estimated/scope_undisclosed)`와 `verification_status(verified/partial/insufficient)`를 분리하고, 실제·잠정·계획·외부 전망·분석 해석을 섞지 않는다.
9. 서로 충돌하는 자료는 범위·회계기준·발행 시점·정정 여부를 확인해 최신 정본을 선택한다.
10. 선택 하위 사실은 근거가 부족하면 제외 또는 한계로 처리한다. 필수 1~8장 계약이 하나라도 부족하면 보고서 전체를 `GATE_STOPPED`로 끝낸다. 9장 비교만 성립하지 않으면 표준 부족 사유를 가진 `Grade.PARTIAL` 기본 보고서로 전환한다.

모든 주장·표 셀·도식 노드는 [사실 원자화와 추론 통제](./사실_원자화와_추론_통제.md)를 통과해야 한다.

## 5. 주장별 근거 기준

### 바로 사용할 수 있는 주장

- 회사 공식 원문에서 대상·기간·내용이 명확히 확인됨
- 계산값은 공식 원수치와 계산식을 모두 재현할 수 있음
- 사실의 `state_evidence` 해시가 연결한 `Source.evidence_hashes`에 포함됨
- 9장의 수치는 자사·비교사 각각의 DART 완료 사업연도 원문에 결속되고 고객·제품/서비스·시장·기간·정의·회계 범위·표본·발행처가 확인됨
- 비교 주장은 양쪽 자료가 같은 축·기간·범위를 사용함

### 9장 후보 원장 v1·v2

- v1은 저장 JSON/HMAC 형식을 읽기 위한 호환 경로다. 실제 1~8장에 포함된 `verified` FactRecord의 한 문장을 `fact_id·source_id·DART corp_code·document_id·정규화 SHA-256`으로 역참조한다. 재출고할 때 현재의 엄격한 경쟁 관계 문법으로 다시 검증하므로 과거 v1도 `GATE_STOPPED`될 수 있다.
- v2는 1~8장 의미 분류와 독립된 후보 원장이다. 자사 공식 Source의 정확한 한 문장과 Source 종류·발행 주체·HTTPS host/URL·문서 ID·위치·날짜·두 해시·seal, 자사 DART 고유번호·attester를 닫힌 값으로 결속한다. `evidence_sha256`은 공백 정규화+casefold 문자열의 UTF-8 해시, `evidence_exact_sha256`은 문장 추출 뒤 `strip`된 저장 문장 문자열 그대로의 UTF-8 해시다. exact는 원 HTTP/PDF 바이트 해시가 아니다. 두 값은 각각 `Source.evidence_hashes`와 `Source.exact_evidence_hashes`에 저장되고 두 목록 모두 HMAC seal에 결속한다. 일반 `FactRecord.state_evidence` 계약은 그대로 유지한다.
- 원문이 경쟁 관계만 명시하면 `경쟁 관계 명시`까지만 기록한다. 고객·제품·시장 겹침을 문장에 없는 내용으로 채우지 않고 공개 비교 전 양사의 별도 공식 원문으로 공통 범위를 확인한다.
- v2의 한 문장은 비교사 후보 선정 증거이며 그 자체가 공개 1~8장 사업 사실이나 양사 비교 결과는 아니다.

### 조건을 붙여 사용할 주장

- 잠정 실적: `잠정`을 해당 주장 옆에 한 번 표시
- 회사 계획: `계획·목표·예정`으로 쓰고 완료형으로 바꾸지 않음
- 외부 추정: 내부 교차검증 메모에만 보존하며 공개 핵심 `FactRecord`로 승격하지 않음
- 회계 재분류·일회성 손익: 해석이 달라지는 주장 옆에 한계를 표시
- 조사자 계산: 원수치·기간·단위·산식을 내부 기록에 보존

### 사용할 수 없는 주장

- 출처가 `업계에 따르면` 등으로만 표시됨
- 회사 공식 자료와 충돌하지만 차이를 설명할 수 없음
- 고객사·계약·원가·이익을 공개 자료 없이 추정함
- 시장 순위의 정의·기간·표본이 없음
- 한 회사의 표현을 다른 회사에도 그대로 적용한 일반론

### 대상 범위와 상태 보존

- 원문의 특정 자회사·제품·모델·지역을 상위 회사·제품군·시장 전체로 넓혀 쓰지 않는다.
- 한 주장에는 하나의 법인·대상·행동 또는 관계·기간·상태만 둔다.
- 같은 제품군이나 자회사라도 상태가 다르면 별도 주장으로 나눈다.
- `개발 중·개발 완료·고객 검증·MOU·본계약·납품·매출 발생·반복 매출`을 서로 바꿔 쓰지 않는다.
- 설비 구축은 가동이 아니며, 자회사 편입이나 사업 목적 등재는 실제 운영을 뜻하지 않는다.

### 해석과 인과

- 조사 메모는 `원문 사실·조사자 계산·출처 해석·분석 추론` 중 하나로 분류한다. 이는 런타임 `claim_type` 열거값과 다른 방법론 분류다.
- `개선·기여·영향·흡수·전환·경쟁력을 만든다` 같은 인과 동사는 원문이 그 인과를 직접 설명할 때만 쓴다. 전후 수치가 재현 가능하다는 이유만으로 인과를 허용하지 않는다.
- `고수익·높은 수익성·상대적 우위` 같은 정량 판정은 같은 정의·기간·범위의 재현 가능한 수치가 있을 때만 쓴다.
- 직접 인과 근거가 없으면 동시 발생 사실만 쓰거나 `확인 변수·효과 미확인`으로 낮춘다.
- `가능하다·이어질 수 있다` 같은 완곡 표현도 근거 없는 인과를 허용하지 않는다.

### 수치 표시와 반올림

- 원수치·원단위·산식·계산 전 정밀값·표시값과 `numeric_checks`를 내부 주장 장부에 보존한다.
- 중간 계산에서는 반올림하지 않고 최종 표시 단계에서만 반올림한다.
- 소수점 표시는 10진수 `ROUND_HALF_UP`을 사용한다. 예: `6.25% → 6.3%`.
- 원문 값을 그대로 옮긴 것과 원수치로 다시 계산한 값을 구분한다.
- `numeric_checks`는 `원수치|나눗수|표시 자릿수|표시값` 형식으로 모든 표시 숫자를 빠짐없이 재현한다.
- 공개 실적표는 `단위: 억원`을 한 번 표시하고 억원 표시값만 쓴다. `821,850,000,000원 (8,219억)`처럼 원 단위와 억원 값을 함께 노출하지 않는다. 원 단위 값은 내부 `raw_value`와 `numeric_checks`에만 보존한다.

## 6. 공식 자료와 외부 자료의 역할 분담

- 공식 자료: 회사가 스스로 설명하는 정체성·사업·제품·파트너·문화와 실제 수치의 기준점
- 외부 자료: 실적 원인·위험·경쟁 해석의 과장 여부를 확인하는 내부 보완재. 현재 런타임은 복수 근거 역할을 공개 `FactRecord`에 표현하지 않으므로 공개 출처·핵심 사실로 내보내지 않는다.
- 회사의 홍보 표현은 공식이라는 이유만으로 분석 결론이 되지 않는다.
- 외부 분석의 전망은 실제 성과가 아니며 회사 공식 계획으로 바꾸지 않는다.
- 공식 자료와 외부 자료가 다르면 어느 쪽이 맞는지 단정하기 전에 정의·기간·연결 범위를 먼저 확인한다.

## 7. 출처 연결 방식

- 본문 사실 문장 끝에는 짧은 출처 번호를 연결한다.
- 부록에는 `번호 | 문서명·발행처 | 발행·확인일 | 원문 위치 | 본문 사용 | 자료·사실 상태`를 기록한다.
- PDF는 페이지·표명, 웹은 페이지 제목·섹션명과 확인일을 부록에 기록한다. 동일 위치는 내부 주장 장부에도 보존한다.
- 같은 출처가 여러 주장을 지지해도 부록 항목은 한 번만 만들고 본문 번호를 재사용한다.
- 출처 번호가 있다고 해서 근거가 충분한 것은 아니다. 주장과 원문이 직접 연결되는지 검토한다.
- 주장 `state_evidence`의 SHA-256이 해당 `Source.evidence_hashes`에 없으면 출처 번호를 삭제하고 사실을 다시 수집한다.

## 8. 완성 보고서에 넣지 않는 메타정보

- `50개 보고서를 조사했다`, `AI가 작성했다`, `교차 검증했다` 같은 제작 과정
- 조사 단계, 에이전트 역할, 검토 순서, 검색 실패 내역
- 독자에게 불필요한 내부 신뢰도 점수와 코딩 기준
- `정리했다·담았다·살펴본다` 같은 작성자 중심 표현

방법론은 내부 기준 문서에만 둔다. 완성 보고서 본문에는 회사 사실·해석·필요한 한계만 출력한다.

## 9. 실패 시 처리

- 공식 자료가 없으면 외부 추정으로 빈칸을 채우지 않는다.
- 최신 자료가 없으면 확인 가능한 마지막 기준일을 분명히 하고 현재 사실처럼 표현하지 않는다.
- 원문 링크가 끊겼으면 공시·회사 저장본·규제기관 원문을 찾아 동일성을 확인한다.
- 수치가 충돌하면 출력 전에 정정 공시와 회계 범위를 확인한다. 해결되지 않으면 해당 수치를 제외한다.
- 항목 자체가 해당 업종에 의미 없으면 업종별 대체 축을 사용하거나 제외한다.
- 후보 수집의 실제 `state`는 `failed·none·ok`뿐이다. 허용 범위를 끝까지 읽은 정상 완전 수집의 `none`만 `후보 없음`으로 판정한다. 접속·TLS·MIME·파서·카탈로그 실패는 `failed`, 페이지·문서·바이트·글자 상한 잘림은 별도 `truncated` state가 아니라 `candidate_scope_complete=False`와 상세 사유로 기록한다. 범위가 불완전한 `failed` 또는 `ok`는 `unknown`으로 남긴다.
- 9장의 양사 공식자료 동일 고객·제품/서비스·시장·기간·정의·회계/사업 범위 비교가 성립하지 않으면 근거 부족 장을 공개하지 않고, 검증된 1~8장을 표준 부족 사유와 함께 `Grade.PARTIAL`로 출고한다.

## 짧은 범용 예시

> 회사 공식 연차보고서에서 사업 범위와 고객을 확인하고, 최신 IR에서 현재 제품 우선순위와 실행 결과를 확인한다. 외부 분석은 원인 해석이 공식 수치와 맞는지 내부에서 점검할 때만 사용하며 공개 사실이나 출처로 내보내지 않는다.
