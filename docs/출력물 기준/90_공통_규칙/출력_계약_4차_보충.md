# 4차 출력 계약 보충

- 기준일: 2026-09-23
- 적용 범위: 이번 수정 코드가 새로 만드는 v2 보고서와 공개 표시 자료
- 상위 계약: [런타임 출고 계약](런타임_출고_계약.md)

이 문서는 이번 변경으로 달라진 출력·관측·저장 호환 경계만 보충한다. 기존 FULL 필수 장, 품질 하한, 근거 부족에 따른 부분보고서 경로와 출고 판정을 새로 정의하지 않는다. 구현 계약의 기록이며 실제 회사의 유료 실측 통과나 배포 완료를 뜻하지 않는다.

## 공개 전 사실 결속 선택과 부족 안내

본문 검수 뒤 요약·최종 봉인 전에 공개 산문과 실제 `FactRecord`의 결속을 정본에서 확인한다. 장 소유권·문장·근거 결속이 맞는 문장만 남기며, 결속되지 않은 문장과 중복 문장의 제외 사유를 진단에 보존한다. 보도 표시 접두사와 정해진 문체 정규화를 고려하되, 단어가 일부 겹친다는 이유로 다른 주체·대상·조건·시점의 사실을 같은 것으로 승인하지 않는다. 해석 표지도 근거 결속을 대신하지 않는다.

이 선택으로 해당 장의 본문 문장이 모두 제외되면 정본 부족 안내를 남기고 기존 최종 조정·품질 판정을 적용한다. 화면에서만 문장을 지워 요약·저장 정본과 어긋나게 만들거나, 새 사실을 넣어 빈 장을 채우지 않는다. FULL의 결속 실패·내용 부족을 부분보고서 안내로 바꿔 통과시키는 규칙은 아니다.

## 검증된 본문을 재사용하는 요약

신규 v2의 엄격 경로와 부분보고서 경로 모두 공개 전 사실 선택을 마친 본문 `FactRecord`를 요약 후보로 사용한다. 후보 문장을 글자 변경 없이 고르고 `verified_fact_reuse`로 결속한다. 제외된 초안, 근거 없는 해석, 본문에 없는 사실을 요약에 남기지 않는다. 요약 전용 AI·Reviewer 호출 수는 0이며 기존 최소 개수와 최종 게이트는 유지한다. 상세 형식은 [핵심 요약 기준](../00_핵심_요약/README.md)을 따른다.

## 선택 9장도 관측하는 품질 자료

품질 관측의 기존 필수 1~8장 집계와 별도로, 실제 존재하는 9장 `competitive_position`은 버전이 있는 `optional_sections` 확장에 문장 관측과 평가를 남긴다. 선택 장이라는 이유로 공개 안전 검사에서 빠지지 않으며, 일반 회계정책이나 근거 없는 우위 문장을 차별점으로 채택하지 않는다. 9장이 없는 구형 관측 자료에 검사를 수행한 것처럼 새 통과 결과를 채워 넣지 않는다.

여기서 `optional`은 품질 관측 자료의 확장 구분이다. FULL에서 9장이 필수라는 기존 의미 계약을 선택 사항으로 낮추거나 필수 1~8장 하한 계산을 바꾸지 않는다. 저장·재조회 때 해당 관측 버전과 무결성을 함께 검증한다.

## 장 간 중복 삭제의 증명 경계

장 간 중복 삭제, 5↔6장 시제 소유 쌍, 장 안 재배치는 같은 삭제 증명을 쓴다. 삭제는 소유 장 문장 전체와 후보 문장 전체가 어절 그대로 대응하거나, 후보가 같은 명시 주어로 시작하는 절들로 나뉘고 각 절이 서로 다른 소유 문장 전체와 대응할 때만 일어난다. 마지막 어미의 좁은 연결·종결형 차이와 인용 밖의 천 단위 쉼표·문장 끝 부호만 같다고 본다. 인용부호·괄호 안 글자, 대소문자, 음수 부호, 원문자는 그대로 비교한다. 앞 절만 같은 경우, 생략 주어, 의역, 소유 문장에 뒤 절이 더 있는 경우는 의미 같음을 증명할 수 없으므로 지우지 않는다.

여러 소유 문장으로 증명한 삭제는 그 문장들이 모두 살아 있어야 이동 안내를 쓴다. 이 경계 때문에 반복이 더 남을 수 있으며 품질 하한은 바꾸지 않는다.

## 새 표시 제목과 선택 표시 필드

신규 4장의 표시 제목은 `주요 변화와 실적`이다. 내부 ID `past_changes`와 [4장 기준 문서](../04_3개년_주요_변화와_실행/README.md)의 기존 폴더명은 유지한다. 제목 변경으로 사건의 시간 상태나 실제 근거의 비교 기간을 바꾸지 않는다.

공개 표시 정본 `PublicReportProjection`에는 다음 선택 필드가 추가된다.

| 필드 | 의미와 결속 경계 |
|---|---|
| `citation_groups` | 같은 문서 신원·정규 URL·전체 내용 SHA-256·발표일을 가진 뉴스 출처를 묶어 표시한다. 기존 인용 번호를 모두 정확히 한 번 포함하며 번호·표시 이름·URL·검증 상태·위치·사용 위치를 봉인한다. `Source`·`FactRecord` 원장과 인용 번호를 다시 쓰지 않는다. |
| `reader_notes` | 부분 완성·미완성 상태와 실제 `Source.failed`가 확인된 자료 범위를 안내한다. 자료 수집 실패를 회사가 정보를 제공하지 않았다는 사실로 바꾸지 않으며, SHADOW의 안전 판정만으로 FULL 차단 상태를 추정하지 않는다. |
| `summary_notes` | 요약 항목 번호와 미감사 설명을 연결한다. 구조화된 미감사 연도와 본문이 참조하는 연도·인용 번호가 맞을 때 적용하며, 제목·문장만 보고 미감사 여부를 추정하지 않는다. |

`ReportTable.unaudited_years`도 선택 필드다. 미감사 연도를 구조화해 전달하며, 구형 제목이나 짧은 미감사 문장을 분석해 이 필드를 추정 복원하지 않는다.

## 구형 저장자료와 봉인 보존

위 표시 선택 필드와 `unaudited_years`는 빈 값이면 정본 직렬화에서 생략한다. 필드가 없는 구형 자료는 빈 값으로 읽고 다시 저장할 때도 생략하므로, 필드를 추가했다는 이유만으로 기존 FULL 지문을 바꾸지 않는다.

이미 봉인된 공개 표시 정본이 있는 구형 FULL 보고서는 저장된 정본을 그대로 사용한다. 조회 때 새 출처 묶음·안내를 다시 계산해 끼워 넣거나 기존 제목·claim·짧은 미감사 본문을 재작성하지 않는다. 이 호환 규칙은 구형 자료에 새 품질 검사를 통과한 상태를 부여하거나 기존 봉인 검증을 생략하는 허용이 아니다.

## 장별 작성 입력 격리

부분보고서 경로의 작성기에는 해당 장의 허용 근거만 입력한다. 다른 장 소유 조각이 프롬프트에 포함되면 다른 장의 사실을 자기 장 안에서 인용하는 오귀속이 발생할 수 있다. 동시상한 3 병렬 작성은 유지한다. 부분보고서의 장별 묶음 작성에는 장마다 같은 전체 근거 공유 앞부분이 없으므로 공유 캐시 표시를 붙이지 않는다. 전체 근거 공유 앞부분은 모든 장이 같은 조각 전체를 보는 legacy flat 모드에만 남는다.

검수·복구 단계는 전체 근거·구조화 표·허용 ID/slot 계약을 그대로 사용한다. 작성 입력만 장별로 격리하고 검수·복구 입력을 줄이지 않는다. 입력 문자 감소를 비용·시간 절감 실측으로 쓰지 않는다. 캐시 공유 접두어 손실을 포함한 실제 순효과는 새 유료 검증 전까지 미측정이다.

## 도식 표시 경계

검수 행(원행)의 원래 칸 수와 인용·receipt 결속은 보존한다. 표시 단계는 공백뿐인 칸에 새 「미확인」 글자를 합성하지 않고, 행 끝의 공백 칸을 표시에서만 뺀다. 칸이 비게 된 이유는 추정하거나 분류하지 않는다. 원행에 실제로 적힌 「미확인」·대시 같은 글자는 공백으로 보지 않고 그대로 표시한다.

흐름 표시는 다음 순서로 정한다. 화살표로 이을 수 없는 머리말 조합으로 이미 정해진 표는 기존대로 카드다. 그 밖의 표는 모든 행에서 끝 공백 칸을 뺀 연속 앞 칸의 길이가 같고, 내부 공백이 없고, 2칸 이상이면 흐름으로 표시한다. 정상 3칸·4칸 행은 그 칸 수 그대로 유지된다. 내부·앞쪽 공백 칸이 있거나, 행마다 표시 길이가 다르거나, 1칸만 남으면 칸을 새로 잇지 않고 원래 머리말 라벨을 붙인 카드로 표시한다. 5장 과제·대응 후보는 이 흐름 규칙보다 먼저 `relation_pairs` 조건을 보고, 조건을 채우지 못하면 카드가 아니라 원표로 남는다.

기존 봉인된 공개 표시 정본(`PublicReportProjection`)의 도식 행을 재해석하거나 변경하지 않는다. Notion 원표가 4칸이라는 한계는 그대로 적용된다.

## 뉴스 4장 보조 슬롯과 주장 단위 보존

4장에 뉴스 보조 슬롯을 허용한다. 공식 구조화 실적 슬롯에는 뉴스를 진입시키지 않는다. 중복 판단은 기사·사건 전체가 아니라 주장 범위로 한다. 같은 수치 두 개가 겹친다는 이유로 서로 다른 사실(제품·지역·추가 맥락)을 사전 삭제하지 않는다.

수집 단계는 같은 날의 확정 동일 사실과 순수 부분 인용만 하나로 정리한다. 발행일이 다른 같은 문장·같은 본문은 주장별 기간 결속을 증명할 수 없으므로 지우지 않고 선택 순서만 뒤로 미룬다. 그래서 날짜별 같은 문장이 반복될 수 있다. 수집 충분성은 기존 판정과 실제 최종 선택 결과를 모두 만족해야 하며, 보존한 재보도를 새 사건으로 세어 수집을 일찍 멈추지 않는다.

기사 제목만 입력에 있고 본문 근거가 없으면 계획 문장을 완료로 바꾸거나 삭제하지 않는다. 검증된 완료 본문이 확보된 별도 양성 사례에만 대체 규칙을 적용한다.

## 선택 후보 슬롯과 필수 커버리지 분리

공식 선택 슬롯은 필수 커버리지 하한·공식 수치 주입 권한과 별개의 경로다. 선택 슬롯 개수를 늘려도 필수 커버리지나 총 예산을 같이 늘리지 않는다. 현재 선택 후보 슬롯은 1장 `identity:official_location`(본점 소재지) 하나이며, 조회 기록·필수 칸 충족·장 준비 판정에 쓰지 않는다. 사업정의(`identity:business_definition`)와 수익 구성(`business_model:revenue_model`)은 선택 슬롯이 아니라 기존 필수 수집 칸이며, 공식 원문의 표준 문형을 그 칸으로 채점하도록 수집 키워드를 보강해 회복한다. 두 경로 모두 typed 정확 슬롯 검사는 유지한다. 같은 장이면 모든 가족 슬롯을 통과시키는 완화는 원문이 지원하지 않는 의미까지 허용하므로 채택하지 않는다.

선택 후보에서 탈락한 사실이 고득점 반복 근거에 밀린 결과인지 확인한다. 필수 대표 → 선택 사실 다양성 → 나머지 동등 보존 순서를 지킨다.

## 수익인식 조건 보존과 제한 재작성

작성 지침과 별도로, 수익원·인식 기준(완료·진행)을 단정하는 주장이 자기 인용 조각에 같은 인식 술어를 갖지 않으면 실제 검수·근거 결속 단계의 기계 가드가 차단한다. 검수 모델의 «참» 판정이나 추가 근거 응답으로 이 차단을 풀지 않는다. 인용 조각의 진행기준 원칙과 한정 특례처럼 원문에 있는 조건은 보존한다. 실제 수익원과 직접 연결된 장(2장 사업 구조)의 설명에서 조건을 빼고 일반화하지 않는다.

수익원 이름을 주어로 둔 절은 다른 수익원을 적은 원문 절의 기준을 빌리지 못한다. 완료·진행 기준을 단정한 후보는 검수 응답이 같은 수익원·기준·기간 한정을 담은 원문 정확 인용(`인식기준`)을 내야 승인된다. 2장 본문에서 자기 인용이 그 수익원을 수익 구성으로 나열하고 같은 인식 절에 조건이 그대로 있으면 회계정책 상용구로 지우지 않는다. 다른 장과 순수 회계 상용구는 종전대로 막는다.

설립 결정이나 사건 사실에 원문에 없는 목적 해석을 붙인 문장은 확인·해석 등급과 무관하게 거절하고, 라벨만 「해석」으로 낮추는 우회 대신 제한 재작성과 재검수로 사실 절을 회복한다. 명시 목적 원문이 있으면 정상 보존한다.

검수 응답 스키마는 안내문이 요구하는 결합 근거의 `범위`·`관계` 칸을 받는다. 칸을 받았다고 승인되지 않으며 원문 결속은 가드가 대조한다. 결합 가드는 아직 운영에서 관측만 하고 막지 않는다. 공급자가 바뀐 스키마 문법을 받아들이는지는 유료 호출 전까지 확인하지 않았다.

## 종속기업 제외 조건과 현재 관계 단정

같은 공시 문서의 관계법인 회계범위 각주가 표의 한 법인 행을 명시적 당기 기준으로 종속기업에서 제외하면, 그 법인을 현재 종속기업·연결 대상으로 단정한 문장은 검수 «참»이어도 기존 사유 `scope_condition_unbound`로 거절하고 제한 재작성 대상으로 보낸다. 문장이 각주를 인용하지 않았어도 같은 문서 신원의 등록 각주는 제약으로만 따로 대조한다. 그 각주를 긍정 근거·인용·영수증에 추가하지 않는다.

다른 문서·다른 법인·전기만 가리키는 표·기간 불명·재편입 사건이 있는 경우와 문서 해시·기간 값이 서로 어긋나는 문서는 제약으로 쓰지 않는다. 정상 거래, 정확한 제외 설명, 과거 관계 서술은 보존한다. 판정 문법은 주체·술어 결속이 확실한 꼴만 보도록 일부러 좁다. 그래서 관계절이 끼는 복잡한 문장은 판단을 보류해 막지 못할 수 있으며, 이 경우는 의미 검수에 맡긴다. 추가 AI 호출은 없다.
