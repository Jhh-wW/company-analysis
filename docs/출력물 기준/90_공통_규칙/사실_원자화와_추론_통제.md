# 사실 원자화와 추론 통제

## 목적

짧고 읽기 쉬운 문장으로 압축하는 과정에서 대상 범위·진행 상태·인과관계가 바뀌는 일을 막는다. 이 규칙은 업종과 장을 가리지 않고 모든 본문 문장·표 셀·도식 노드·차트 라벨에 적용한다.

## 1. 한 주장에는 하나의 상태만 둔다

하나의 주장 단위는 다음 여섯 요소를 모두 가진다.

`법인·대상 | 구체 제품·활동·관계 | 기간·시점 | 확인된 상태 | 값 | 직접 근거`

- 한 문장에는 하나의 법인·대상·행동 또는 관계·기간·상태만 둔다.
- 여러 대상을 묶으려면 대상들의 상태·기간·근거가 모두 같아야 한다.
- 하나라도 다르면 문장·표 행·도식 노드를 분리한다.
- 원문이 특정 자회사·제품·모델·지역을 말하면 그 범위를 상위 회사·제품군·시장 전체로 넓히지 않는다.
- 요약 과정에서도 원문의 공식 제품명과 상태를 보존한다.
- 발생 상태 `fact_status(actual/provisional/planned/estimated/scope_undisclosed)`와 원문 대조 결과 `verification_status(verified/partial/insufficient)`를 분리한다. 공식 자료의 계획은 `planned`이지 `actual`이 아니며, 공개 본문에는 `verified`만 쓴다.

### 상태는 서로 바꿔 쓰지 않는다

`개발 중 → 개발 완료 → 고객 검증 → MOU → 본계약 → 납품 → 매출 발생 → 반복 매출`

- 뒤 단계가 공식적으로 확인되지 않으면 앞 단계까지만 쓴다.
- 개발 완료는 양산·납품·매출 발생을 뜻하지 않는다.
- 설비 발주·구축은 가동을 뜻하지 않는다.
- MOU는 본계약을 뜻하지 않는다.
- 사업 목적 등재나 자회사 편입은 실제 운영을 뜻하지 않는다.
- `생산·운영·판매 중`은 기준일 현재 생산·가동·납품·매출 중 직접 실행 근거가 있을 때만 쓴다.

## 2. 주장 유형을 먼저 고정한다

모든 주장에는 내부적으로 다음 중 하나를 지정한다.

- `원문 사실`: 공식 원문이 직접 말하는 내용
- `조사자 계산`: 공식 원수치로 재현 가능한 계산
- `출처 해석`: 회사 또는 외부 분석기관이 밝힌 원인·전망. 외부 분석기관의 해석은 내부 교차검증 메모에만 둔다.
- `분석 추론`: 보고서 작성자가 앞 사실을 종합한 해석

작가와 레이아웃 작성자는 주장 유형을 바꾸지 않는다. 외부 분석의 전망을 원문 사실이나 회사 공식 계획으로 바꾸지 않는다.

## 3. 인과·수익성 표현 하드 게이트

인과 동사와 정량 판정은 서로 다른 근거를 요구한다.

`개선한다 | 기여한다 | 영향을 준다 | 좌우한다 | 흡수한다 | 전환한다 | 고수익이다 | 경쟁력을 만든다`

- `개선한다·기여한다·영향을 준다·좌우한다·흡수한다·전환한다·경쟁력을 만든다` 같은 인과 동사는 원문이 그 인과를 직접 설명할 때만 허용한다. 전후 수치만으로는 허용하지 않는다.
- `고수익·높은 수익성·상대적 우위` 같은 정량 판정은 같은 정의·기간·범위의 재현 가능한 수치가 있을 때만 허용한다.
- 원문이 원인이라고 직접 설명하면 주체를 붙인다. 예: `회사는 원가 절감을 이익 개선 요인으로 설명했다.`
- 외부 분석의 해석이면 내부 교차검증 메모에 발행처와 해석 상태를 붙이되 공개 `FactRecord`·출처로 승격하지 않는다.
- 단지 두 현상이 같이 나타났다면 `동행했다`라고만 쓴다.
- 인과 근거가 없으면 `확인 변수`, `효과 미확인`, `공개되지 않음`으로 낮추거나 삭제한다.
- `가능하다`, `영향이 있다`, `이어질 수 있다` 같은 완곡 표현도 근거 없는 인과를 허용하지 않는다.

## 4. 수치와 반올림

내부 주장 장부에 다음을 보존한다.

`원수치 | 원단위 | 산식 | 계산 전 정밀값 | 표시 단위 | 표시값 | numeric_checks | 반올림 규칙`

- 중간 계산에서는 반올림하지 않는다.
- 최종 표시 단계에서만 `ROUND_HALF_UP`을 사용한다.
- 이진 부동소수점의 기본 반올림에 의존하지 않는다. 구현은 10진수형을 사용한다.
- 예: 공식 표시값 `6.25%`를 소수 첫째 자리로 줄이면 `6.3%`다.
- 반올림된 구성비 합계가 99.9%나 100.1%가 되어도 특정 항목을 임의 조정하지 않는다.
- 원문 값을 그대로 옮겼는지, 원수치로 다시 계산했는지 내부 장부에 구분한다.
- `numeric_checks`는 `원수치|나눗수|표시 자릿수|표시값`으로 저장하며 모든 표시 숫자를 빠짐없이 재현해야 한다.
- 공개 3개년 실적표는 행을 완료 사업연도, 열을 지표로 구성한다. 표 위에는 `단위: 억원`을 한 번만 쓰고 셀에는 억원 표시값만 둔다. 원 단위 원값은 내부 `raw_value`와 `numeric_checks`에만 보존하며 공개 셀에 중복 표시하지 않는다.

## 5. 도표·흐름도의 상태 보존

- 각 노드는 하나의 법인·제품·활동·현재 상태만 나타낸다.
- 가동 중 법인과 구축·준비 중 법인을 같은 상자에 넣지 않는다.
- 서로 다른 공정은 고객 가치가 비슷해도 한 화살표로 합치지 않는다.
- 화살표는 공식적으로 확인된 물리적·계약적·수익적 흐름만 표시한다.
- 계획 노드는 `계획·예정·구축 중`을 노드 안에 직접 적는다.
- 도표를 문장으로 바꿔 읽었을 때 상태가 달라 보이면 출고하지 않는다.

## 6. 시장 단계와 포트폴리오 라벨

- 매출이 발생했다는 사실만으로 `성장시장`이라고 부르지 않는다.
- `성장`은 두 시점 이상의 확대 신호 또는 공식 투자·인력·제품·채널 확대가 함께 확인될 때만 쓴다.
- `진입`은 시험·첫 출시·MOU·초도 납품처럼 초기 실행이 확인될 때 쓴다.
- 분석 라벨은 회사 공식 분류와 구분하고, 근거가 약하면 관찰된 사실만 적는다.
- 제품별 단가·마진이 비공개면 `고부가·고마진·단가 확대`라고 쓰지 않는다.

## 7. 경쟁 비교

- 비교 행마다 자사 근거·비교사 근거·같은 고객·제품/서비스·시장·기간·정의·회계/사업 범위를 모두 확보한다.
- 비교사에 동일 지표가 없으면 자사의 운영 특성만 설명하고 `차이·우위·차별점`이라고 부르지 않는다.
- `비교 근거 부족` 행은 핵심 요약이나 종합 판단에서 경쟁력으로 다시 승격하지 않는다.
- 운영 방식의 차이는 성과 결과가 없으면 `운영 특성`으로만 표시한다.
- 9장은 조건부이므로 양사 공식자료의 동일 고객·제품/서비스·시장·기간·정의·회계/사업 범위 비교가 하나도 성립하지 않으면 근거 부족 행·빈 장을 공개하지 않는다. 검증된 1~8장은 표준 부족 사유를 가진 `Grade.PARTIAL` 기본 보고서로 출고한다.

## 8. 출처 신원

각 자료는 다음 필드를 따로 관리한다.

`공식 문서명 | 저자·애널리스트 | 실제 발행처 | 호스팅 기관 | 발행일 | 문서 식별자 | 원문 위치 | evidence_hashes`

- 발행처는 URL 도메인·다운로드 사이트·파일명이 아니라 원문 표지·머리글·판권으로 확정한다.
- KIND·DART·거래소·포털이 문서를 호스팅해도 발행처와 동일하다고 보지 않는다.
- 출처표는 잠긴 자료 등록부에서 생성하며 발행처를 수작업으로 다시 입력하지 않는다.
- 문화·제품 기능처럼 웹 세부 페이지의 문장이 근거라면 해당 세부 페이지를 직접 연결한다.
- 사실의 `state_evidence` SHA-256이 연결한 `Source.evidence_hashes`에 실제로 포함돼야 한다. 출처 ID만 맞고 원문 조각이 등록되지 않은 사실은 탈락한다.

## 9. 독립 전수 검수

최종 PDF를 만든 뒤 조사·작성에 참여하지 않은 검토자가 다음을 수행한다.

1. PDF 전체 텍스트를 추출한다.
2. 모든 사실 문장을 잠긴 주장 장부의 `fact_id`와 1:1로 대조한다.
3. 각 문장의 `주체·대상·시점·상태·출처` 다섯 항목을 확인한다.
4. 모든 차트 라벨·표 셀·도식 노드도 같은 방식으로 검사한다.
5. 출처표의 모든 행을 원문 표지와 대조한다.
6. 실패한 문장 수와 `fact_id`를 기록한다.

핵심 문장 표본검사나 `전반적으로 이상 없음`이라는 평가는 승인으로 인정하지 않는다. 실패가 한 건이라도 있으면 수정 후 전수 검수를 다시 실행한다.
