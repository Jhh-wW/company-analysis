# 빈 의미 칸 근거 재판정

- 상위 문서: [자료 수집과 근거](./자료_수집과_근거.md)
- 적용 범위: 1~9장 공통. 조사 절차 안의 삽입 지점은 한 곳뿐이다.
- 실행 조건: 스위치 `EVIDENCE_RECLASSIFY`가 정확히 `1`일 때만 동작한다. 꺼져 있으면 결과는 지금과 같다.

결정론 채점만으로는 이미 수집한 원문 안에 있는 근거를 장별 필수 의미 칸에 연결하지
못하는 경우가 있다. 이 규칙은 그 빈 칸에 한해 이미 수집·봉인된 원문 문단을 다시
배정하는 절차를 정한다. 새 자료를 찾지 않고 채점 어휘 목록도 늘리지 않는다.

## 1. 실행 조건

- 결정론 채점(키워드로 문단을 장·의미 칸에 배정하는 문지기)이 끝난 뒤, 근거 사전검사가 장별 판정을 확정하기 전에 검사한다.
- 필수 의미 칸이 비어 `READY`가 되지 못한 장이 하나라도 있을 때만 실행한다. 모든 장이 `READY`면 실행하지 않는다.
- 아홉 장을 각각 따로 부르지 않는다. 빈 장을 묶어 한 번에 처리하며 삽입 지점은 하나다.
- 출시 모드(`REPORT_RELEASE_MODE=FULL`)와 연습 모드(`REPORT_RELEASE_MODE=SHADOW`)에서 같은 조건으로 동작한다.
- 통과한 결과는 기존 근거 조각과 같은 모양으로 후보 묶음에 더해질 뿐이다. 이후의 근거 사전검사·사실 선택·작가·출고 게이트 계약은 바뀌지 않는다.

## 2. 입력

- 빈 장 목록과 각 장의 목적 문장, 그 장의 필수 의미 칸(장별 닫힌 `claim_type` 자리)의 한국어 이름.
- 후보 문단: 어느 장에도 배정되지 않은 문단과 낮은 점수로 다른 장에 배정된 문단. 「II. 사업의 내용」·「회사의 개요」와 주석의 영업부문·수익 구분 구간을 먼저 넣는다.
- 문단마다 문단 id와 원문을 함께 넣고 후보 문단 전체에 길이 상한을 둔다. 상한값은 구현 시 확정한다(설계 초안 60,000자).
- 이미 수집·봉인된 원문만 사용한다. 뉴스·검색 결과·외부 분석을 새로 수집하지 않는다.

## 3. 지시 내용

재판정은 두 가지를 함께 요구한다.

- **넣기**: 빈 의미 칸의 목적에 맞는 문단을 고르고 근거 문장을 문단 원문에서 글자 그대로 인용한다. 출력 항목은 `문단 id · 장 · 의미 칸 · 인용`이다.
- **빼기**: 이미 배정됐지만 그 장의 목적에 맞지 않는 상투문구를 지목한다. 출력 항목은 `문단 id · 장 · 사유`다.

인용은 요약·다듬기·이어붙이기 없이 해당 문단 안의 연속된 한 조각이어야 한다. 문장을
새로 만들거나 떨어진 부분을 합치면 다음 절에서 폐기된다.

## 4. 프로그램 검증

AI 출력을 그대로 채택하지 않는다. 아래를 프로그램이 검사하고 통과한 항목만 남긴다.

| 검사 | 폐기 조건 |
|---|---|
| 인용 위치 | 공백을 정규화한 뒤에도 인용이 그 문단 원문의 연속 부분 문자열이 아님 |
| 닫힌 목록 | 장 이름 또는 의미 칸 이름이 런타임의 닫힌 목록 밖 |
| 문단당 상한 | 한 문단에 배정된 의미 칸이 3개를 넘음 |
| 시간 상태 | 계획·전망 어휘가 든 인용을 `future_strategy` 외의 칸에 배정 |

- 통과한 항목만 기존 근거 조각과 같은 구조로 바꾼다. 원문 조각 해시는 기존 규칙 그대로 만들어 해당 `Source.evidence_hashes`에 등록하며, `state_evidence` 결속 계약은 변하지 않는다.
- 빼기는 해당 조각의 의미 칸 목록에서 그 장의 칸만 지운다. 조각 자체는 지우지 않는다.
- 빼기 결과로 `READY`였던 장이 `INSUFFICIENT`로 내려가면 그대로 반영한다. 성립 개수를 지키려고 판정을 되돌리지 않는다.
- 인용 검증은 그 문장이 원문에 실제로 있다는 것만 보증하고 의미가 맞는지는 보증하지 않는다. 홍보·계획 문장이 사실 칸에 들어가는 위험은 위 시간 상태 검사와 기존 작가·Reviewer 검수로 함께 막는다.

## 5. 하지 않는 것

- 채점 어휘 목록 확장, 문단을 한 장에 고정하는 규칙 변경
- 작가에게 원문 전문을 넘겨 근거를 스스로 고르게 하는 방식
- 뉴스·검색·외부 분석 등 canonical 런타임이 쓰지 않는 자료의 수집
- 재판정 결과로 새 사실 문장·새 인과·새 수치를 만드는 일

## 6. 호출·캐시·비용

- 한 요청에서 재판정 호출은 정확히 1회다. 결과가 비어도 다시 부르지 않는다.
- 요청당 AI 호출 상한에서 한 칸을 사용하고, 예산 단계에 입력 상한 기준 1회분을 미리 예약한다(설계 초안 150원 이하).
- 캐시 키는 공시 접수번호 묶음·프롬프트 버전·모델이다. 같은 회사의 같은 원문 묶음을 다시 조사하면 추가 비용이 들지 않는다.
- 재판정으로 출시 모드 출고가 늘면 뒤 단계의 비용 구성이 달라질 수 있으므로 실측으로 확인한다.

## 7. 표식과 공개 경계

- 재판정으로 들어온 근거 조각은 `origin="ai_reclassified"` 표식을 갖는다.
- 이 표식은 부록과 관리자 진단에서 다른 조각과 구분하기 위한 값이다. 공개 본문에는 어떤 형태로도 표시하지 않으며 근거를 어떻게 찾았는지 독자에게 설명하지 않는다.
- 부록에서 이 표식을 어떻게 보이게 할지(열 추가·각주·표시하지 않음)는 설계에 정해져 있지 않다. 구현 시 확정하며, 공개 부록에 제작 과정 설명을 넣지 않는다는 [부록 기준](../10_부록_출처와_검증_상태/README.md)과 함께 판단한다.
- 표식이 붙었다고 근거 기준이 낮아지지 않는다. 공식 원문 결속·해시·검증 상태 조건은 다른 조각과 같다.

## 8. 진단 기록

- 총 항목 수와 폐기된 항목 수를 남긴다.
- 폐기 사유별 개수를 인용 불일치·닫힌 목록 밖·문단당 상한 초과·시간 상태 위반으로 나눠 남긴다.
- 빼기로 `INSUFFICIENT`가 된 장이 있으면 그 장과 사유를 남긴다.
- 이 기록은 내부 진단이며 공개 보고서 본문·부록에 넣지 않는다.

## 9. 구현 시 확정할 항목

- 후보 문단 전체 길이 상한의 최종값
- 부록에서의 `origin="ai_reclassified"` 표기 방식과 공개 여부
- 진단 기록의 저장 위치와 필드 이름
