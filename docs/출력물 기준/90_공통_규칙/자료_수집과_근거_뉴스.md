# 뉴스 조사와 본문 근거

DART 공시는 보고서의 중심 자료다. 뉴스는 빈칸을 조금 메우는 데 그치지 않고,
공시 이후의 사업 변화·제품·계약·당면 과제·회사 계획을 확인하는 별도의 조사 축이다.
공시가 충분한 기업도 뉴스를 조사한다. 기사 수를 같게 맞추거나 한 건을 의무적으로
끼워 넣지 않는다. 자료가 적으면 확인한 내용만 제공하고 한계를 밝힌다.

## 1. 실행과 현재성

- `NEWS_INTAKE="1"`인 v2 조사에서 공식 근거의 READY 여부·공식 웹 문서 수와 무관하게 실행한다. OFF이면 뉴스 호출을 하지 않으며, 미조사를 자료 없음으로 표현하지 않는다.
- 검색 결과를 생성 캐시 조회 전에 고정한다. 질의·응답·실패 상태·정책 버전의 digest와 보고서 기준일을 생성 입력에 결속한다. 공시가 같아도 뉴스나 기준일이 바뀌면 과거 보고서를 그대로 재사용하지 않는다.
- 유료 본문 분석은 중복 생성 조정에서 작업 소유권을 얻은 뒤에 실행한다. 검색 snapshot 밖의 추가 검색을 숨겨서 수행하지 않는다.
- 최근 12개월을 먼저 검토하고, 유용한 사건·주제 근거가 부족하면 24개월, 이후 36개월까지 순차적으로 넓힌다. 오래된 기사를 최신 뉴스처럼 표시하지 않는다.
- 기사 발행일과 실제 사건일·계획 시점을 분리한다. 수정일이나 검색 서비스 등록일을 사건 발생일로 쓰지 않는다.

## 2. 출처와 회사 일치

- 대상 회사에 결속된 공식 발표와 신뢰할 수 있는 언론 보도를 사용한다. 블로그·커뮤니티·투자 추천·익명 소문은 사실 근거로 승격하지 않는다.
- 법인명과 공시에서 확인한 별칭, 사업 관련 질의로 검색한다. 본문 분석에는 공식 회사 개요·제품·대표자 등 확인된 문맥을 함께 준다.
- 제목의 이름 일치만으로 관련성을 확정하지 않는다. 동명이의어, 대학의 여러 캠퍼스, 다른 회사 소속 가수, 관계없는 계열사·업계 일반론을 본문에서 구분한다.
- 신뢰 출처 판단과 회사 관련성 판단은 별개다. 신뢰 매체라도 회사의 실질 사업 사실이 없으면 제외한다. 출처를 확인하지 못한 경우도 진단에 남긴다.
- 같은 URL·동일 본문·보도자료 전재·같은 사건을 중복 집계하지 않는다. 문장 두 개가 독립 기사 두 건은 아니다.

## 3. 본문 읽기와 근거 검증

- 기사 본문을 먼저 읽고 회사 문맥과 함께 분석한다. 제목·요약만 보고 고른 뒤 첫 문장을 복사하는 경로는 사용하지 않는다.
- JSON-LD 기사 본문·article 구역·탐색 구역을 제거한 본문 추출을 사용한다. 메뉴·기사 목록·메타 설명만 있는 응답은 본문으로 인정하지 않는다.
- 근거 문장은 읽은 본문에 실제로 존재하는 정확한 범위여야 한다. 숫자·날짜·대상·계획 상태를 모델이 바꾸면 거절한다. 분석 실패를 옛 첫 문장 추출기로 대체하지 않는다.
- 회사가 발표한 계획과 완료된 사실을 구분한다. 과거의 계획을 현재 이미 완료한 일로 쓰지 않는다.
- robots.txt·SSRF 방어·응답 크기·시간 상한을 유지한다. 실제 본문을 읽은 최종 주소를 출처에 연결하고 접근 제한을 우회하지 않는다.

## 4. 숫자와 공식 자료의 경계

- 보도된 숫자는 원문 검증과 Writer/Reviewer 검사를 거쳐 **출처·발행일과 함께 본문에 사용한다.** 숫자가 있다는 이유로 문장을 버리지 않는다.
- 언론 보도는 `news`·`TIER_SUPPLEMENTARY`이며 공식 공시로 승격하지 않는다. 보도 수치와 공식 재무표 수치를 구별하고 정의·기간·범위가 다른 숫자를 합치지 않는다.
- 법인 신원, 공식 재무표와 재무 계산, 9장의 공식 자기 선언·공식 비교 계약을 뉴스로 대체하지 않는다.
- `counts_toward_document_floor=False`는 수집·packet·본문 검증·최종 품질 집계까지 유지한다. 뉴스가 본문 사실이 되어도 독립 공식 문서 수 하한에 합산하지 않는다.

## 5. 본문과 뉴스 목록

- 유용하고 검증된 뉴스는 해당 장의 본문 근거로 사용한다. Writer에는 발행처·발행일·사건 상태·근거 범위를 함께 준다.
- Writer가 놓친 유효 근거는 기존 Reviewer 검사 전에 검토한다. 중복·관련성 부족·시점 부적합 등 합리적인 제외를 존중하며, 검수에서 거절한 문장을 뒤에 다시 삽입하지 않는다.
- 뉴스 목록에는 제목·발행일·발행처·연결 주소가 드러나야 한다. 원문 문장 수가 아니라 독립 기사 수로 센다. 같은 기사를 여러 장에 반복해 분량을 부풀리지 않는다.
- 본문 활용 여부와 제외 사유를 진단한다. 목록에 있다는 이유만으로 본문이 최신 근거를 충분히 사용했다고 평가하지 않는다.
- 웹·PDF·Notion에 같은 검증 결과를 쓴다. 공개 구조를 결속한 뒤 내용을 추가하거나 특정 출시 모드에서 뉴스만 조용히 삭제하지 않는다.

## 6. 부족과 장애 구분

| 상태 | 표시 원칙 |
|---|---|
| 정상 조사했지만 관련 자료가 적음 | 확인된 공개 자료가 제한적임을 표시 |
| 키 없음·인증 실패·검색 장애 | 조사를 완료하지 못했음을 표시. 자료가 없다고 단정하지 않음 |
| 접근 실패·본문 없음·분석 실패 | 확인된 기사만 사용하고 미확인 범위를 표시 |
| 시간·비용·본문 상한 도달 | 조사 범위가 제한되었음을 표시 |
| 뉴스 기능 꺼짐 | 뉴스 미조사로 표시 |

검색·본문·검증이 미완료이면 캐시 재사용 가능으로 저장하지 않는다. 뉴스 장애만으로
확인된 공식 사실까지 버리지 않지만, 필수 신원·안전 검사를 우회하지 않는다.

## 7. 비용 경계와 진단

구체적인 상한은 `app/src/features/news_intake/constants.py`의 수집 정책이 정본이다.
검색·본문·분석 호출·총 입력량·전체 시간을 제한하고 실제 비용 원장에 기록한다.
상한은 채울 기사 할당량이 아니다. 충분한 서로 다른 사건·주제가 확인되면 조기에
멈추며, 부족해도 무관한 기사를 추가하지 않는다.

`5b_뉴스_검색스냅샷`과 `5b_뉴스_수집`에 검색 호출, 기간별 후보·본문·검증 기사,
독립 기사·사건·주제, 제외·실패·상한 사유, 완전성과 캐시 가능 여부를 남긴다.
내부 진단과 별개로 독자가 볼 수 있는 조사 한계도 제공한다.

## 8. 품질 검증

회사별 특례가 아니라 같은 정책으로 산업·규모·자료량을 나누어 시험한다.
회사 일치·최신성·숫자 정확성·중복 사건·본문 활용·기사 목록·장애 표시를 각각 검사한다.
단위 시험이나 생성 성공만으로 내용 품질을 보증하지 않는다. 유한한 표본 결과를
모든 회사의 동일 품질을 입증한 것으로 과장하지 않는다.
