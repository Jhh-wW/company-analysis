# 기업분석 보고서 출력물 기준

- 상태: **현재 정본(Canonical)**
- 확정일: 2026-08-20
- 적용 대상: 이 서비스가 새로 만드는 모든 기업분석 보고서
- 검증 사례: 업종이 다른 실제 회사 보고서를 추가할 때마다 이 기준으로 회귀 검수
- 캐시 계약: `product:company-analysis` + `schema:company-report-v3-canonical`; 보고서의 `schema_version` 값은 `company-report-v3-canonical`
- 구조 설계 근거: 25개 기업의 공식 문서 25개와 외부 분석 25개를 짝지어 검토한 [50개 매칭 표본 분석](../evidence/reference-reports-50-analysis-summary.md)

## 1. 보고서의 목적

기업이 취업준비생에게 **자사에 관해 반드시 알아야 한다고 판단하는 정보**를 쉽고 근거 있게 전달한다.

이 보고서는 회사 이해를 위한 자료다. 다음 정보는 제공하지 않는다.

- 직무별 업무·KPI·필수역량
- 채용공고별 맞춤 분석
- 자기소개서 문장·면접 답변·개인 경험 연결
- 연봉·평균 근속·복지처럼 지원자가 궁금해하지만 회사 이해의 핵심이 아닌 정보
- 목표주가·투자의견·밸류에이션처럼 투자자에게만 필요한 정보

직무·공고·지원자별 변수를 억지로 포함하면 보고서마다 품질과 정확성이 흔들리므로 회사 공통 정보에 집중한다.

없으며 9장 다음 항목은 번호 없는 `부록. 출처와 검증 상태`다.

## 3. 품질을 고정하는 일곱 가지 원칙

1. **공식 자료 필수**: 1~8장의 공개 핵심 사실은 자사 공시·IR·회사 공식 웹·공식 파트너·규제기관 원문으로만 확정한다. 외부 분석·뉴스·증권사 자료는 원인·위험·과장 여부를 내부에서 점검하는 보조자료이며 공개 `FactRecord`나 출처 부록으로 승격하지 않는다.
2. **회사 고유성**: 회사명을 경쟁사로 바꿔도 성립하는 문장은 삭제한다.
3. **시간 상태 분리**: 완료된 실행은 4장, 해결 중인 문제는 5장, 미실행 계획은 6장에만 둔다.
4. **사실 단일 소유**: 같은 수치·사건·파트너 역할은 본문 한 장과 한 표현 형식에만 둔다.
5. **필요한 시각화만 사용**: 그림을 넣었을 때 관계나 변화가 문장보다 즉시 이해될 때만 차트·흐름도를 쓴다.
6. **사실 원자화**: 한 문장·표 행·도식 노드에는 같은 대상·시점·상태의 사실만 두고, 원문보다 범위를 넓히지 않는다.
7. **런타임 게이트**: 조사·작성·웹 표시·PDF 변환 전후에 같은 구조화 검사를 실행하며, 한 단계라도 실패하면 출고하지 않는다.

1~9장은 선택 목차가 아니라 모두 필수다. 필수 장 하나라도 검증 가능한 내용 계약을
충족하지 못하면 빈칸·근거 부족 카드·구형 목차로 대체하지 않고 보고서 전체를
`GATE_STOPPED`로 끝낸다. 핵심 요약은 1~8장 내부 초안에 9장을 결합한 뒤 작성하고,
요약까지 붙은 전체 객체에 최종 게이트를 실행한다. 통과한 요약은 독자에게 첫 장에 먼저
보여 준다.

## 4. 출고 불가 조건

아래 항목이 하나라도 있으면 PDF를 출력하지 않는다.

- 출처를 추적할 수 없는 핵심 주장
- 같은 실적 수치나 사건의 본문 반복
- 계획을 완료 사실처럼 쓰거나 잠정치를 확정치처럼 쓴 문장
- 회사 공식 분류가 아닌 분석 라벨을 공식 판단처럼 표시
- 빈 상자·원문 덤프·회사명만 바꿔도 성립하는 일반론
- 직무별 KPI·맞춤 지원전략 등 서비스 범위 밖 정보
- 잘림·겹침·깨진 글자·6.5pt 미만 텍스트·읽을 수 없는 표
- 비교기간·정의·범위가 다른 경쟁사 수치를 순위처럼 제시
- 표시 수치가 원수치·산식·단위 변환·`ROUND_HALF_UP` 반올림으로 재현되지 않음
- 공개 3개년 실적표가 `단위: 억원`과 억원 표시값 외에 원 단위 원값을 중복 노출함
- 특정 법인·제품·지역의 사실을 상위 회사·제품군·시장 전체로 확대
- 실제 운영 중인 대상과 준비·개발·계획 중인 대상을 한 상태나 한 도식 노드로 묶음
- 원문이 직접 뒷받침하지 않는 인과·수익성·우위 표현
- 출처표의 문서명·발행처가 원문 표지·발행 정보와 불일치
- 구형 `4-1·4-2·4-3·활용` 섹션, 직무·공고 필드 또는 준비 질문이 신규 출력에 노출
- `schema:company-report-v3-canonical`이 아닌 캐시 자료를 신규 정본처럼 재사용
- 1~9장 중 하나라도 빠졌거나 필수 사실 계약을 충족하지 못함
- 3장 중점 제품·서비스가 없거나, 각 항목에 정확한 대상·사업 역할·서로 다른 실제 우선 신호 2개가 결속되지 않음
- 9장의 양사 공식자료·동일 고객/제품/시장·동일 기간·정의·회계 범위 비교가 성립하지 않음
- 공개 웹·PDF·Notion이 동일 보고서·PDF·모든 페이지 PNG 해시·전체 `fact_id`에 결속된 필수 자동검사 전 항목을 통과하지 않음

최초 25건 사용자 검토는 자동검사 보정용 파일럿이며 개별 서비스 보고서의 승인 절차가 아니다. 실제 서비스는 필수 자동검사 전 항목 통과 시 자동출고하고, 하나라도 실패하거나 검사 후 해시가 바뀌면 웹·PDF·Notion 전체를 `GATE_STOPPED`한다.

## 6. 기준 변경 방법

다른 회사를 시험한 뒤 기준을 바꿀 때는 다음 순서를 지킨다.

1. 실패한 실제 출력과 해당 근거를 보존한다.
2. 특정 회사만의 예외인지 여러 업종에서 반복되는 문제인지 구분한다.
3. 두 개 이상 서로 다른 업종에서도 같은 문제가 확인될 때 공통 규칙을 수정한다.
4. 목차별 파일과 공통 규칙을 함께 갱신한다.
5. 기존 기준 사례와 새 시험 보고서를 모두 다시 검수한다.

한 회사의 특수 사례 때문에 전체 목차를 즉시 바꾸지 않는다.

단, 수치 정확성·대상 범위·시간 상태·출처 신원 오류는 업종과 무관한 데이터 무결성 결함이므로 한 사례만 확인돼도 공통 규칙과 회귀 검수 사례에 즉시 추가한다.
