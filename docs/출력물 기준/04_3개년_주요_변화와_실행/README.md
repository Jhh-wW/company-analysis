# 4. 3개년 주요 변화와 실행 `#과거`

## 목적

최근 3년에 회사가 **실제로 실행한 일과 그 결과 확인된 사업 변화**를 연결해 보여 준다. 단순한 3개년 실적표가 아니라, 제품·고객·지역·운영 구조의 무게가 어디로 이동했는지를 설명하는 장이다.

- 완료 실행 사건의 표준 분석 범위는 보고서 기준일 이전 36개월이다.
- 재무 추세는 회사의 실제 결산월을 기준으로 가장 최근의 **비교 가능한 완료 사업연도(`fiscal_year`) 3개**를 쓴다. 모든 업종·회사에 달력연도 12월 31일을 일괄 적용하지 않는다.
- 직무별 맞춤 정보와 지원자 행동 지침은 범위 밖이다.

## 답할 질문

1. 3년 전과 비교해 현재 사업의 무게중심은 어디로 옮겨갔는가?
2. 그 변화를 만든 회사의 실제 실행은 무엇인가?
3. 실행 전·후에 확인된 결과는 무엇인가?
4. 이 결과는 단기 실적인가, 사업 구조의 변화인가?
5. 결과를 전부 해당 실행 효과로 볼 수 없게 하는 외부 요인은 무엇인가?

## 사실의 시간 상태 정의

### 이 장에 넣는 `#과거`

다음 네 조건을 모두 만족해야 한다.

1. 보고서 기준일 이전에 실제 실행되었다.
2. 출시·가동·인수·조직 개편·유통 확대 등 확인 가능한 완료 사건이나 완료 단계가 있다.
3. 실행 이후 실적·고객·생산·지역·운영 지표 중 하나 이상의 결과가 확인됐다.
4. 아직 미해결된 문제를 설명하는 사실이 아니다.

완료 실행은 `claim_type=completed_execution`으로 저장하고 원문에서 확인되는 실제 사건일을
`event_date`(`YYYY` 또는 `YYYY-MM-DD`)에 둔다. 문서 발행일·수집일·보고서 기준일을
사건일로 대신 쓰지 않는다.

### 다른 장으로 보내는 경우

- 지금 시점의 제품·서비스 구성과 그 이름, 어느 사업·부문이 수익을 벌어오는가: `3장`
- 현재도 해결 중인 문제와 대응: `5장 #현재`
- 아직 실행되지 않은 예정·목표·일정: `6장 #미래`
- 현재 반복적으로 작동하는 생산·기술·유통·파트너 관계: `7장`
- 최근 분기나 당해 수치가 현재 미해결 과제의 증거일 때: `5장`

전사 전환이 진행 중이어도 **이미 완료된 단계와 확인된 결과**만 잘라 4장에 넣는다. 남은 일정은 6장에서 다룬다.

## 입력자료 우선순위

1. 감사된 연간보고서·사업보고서·재무제표
2. 각 연도의 공식 IR 실적발표서와 투자자데이 자료
3. 회사가 발표한 출시·인수·가동·제휴·조직 개편 자료
4. 관련 종속회사·파트너·규제기관의 공식 자료
5. 동일 사건과 기간을 분석한 외부 보고서(내부 교차검증 전용)

외부 분석은 결과의 원인과 지속 가능성을 내부에서 검토하는 용도다. 공개 `FactRecord`·출처로 승격하지 않으며 회사·공시·규제기관 공식 원문이 직접 밝히지 않은 인과는 공개 문장으로 만들지 않는다.

## 독립 조사 절차

1. **비교 기간 고정:** 재무 수치는 회사 결산월에 따른 최근 완료 3개 사업연도, 사건은 기준일 이전 36개월로 고정한다. 보고서 기준일의 연도만 보고 `직전 3개 달력연도`로 계산하지 않는다.
2. **변화축 선정:** 제품·고객·지역·채널·비용·생산·수익구조 중 의미 있는 변화를 찾는다.
3. **지표 비교:** 정의·통화·연결/별도·사업연도가 같은 수치만 비교한다. 재분류가 있으면 가장 최근 기준으로 3개년을 맞춘다.
4. **실행 후보 수집:** 제품 출시, 설비 가동, 인수, 유통 확대, 가격 변경, 조직·플랫폼 개편 등을 모으고 완료 실행마다 `event_date`를 원문에 결속한다.
5. **실행–결과 매칭:** 각 실행 이후 확인된 지표를 별도 `fact_id`로 붙이고, 변화 해석의 `basis_fact_ids`가 해당 완료 실행·완료 실적만 가리키게 한다. 공식 설명과 외부 요인을 나란히 검토한다.
6. **중요도 필터:** 단기 뉴스나 작은 프로모션을 빼고, 공식 근거가 가장 강한 완료 실행 1~4개만 남긴다. 개수를 맞추기 위해 약한 실행을 추가하지 않는다.
7. **시간 상태 검사:** 각 사건을 4·5·6·7장 중 한 곳에만 배정한다.
8. **인과 표현 검사:** 직접 원인이 확인되지 않았으면 `같은 기간 관찰됐다`처럼 시간적 동시성만 쓰고 `이어졌다·기여했다·영향을 줬다·개선했다·만들었다`와 완곡한 `이어질 수 있다`를 쓰지 않는다.
9. **중복 검사:** 표·그래프·문장에 같은 수치와 사건이 두 번 들어간 경우 하나만 남긴다.

## 포함 기준

- 비교 가능한 3개년의 사업별·제품별·지역별 구성 변화
- 이미 실행된 신제품·신사업·현지화·생산능력·플랫폼 변화
- 공식 원문이 인수·매각·자회사 재편을 실적·사업 구조 변화의 직접 요인으로 설명한 경우
- 실행 전·후를 연결할 공식 지표나 확인 가능한 운영 결과
- 일회성 손익·회계 재분류·환율 효과처럼 해석에 필수적인 한계
- 회사 결산월과 연결/별도 범위가 같은 완료 사업연도 `fiscal_year` 3개
- 기준일 이전 36개월 안의 `completed_execution`과 원문에 적힌 `event_date`
- 변화 해석을 직접 뒷받침하는 완료 실행·실적의 `basis_fact_ids`

## 제외 기준

- 숫자만 나열한 3개년 재무제표
- 실행 이유나 결과와 연결되지 않는 단발성 행사·캠페인·수상
- 아직 예정인 출시·투자·증설·해외 진출
- 현재 해결 중인 과제와 그 대응
- 협력 상대와 현재 계속되는 역할 설명
- 투자자의 목표주가·밸류에이션·주가 전망

## 출력 필드와 표 형식

장 상단에 `분석 범위: FY YYYY~FY YYYY 완료 사업연도(결산월·연결/별도 범위) / 사건: 기준일 이전 36개월`을 한 번만 표시한다. 각 행에 `YYYY.MM.DD 기준`을 반복하지 않는다.

### 1. 핵심 결론

숫자 없는 한 문장으로 3년간 가장 큰 사업 이동을 설명한다.

### 2. 3개년 변화 지표

그래프나 표 중 하나만 쓴다. 지표는 전체 매출·이익에 한정하지 않고, 핵심 변화를 설명하는 2~4개만 선택한다.

표를 쓰면 행은 회사 결산월에 따른 연속된 완료 사업연도 3개, 열은 지표 2~4개로
고정한다. 표 위에 `단위: 억원`을 한 번만 표시하고 각 셀에는 억원 표시값만 쓴다.
원 단위 원값은 공개 표에 함께 적지 않고 내부 `FactRecord.raw_value`와
`numeric_checks`에 보존한다.

제품·지역별 매출 구성 변화 표(3개년)는 4장이 소유한다. 표의 수치는 산문에
반복하지 않고 산문은 구성비가 늘거나 준 방향만 설명한다.

| 사업연도 | 지표 A | 지표 B | 지표 C |
|---|---:|---:|---:|
| FY YYYY | 억원 표시값 | 억원 표시값 | 억원 표시값 |
| FY YYYY | 억원 표시값 | 억원 표시값 | 억원 표시값 |
| FY YYYY | 억원 표시값 | 억원 표시값 | 억원 표시값 |

### 3. 실행–결과 표

| 사건일·변화축 | 완료 실행 | 확인된 결과 | 사업적 의미·해석 한계 | 근거 |
|---|---|---|---|---|
| `event_date`·제품/시장/운영 변화 | `completed_execution` | 객관적 수치·사건 | `basis_fact_ids`로 결속된 해석과 기타 동시 요인·미공개 범위 | [n] |

- 행은 근거가 확인된 1~4개로 제한한다.
- `시점`은 원문 발행일이 아니라 실행·결과의 시점이다.
- 같은 수치를 그래프와 표에 동시에 쓰지 않는다. 그래프에 들어간 수치는 표에서 `상승·하락·확대·축소`로만 연결한다.

## 원인·결과 연결 규칙

기본 구조는 `실행 → 중간 지표 → 확인된 사업 변화 → 해석 한계`다.

- 회사·공시·규제기관 공식 원문이 원인을 직접 설명한 경우에만 주체를 밝혀 `회사는 ...를 개선 요인으로 설명했다`고 쓴다. 외부 분석은 과장 여부의 내부 교차검증에만 사용한다. 같은 조건의 실행 전·후 지표만 있으면 `실행 전후로 변했다`고 쓰며 인과를 단정하지 않는다.
- 환율·일회성 손익·업황·회계 재분류가 섞이면 `함께 나타났다`로 표현한다.
- 단일 분기 증감만으로 구조적 변화를 선언하지 않는다.
- 지표가 같은 방향으로 2개 기간 이상 지속되거나 사업 구성비가 바뀌었을 때 `구조 변화`로 판단한다.
- 결과가 없는 실행은 이 장의 주요 행으로 쓰지 않는다.

## 다른 장과 중복 방지

- 3장은 지금 시점의 구성(무엇을 파는가·어느 사업이 버는가)을 소유하고, 4장은 그 구성이 3개년 동안 **얼마나 변했는가**(추세·변화)를 소유한다. 같은 제품이라도 현재 역할은 3장, 3개년 이동은 4장이다.
- 3장에서 제품의 현재 역할을 설명했다면, 4장은 그 제품 출시 후 **전사 구조가 바뀐 결과**만 소유한다.
- 5장의 최신 과제 수치를 4장 그래프에 삽입하지 않는다.
- 6장의 예정 일정을 4장 타임라인의 뒤에 붙이지 않는다.
- 7장의 현재 파트너 역할은 반복하지 않고 `운영 기반이 확대됐다(7장)`처럼 결론만 연결한다.
- 9장은 자사 수치를 복사하지 않고 `자사 변화는 4장 참조`로 연결한다. 비교사 수치만 9장의 동일 고객·제품/서비스·시장·기간·정의·회계 범위 계약을 통과한 표에서 한 번 제시한다.

## 시각화 사용 조건

다음 중 하나를 만족할 때만 사용한다.

- 3개년의 동일 지표를 동일 정의로 비교할 수 있고, 방향 변화가 문장보다 빠르게 보일 때
- 3개 이상의 실행이 순서를 이루어 사업 구조가 변한 과정을 보여야 할 때
- 매출 구성·제품 구성·지역 구성의 이동이 핵심 결론일 때

선 그래프는 추세, 누적 구성 막대는 구성비, 타임라인은 사건 순서에만 쓴다. 시각화와 본문이 같은 숫자를 반복하면 시각화를 제거한다.

## 근거 부족 시 처리

- 3개년 수치 정의가 달라졌으면 재분류된 공식 수치로 맞춘다. 회사 결산월·범위가 같은 완료 사업연도 3개를 확보하지 못하면 그래프만 생략하는 것이 아니라 4장 필수 계약 실패로 보고 전체를 `GATE_STOPPED`로 끝낸다.
- 실행은 확인되지만 결과가 없으면 주요 항목에서 제외한다. 결과가 결속된 완료 실행이 하나도 남지 않으면 4장 필수 계약 실패로 처리한다.
- 원인이 공식 자료에 없으면 외부 분석은 내부 교차검증에만 쓰고, 공개 본문에는 원인·기여·영향·개선 또는 이를 완곡하게 암시하는 표현을 넣지 않는다.
- 실행과 결과 사이에 시간적 순서만 있고 연결 근거가 없으면 열을 비우지 않고 `인과 확인 불가`로 표시한다.
- 적합한 실행이 2개 이하면 억지로 행을 채우지 않고 표를 축소한다.

## 출고 체크리스트

- [ ] 수치는 가장 최근의 비교 가능한 완료 3개 사업연도인가?
- [ ] 실제 회사 결산월을 사용했고 모든 회사를 12월 31일로 고정하지 않았는가?
- [ ] 각 완료 실적에 올바른 `fiscal_year`와 연결/별도 범위가 있는가?
- [ ] 모든 `completed_execution`에 원문이 뒷받침하는 `event_date`가 있는가?
- [ ] 모든 변화 해석의 `basis_fact_ids`가 같은 장의 완료 실행·실적 사실만 가리키는가?
- [ ] 모든 주요 행에 `실제 실행`과 `확인된 결과`가 모두 있는가?
- [ ] 예정·목표·진행 중 대응을 제거했는가?
- [ ] 지표의 통화·범위·회계 정의가 같은가?
- [ ] 3개년 실적표가 `행=완료 사업연도·열=지표`이며 `단위: 억원`과 억원 표시값만 공개하는가?
- [ ] 원 단위 원값이 공개 표가 아니라 내부 `raw_value`·`numeric_checks`에만 보존되는가?
- [ ] 일회성 손익·재분류·역산 수치의 한계를 표시했는가?
