# 핵심 요약 출력 기준

## 목적

본문을 읽기 전에 회사의 실체와 현재 상황을 30초 안에 파악하게 하는 안내판이다. 새 사실을 추가하거나 다시 쓰는 장이 아니라, 원문 완전일치 코드 확정 또는 독립 Reviewer를 통과한 본문의 회사 고유 문장 3~5개를 그대로 골라 해당 장으로 연결한다.

> 내부 설계 근거: 50개 표본에서 제품·고객·실적·실행·전략·경쟁력은 사실상 모든 회사에 등장했다. 요약은 이를 다시 나열하는 축약 실적표가 아니라, 지원자가 본문에서 무엇을 먼저 읽어야 하는지 알려주는 구조로 고정한다. 이 설명은 완성 보고서에 출력하지 않는다.

## 이 장이 답할 질문

- 이 회사는 본질적으로 어떤 기업인가?
- 누구에게 어떤 가치로 돈을 버는가?
- 현재 사업의 중심과 가장 중요한 변화는 무엇인가?
- 지금 풀어야 할 과제와 다음 방향은 무엇인가?
- 동종업계와 비교해 9장이 근거로 확인한 차이는 무엇인가?

## 필수 입력자료 우선순위

1. 검증된 1~9장에서 원문 완전일치 코드 확정 또는 독립 Reviewer를 통과한 본문 문장. 9장이 빠진 상태는 연습 모드에서만 생긴다. 아직 최종 공개 게이트 전 객체다.
2. 각 결론을 직접 뒷받침하는 본문 `fact_id` 부분집합과 사실 소유권
3. 해당 사실 묶음의 근거 텍스트와 Writer 검수 결과(원문 완전일치 코드 확정 또는 독립 Reviewer)
4. 중복 검사 결과

요약을 위해 원문을 새로 조사하지 않는다. 본문에 없는 사실은 요약에도 쓸 수 없다.

## 조사 절차

1. 검증된 1~8장을 공개 불가 내부 초안으로 조립하고 9장을 결합한다. 출시 모드는 9장까지 갖춰야 하고, 동일 조건 비교가 성립할 때만 결합하는 것은 연습 모드다.
2. 각 장에서 Writer 검수를 완료한 회사 고유 본문 문장을 후보로 뽑는다.
3. 출처 각주·제작 메타정보가 들어간 문장은 고쳐 쓰지 않고 후보에서 제외한다. 같은 장에서는 숫자 없는 문장을 먼저 고르되, 그 장의 검증 문장이 숫자를 포함한 것뿐이면 해당 문장을 글자 변경 없이 후보로 허용한다.
4. 같은 장과 같은 문장을 중복 선택하지 않고 고정된 입력 순서에서 장당 최대 1개씩 3~5개를 고른다.
5. 후보 문장의 글자를 바꾸거나 새 연결·인과·평가를 추가하지 않는다.
6. 각 문장 끝에 사실을 소유한 본문 장을 하나만 연결하고, 요약이 직접 사용한 `fact_ids` 부분집합을 내부 레코드에 저장한다.
7. 그대로 고른 본문 문장·근거 사실 묶음·Writer 검수 판정을 `verification_binding`으로 잠그고, 상태를 `verified_fact_reuse`로 기록한다. 요약 전용 AI·Reviewer는 호출하지 않는다.
8. 모든 문장이 다른 회사에 그대로 적용되지 않는지 마지막으로 확인한다.
9. 요약을 결합한 필수 1~9장 전체에 `build_published_report` 최종 게이트를 정확히 한 번 실행한다. 이때까지 초안·요약을 저장·캐시·공개 렌더링하지 않는다.

## 포함 기준

- 회사의 정체성·수익 구조·우선시장·사업 변화·당면 과제·전략·비교 차이 중 지원 전 반드시 알아야 할 결론
- 본문에서 충분한 근거와 한계가 검증된 결론
- 다른 요약 문장과 역할이 겹치지 않는 결론
- 회사명만 바꾸면 성립하지 않는 회사 고유 내용

## 제외 기준

- 검증된 본문에 없는 수치의 추가·변경, 또는 검증된 숫자 문장을 요약용으로 다시 쓰는 행위
- 구체적인 날짜·실행 사례·출처 번호의 재기재
- `혁신 기업`, `글로벌 리더`, `고객 중심`처럼 근거 없는 홍보 문구
- 보고서가 무엇을 조사·검증했는지 설명하는 제작 메타정보
- 연봉·평균 근속연수·복지처럼 회사 사업 이해의 핵심이 아닌 정보
- 직무별 업무·KPI·개인별 지원전략·자기소개서 문구. 이는 서비스 범위 밖이다.

## 출력 필드/형식

각 결론을 동일한 크기의 카드 또는 번호 목록으로 출력한다.

`번호 | 2~6자의 짧은 제목 | 검증된 본문 결론 1문장 | [관련 장]`

- 카드 수: 3~5개
- 결론 길이: 한 문장, 원칙적으로 두 줄 이내
- 연결 장: 문장당 1개. 여러 장이 필요하면 결론 범위가 넓은 것이므로 다시 나눈다.
- 요약 자체에는 출처 각주를 붙이지 않는다. 근거는 연결된 본문 장에서 확인한다.
- 공개 표에는 내부 필드를 노출하지 않지만 각 항목은 `section_id·fact_ids·evidence_text·verification_status·verification_binding`에 결속돼야 한다.

## 후보 문장 선택법

- 본문 Writer 단계에서 이미 검수를 완료한 `주어 + 확인된 사업적 사실 + 현재 의미` 문장을 그대로 고른다.
- 같은 장에 숫자 없는 검증 문장이 있으면 이를 우선한다. 숫자가 있는 검증 문장만 있으면 숫자까지 그대로 재사용하며, 숫자를 지우거나 방향 표현으로 바꿔 쓰지 않는다.
- `~해야 한다`는 회사 과제에서 이미 확인된 경우에만 사용하고 지원자 행동으로 바꾸지 않는다.
- 작성 과정을 뜻하는 `정리했다·살펴본다·제시한다`는 쓰지 않는다.
- Writer 권장형: `[핵심 자산/구조]가 [사업 역할]을 맡고 있으며, [확인된 변화·조건]이 현재의 핵심이다.` 요약 단계에서는 이 문장을 다시 쓰지 않고 장 연결만 덧붙인다.

## 시각화 사용 조건

- 기본 형식은 3~5개의 텍스트 카드다.
- 그래프·도표·아이콘형 인포그래픽은 사용하지 않는다. 요약에 별도 시각화를 넣으면 본문의 사실과 수치를 반복하기 때문이다.
- 카드의 색은 의미 체계를 하나만 사용하고, 카드마다 임의의 색을 부여하지 않는다.

## 업종별 변형

- 제조: 핵심 제품군, 생산·고객 구조, 증설 또는 수요 변화 중심
- 플랫폼·SaaS: 핵심 사용자와 지불 고객, 네트워크 또는 구독 구조 중심
- 금융: 고객군, 주요 상품, 이자·수수료 구조와 건전성 과제 중심
- 바이오: 핵심 파이프라인 단계, 기술이전·판매 경로, 임상·허가 불확실성 중심
- 콘텐츠·IP: 핵심 IP, 음악·공연·상품·라이선스 등 확장 경로 중심
- 유통: 점포·온라인 채널, 상품 조달, 회전율·점포 생산성 변화 중심

업종이 달라도 요약의 역할과 카드 수는 바꾸지 않는다.

## 실패 시 처리

- 근거가 충분한 결론이 3개 미만이면 요약을 억지로 채우지 않고 본문 조사로 되돌린다.
- 같은 사실이 두 카드에 걸치면 사실 소유 장에 맞춰 하나만 남긴다.
- 요약에서만 등장하는 사실이 발견되면 삭제하거나 해당 본문 장에서 먼저 검증한다.
- `fact_ids`가 비었거나 본문에 없는 사실을 가리키거나 Writer 검수 결속이 맞지 않으면 요약만 생략하지 않고 보고서 전체를 `GATE_STOPPED`로 끝낸다.
- 회사 고유성이 약하면 회사명·산업명·대표 제품을 넣는 방식이 아니라, 가치 제공과 수익 구조를 다시 조사한다.

## 출고 전 체크리스트

- [ ] 필수 1~9장이 확정된 뒤 선택했는가?
- [ ] 3~5개 결론만 남겼는가?
- [ ] 모든 문장이 하나의 본문 장으로 연결되는가?
- [ ] 각 문장이 그 장의 실제 `fact_ids` 부분집합에 결속됐는가?
- [ ] 요약 근거와 Writer 검수 판정에 대한 `verification_binding`이 유효하고 상태가 `verified_fact_reuse`인가?
- [ ] 요약 전용 AI·Reviewer 호출 수가 0이고 본문 문장이 글자 변경 없이 재사용됐는가?
- [ ] 같은 장에서는 숫자 없는 문장을 우선했고, 숫자 문장을 골랐다면 검증된 본문 그대로 재사용했는가?
- [ ] 정체성/수익 구조와 현재 변화/과제가 함께 포함됐는가?
- [ ] 회사명만 바꿔도 성립하는 문장을 제거했는가?
- [ ] 직무별 업무·KPI·맞춤 지원전략을 넣지 않았는가?
- [ ] 요약끼리, 요약과 본문 사이에 사실 중복이 없는가?

## 짧은 범용 예시

> **수익 구조**  핵심 장비 판매는 초기 매출, 유지보수 계약은 반복 매출 경로로 공식 분류된다. [2장]

이 문장은 형식 예시일 뿐이며, 완성 보고서에서는 회사의 공식 자료로 확인된 고유 사실로 교체한다.
