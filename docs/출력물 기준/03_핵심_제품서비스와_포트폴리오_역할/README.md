# 3. 핵심 제품·서비스와 포트폴리오 역할 출력 기준

## 목적

회사의 현재 수익을 실제로 만드는 제품·서비스·브랜드·IP·사업 단위를 원문에 적힌 이름 그대로 **근거가 확인된 1~3개**만 보여준다. 무엇을 팔아 돈을 버는지, 어느 사업·부문이 그 수익을 벌어오는지, 각 대상이 전체 포트폴리오에서 맡는 역할을 같은 사실 블록 안에서 설명한다. 단순 제품 소개가 아니라 정확한 대상(`subject_label`), `매출 기여 또는 실행 근거`, 사업 전체에서의 역할(`product_role`)을 함께 보여준다.

3장은 지금 시점의 구성(무엇을 파는가·어느 사업이 버는가)을 소유하고, 4장은 그 구성이 3개년 동안 얼마나 변했는지(추세·변화)를 소유한다.

> 내부 설계 근거: 제품·서비스는 50개 문서 모두에 등장했지만 독립 제목은 24개뿐이었다. 전용 장이 없으면 제품 정보가 실적·전략 속에 흩어진다. 현재 JYP 예시에서 드러난 반복 기준일 문제를 막기 위해 공통 기준일은 표 위에 한 번만 표시한다. 이 설명은 완성 보고서에 출력하지 않는다.

## 이 장이 답할 질문

- 회사는 지금 무엇을 팔아 돈을 버는가?
- 그 수익을 벌어오는 사업·부문은 어디이고, 해당 제품·서비스·IP의 이름은 무엇인가?
- 매출 기여나 실행을 공식 자료에서 확인해 주는 근거는 무엇인가?
- 어떤 고객·시장에서 어떤 방식으로 수익과 확장을 만드는가?
- 전체 포트폴리오에서 신규·성장·주력·안정 중 어떤 역할을 맡는가?
- 제품별로 공개되지 않았거나 아직 확인되지 않은 것은 무엇인가?

## 필수 입력자료 우선순위

1. 최신 공식 실적발표·IR의 제품별 경영진 설명과 실행 내역
2. 공식 제품·서비스 페이지, 출시 자료, 수주·계약·허가 공시
3. 최신 사업보고서의 주요 제품·매출·연구개발·생산 정보
4. 공식 투자·증설·유통 확대·파트너 발표
5. 정부·규제기관 공식 원문 등 제품 성과를 확인할 허용된 제3자 원자료
6. 외부 기업분석은 우선순위와 성과 해석의 과장을 내부에서 점검할 때만 사용하며 공개 `FactRecord`·출처로 승격하지 않음

제품의 존재를 보여주는 오래된 소개보다 최근 실제 실행을 우선한다. 미래 계획만 발표된 제품은 6장이 소유하며, 이 장의 현재 핵심 제품으로 쓰려면 확인된 매출 기여나 이미 시작된 실행 근거가 있어야 한다.

이름 표 발췌 조각은 제품·브랜드·사업부문·종속회사·주요 계약의 이름을 원문 그대로 보존한다.
이 조각은 `portfolio:product_role`을 지원하는 근거로 3장에 들어간다.
이름은 프로그램이 원문 표에서 찾으며 AI가 고르지 않는다.

## 조사 절차

1. 현재 판매·운영·개발 중인 제품·서비스와 매출을 벌어오는 사업·부문 단위 후보를 폭넓게 수집한다.
2. 후보마다 다음 신호를 확인한다.
   - 최신 공식 자료에서 반복적으로 강조됨
   - 실제 출시·수주·투자·증설·유통 확대가 시작됨
   - 매출·이용·출하·계약 등 결과가 확인됨
   - 공식 전략에서 다음 확장 경로가 구체적으로 연결됨
3. 위 신호 가운데 제품·서비스마다 인용 근거에 **매출 기여 확인 또는 실행 근거(출시·판매·운영·수주·투자·유통 확대 중 하나)가 하나 이상** 있는 후보만 남긴다. 계획·홍보 문구·단순 제품 소개처럼 매출 기여도 실행도 원문에서 확인되지 않는 후보는 근거로 세지 않는다.
4. 고객과 가치가 지나치게 비슷한 후보는 하나의 제품·서비스 축으로 묶는다.
5. 원문에 실제로 적힌 정확한 제품·서비스명을 `subject_label`로 잠그고, 원문의 상위 제품군이나 다른 모델로 범위를 넓히지 않는다.
6. 가장 근거가 강하고 사업 역할이 서로 다른 후보를 1~3개 선정한다. 세 개를 맞추기 위해 약한 후보를 추가하지 않는다.
7. 선정 항목마다 `subject_label·제품/서비스 범위·매출 기여 또는 실행 근거·수익 연결·product_role·해석 한계`를 구조화한다.
8. 포트폴리오 단계는 아래 내부 판정 기준으로 부여하고 회사의 공식 분류처럼 표현하지 않는다.
9. 공통 기준일은 장 위에 한 번만 적고, 각 제품 블록에 같은 `기준일` 문구를 넣지 않는다.

같은 상위 제품군 안에서도 모델별 상태가 다르면 각각 분리한다. 특정 모델의 `개발 완료`를 제품군 전체의 완료로 넓히지 않으며, `개발 중·고객 검증·MOU·납품·매출 발생`을 카드 안에서도 정확히 구분한다.

### 포트폴리오 단계 판정 기준

- `신규`: 출시·사업화·시장 진입이 시작됐으나 반복 성과가 아직 확인되지 않음
- `성장`: 고객·지역·매출·사용량·생산능력 중 확장 신호가 두 시점 이상에서 확인됨
- `주력`: 전사 수익·고객 확보·시장 지위에서 핵심 역할이 공식 수치나 반복 실행으로 확인됨
- `안정`: 장기간 운영되며 반복 고객·카탈로그·유지보수·현금창출 기반을 제공하지만 빠른 확대가 핵심은 아님

단계는 보고서의 분석 분류다. 회사가 직접 사용한 분류가 아니면 `보고서 분류`임을 표 제목이나 주석에 한 번 표시한다.

## 포함 기준

- 회사의 현재 수익을 만드는 것으로 확인되는 제품·서비스·사업 단위 1~3개
- 제품의 고객·시장, 수익 경로, 전사 포트폴리오 역할
- 원문에 직접 적힌 정확한 `subject_label`과 분석용 `product_role`
- 제품마다 인용 근거에서 확인되는 매출 기여 또는 실행 근거(출시·판매·운영·수주·투자·유통 확대 중 하나) 하나 이상
- 해석에 필수적인 회계 재분류·잠정치·일회성·개별 매출 비공개 등의 한계

## 제외 기준

- 아직 실행되지 않은 출시·투자·진출 계획
- 기능과 사양만 길게 나열한 카탈로그식 설명
- 제품별 근거가 없는 `대표·혁신·차세대·고수익` 표현
- 전사 3개년 실적과 현재 과제 수치의 반복
- 파트너의 세부 역할, 계약 조건, 유통 구조의 반복
- 모든 행에 반복되는 동일 기준일·동일 출처·동일 상태 문구
- 직무별 담당 조직·업무·KPI·맞춤 지원전략. 이는 서비스 범위 밖이다.

매출 기여가 확인된 것과 회사가 미는 것을 구분해 표기한다. 매출 규모와 회사의 중점 추진은 서로 다른 근거이므로 한쪽만 확인되면 확인된 쪽만 쓰고 다른 쪽을 함께 확인된 것처럼 적지 않는다.

## 출력 필드/형식

### 현재 중점 제품·서비스

근거가 확인된 1~3개의 동일 형식 카드로 출력한다.

`번호·공식 제품·서비스명(subject_label)`

- `제품·서비스명`: 인용 조각에 글자 그대로 있어야 하며, 없으면 빈 칸
- `제품·서비스 범위`
- `중점 추진 근거` — 매출 기여 확인 또는 실행 근거(출시·판매·운영·수주·투자·유통 확대 중 하나) 하나 이상
- `사업적 역할(product_role)`
- `해석 한계` — 필요한 경우에만

제품·서비스별 매출 비중 표는 이 장(3장)이 소유하고, 3개년 변화 수치는 4장이 소유한다. 현재 중점 제품·서비스 카드 칸에는 숫자·퍼센트·연도를 쓰지 않는다.

`무엇을 파나`, `지금 미는 근거`, `주의` 같은 구어체 소제목은 사용하지 않는다.

별도의 3~6개 자산군 표를 덧붙이지 않는다. 현재 canonical `portfolio`의 공개 사실은
`priority_product` 1~3개뿐이므로 각 대상의 `product_role`과 필요한 단계·불확실성을 위
제품 블록에서 한 번만 표현한다. 핵심 고객·시장과 수익 경로는 2장에서 정한 분류명만
짧게 참조하고 고객 가치·과금 방식·우선순위·수치를 다시 쓰지 않는다. 개별 수익이
공개되지 않았으면 숫자를 추정하지 않고 필요한 경우 `개별 기여 미공개`라고 한 번만
밝힌다.

## 문장 작성법

- 제품 이름 뒤에는 2장에서 정한 고객·시장·수익 분류명과 제품의 포트폴리오 역할을 연결한다.
- `중점 추진`은 회사의 표현이 아니라 분석 결론이므로 근거를 같은 카드 안에 둔다.
- 단계 태그만으로 평가하지 말고 포트폴리오에서 실제 맡는 기능을 서술한다.
- 같은 실적 수치는 이 장의 한 근거에서만 쓰고 다른 카드·표에서 되풀이하지 않는다.
- 제품의 장점과 회사 경쟁우위를 혼동하지 않는다. 동종업계 비교 판단은 9장이 소유한다.
- 권장형: `[제품·서비스]는 2장의 [고객·시장·수익 분류]와 연결되며, [최근 실행 근거]에 따라 현재 [사업 역할]을 맡는다. 다만 [불확실성]은 확인되지 않았다.`

## 시각화 사용 조건

- 기본은 현재 중점 `제품 블록 1~3개`다. 각 `priority_product` 사실은 블록·표·매트릭스 중 한 표현 형식에서만 완전하게 출력한다.
- 별도 포트폴리오 표나 시장/단계 매트릭스로 같은 대상·역할·신호를 다시 표현하지 않는다.
- 제품·서비스별 매출 비중 표는 3장이 소유하고, 지역별 매출 비중 표는 2장에 둔다. 3개년 변화는 4장에서만 다룬다.
- 제품 사진·로고는 식별에 꼭 필요할 때만 사용하고 장식 목적으로 넣지 않는다.

## 업종별 변형

- 콘텐츠·엔터테인먼트: 아티스트·캐릭터·콘텐츠 IP를 역할군으로 묶고 음악·공연·MD·라이선스 연결 표시
- 제조: 제품군·세대·장비 플랫폼을 묶고 장비 판매·소모품·유지보수 역할 표시
- SaaS: 모듈·요금제·산업 솔루션을 묶고 신규 유입·업셀·리텐션 역할 표시
- 금융: 예금·대출·카드·자산관리 등 상품군을 묶고 고객 유입·이자·수수료·잔존 관계 역할 표시
- 바이오: 파이프라인을 연구·임상·허가·상업화 단계로 구분하고 기술이전·마일스톤·직접 판매 경로 표시
- 플랫폼: 사용자 기능·광고 상품·판매자 도구를 묶고 트래픽·거래·수익화 역할 표시
- 유통: 브랜드·점포 형식·온라인 채널을 묶고 유입·객단가·재구매·지역 확장 역할 표시

## 실패 시 처리

- 근거가 있는 중점 제품이 3개보다 적으면 확인된 1~2개만 출력한다. 숫자를 맞추려고 후보를 만들지 않는다.
- 제품·서비스마다 인용 근거에 매출 기여 확인 또는 실행 근거(출시·판매·운영·수주·투자·유통 확대 중 하나)가 하나 이상 있어야 한다. 그런 후보가 하나도 없으면 3장 필수 계약이 성립하지 않으므로 보고서 전체를 `GATE_STOPPED`로 끝낸다.
- 제품별 매출이 없으면 기여도를 추정하지 않고 2장의 수익 분류명만 참조한다.
- 최신 실행이 없는 제품은 이 장의 공개 제품 블록에서 제외한다.
- 단계 판정 근거가 약하면 선택 단계 태그를 붙이지 않고, 공식 근거로 확인되는 기능적 `product_role`만 쓴다.
- 공식 명칭이 자주 바뀌면 기준일 현재 명칭을 쓰고 과거 명칭의 변화는 4장으로 넘긴다.
