## 포함할 내용

- 본문에서 실제 사용한 일반 citation과 9장 후보 선정에 실제 사용한 후보 원문 citation만 수록. `attestation_only`를 포함한 내부 provenance dependency는 수록하지 않음
- 자료명·발행처·발행일 또는 확인일
- PDF 페이지·표·웹 섹션 등 구체적 위치
- 본문에서 사용한 장 또는 주장 범위
- 자료 유형과 사실 상태
- 직접 열 수 있는 원문 링크
- 해석에 필요한 잠정·계획·재분류·일회성 상태
- 실제로 인용한 언론 보도 행. 기존 메타 칸(발행처·제목·날짜·URL)을 그대로 쓰고 인용 원문을 담는 새 열을 만들지 않는다
- 공개 부록에는 후보로 실제 사용한 원문 citation만 수록한다. 후보 수집의 `failed·none·ok`, `candidate_scope_complete`, 상세 사유와 `attestation_only` Source는 내부 실행·감사 상태이므로 공개하지 않는다.

## 제외할 내용

- 본문에서 쓰지 않은 참고자료
- 검색결과·AI 요약·내부 메모·프롬프트
- `50개 보고서를 비교했다` 같은 제작 메타정보
- 에이전트 구성·검증 순서·작성 과정 설명
- 출처 없이 `다수 기사`, `업계 자료`, `회사 홈페이지`라고만 적은 행
- 열리지 않는 링크를 정상 출처처럼 표시한 행
- 긴 원문 URL을 셀 안에 그대로 노출한 형식
- 출처 번호만 있고 페이지·섹션 위치가 없는 문서
- 본문에서 인용하지 않은 언론 보도. 수집만 하고 문장에 쓰지 않은 기사는 부록에 남기지 않는다

## 출력 형식

| 번호 | 자료·발행처 | 발행·확인일 | 원문 위치 | 본문 사용 | 자료·사실 상태 |
|---|---|---|---|---|---|
| [1] | 클릭 가능한 문서명 / 발행처 | YYYY.MM.DD | PDF p.00·표명 또는 웹 섹션 | 사용 장·주장 | 공식 공시 · 실제 |

### 열 작성 규칙

- `자료·발행처`: 공식 문서 제목을 임의로 바꾸지 않고, 발행처는 별도로 식별한다. 언론 보도는 기사 제목과 언론사명을 그대로 쓴다.
- `발행·확인일`: 문서 발행일을 우선한다. 날짜가 없는 웹페이지만 확인일을 쓴다. 언론 보도는 보도일이 필수이며 확인일로 대체하지 않는다.
- `원문 위치`: PDF는 실제 PDF 페이지, 웹은 섹션명·표명·문단 제목을 쓴다. 언론 보도는 기사 본문 위치를 쓴다.
- `본문 사용`: `정체성·사업 모델`처럼 실제 사용 범위만 적는다.
- `자료·사실 상태`: 자료 유형, `fact_status`, `verification_status`를 서로 구분해 적는다. 언론 보도 행은 `언론 · 외부 보도`다.
- 같은 기준일을 본문의 여러 표에 반복하지 않는다. 시점 정보는 이 부록과 해당 장의 캡션 한 곳에서 관리한다.

## 중복 방지

- 같은 문서·URL은 출처표에 한 번만 등록한다.
- 하나의 출처가 여러 장에 쓰였으면 `본문 사용` 열에 장을 묶어 적는다.
- attester는 내부 Report JSON·저장·감사 등록부에만 한 번 보존한다. 공개 웹·PDF·Notion·Markdown 출처 목록에서는 완전히 숨기고 후보 원문 citation만 표시한다.
- 본문에 이미 있는 수치·사건을 부록에서 다시 설명하지 않고 사용 범위만 기록한다.
- 동일한 주의사항을 모든 출처 행에 반복하지 않는다. 문서 전체 공통 조건은 표 위에서 한 번 설명한다.
- 보고서 전체 기준일 문구는 출처 행에 반복하지 않는다. 다만 각 자료의 고유 발행일·확인일은 모든 행에 반드시 적는다.

## 시각화 조건

부록은 출처표만 사용한다. 그래프·플로우차트·출처 비율 도넛차트는 넣지 않는다. 출처 수가 많으면 표를 다음 페이지로 나누고 머리글을 반복한다.

상태는 텍스트로 구분한다. 여러 색의 배지나 신호등 색만으로 의미를 전달하지 않는다.

## 업종별 변형

| 업종 | 우선 원문 | 위치 표기 예시 |
|---|---|---|
| 상장사 공통 | 사업·분기보고서, 감사보고서, 공식 IR | 공시 접수번호, PDF 페이지·표명 |
| 제조·산업재 | 회사 공식 자료, 규제기관 등록·수주·설비 공시 | 등록번호, 공시 항목, 공장·제품 범위 |
| 플랫폼·SaaS | 공식 KPI 발표, 제품·요금 페이지 | 실적자료 표, 웹 섹션, 확인일 |
| 소비재·유통 | 점포·브랜드·유통 공식 페이지 | 지역·채널 표, 제품 페이지, 확인일 |
| 콘텐츠·IP | 회사 공식 자료, 공식 파트너의 투어·유통·라이선스 자료 | 자료명·집계기간, 작품·공연 범위 |
| 금융·바이오 | 감독기관 통계, 인허가·임상 등록 | 지표 정의, 허가번호, 시험 식별자 |

출처 유형만 달라질 뿐 `발행 주체·날짜·원문 위치·사실 상태·직접 링크` 필드는 모든 업종에서 유지한다.

## 근거가 부족할 때

- 원문 페이지를 찾지 못하면 해당 주장을 다시 조사하고, 끝내 확인할 수 없으면 본문에서 뺀다.
- 9장 후보 수집의 실제 `state`는 `failed·none·ok`뿐이다. 허용 범위를 끝까지 읽은 정상 완전 탐색의 `none`만 후보 없음이다. 접속·TLS·MIME·파서·카탈로그 실패는 `failed`, 상한 잘림은 별도 `truncated` state가 아니라 `candidate_scope_complete=False`와 상세 사유로 내부 감사 등록부에 남긴다. 불완전한 `failed`나 `ok`는 음성 결론이 아닌 `unknown`으로 처리한다.
- 공식 원문이 없고 외부 분석만 있으면 내부 실패 기록에만 남기고 공개 본문·부록에서 제외한다. 그 결과 출시 모드(`REPORT_RELEASE_MODE=FULL`) 필수 1~9장 계약 중 하나라도 부족하면 보고서 전체를 `GATE_STOPPED`로 끝낸다. 9장은 회사가 밝힌 차별점이 없을 때 미달이며, 선택적 양사 비교만 성립하지 않은 경우에는 비교 행만 빼고 계속 제공한다. 한 번만 보충한 뒤에도 미달이면 보고서를 내지 않고 이용 건수도 차감하지 않는다. 표준 부족 사유를 붙인 `Grade.PARTIAL` 기본 보고서로 출고하는 것은 연습 모드(`REPORT_RELEASE_MODE=SHADOW`)뿐이다.
- 언론 보조 근거는 부족을 메우는 수단이 아니다. 뉴스만 있는 장은 필수 계약을 통과하지 못하며, 검색·분류·본문 읽기가 실패해도 보고서는 뉴스 없이 계속 진행한다.
- 웹페이지에 날짜가 없으면 확인일과 구체적 섹션명을 남긴다.
- 링크가 사라졌지만 규제기관 문서가 있으면 규제기관 원문으로 교체한다.
- 서로 다른 공식 자료가 충돌하면 최신 자료를 우선하고, 해석에 중요한 변경은 해당 주장 옆에 남긴다.
- 검증되지 않은 주장을 출처표에만 넣어 본문 신뢰를 보완하려 하지 않는다.

## 출력 전 체크리스트

- [ ] 본문의 모든 출처 번호가 부록에 존재한다.
- [ ] 부록의 모든 출처가 본문에서 실제 사용됐다.
- [ ] 외부 분석·증권사 자료가 공개 부록에 없고, 1~8장 핵심 사실과 9장 비교 수치는 허용된 공식 원문만 사용하는가?
- [ ] 언론 보도 행이 `NEWS_INTAKE="1"` 실행에서 실제 인용한 기사뿐이고, 발행처·제목·보도일·URL·원문 위치가 모두 있으며, 독립 문서 수 하한에 합산되지 않았는가?
- [ ] 언론 보도를 인용한 본문 문장에 숫자가 없는가?
- [ ] 9장 후보 원문이 자사 DART 또는 DART 도메인 attestation을 통과한 자사 공식 HTML IR·공식 웹인가? 문서일을 결속하지 못한 공식 IR PDF가 후보에서 제외됐는가?
- [ ] 안정 회사 페이지는 봉인 수집일, 문서형 공식 웹은 봉인 machine-readable 문서일을 사용하고 보고서 `as_of_date` 기준 0~400일을 지켰는가? 검색 결과를 날짜와 무관하게 제외하고 캐시도 조회 당일 기준으로 재검사했는가?
- [ ] 후보 법인명이 현재형의 명시적 경쟁 술어 target/list slot에 있고, `시장점유율`·과거·잠재·부정·제외·인용·제3자·협력·지원·관계사 경쟁·모호 별칭·`or/또는`를 거부했는가?
- [ ] v2의 정규화 해시와 exact 저장 문장 해시가 각각 Source 두 목록 및 HMAC seal에 결속됐고, exact를 원 HTTP/PDF 바이트 해시로 오해하지 않았는가?
- [ ] v1 저장 형식 읽기 호환 자료도 현재 엄격 문법으로 재검증하고 순수 경쟁 문장을 1~8장 사실로 위장하지 않았는가?
- [ ] attester가 내부 provenance dependency로 보존되면서 공개 웹·PDF·Notion·Markdown에서는 완전히 숨겨졌는가?
- [ ] 공식 IR PDF 고정 상한·격리 파서 검사를 통과하고 수집일을 문서 사실 기준일로 쓰지 않았는가?
- [ ] 수집 상태는 `failed·none·ok`만 사용하고 잘림을 `candidate_scope_complete=False`와 상세 사유로 기록했는가?
- [ ] 관계만 명시한 후보의 공통 범위를 별도 증명하고 실제 비교 수치를 양사 DART 같은 완료 사업연도에서 가져왔는가?
- [ ] 자료명·발행처·날짜·원문 위치가 있다.
- [ ] PDF 페이지 또는 웹 섹션까지 추적할 수 있다.
- [ ] 자료 유형과 사실 상태가 분리돼 판정됐다.
- [ ] `fact_status`와 `verification_status`가 별도 필드이며 공개 사실은 모두 `verified`인가?
- [ ] 모든 `state_evidence` 해시가 연결된 `Source.evidence_hashes`에 포함되는가?
- [ ] 모든 표시 수치가 `numeric_checks`와 `ROUND_HALF_UP`으로 재현되는가?
- [ ] 잠정·계획·재분류·일회성 영향이 표시됐다.
- [ ] 부록의 자료명이 클릭 가능하고 모든 외부 링크가 원문으로 열린다.
- [ ] 본문 출처 번호와 부록 번호가 빠짐없이 대응한다.
- [ ] 검색결과·AI 요약·내부 문서가 최종 출처에 없다.
- [ ] 제작 과정·검증 절차 설명이 보고서 본문에 없다.
- [ ] 출처표 안에 긴 원문 URL이나 잘린 문자열이 없다.
- [ ] 같은 문서가 중복 등록되지 않았다.
- [ ] 독립 검토자가 모든 출처 행의 문서명·발행처·발행일을 원문 표지와 전수 대조했는가?
- [ ] 같은 기준일이 여러 행·본문 표에 불필요하게 반복되지 않는다.
