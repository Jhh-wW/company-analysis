## 1. 이 프로그램이 뭐고 지금 뭐가 문제인가

회사 이름과 채용공고를 넣으면 AI가 기업 분석 보고서를 만들어 주는 웹 서비스다.
FastAPI + SQLite(WAL)로 만들었고 Docker로 Render에 올린다. 웹 프로세스는 1개다.
쓰는 방법은 두 가지 — ① 관리자가 로그인해서 직접 돌린다 ② 인사팀에게 `/k/<열쇠>` 공유 링크를 준다.

**지금 상태: 시험 2,165건이 전부 통과하지만 출시하면 안 된다.**

핵심 문제는 하나로 요약된다 — **문을 여러 겹 잠가 뒀는데, 어느 문도 자기가 잠겼다고 말하지 않는다.**

- 공유 링크를 누르면 보고서가 아니라 구글 로그인 화면이 뜬다 (겹1)
- 그 벽을 넘어도 보고서 화면이 409로 막힌다 (겹2)
- 그런데 `/healthz`는 200을 돌려주고, Render는 그 배포를 「성공」으로 찍는다
- 화면 문구는 "자료가 부실하다" / "화면은 그대로 쓸 수 있다"고 하는데 둘 다 사실이 아니다

리뷰 3건의 판정이 모두 같다: **수정 후 머지.**

## 2. 확정된 방향

1. **공유 링크는 「화면은 열고, PDF 파일만 3인 승인」으로 간다.** 사이트 전체 로그인 벽(`BETA_ADMIN_ONLY=1`)은 **계속 켜 두고**, 살아 있는 열쇠를 가진 요청만 예외로 통과시킨다.
2. **원격 저장소를 붙이고 push → CI 첫 통과 → `master` 병합** 순으로 간다. 로컬 병합만 하지 않는다.
3. **공유 링크 열쇠를 SHA-256 지문으로 저장한다.** 기존 링크는 무효가 되지만, 운영 배포가 아직 한 번도 없었으므로 실제로 잃는 링크는 없다.
4. **백업은 Render cron으로 자동화한다.** 사람이 손으로 치는 방식은 안 쓴다.
5. **유료(`PIPELINE=real`) 전환은 T1~T10을 전부 닫은 뒤에 한다.**

### T1. 공유 링크가 실제로 열리게 한다 ★ 최우선

두 겹을 **같이** 풀어야 한다. 하나만 풀면 여전히 아무것도 안 보인다.

**T1-A — 로그인 벽 예외**

- **대상**: `app/src/web/main.py:30-52` (`beta_admin_gate`), `app/src/features/auth/constants.py:46-57`
- **지금 상태**: `BETA_ADMIN_ONLY=1`일 때 통과 목록이 `/auth/*` · `/healthz` · `/static/`뿐이다. `/k`도 `/result`도 없어서 링크 방문자는 303으로 `/auth/login`에 튕긴다.
- **바꿀 것**:
  1. `BETA_PUBLIC_PATH_PREFIXES`에 `"/k/"`를 추가한다. 첫 요청에는 아직 쿠키가 없으므로 경로로 열어야 한다.
  2. 관리자 세션 확인이 실패한 뒤, **열쇠 쿠키가 있을 때만** `request_helpers._raw_share_key(request)`를 부르고 빈 문자열이 아니면 통과시킨다. 이 함수는 DB에 실제로 있고 살아 있는 열쇠만 인정한다(`app/src/web/request_helpers.py:251`).
  3. **`/admin`으로 시작하는 경로는 이 예외에서 제외한다.** (admin 라우터마다 자체 `require_admin`이 또 있지만 겹으로 둔다.)
  4. 순환 import가 나면 함수 안에서 지연 import 한다 — `app/src/web/runtime.py:82`가 쓰는 방식과 같다.
- **하지 말 것**: 쿠키가 없는 요청에까지 DB를 열지 않는다. 매 요청 SQLite를 여는 비용이 붙는다.

**T1-B — PDF 승인 409를 화면과 파일로 분리**

- **대상**: `app/src/web/routers/reports.py:269-274`(저장 보고서), `reports.py:323-328`(메모리 보고서)
- **지금 상태**: 두 곳 모두 `preview = released is None` 다음에 `if preview and not _is_admin_request(request): return _pdf_review_pending_response(...)`가 있어, 승인 없는 보고서를 관리자 아닌 모두에게 409로 막는다.
- **바꿀 것**: 위 `if` 블록 **두 곳만** 지운다. 바로 위의 `except PDFReleaseBlockedError` 처리(`reports.py:265-266`, `reports.py:319-320`)는 **그대로 둔다.** 화면에는 `internal_review_preview=True`가 이미 넘어가므로 「검수 전 미리보기」 배지로 표시한다.
- **건드리지 말 것**: `reports.py:700-703`의 `/download/pdf/{job_id}` 승인 검사. **파일로 나가는 것만 검수한다**는 원래 취지는 지킨다.
- **완료 기준 (T1 전체)**:
  1. `BETA_ADMIN_ONLY=1`, `PIPELINE=demo`로 서버를 띄운다
  2. 관리자로 보고서 1건을 만들고 공유 링크를 발급한다
  3. **쿠키가 하나도 없는 새 브라우저**로 `GET /k/<열쇠>` → 303 `/result/<ID>`
  4. 이어서 `GET /result/<ID>` → **200**, 보고서 본문이 보인다
  5. `GET /download/pdf/<ID>` → **409** (승인 전이므로 그대로 막혀야 정상)
  6. `GET /admin` → 로그인/거부. **200이 나오면 실패다.**
- **같이 깨진다**: `app/src/web/tests/test_pdf_download_route.py`, `app/src/web/tests/test_result_design.py`에 이 409를 기대하는 시험이 있다. 기대값을 「화면 200 · 파일 409」로 옮긴다. 고친 뒤 `python -m pytest app/src app/tools/tests -q`를 **전체로** 돌린다.

### T2. `PROVENANCE_SEAL_SECRET` 없이 시작하지 못하게 한다

- **대상**: `app/src/features/provenance/sources.py:41-51`, `render.yaml:51-52`, `app/src/web/runtime.py`의 `_lifespan`
- **지금 상태**: 위조 방지 도장 열쇠를 모듈 로드 때 한 번 정한다. 환경변수가 없거나 32바이트 미만이면 `secrets.token_bytes(32)`로 **그 프로세스에서만 쓰는 난수**를 만든다. `render.yaml:51`은 `sync: false`라 사람이 배포 화면에서 안 넣으면 빈 값이다.
  → 서버가 재시작되면 열쇠가 바뀌어 **저장된 보고서 전부가 409**가 되고, 화면에는 "근거가 충분하지 않아"라고 뜬다. 기술 장애를 사실 판정으로 뒤집어 보여준다.
- **바꿀 것**:
  1. `render.yaml`의 해당 항목을 `sync: false` 대신 `generateValue: true`로 바꿔 Render가 자동 생성하게 한다.
  2. `sources.py`에 `def seal_key_is_persistent() -> bool: return len(_configured_seal_key) >= 32`를 추가한다.
  3. `_lifespan`의 `evaluation_mode.validate_startup_configuration()` 바로 뒤에서 이 함수를 확인하고, 거짓이면 `RuntimeError`로 시작을 막는다. **단 `PIPELINE != "real"`이면 경고 로그만 남기고 통과시킨다** — 로컬 시험이 막히면 안 된다.
  4. `app/.env.example`에 "한 번 정하면 절대 바꾸지 않는 값"이라고 적는다. 운영 중에 바꾸면 그 이전 보고서가 전부 다시 막힌다.
- **완료 기준**: 같은 `STORAGE_DB_PATH`로 프로세스를 두 번 띄운다. 1번에서 만든 보고서를 2번에서 `/result/<ID>`로 열면 **200**이다. 그리고 `PROVENANCE_SEAL_SECRET`을 지우고 `PIPELINE=real`로 띄우면 요청을 받기 전에 시작이 실패한다.

### T3. 배포 브랜치·원격 저장소·CI

- **대상**: 저장소 전체, `.github/workflows/quality-gate.yml:5-7`, `render.yaml`
- **지금 상태**: 원격이 **하나도 없다**(`git remote -v`가 비어 있음). `beta-runtime`(`71edf08`)이 `master`(`d4ef0a4`)보다 **21커밋 앞선다**. CI는 `push: branches: [master]`와 `pull_request`에서만 도는데 push한 적이 없어 **한 번도 실행된 적이 없다.** 즉 2,165건 통과는 이 컴퓨터의 파이썬 3.14.6 기준이고, 배포는 3.13.15다. 그 조합은 아무도 시험하지 않았다.
  또 `master`의 `sessions.py`는 로그인 토큰을 **평문으로** 저장한다. 그 코드가 올라가면 DB 유출이 곧 관리자 로그인이다.
- **바꿀 것**: 순서를 지킨다.
  1. 원격을 붙인다 — `git remote add origin <주소>`
  2. `beta-runtime`을 push하고 pull request로 CI를 **처음으로** 통과시킨다 (지금 바로 해도 된다)
  3. T1~T10을 다 닫은 뒤 `master`로 병합한다
  4. 병합 전에는 Render 자동 배포를 켜지 않는다
- **완료 기준**: `git rev-list --left-right --count master...beta-runtime`이 `0	0`이고, GitHub Actions `quality-gate` 기록에 `tests`와 `container-smoke` 두 작업이 모두 초록으로 남아 있다.
- **미리 알릴 것**: `master`로 만들어진 SQLite가 있는 서버에 새 코드를 올리면 `db.py:201-209`의 `_migrate_sessions_to_token_hash()`가 **기존 로그인 세션을 전부 폐기한다.** 의도된 동작이다. 배포 직후 전원 재로그인이 필요하다고 미리 알린다.

### T4. 공유 링크 열쇠를 해시로 저장

- **대상**: `app/src/features/sharelink/store.py:26`(`CREATE_SQL`), 같은 파일 `:99` `:129` `:142`, `app/tools/backup_sqlite.py:170`
- **지금 상태**: 128비트 열쇠를 `key TEXT PRIMARY KEY`에 **원문 그대로** 저장하고 같은 원문으로 조회한다. 세션 토큰은 이미 SHA-256 지문으로 저장하는데 여기만 평문이다. 링크 하나가 **하루 3,000원짜리 출입증**이므로, DB나 백업 파일을 읽은 사람은 바로 남의 예산을 쓸 수 있다.
- **바꿀 것**: 세션과 같은 방식으로 간다. `key_hash` 열을 두고 SHA-256 지문을 저장한다. 요청으로 받은 `/k/{key}` 값을 해시해서 조회한다. 원문은 발급하는 순간 화면과 QR에만 보여 준다. 기존 행은 migration에서 옮긴다(원문을 해시로 바꿔 채우고 원문 열을 지운다).
- **완료 기준**: 새 링크를 발급한 뒤 `SELECT * FROM share_links`와 백업 파일 어디에도 URL에 들어가는 원문 열쇠가 없다. 원문 링크는 정상 접속되고 틀린 열쇠는 거부된다. 하루 3,000원 상한과 링크 폐기가 기존과 똑같이 동작한다.
- **같이 깨진다**: `app/src/web/routers/admin.py:459`(발급) `:653`(링크 상세) `:662`(보고서 연결) `:766`(폐기), QR 생성, 링크 복사 화면.

### T5. `/healthz`를 「살아 있나」와 「쓸 수 있나」로 나눈다

- **대상**: `app/src/web/routers/health.py:15-23`, `render.yaml:10`
- **지금 상태**: `runtime._check_storage_read_ready()`로 SQLite에 `SELECT 1` **한 번만** 하고 200을 준다. 그래서 ① 구글 로그인 설정이 비어 아무도 못 들어와도 200 ② 비용 원장이 잠겨 유료 조사가 전부 막혀도 200이다. `render.yaml:12`가 `autoDeployTrigger: checksPass`이므로 **아무도 못 쓰는 배포가 「성공」으로 찍히고 롤백도 안 된다.**
- **바꿀 것**:
  - `/healthz` = liveness. 프로세스가 살아 있으면 200. 지금 동작 유지.
  - `/readyz` = readiness를 새로 만들고 `render.yaml`의 `healthCheckPath`를 여기로 바꾼다. 아래를 검사해 하나라도 어긋나면 **503**:
    1. SQLite 읽기 (기존 검사)
    2. `BETA_ADMIN_ONLY=1`인데 `ADMIN_EMAILS` · `GOOGLE_CLIENT_ID` · `GOOGLE_CLIENT_SECRET` · `GOOGLE_REDIRECT_URI` 중 빈 값이 있으면 503
    3. `PIPELINE=real`인데 `paid_runtime._BUDGET_STORE_HEALTHY`가 거짓이면 503 (demo 모드에서는 검사하지 않는다)
  - 응답 본문에 **어느 검사가 실패했는지** 넣는다. 단 값은 절대 넣지 않고 항목 이름만 넣는다.
  - `/readyz`도 `BETA_PUBLIC_PATHS`에 추가한다. 안 그러면 로그인 벽에 막혀 Render가 못 부른다.
- **완료 기준**: `GOOGLE_CLIENT_ID`를 지우고 띄우면 `/readyz`가 503이고 본문에 그 항목 이름이 있다. 전부 채우면 200이다. `PIPELINE=real`에서 `runs.jsonl` 끝에 `{"run_id":"x"}` 한 줄을 붙이고 띄우면 `/readyz`가 503, 같은 조건의 `demo`는 200이다.
- ⚠️ **이걸 켜면 설정이 빠진 배포는 아예 안 올라간다.** 그게 목적이지만 첫 배포가 한 번 실패할 수 있다.

### T6. 종료 대기 10초 → 240초

- **대상**: `app/src/web/job_runtime.py:88` (`_JOB_DRAIN_TIMEOUT_SEC = 10.0`)
- **지금 상태**: `render.yaml:11`이 `maxShutdownDelaySeconds: 300`으로 300초를 주는데 앱은 10초만 기다리고 진행 중인 조사를 취소한다. 작업 상태는 메모리(`_JOBS`)에만 있어서 재시작 뒤 사라지고, 사용자가 진행 주소를 다시 열면 410이 뜬다.
- **바꿀 것**: `240.0`으로 올린다. 그리고 종료가 시작되면 **신규 작업 접수를 먼저 막는다.** 유예 안에 못 끝낸 작업은 DB에 `interrupted`로 남겨, 재시작 뒤 사용자가 410 대신 "중단됨 · 다시 시도" 안내를 보게 한다.
- **완료 기준**: 30초 걸리는 가짜 provider 작업을 돌리는 중에 SIGTERM을 보내면 작업이 정상 완료되고 결과 주소가 열린다. 유예를 넘긴 작업은 재시작 뒤 410이 아니라 중단 사유와 재시도 안내가 나온다.

### T7. `/result` 열 때마다 PDF를 다시 만드는 것을 멈춘다

- **대상**: `app/src/web/routers/reports.py:244`(`async def result_page`) 안의 `:261`·`:315`, `reports.py:420-448`(`_release_state`)
- **지금 상태**: 화면을 열 때마다 `_release_state()`가 `prepare_pdf_release(report)`를 부른다. PDF를 처음부터 다시 만들고 모든 페이지를 1.5배율 PNG로 그려 지문을 계산한다. 결과를 저장하지 않아 새로고침마다 통째로 반복한다. 게다가 `result_page`는 `async def`인데 이 무거운 계산을 `await asyncio.to_thread(...)` 없이 **그 자리에서** 부른다. 워커가 1개(`app/Dockerfile:47`)라서 그 0.4~0.6초 동안 **다른 모든 요청이 대기한다** — `/api/progress` 자동 갱신, 남의 첫 화면, `/healthz` 전부.
- **바꿀 것**: 두 가지를 같이 한다.
  1. `_release_state`는 동기 함수로 두고 호출부만 `await asyncio.to_thread(_release_state, report_id=..., report=...)`로 바꾼다. `result_page` · `review_pdf` · `download_pdf` · `send_to_notion` 네 곳이다. `import asyncio`가 필요하다.

- **완료 기준**: 같은 `/result/<ID>`를 두 번째로 요청하면 응답이 0.05초 아래다. `/result`를 처리하는 중에 다른 창에서 `/healthz`를 부르면 즉시 200이 온다.
- **주의**: `_release_state` 안의 `storage_db.connect()`가 다른 실행 흐름에서 열린다. `db.py`는 요청마다 연결을 새로 열고 닫게 이미 설계돼 있어 문제없지만, 옮긴 뒤 전체 시험을 한 번 돌린다.

### T11. 돈이 나가는 구간을 컨텍스트 매니저로 감싼다

- **대상**: `app/src/web/routers/analysis.py:425-1031`(`confirm_page`, 607줄), `app/src/web/job_runtime.py:864-1167`(`_start_with_reserved_slot`, 304줄)
- **지금 상태**: 함수 하나에 CSRF 확인 · 공유 링크 범위 검사 · DART 회사 식별(유료) · Google Places 검색(유료) · 후보 서명 검증 · 일회용 토큰 발급 · 비용 표식 시작/취소/정산이 전부 들어 있다. 유료 호출 앞뒤로 `_begin_paid_phase` / `_cancel_paid_phase` / `record_end`를 짝맞춰 불러야 하는 갈래가 여러 겹이다.
  → 갈래를 하나 더 넣으면서 정리를 빠뜨리면 비용 표식이 「진행 중」으로 남고, 그 통장의 유료 조사가 **사람이 원장을 확인할 때까지 닫힌다.** 지금 코드에서 실제 누락은 찾지 못했다. 「지금 틀렸다」가 아니라 「다음 수정에서 틀리기 쉽다」는 지적이다.
- **바꿀 것**: **전면 재작성이나 폴더 구조 변경은 하지 않는다.** `app/src/web/paid_runtime.py`에 컨텍스트 매니저를 하나 추가하고, `confirm_page()`의 유료 구간을 **하나씩만** 옮긴다. 옮길 때마다 시험을 돌린다.

```python
@contextlib.contextmanager
def paid_phase(*, run_id: str, phase: str, share_key: str, cap_krw: float):
    """provider를 부르기 전 표식을 잡고, 어떤 갈래로 빠져나가도 정확히 한 번 닫는다."""
    ticket = _begin_paid_phase(
        run_id=run_id, phase=phase, share_key=share_key, cap_krw=cap_krw
    )
    if ticket is None:
        yield None
        return
    settled = False
    try:
        yield ticket
    except BaseException:
        _settle_paid_phase(ticket, amount_krw=0.0, billing_uncertain=True)
        settled = True
        raise
    finally:
        if not settled:
            _cancel_paid_phase(ticket)
```

- ⚠️ **`billing_uncertain`은 "이미 provider를 불렀을 수 있다"는 뜻이다.** 아직 provider를 안 부른 갈래에서 `_settle`을 부르면 **안 쓴 돈을 쓴 것으로 기록한다.** 위 예시가 `except`에서 `_settle`, 정상 종료에서 `_cancel`을 부르는 이유가 이것이다. 옮길 때 이 구분을 반드시 지킨다.
- **완료 기준**: `confirm_page()` 안에서 `_begin_paid_phase(`를 직접 부르는 곳이 0개고, `python -m pytest app/src app/tools/tests -q`가 전부 통과한다. 통과를 확인한 커밋 해시를 함께 남긴다.
- **함수를 통째로 쪼개는 것은 별도 승인 뒤에 한다.**
