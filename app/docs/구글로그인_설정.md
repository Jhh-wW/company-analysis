# 구글 로그인 설정 안내

**결론:** 관리자 화면을 쓰려면 (1) 구글 클라우드 콘솔에서 열쇠 4개를 발급받고,
(2) 그 열쇠를 이 컴퓨터에 "환경변수(프로그램이 실행될 때 참고하는 임시 설정값)"로
넣은 다음, (3) 서버를 켜면 됩니다. 아래 순서를 그대로 따라 하시면 됩니다.

이 문서는 개발 지식이 없어도 따라 할 수 있게 썼습니다.
**구글이 화면 문구를 자주 바꿉니다** — 실제로 2024~2025년에 크게 바뀌었습니다
(2026-08-15 기준으로 최신 이름을 적고, 옛 이름을 괄호로 함께 적었습니다).
아래와 완전히 똑같지 않아도 **「대상」·「테스트 사용자」·「클라이언트」** 같은
단어가 보이면 그 화면이 맞습니다.

이 프로그램은 **Windows**에서 돌립니다. 아래 명령어는 모두
**PowerShell**(윈도우 시작 메뉴에서 "PowerShell"이라고 검색하면 나오는 파란/검은
창) 기준입니다.

---

## 준비물

- 구글 계정 (본인 소유 아무 계정이나 가능. 회사 계정도 됩니다)
- 이 프로그램을 실행할 컴퓨터 (Windows)
- 로그인을 시도할 사람들의 **구글 이메일 주소 목록** (미리 알아두세요, 2단계에서 씁니다)

---

## 1단계 — 구글 클라우드 콘솔에서 프로젝트 만들기

"프로젝트"는 구글이 "이 열쇠들이 어느 앱 것인지" 구분하는 상자 하나입니다.

1. 브라우저에서 <https://console.cloud.google.com/> 으로 들어갑니다.
2. 화면 위쪽, 구글 로고 옆의 **프로젝트 선택** (또는 이미 프로젝트가 있으면
   그 이름)을 누릅니다.
3. 오른쪽 위 **새 프로젝트**를 누릅니다.
4. 프로젝트 이름에 `기업분석-로그인` 처럼 알아보기 쉬운 이름을 넣고
   **만들기**를 누릅니다.
5. 몇 초 기다리면 프로젝트가 생성됩니다. 화면 위쪽에서 **방금 만든
   프로젝트가 선택되어 있는지** 확인합니다 (다른 프로젝트가 선택된 채로
   다음 단계를 하면 열쇠가 엉뚱한 곳에 생깁니다).

---

## 2단계 — 동의 화면 설정 + 테스트 사용자 등록

"동의 화면"은 사용자가 로그인할 때 "이 앱이 당신의 이메일을 보려고 합니다"라고
보여주는 화면입니다. 이걸 먼저 만들어야 열쇠를 발급받을 수 있습니다.

> ⚠️ **구글이 2024~2025년에 이 메뉴 이름을 바꿨습니다** (2026-08-15 확인).
> 옛 이름 「OAuth 동의 화면」이 지금은 **「Google Auth Platform」**이고,
> 그 안이 **브랜딩(Branding) · 대상(Audience) · 클라이언트(Clients)** 로 나뉩니다.
> 화면에 옛 이름이 보이면 그것도 맞습니다 — 계정마다 전환 시기가 다릅니다.

1. 왼쪽 메뉴(☰)에서 **API 및 서비스** → **Google Auth Platform**
   (옛 이름: **OAuth 동의 화면**)을 누릅니다.
2. 처음이면 **시작하기(Get started)**가 나옵니다. 앱 이름 · 사용자 지원
   이메일을 채웁니다.
3. **대상(Audience)** 에서 **외부(External)**를 고릅니다.
   (구글 워크스페이스 회사 계정이 아니면 이 선택지만 나옵니다)
4. 개발자 연락처 이메일을 채우고 저장합니다. (이 값들은 사용자에게 보이는
   안내문일 뿐이라 자유롭게 적어도 됩니다)
5. ★ **왼쪽 「대상(Audience)」 메뉴**로 들어가 **테스트 사용자(Test users)**
   에서 **+ 사용자 추가(Add users)**를 누르고, 로그인할 사람들의 구글
   이메일을 한 줄에 하나씩 추가합니다.
   **여기에 없는 이메일은 로그인 자체가 안 됩니다.**
6. 「데이터 액세스(Data access)」·「범위(Scopes)」는 **손대지 않아도 됩니다.**
   이 프로그램은 이메일 확인용 최소 권한만 씁니다.

> ⚠️ **여기서 등록하는 "테스트 사용자" 목록과, 이 프로그램의
> "관리자 이메일(`ADMIN_EMAILS`)" 목록은 서로 다른 것입니다.**
> - 구글 테스트 사용자 목록 = **로그인 자체가 되는지**를 구글이 정하는 관문
> - 우리 프로그램의 관리자 목록 = 로그인은 됐는데, **관리자로 인정할지**를
>   우리 프로그램이 정하는 관문
>
> 두 목록에 같은 이메일을 넣어야 그 사람이 "로그인도 되고 관리자 화면도
> 보이는" 상태가 됩니다.

---

## 3단계 — 사용자 인증 정보(열쇠) 발급받기

1. 왼쪽 메뉴에서 **Google Auth Platform** → **클라이언트(Clients)** 를 누릅니다.
   (옛 화면이면 **API 및 서비스** → **사용자 인증 정보(Credentials)**)
2. **+ 클라이언트 만들기(Create client)** 를 누릅니다.
   (옛 화면이면 **+ 사용자 인증 정보 만들기** → **OAuth 클라이언트 ID**)
3. 애플리케이션 유형에서 **웹 애플리케이션**을 선택합니다.
4. 이름은 아무거나 적어도 됩니다 (예: `기업분석-웹`).
5. ★ **칸이 두 개라 헷갈립니다. 반드시 아래쪽 칸에 넣으세요.**

   | 칸 이름 | 무엇 | 우리는 |
   |---|---|---|
   | **승인된 JavaScript 원본** | 주소만 (`http://localhost:8000`). **경로를 못 넣는다** | **비워둔다** |
   | **승인된 리디렉션 URI** | 경로까지 (`.../auth/callback`) | ⭕ **여기에 넣는다** |

   > 위 칸에 넣으면 **「올바르지 않은 출처: URI는 경로를 포함하거나 '/'로 끝날 수 없습니다」**
   > 오류가 납니다. 칸을 잘못 고른 것이지 주소가 틀린 게 아닙니다.
   > 그 줄의 🗑️을 눌러 지우고 아래 칸에 다시 넣으세요.

   **승인된 리디렉션 URI**(로그인이 끝난 뒤 구글이 돌려보낼 주소) 항목에서
   **+ URI 추가**를 누르고 아래 주소를 **정확히 그대로** 넣습니다.
   ```
   http://localhost:8000/auth/callback
   ```
   (다른 컴퓨터에 올려서 쓸 때는 `localhost:8000` 자리를 실제 주소로
   바꿔야 합니다. 그때는 뒤쪽 "배포할 때" 항목을 다시 보세요)
6. **만들기**를 누르면 화면에 **클라이언트 ID**와 **클라이언트 보안 비밀**
   두 값이 뜹니다. **이 창을 닫기 전에 두 값을 복사해 메모장 같은 곳에
   잠시 붙여넣어 두세요.** (나중에 클라이언트 보안 비밀은 다시 안
   보여줍니다 — 잃어버리면 이 단계를 다시 해야 합니다)

## 4단계 — 발급받은 값을 환경변수로 넣기 (PowerShell)

방금 받은 값 2개 + 리디렉션 주소를 컴퓨터에 "이번 실행 동안만" 기억시킵니다.
PowerShell 창을 열고, **`app` 폴더로 이동한 뒤** 아래 4줄을 한 줄씩
붙여넣고 엔터를 누릅니다. **따옴표 안의 값만 본인 것으로 바꾸세요.**

```powershell
cd "C:\프로젝트를_받은_폴더\기업분석2\app"
$env:GOOGLE_CLIENT_ID = "여기에_3단계에서_복사한_클라이언트ID"
$env:GOOGLE_CLIENT_SECRET = "여기에_3단계에서_복사한_클라이언트보안비밀"
$env:GOOGLE_REDIRECT_URI = "http://localhost:8000/auth/callback"
```

**로컬(내 컴퓨터)에서 시험 삼아 켤 때만** 아래 한 줄을 추가로 넣습니다.

```powershell
$env:AUTH_COOKIE_INSECURE = "1"
```

> ⚠️ **`AUTH_COOKIE_INSECURE`는 로컬 시험용입니다. 실제로 인터넷에
> 올려서(배포해서) 쓸 때는 이 줄을 절대 넣지 마세요.** 이 값을 켜 두면
> 로그인 기록(쿠키)이 암호화되지 않은 통로로 오갈 수 있어, 다른 사람이
> 훔쳐볼 위험이 생깁니다. `http://localhost`에서만 어쩔 수 없이 켜는
> 예외입니다.

관리자로 로그인할 이메일을 반드시 넣습니다. 여러 명이면 콤마로 구분합니다.

```powershell
$env:ADMIN_EMAILS = "admin@example.com,other-admin@example.com"
```

이 줄을 넣지 않으면 관리자가 한 명도 없어 관리자 화면에 들어갈 수 없습니다.
실제 이메일은 코드나 문서가 아니라 환경변수에만 보관합니다.

> ℹ️ 이렇게 넣은 값은 **이 PowerShell 창을 닫으면 사라집니다.** 컴퓨터를
> 새로 켜거나 창을 새로 열 때마다 위 명령어를 다시 입력해야 합니다.
> 매번 입력하기 번거로우면 "환경 변수를 영구히 저장하는 법"은 검색을
> 통해 별도로 찾아보시거나, 담당자에게 문의해 주세요.

## 5단계 — 서버 켜기

같은 PowerShell 창에서 이어서 입력합니다.

```powershell
pip install -r requirements.txt
python -m uvicorn src.web.main:app --port 8000
```

브라우저에서 **http://localhost:8000** 을 열고, 화면 오른쪽 위의
**「구글로 로그인」**을 눌러 확인합니다.

---

## ⚠️ 테스트 모드 제약 (반드시 읽어주세요)

동의 화면을 "테스트(Testing)" 상태로 두면(2단계에서 그대로 뒀다면 이
상태입니다), 구글이 정식으로 앱을 검토하지 않은 상태라 아래 제약이
따라옵니다.

| 제약 | 내용 |
|---|---|
| **로그인 가능 인원** | 최대 **100명**. 2단계에서 등록한 테스트 사용자만 로그인됩니다 |
| **로그인 유지 기간** | **7일마다** 다시 로그인해야 합니다 (구글이 강제로 로그인을 풀어버립니다) |
| **경고 화면** | 로그인할 때 "Google에서 확인하지 않은 앱입니다"라는 **주황색 경고**가 뜹니다 |

**경고 화면이 뜨면** 아래처럼 진행하시면 됩니다 (당황하지 않으셔도
됩니다 — 테스트 사용자로 등록된 본인 계정이면 안전합니다).

1. 경고 화면 아래쪽의 **고급(Advanced)**을 누릅니다.
2. **"OO(으)로 이동(안전하지 않음)"** 링크를 누릅니다.
3. 평소처럼 계정을 선택하면 로그인이 이어집니다.

이 경고를 없애려면 구글의 **정식 앱 검토**를 신청해야 하는데, 이는 이
1단계 범위를 벗어나는 별도 작업입니다. 지금은 관리자 몇 명만 쓰는
용도이므로 테스트 모드로 충분합니다.

## 배포할 때 (인터넷에 올려서 여러 사람이 쓸 때)

1. **3단계**로 돌아가 **승인된 리디렉션 URI**에 실제 주소를 추가로
   등록합니다. 예: `https://내도메인.com/auth/callback`
2. **4단계**의 `GOOGLE_REDIRECT_URI` 값도 그 주소로 바꿉니다.
3. **`AUTH_COOKIE_INSECURE`는 반드시 빼거나 값을 비웁니다.** (로컬
   전용 예외라 배포 환경에 남아있으면 안 됩니다)
4. 서버가 실제로 `https`(자물쇠 표시가 붙는 주소)로 열려 있는지
   확인합니다. 아니면 로그인 후 쿠키가 심기지 않아 로그인이 반복해서
   풀립니다.

## 자주 틀리는 지점 (미리 확인하세요)

1. **리디렉션 URI 오탈자.** `http://localhost:8000/auth/callback`을
   3단계 구글 화면과 4단계 PowerShell 양쪽에 **글자 하나까지 똑같이**
   넣어야 합니다. 끝에 `/`가 하나 더 붙거나, `http`와 `https`를
   헷갈리면 로그인이 실패합니다.
2. **테스트 사용자 등록을 빼먹음.** 2단계에서 로그인할 사람의 이메일을
   등록하지 않으면, 3~5단계를 다 맞게 해도 그 사람은 "액세스 차단됨"
   화면만 봅니다.
3. **테스트 사용자 ≠ 관리자.** 2단계에 등록해서 로그인은 되는데,
   `ADMIN_EMAILS`(또는 기본 관리자)에 없으면 로그인은 되지만
   "관리자만 볼 수 있는 화면입니다"로 보내집니다. 이는 정상 동작입니다.
4. **`AUTH_COOKIE_INSECURE`를 안 켠 채 로컬에서 시험함.** `http://`
   (자물쇠 없는 주소)인 내 컴퓨터에서는 이 값을 `1`로 켜야 로그인
   기록이 남습니다. 안 켜면 로그인은 성공했다고 나오는데 새로고침하면
   다시 로그아웃 상태로 보입니다.
5. **PowerShell 창을 닫고 다시 엶.** 환경변수는 그 창에만 남아있다가
   창을 닫으면 사라집니다. 서버가 갑자기 "로그인을 쓸 수 없습니다"라고
   하면, 4단계 명령어부터 다시 입력했는지 확인하세요.

## 참고 — 환경변수 이름 정리

| 이름 | 필수 여부 | 값 |
|---|---|---|
| `GOOGLE_CLIENT_ID` | 필수 | 3단계에서 발급받은 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | 필수 | 3단계에서 발급받은 클라이언트 보안 비밀 |
| `GOOGLE_REDIRECT_URI` | 필수 | `http://localhost:8000/auth/callback` (배포 시 실제 주소) |
| `ADMIN_EMAILS` | **필수** | 관리자로 인정할 이메일, 여러 명이면 콤마로 구분 |
| `AUTH_COOKIE_INSECURE` | **로컬에서만** 선택 | 로컬 시험 중에만 `1`. 배포 시 반드시 빼기 |
