# 배포 리허설 사용법

**결론 먼저.** `배포리허설켜기.ps1`은 인터넷에 올리기 «직전»의 최종본을 내 컴퓨터에서
그대로 켜 보는 실행기입니다. 진짜 조사(PIPELINE=real)로 돌고, 관리자 로그인 게이트도
배포와 똑같이 켜져 있어서 **구글 로그인을 통과해야만 관리자 화면까지 볼 수 있습니다.**

기존 실행기 3개로는 이걸 못 했습니다. `로컬데모켜기.ps1`은 관리자는 되지만 가짜
데이터이고, `실시간성능시험켜기.ps1`은 진짜 데이터지만 로그인 게이트를 꺼 버립니다.

---

## 1. 준비물 (없으면 실행기가 멈춥니다)

이 실행기는 «조용히 열리지 않습니다». 아래가 하나라도 없으면 시작을 거부합니다.

| 필요한 것 | 어디서 얻나 | 어떻게 넘기나 |
|---|---|---|
| 관리자 이메일 | 본인 구글 계정 | `-AdminEmails` 인자 |
| `GOOGLE_CLIENT_ID` · `GOOGLE_CLIENT_SECRET` | 구글 클라우드 콘솔 | 환경변수 · 파일 · 실행 중 질문 |
| `ANTHROPIC_API_KEY` · `DART_API_KEY` · `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` | 각 서비스 | 환경변수 · 파일 · 실행 중 질문 |
| 리디렉션 URI 등록 | 구글 클라우드 콘솔 (사람이 직접) | 아래 2번 |

> 값은 어디에도 저장되지 않습니다. 화면에도 「있다/없다」만 찍고 값은 안 찍습니다.

### ★ 구글 로그인 말고 다른 길은 없습니다

코드를 확인한 결과입니다. 이 저장소에는 OAuth(구글 로그인) 없이 관리자가 되는
「로컬 데모 입구」가 있긴 한데, 그 입구는 **PIPELINE이 demo이고 BETA_ADMIN_ONLY가 0일
때만** 열립니다 (`src/features/auth/logic.py:171-186`). 배포 리허설은 정반대
(real + 1)라 그 문은 닫혀 있습니다. 즉 **구글 로그인이 필수**입니다.

---

## 2. 구글 클라우드 콘솔에 «미리» 해 둘 일 (사람의 일)

리디렉션 URI(로그인이 끝난 뒤 구글이 브라우저를 돌려보낼 주소)를 등록해야 합니다.
등록이 안 돼 있으면 구글이 `redirect_uri_mismatch`라며 거절합니다.

**승인된 리디렉션 URI**에 아래 주소를 «그대로» 추가하세요. 8030은 기본 포트입니다.

```
http://127.0.0.1:8030/auth/callback
```

화면 위치와 클릭 순서는 `docs/구글로그인_설정.md`의 3단계와 같습니다.
다른 포트를 쓸 거면 그 포트로 등록해야 합니다 (실행기가 켜질 때 등록할 주소를
화면에 다시 알려줍니다).

---

## 3. 켜는 법

PowerShell을 열고 `app` 폴더에서 아래를 입력합니다. `본인@gmail.com` 자리에는
관리자로 쓸 «본인 구글 계정»을 넣으세요.

```powershell
.\배포리허설켜기.ps1 -AdminEmails "본인@gmail.com" -ConfirmRealSpending
```

`-ConfirmRealSpending`은 **돈이 나간다는 걸 알고 있다**는 확인입니다. 이걸 빼면
실행기가 예상비용 안내만 보여주고 멈춥니다.

키를 아직 환경변수에 넣지 않았다면, 실행기가 없는 것만 하나씩 물어봅니다.
보안 비밀은 입력해도 화면에 보이지 않습니다.

파일로 한 번에 넘기고 싶다면 `이름=값` 형식의 파일을 만들어 이렇게 씁니다.

```powershell
.\배포리허설켜기.ps1 -AdminEmails "본인@gmail.com" -ConfirmRealSpending -ProviderEnvFile "C:\내폴더\키.txt"
```

### 자주 쓰는 다른 인자

| 인자 | 뜻 |
|---|---|
| `-Port 8031` | 8030이 이미 쓰이고 있을 때. 리디렉션 URI도 같은 포트로 등록해야 합니다 |
| `-DisableEngineV2` | 새 엔진(v2) 대신 기존 v1로 돌려 비교할 때 |
| `-DeleteDataOnExit` | 끄는 순간 이번 실행 데이터를 지웁니다 |
| `-GoogleRedirectUri` | `localhost` 쪽 주소를 등록해 뒀을 때 |

---

## 4. 들어가는 법

1. 브라우저에서 **http://127.0.0.1:8030** 을 엽니다.
2. 곧바로 로그인 화면으로 넘어갑니다. 이게 정상입니다 — 배포와 같은 게이트입니다.
3. `-AdminEmails`에 넣은 계정으로 구글 로그인을 합니다.
4. 관리자 화면은 **http://127.0.0.1:8030/admin** 입니다.

다른 계정으로 로그인하면 「관리자가 아닙니다」 화면이 나옵니다. 이것도 정상입니다.

끄려면 실행한 창에서 **Ctrl+C**를 누릅니다.

---

## 5. 배포와 «일부러» 다르게 둔 것 두 가지

리허설이 배포와 100% 같지는 않습니다. 아래 두 가지는 로컬에서 그렇게 해야만
동작하기 때문에 다릅니다. 숨기지 않고 적어 둡니다.

**하나 — 주소가 https 공개주소가 아니라 `http://127.0.0.1`입니다.**
그래서 쿠키(로그인 상태를 기억하는 작은 표식)의 HTTPS 전용 표시를 잠시 끕니다.
앱은 이 설정만으로 쿠키를 약하게 만들지 않고, 요청·서버·접속자가 모두 내 컴퓨터일
때만 예외를 줍니다 (`src/web/request_helpers.py:574-605`).

**둘 — 배포 계약값(`DEPLOYMENT_RUNTIME_CONTRACT`)이 `local-web-v1`입니다.**
배포가 쓰는 `render-admin-real-no-forwarded-v1`을 로컬에 그대로 쓰면 **모든 저장·실행
요청(POST)이 거부됩니다.** 그 계약에서는 요청의 출처가 고정된 «https» 공개주소와
정확히 같아야 하는데, 로컬 브라우저는 `http://127.0.0.1:8030`을 보내기 때문입니다
(`src/web/request_helpers.py:727-741`, `src/web/deployment_mode.py:98-110`).

> 로그인 게이트(`BETA_ADMIN_ONLY=1`)는 이 계약과 무관하게 배포와 똑같이 켜져 있습니다.

## 6. 비용과 데이터

**비용.** 진짜 조사라 조사 1건마다 실제 요금이 나갑니다. 저장소에 적힌 단계별
예상비용 차단 기준은 후보 50원 / 회사확정 100원 / OCR 100원 / 본조사 900원입니다
(`src/features/budget/constants.py:104-109`).

이건 청구서를 막아 주는 상한이 «아닙니다». 호출하기 전에 예상액을 미리 잡아 두고
넘치면 그 단계를 거절하는 기준일 뿐이라, 실제 단가·사용량에 따라 넘을 수 있습니다.

**데이터.** 실행할 때마다 `app\.local_deployment_rehearsal_runs` 아래에 «이번 실행
전용» 폴더가 새로 생기고, 데이터베이스·기록·캐시가 전부 그 안에만 쌓입니다.
개인정보가 들어갈 수 있으니 24시간 안에 확인하고 지우는 걸 권합니다.

## 7. 안 될 때

| 증상 | 원인과 할 일 |
|---|---|
| 구글이 `redirect_uri_mismatch`라고 함 | 2번의 주소가 콘솔에 등록 안 됐거나 포트가 다릅니다 |
| 로그인 화면 대신 「준비하고 있습니다」 | 구글 값 3개 중 하나가 비었습니다. 실행기 첫 화면의 yes/no를 확인하세요 |
| 로그인은 됐는데 「관리자가 아닙니다」 | `-AdminEmails`에 넣은 주소와 로그인한 계정이 다릅니다 |
| `포트 8030 는 이미 사용 중입니다` | `-Port 8031`처럼 다른 번호를 쓰고, 리디렉션 URI도 그 포트로 등록하세요 |
| 실행기가 예상비용만 보여주고 멈춤 | `-ConfirmRealSpending`을 빠뜨렸습니다 |
