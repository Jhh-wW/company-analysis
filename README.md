## 무엇을 해결하나

취업준비생이 회사 한 곳을 제대로 알아보려면 사업보고서·IR 자료·회사 홈페이지를 각각 열어
읽고 대조해야 합니다. 시간도 오래 걸리지만 더 큰 문제는 **어디까지가 회사가 공식적으로 밝힌
사실이고 어디부터가 기사나 블로그의 해석인지 구분이 안 된다**는 점입니다.

이 서비스는 그 구분을 자동으로 합니다. 금융감독원 전자공시(DART)와 회사 공식 웹사이트에서
**원문 그대로** 근거를 모으고, 원문에 없는 문장은 보고서에 넣지 않습니다.
뉴스 검색과 AI의 자유 서술은 설계 단계에서 배제했습니다.

## 이렇게 나옵니다

아래는 실제로 생성된 보고서입니다. 모든 문장 옆의 작은 숫자는 **그 문장이 어느 공식 원문에서
왔는지**를 가리키는 각주입니다.

![생성된 보고서의 표지와 핵심 요약](docs/images/03-report.png)

장마다 근거 사실과 **범위·한계**를 같이 적습니다. 확인되지 않은 것은 "확인되지 않음"이라고
쓰지, 그럴듯한 문장으로 메우지 않습니다.

![4장 - 3개년 실적 차트와 근거 사실 카드](docs/images/04-report-chapter.png)

보고서 목차는 **10개 장 + 부록**으로 고정입니다. 회사마다 목차가 달라지면 지원자가 여러 회사를
비교할 수 없기 때문입니다.

| 장 | 내용 | 장 | 내용 |
|---|---|---|---|
| 0 | 핵심 요약 | 6 | 성장 전략 `#미래` |
| 1 | 기업 정체성 | 7 | 사업 운영과 파트너 구조 |
| 2 | 사업 구조와 수익 모델 | 8 | 인재상과 일하는 방식 |
| 3 | 핵심 제품·서비스 | 9 | 경쟁사 대비 핵심 경쟁력 *(조건부)* |
| 4 | 3개년 주요 변화와 실행 `#과거` | 10 | 부록 — 출처와 검증 상태 |
| 5 | 당면 과제와 대응 `#현재` | | |

9장은 **양사의 공식 원문이 같은 기준으로 존재할 때만** 씁니다. 조건이 안 맞으면 억지로
비교하지 않고 9장을 빼고 `PARTIAL` 등급으로 표시합니다.

## 핵심 기능

- **공식 근거만 수집** — DART 전자공시와 회사 공식 웹사이트의 원문 조각을 모읍니다.
  각 문장이 어느 원문 어느 위치에서 왔는지 식별자로 추적됩니다.
- **사실 원장과 단일 소유** — 같은 사실이 여러 장에 중복해서 나오지 않도록 사실마다 소유
  장을 하나만 둡니다. 과거·현재·미래 시점도 사실 단위로 구분합니다.
- **출고 게이트(fail-closed)** — 목차·출처·수치·중복·금지 문구 검사를 하나라도 통과하지
  못하면 **부분 공개 없이 전체를 막습니다**(`GATE_STOPPED`).
- **웹 · PDF · Notion 동등 출력** — 같은 보고서 객체를 채널만 바꿔 렌더합니다.
  PDF는 전 페이지를 이미지로 떠서 구조·시각 검사까지 통과해야 다운로드가 열립니다.
- **비용 상한과 동시 실행 제한** — 조사 1건마다 단계별 비용을 기록하고 상한에서 끊습니다.

## 빠르게 실행하기

Python 3.13이 필요합니다. **로컬 데모는 외부 API를 한 번도 부르지 않아 비용이 0원**이고,
서버를 내 컴퓨터에서만 엽니다.

```powershell
git clone https://github.com/Jhh-wW/company-analysis.git
cd company-analysis

# 가상환경은 ★저장소 루트★에 만든다 (app/ 안이 아니다)
py -3.13 -m venv .venv
.\.venv\Scripts\python -m pip install -r app\requirements.txt

cd app
.\로컬데모켜기.ps1
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 포트를 바꾸려면 `.\로컬데모켜기.ps1 -Port 8010`.
데모 기록은 `app/.local_demo/`에 격리되고, 관리자 화면은 실행 창에 찍힌 **로컬 전용 주소**로만
들어갑니다.

컨테이너로 빌드하려면:

```bash
docker build --file app/Dockerfile --tag company-analysis .
```

빌드 컨텍스트는 **저장소 루트**입니다. `app/`으로 좁히면 조사 엔진 복사가 깨집니다.
실행에 필요한 환경변수는 [`deploy/runtime-config.example`](deploy/runtime-config.example)에 있습니다.

## 어떻게 동작하나

```text
회사 이름 (+ 선택 주소 힌트)
        │
        ▼
  회사 후보 제시 ──── 사람이 법인을 확정한다 (같은 이름의 다른 회사 오인 방지)
        │
        ▼
  공식 근거 수집 ──── DART 전자공시 · 회사 공식 웹사이트 · IR 자료
        │
        ▼
  사실 원장 생성 ──── 문장마다 원문 위치를 붙이고, 사실마다 소유 장을 하나만 준다
        │
        ▼
  1~8장 작성 ──────── 원문 범위 안에서만 문장을 쓰고, 원문과 다르면 별도 검수를 건다
        │
        ▼
  9장 (조건부) ────── 양사 공식 원문이 같은 기준으로 있을 때만 비교한다
        │
        ▼
  출고 게이트 ─────── 목차·출처·수치·중복·금지문구·PDF 시각 검사
        │              (하나라도 실패하면 전체 차단)
        ▼
  웹 · PDF · Notion ── 같은 보고서 객체를 채널만 바꿔 렌더한다
```

![4단계 조사 진행 화면](docs/images/02-progress.png)

핵심은 **마지막에서 두 번째 칸**입니다. 검사에 하나라도 걸리면 «일부만 보여주기»를 하지 않고
전체를 막습니다. 반쯤 검증된 보고서는 검증된 것처럼 보이기 때문입니다.

## 기술적 선택과 근거

**뉴스 검색을 넣었다가 다시 뺐다**
처음에는 뉴스 검색으로 기사 후보를 모으고 AI가 고르게 했습니다. 그런데 실제로 돌려 보니
공개 사실 판정 단계에서 **뉴스 조각이 항상 폐기**되고 있었습니다. 효과 없이 AI 호출 1회와 입력
토큰만 늘리고 있어서, 공식 경로에서는 **검색 단계 자체를 제거**했습니다.
(근거: `app/src/features/pipeline/real.py`의 `6_수집_뉴스` 단계 주석)

**실패하면 전부 막는다(fail-closed)**
대안은 «통과한 장만 보여주기»였습니다. 하지만 그러면 검증에 실패한 이유가 화면에서 사라지고,
읽는 사람은 남은 내용을 «검증된 것»으로 받아들입니다. 그래서 검사 하나만 실패해도 보고서 전체를
`GATE_STOPPED` 합니다.

**SQLite + 단일 인스턴스**
동시 사용자가 적은 관리자 베타에서는 Postgres 운영 비용보다 단순함이 이득이라고 봤습니다.
대신 그 전제를 **말이 아니라 시험으로** 못 박았습니다 — `render.yaml`의 `numInstances: 1`과
영속 disk 설정을 시험이 직접 읽어 검사하고, 이 전제를 깨려면 무엇을 먼저 만들어야 하는지를
[배포 교체 계약](docs/architecture/deployment-contract.md)에 남겼습니다.

**레이어가 아니라 기능 단위로 나눴다**
`models/ services/ routers/`로 나누면 기능 하나를 고칠 때 폴더 세 개를 오갑니다. 그래서
`src/features/<기능>/` 안에 그 기능의 로직·상수·시험을 같이 뒀습니다.
버그가 생기면 **폴더 하나만 열면 됩니다.** ([ADR 0001](docs/adr/0001-feature-oriented-structure.md))

**기본값을 안전한 쪽에 뒀다**
외부 AI를 실제로 부르는 `real` 모드는 **코드 기본값이 아닙니다.** 코드 기본값은 비용 0인 `demo`이고,
운영 배포에서만 `render.yaml`이 `real`로 올립니다. 로컬에서 실수로 요금이 나갈 수 없습니다.

## 품질을 어떻게 지키나

자동 시험 **5,580건**이 통과합니다(2026-09-01 실측, 실패 0건).
시험 코드가 제품 코드보다 많습니다 — 제품 121,934줄 / 시험 122,442줄.

시험이 실제로 막아 주는 것은 이런 것들입니다.

- 원문에 없는 문장이 보고서에 들어가는 것
- 같은 사실이 여러 장에서 중복 소유되는 것
- PDF 페이지가 깨졌는데 다운로드가 열리는 것
- 배포 설정이 단일 인스턴스 전제를 깨는 것

```powershell
# 웹서비스 — ★ 반드시 app 폴더에서 돌린다
cd app
..\.venv\Scripts\python -m pytest -q -m "not local_integration"

# 조사 엔진 · 배포 계약 · 운영 절차
cd ..
.\.venv\Scripts\python -m pytest analysis_engine/src -q
.\.venv\Scripts\python -m pytest deploy ops -q
```

시험 의존성은 `.github\requirements-ci.txt`에 따로 있습니다.
`app/`에서 돌리는 이유는 `test_logic.py`라는 같은 이름의 파일이 두 폴더에 있어
저장소 루트에서는 수집이 중단되기 때문입니다.

GitHub Actions는 위 시험에 더해 **실제 Docker 이미지를 만들고 컨테이너를 띄워 `/readyz`
응답까지** 확인합니다.

## 저장소 구조

```text
├── app/                  운영 웹서비스 (FastAPI)
│   ├── src/features/     기능별 로직·상수·시험 — 버그는 여기서 폴더 하나만 연다
│   ├── src/core/         여러 기능이 실제로 공유하는 형식·경로
│   └── src/web/          HTTP·화면·라우팅·기능 조립
├── analysis_engine/      실제 조사 엔진 (DART·홈페이지 수집)
├── deploy/               컨테이너·배포 검증과 릴리스 계약
├── ops/                  배포·운영 절차와 그 절차를 지키는 시험
├── docs/                 보고서 정본 기준 · 아키텍처 · ADR
└── .github/workflows/    자동 시험과 컨테이너 스모크
```

## 한계와 다음 단계

**지금 안 되는 것**

- **일반 공개가 아닙니다.** `BETA_ADMIN_ONLY=1`로 관리자 계정만 들어갈 수 있는 베타입니다.
- **자동 배포를 꺼 뒀습니다.** 커밋을 올려도 반영되지 않고 사람이 직접 배포를 누릅니다
  (`render.yaml`의 `autoDeployTrigger: off`). 보고서 품질이 걸린 서비스라 의도한 설정입니다.
- **정기 작업(cron)이 아직 붙지 않았습니다.** 외부 백업·주간 관리자 리포트·휴지통 정리는
  코드와 인증 경로는 준비돼 있지만 스케줄이 선언돼 있지 않습니다.
- **수평 확장이 안 됩니다.** SQLite와 인메모리 작업 상태 때문에 인스턴스 1개가 계약입니다.

**다음 단계**

- 허용 사용자를 단계적으로 열어 실제 취업준비생 피드백 받기
- 정기 백업 스케줄 연결과 복구 리허설 자동화
